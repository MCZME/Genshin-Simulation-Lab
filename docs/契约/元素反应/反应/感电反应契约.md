## 2. 签名与双 Aura

| incoming_element | observed_aura_kind |
| --- | --- |
| `hydro` | `electro` |
| `electro` | `hydro` |

普通感电 occurrence 的 `ElementalTransitionEffect` 必须满足：

```text
incoming_consumed = 0
aura_consumed = 0
incoming_remaining = incoming_amount
aura_remaining = aura_amount
```

后手剩余量必须通过 `PersistentIncomingAuraApplicationEffect` 使用 `STANDARD_20_PERCENT` 损耗形成普通持久 Aura。已有 Aura 保留，最终形成水雷共存。ICD 后预算为零、缺少匹配的正 Aura 或同元素施加是正常空结果。

## 3. ElectroChargedState

目标级状态稳定字段：

```text
instance_ref
subject_ref
created_by_occurrence_ref
current_effect_owner
captured_scaling_basis
created_frame
next_tick_frame
next_tick_index
revision
```

约束：

- `captured_scaling_basis.source_ref` 必须等于 `current_effect_owner`；
- `next_tick_frame > created_frame`；
- `next_tick_index` 和 `revision` 必须为正整数；
- 同一主体只允许一个 `ReactionStateSlot.ELECTRO_CHARGED`；
- 状态不得保存或复制水雷 Aura 当前量；
- `next_required_frame` 等于 `next_tick_frame`。

首次建立创建新实例，`next_tick_frame = frame + 60`、`next_tick_index = 1`。活动状态再附着保留实例、创建信息和两个周期字段，只替换 `current_effect_owner`、`captured_scaling_basis` 并增加 revision；不得生成额外首次脉冲。

## 4. 周期根与因果

帧协调器必须先把 Aura 衰减到目标帧，再检查感电状态：

- 任一水雷 Aura 缺失时移除状态，不生成周期根；
- `next_tick_frame == frame` 时生成一个 `ElectroChargedTickRootWork`；
- 根生成后把状态游标推进到 `frame + 60` 和下一个 tick index；
- 不得跨过任一状态的 `next_required_frame`。

Root identity 必须由状态实例、帧和 tick index 确定性派生。周期 Effect 使用 `ScheduledStateTickCause`，`parent_occurrence_ref = None`，不得为周期伪造新的 occurrence。

Scheduled adapter 只接受仍存在且实例一致的状态；状态已结束时返回 `cancelled_state_ended`，不得产生 Effect Group。

## 5. Damage Effect 与公式

首次和周期 `GeneratedDamageImpactEffect` 都必须显式冻结：

```text
damage_element = electro
transformative_base_multiplier = 2.0
elemental_amount = 0
can_crit = false
strike_type = None
```

协调器不得按 `reaction_key`、`damage_kind_key` 或 Damage Profile 推导基础倍率。共享公式为：

```text
mastery_bonus = 16 * EM / (EM + 2000)

damage =
    level_multiplier
    * 2.0
    * (1 + mastery_bonus + reaction_bonus)
    * electro_resistance_multiplier
```

当前捕获基础固定 `reaction_bonus = 0.0`。90 级角色、`EM = 0`、抗性乘数 `1.0` 的 golden 值为：

```text
1446.853 * 2.0 = 2893.706
```

伤害不读取攻击力、普通技能倍率、普通伤害加成、暴击或标准防御区。共享输入与审计遵守[剧变反应伤害契约](../剧变反应伤害契约.md)。

## 6. Damage Gate 与条件消费

```text
window_frames = 30
max_damage_instances = 1
```

首次、周期和传导伤害共享同一 Gate Definition 与 damage kind；不同来源或不同目标独立分槽。

目标通过 Gate 且同时存在有效感电状态、正水 Aura 和正雷 Aura 时：

```text
consume hydro by min(current_hydro, 2/5 GU)
consume electro by min(current_electro, 2/5 GU)
```

消费后任一 Aura 消失必须在同一脉冲计划中移除状态。Gate blocked 时不得产生 Damage、消费 Aura 或接管状态来源，但已物化周期根的游标不回退。

## 7. 传播

`ElectroChargedPropagationSelection` 固定：

```text
radius = 13.0
geometry = circle_xz
sort = primary_then_subject_ref
```

主目标始终为第一个候选；其他候选必须具有正水 Aura，并按主体引用稳定排序。每个候选独立检查 hostile 关系、Damage capability 和 Damage Gate。

水单 Aura 目标通过 Gate 后只受到零元素量单体雷伤，不消费水、不施加雷、不创建状态。

已有感电状态的传播目标通过 Gate 后执行双 Aura 消费；消费后仍成立时保留实例和 tick index，替换效果来源与捕获基础，设置 `next_tick_frame = current_frame + 60` 并增加 revision。该接管不创建 occurrence。

主目标关系不合法或失去 Damage capability 时移除其感电状态。单个传播目标正常阻止不得撤销同组其他目标。

## 8. 多 Aura 顺序

水雷共存组合由 Reaction Runtime 公共候选拥有，不得由感电机制目录调用其他机制 Runtime：

- 火、冰、岩先处理雷；火或冰只有在雷耗尽且预算仍有剩余时继续处理水；
- 冰同时完成超导与冻结时，超导 Damage Effect 被显式抑制，超导 occurrence 与 Status Effect 保留；
- 风的水雷双扩散和草的感电目标组合使用各自后续版本已经冻结的 DecisionSequence；
- 任一步骤使水或雷消失时，主交互最终投影必须移除感电状态。

## 9. 事务、事实与失败

一个感电脉冲 Effect Group 必须在首次写入前冻结目标集合并完整准备逐目标 Gate、条件 Aura 消费、State 移除或接管以及统一 Damage Impact。Aura 和 `ReactionStoreMutationPlan` 必须全部预校验，Damage 记录必须在提交前准备完成。

Gate blocked、关系不适用、capability 缺失和 scheduled state 已结束是正常结果。缺少 Aura/Reaction/Damage/Space 端口、错误 Effect 类型、错误 damage kind、来源缺少 owner slot、stale plan 或非法倍率必须在事实发布前失败。

首次建立和再附着 occurrence 发布 `REACTION_OCCURRED`；周期根不发布该事实。状态、Aura、Damage 和最终 batch 事实只描述已提交结果。
