# 元素反应公共模型契约

> 状态：已实现。本文冻结当前元素交互型、状态型和即时 Effect 反应共享的 Reaction 公共字段。

最后更新：2026-08-01

## 1. 文本、身份与精度

- 所有 `*_key`、`*_ref`、`interaction_id` 和 `operation_id` 必须是非空文本。
- `reaction_key` 标识反应机制，`handler_key` 标识代码实现，两者不得混用。
- `direction_key` 在单个 Definition 内唯一。
- `profile_key` 全局使用稳定命名，不由显示名称或注册顺序推导。
- 元素量使用 `AuraAmount` 精确值；反应消费与归零不得用浮点比较决定。
- `target_impact_ref` 关联目标级 Impact，不作为批次或请求幂等身份。

## 2. ReactionTriggerSignature

稳定字段：

```text
incoming_element: Element
observed_aura_kind: AuraKind
direction_key: str
```

含义：一个明确的后手元素与先手 Aura 组合映射到一个方向。普通蒸发、融化不使用“任意可反应元素”回退签名。

## 3. AmplifyingReactionProfile

稳定字段：

```text
profile_key: str
reaction_key: str
direction_key: str
trigger_element: Element
base_multiplier: float
```

约束：

- `base_multiplier` 必须是正数；
- `trigger_element` 必须与方向签名的后手元素一致；
- Profile 的 `reaction_key`、`direction_key` 必须指向所属 Definition；
- Profile 不保存元素精通或最终伤害乘数。

当前代码保留 `ReactionProfile` 作为 `AmplifyingReactionProfile` 的兼容公共名；新文档和新代码优先使用强类型名称。

## 4. TransformativeReactionProfile

稳定字段：

```text
profile_key: str
reaction_key: str
direction_key: str
trigger_element: Element
damage_profile_key: str
damage_element: Element
base_multiplier: float
gate_definition_key: str
damage_kind_key: str
```

Profile 只冻结剧变 Damage 的稳定定义引用和倍率，不保存空间目标、Gate Record、最终伤害或 Buff 类型。`base_multiplier` 必须为正，并由机制生成的 Damage Effect 显式携带给协调器。

`ReactionProfileVariant` 当前至少包含：

```text
AmplifyingReactionProfile | TransformativeReactionProfile | StateReactionProfile | ...
```

`StateReactionProfile` 稳定表达不直接修改当前伤害的持续状态方向：

```text
profile_key
reaction_key
direction_key
trigger_element
```

## 5. ReactionDefinition

稳定字段：

```text
reaction_key: str
handler_key: str
trigger_signatures: tuple[ReactionTriggerSignature, ...]
profiles: tuple[ReactionProfileVariant, ...]
rule: InteractionReactionRule
entry_kind: ReactionEntryKind
```

元素交互型 Definition 约束：

- `trigger_signatures` 与 `profiles` 均非空；
- 签名内 `direction_key` 不重复；
- Profile 方向集合与签名方向集合完全相等；
- `profile_for(direction_key)` 只能返回已声明方向；
- Registry 中 `reaction_key` 不得重复。

`entry_kind = STATE_TRIGGER` 的 Definition 可以不声明元素签名和方向 Profile，但必须由规则检查强类型状态资格。普通碎冰使用该入口。

## 6. ReactionEvaluationRequest

普通蒸发、融化依赖的稳定字段：

```text
interaction_id: str
target_impact_ref: str
frame: int
order: int
source_ref: ElementalSourceRef
subject_ref: ElementalSubjectRef
incoming_element: Element | None
incoming_amount: AuraAmount
observed_aura: AuraView
current_damage_element: Element | None
transformative_source_observation?
trigger_context?
observed_frozen_state?
freeze_resistance_observation?
```

约束：

- `frame`、`order` 为非负整数；
- `incoming_amount` 不得为负；
- `incoming_element is None` 时不得伪造正元素施加型反应；
- `observed_aura` 是只读观察，Reaction 不持有 Aura MutationPlan；
- 同一 `ReactionBatchPlanner` 中 `interaction_id` 与 `order` 各自唯一；
- 即时剧变反应需要中立、强类型的来源观察；
- 零元素量不能形成元素施加型反应，但 `trigger_context.strike_type` 等稳定证据可以形成状态型反应。
- `ReactionTriggerContext` 至少包含正元素施加或 `strike_type` 之一；物理不进入 `Element`；
- `observed_frozen_state` 必须与 `observed_aura` 中的 `FROZEN` Component 通过同一 Link 对应；
- `FreezeResistanceObservation` 的主体和帧必须与请求一致，值域为 `[0, 1]`。

## 7. ElementalTransitionEffect

稳定字段：

```text
aura_kind: AuraKind
incoming_before: AuraAmount
incoming_consumed: AuraAmount
incoming_remaining: AuraAmount
aura_before: AuraAmount
aura_consumed: AuraAmount
aura_remaining: AuraAmount
```

必须满足：

```text
incoming_remaining = incoming_before - incoming_consumed
aura_remaining = aura_before - aura_consumed
0 <= incoming_consumed <= incoming_before
0 <= aura_consumed <= aura_before
```

当前模型没有 `matched_component_ref`。消费者不得依赖临时文档中的旧草图字段。

## 8. ReactionOccurrence

普通蒸发、融化使用的稳定字段：

```text
occurrence_ref: str
interaction_id: str
reaction_key: str
direction_key: str
profile_key: str
source_ref: ElementalSourceRef
subject_ref: ElementalSubjectRef
transition: ElementalTransitionEffect
effect_groups: tuple[ReactionEffectGroup, ...]
```

普通蒸发、融化的 `effect_groups` 为空。普通超载、超导各冻结一个 Effect Group。`occurrence_ref` 必须稳定关联所属 interaction 和顺序，且不能与父 occurrence 自引用。

## 9. Reaction Effect Group

`ReactionEffectGroup` 稳定表达：

```text
effect_group_ref
cause / parent_occurrence_ref
execution_scope
emission_order
target_selection
effects
```

即时剧变使用 `execution_scope = next_settlement_round`。group 与 effect 是不可变计划数据，不持有 Runtime、Store、Protocol 或回调。

第二版直接使用：

```text
AreaAroundSubjectSelection
GeneratedDamageImpactEffect
ReactionStatusEffect
CapturedTransformativeScalingBasis
```

范围选择保存稳定锚点、半径、几何、资格策略和排序策略。Damage Effect 的共享缩放字段与校验见[剧变反应伤害契约](./剧变反应伤害契约.md)；超导 Status Effect 的数值见其专门契约。

## 10. CurrentImpactDamageAdjustment

稳定字段：

```text
target_impact_ref: str
occurrence_ref: str
reaction_profile_key: str
trigger_element: Element
base_multiplier: float
reaction_bonus: float = 0.0
```

`base_multiplier` 必须为正。该对象只表达 Reaction 对当前关联伤害的调整意图，最终公式和属性读取属于 Damage。

## 11. DecisionSequence

`ReactionDecisionStep` 至少保存：

```text
step_ordinal
selected_candidate_keys
elemental_transition_effects
state_transition_effects
occurrences
state_planning_intents
```

约束：

- `selected_candidate_keys` 非空且不重复；
- `step_ordinal` 从 `0` 连续编号；
- `ReactionDecisionSequence.steps` 保持已决策顺序；
- 普通蒸发和融化各形成单步骤、单 occurrence；
- 状态型候选可以先修改虚拟 Aura/State，再让后续步骤读取投影；
- 无反应使用空序列，不使用伪 `NO_REACTION` occurrence。

## 12. ReactionResolution

稳定字段：

```text
request
occurrence?
damage_adjustment?
decision_sequence?
generated_impact_batches
establishment_gate_resolutions
```

约束：

- 有 occurrence 时，它必须等于规范化序列中的第一个 occurrence；
- `damage_adjustment` 只能引用当前决议中的 occurrence；
- 普通蒸发、融化的 `generated_impact_batches`、Effect Group 和成立 Gate 为空；
- 普通超载、超导通过 occurrence 的 Effect Group 输出后续工作，不直接创建 DamageRequest；
- 无匹配返回空序列和空 adjustment。
