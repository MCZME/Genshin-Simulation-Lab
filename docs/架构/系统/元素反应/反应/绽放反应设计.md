# 绽放反应设计

> 状态：已实现（普通绽放、绽放爆炸、超绽放、烈绽放）
> 最后更新：2026-08-02
> 对应契约：[绽放反应契约](../../../../契约/元素反应/反应/绽放反应契约.md)

## 1. 定位

普通绽放是一个共享草原核状态和后续效果的机制簇，包含四个 Reaction Definition：

- 普通绽放 `Bloom`：水与普通草或激元素、或普通草与水的正向交互，创建一枚草原核；
- 绽放爆炸 `Bloom Explosion`：草原核自然到期或容量淘汰后的终态效果；
- 超绽放 `Hyperbloom`：雷元素接触活动草原核，终结草原核并按锁定目标创建蔓生弹；
- 烈绽放 `Burgeon`：火元素接触活动草原核，终结草原核并在其位置产生范围伤害。

四者不能拆成互相直接调用的独立状态机。Reaction 拥有草原核、蔓生弹、终态竞争、反应 occurrence 和后续 Effect 声明；Aura、Space、Damage、Health 与协调器仍拥有各自领域的运行时真值。

月绽放是与本机制簇并列的独立反应，不归入普通绽放机制目录；其候选、草露资源和月曜伤害见[月绽放反应设计](./月绽放反应设计.md)。月绽放与普通绽放通过中立的草原核创建计划共享元素消费、`DendroCoreState` 和 Space 创建声明，但两个机制的 Definition、Rule、Profile 和 Damage 路径相互独立。

## 2. 领域所有权

| 领域 | 绽放相关职责 |
| --- | --- |
| Aura | 普通草、水、雷和 `QUICKEN` 的元素量、贡献账本、精确消费与后值 |
| Reaction | 四个 Definition、2:1 消费、草原核/蔓生弹 State、容量、终态、Gate 和 Effect 声明 |
| Space | `REACTION_OBJECT` 的位置、生命周期投影、核心接触解析、范围查询和目标候选 |
| Impact | 元素命中已经接触的核心引用及关联 Impact 事实 |
| Damage | 剧变公式、实时属性、受方抗性、伤害结果和专属伤害分类 |
| Health | 当前场上角色的生命、护盾和受伤事实；普通目标没有生命真值 |
| Coordination | 将 Aura/Impact/Space 证据编排成 Reaction 计划，并以批次原子提交 |

Reaction 不直接读取 Attribute Runtime，不直接修改 Aura、Space、Damage 或 Health，也不在提交阶段重入其他系统。跨系统写入统一经过 `core/coordination/elemental_reaction/` 的窄协议。

## 3. 稳定 Definition 与元素消费

绽放机制簇 Definition 由 `create_default_reaction_bootstrap()` 组合进当前生产 Registry。稳定反应键和方向如下：

```text
reaction.bloom       / reaction_handler.bloom
reaction.bloom_explosion / reaction_handler.bloom
reaction.hyperbloom  / reaction_handler.hyperbloom
reaction.burgeon     / reaction_handler.burgeon

incoming_hydro_on_dendro
incoming_hydro_on_quicken
incoming_dendro_on_hydro
incoming_electro_on_core
incoming_pyro_on_core
```

设后手实际预算为 `T`、先手可用量为 `A`：

```text
水触发草或激元素：
hydro_used        = min(T, 2 * A)
dendro_like_used = hydro_used / 2

草触发水：
dendro_used = min(T, A / 2)
hydro_used  = dendro_used * 2
```

两侧实际消费均为正时才产生普通绽放 occurrence；正元素施加即使没有伤害也可以成立。普通绽放不直接造成伤害，反应量不改变草原核的持续时间、容量或终结伤害。

`QUICKEN` 作为类草元素参与上述方向，但其 Aura 的建立、覆盖和衰减仍由激化机制拥有。交互中前置候选留下的预算只能作为后续候选的输入，不能重新读取初始 Aura 或递归重入 Reaction。

## 4. 草原核状态与空间实体

### 4.1 DendroCoreState

每个正普通绽放 occurrence 原子创建一份 `DendroCoreState`：

```text
DendroCoreState
├── instance_ref
├── subject_ref
├── space_entity_ref
├── created_by_occurrence_ref
├── core_creator_ref
├── dynamic_scaling_basis
├── pool_scope = player_team
├── created_frame
├── expires_at_frame = created_frame + 360
├── creation_sequence
└── revision
```

State 只保存稳定身份、来源和生命周期锚点，不保存 Aura、元素量、生命值、等级、EM 或伤害快照。引用使用确定性规则：

```text
reaction-state:dendro-core:<created_by_occurrence_ref>
reaction_object:dendro_core:<created_by_occurrence_ref>
```

草原核有效区间为 `[created_frame, expires_at_frame)`；到期帧先执行终态工作，再处理同帧后续元素命中。`next_required_frame` 固定为 `expires_at_frame`。终态不写入活动 State 的生命周期字段，而通过终结 receipt/fact 记录。

### 4.2 容量

玩家队伍共享 `pool_scope = player_team` 的活动草原核池，容量为 `5`。创建第六枚时按 `(creation_sequence, instance_ref)` 的稳定顺序淘汰最老活动核心。淘汰与新核心创建、Space 移除、绽放爆炸 occurrence 在同一批次提交；不存在独立的第二份核心数量真值。

### 4.3 Space Entity

核心使用 `SpatialEntityKind.REACTION_OBJECT` 投影到 Space：

```text
entity_ref = reaction_object:dendro_core:<created_by_occurrence_ref>
binding_ref = core.instance_ref
lifecycle = [created_frame, expires_at_frame)
```

Space Entity 只提供核心存在性、接触引用、终结位置和范围查询锚点，不模拟移动、吸引、碰撞体、遮挡、投射物阻挡、普通 Aura 或普通受击。

## 5. 核心终态竞争

活动核心只有一个成功终态：

```text
EXPIRED
CAPACITY_EVICTED
HYPERBLOOM_TRIGGERED
BURGEON_TRIGGERED
```

终态提交必须同时移除活动 State、容量索引、到期工作和对应 Space Entity，并保留 `termination_reason`、来源、帧、occurrence 与 Effect 关联。核心终结是幂等的；过期、已终结或 stale 的引用不会重复产生伤害。

核心自然到期与容量淘汰都产生同一个绽放爆炸 Profile，只在事实中区分终态原因。雷、火接触与自然到期没有隐式优先级；同帧按稳定影响顺序，第一个成功请求取得终态，后续请求看到已终结核心并跳过。

## 6. 核心接触协调

元素命中或 Space 影响解析层负责确定实际接触的核心；Reaction 不从位置或攻击几何自行推断。请求的稳定形状为：

```text
BloomCoreTriggerRequest
├── operation_id
├── frame
├── source_ref
├── incoming_element
├── incoming_amount
├── contacted_core_refs
├── associated_impact_ref
└── source_context
```

只有正雷或正火请求进入核心终态流程。零量、草、水、冰、风和岩请求稳定为空决议，不要求关联 Impact。正雷/正火请求必须带 `associated_impact_ref`，并通过协调器注入的 `CommittedElementalImpactEvidencePort` 做一致性校验：已提交证据的帧、来源、元素和元素量必须分别与请求完全相等。缺失、未知或不匹配均在状态/空间计划提交前失败。

一次请求可以终结所有明确接触且仍为活动状态的核心；元素量不会按核心数量重复消耗。请求以 `operation_id` 幂等，非活动核心被跳过，不影响其他活动核心。核心引用必须同时通过 ReactionState 与 Space binding 校验，不能用调用方自造位置或未提交的引用替代。

## 7. 绽放爆炸

自然到期或容量淘汰后，在核心终结位置产生独立的 `GeneratedDamageImpactEffect`：

```text
profile = reaction_profile.bloom_explosion.core_termination
damage_profile = damage_profile.reaction.bloom_explosion
damage_kind = reaction_damage.bloom_explosion
```

伤害语义：

- 来源为 `core_creator_ref`，在实际 Damage 准备时读取该来源当前等级、EM 和反应加成；
- 怪物受方倍率 `2.0`，角色受方倍率 `0.1`；
- 以核心位置为中心，范围半径 `5m`；
- 元素为草，元素量为 `0`，不可暴击，不附着草元素，也不继续触发反应；
- 使用 `TRANSFORMATIVE_REACTION`、近似单位防御乘数，并不产生削韧、硬直、击退或其他控制效果。

## 8. 烈绽放

正火接触活动核心时，核心进入 `BURGEON_TRIGGERED`，然后产生烈绽放 occurrence 和独立伤害 Effect。Effect 使用：

```text
profile = reaction_profile.burgeon.incoming_pyro_on_core
damage_profile = damage_profile.reaction.burgeon
damage_kind = reaction_damage.burgeon
```

来源为火元素触发者，而不是核心创建者；伤害准备时动态读取火触发者的等级、EM 和反应加成。怪物/角色倍率分别为 `3.0 / 0.15`，范围半径 `5m`，其余元素、暴击、防御和控制语义与绽放爆炸相同。由扩散派生的火元素命中时，沿用该次派生施加的稳定来源。

## 9. 超绽放与蔓生弹

正雷接触活动核心时，核心进入 `HYPERBLOOM_TRIGGERED`，产生超绽放 occurrence。以终结核心的位置在当前 Space 的 X/Z 平面查询最近合法敌方目标，已确认索敌数据为 `15,15`，当前运行时为包含边界的半径 `15m`：

```text
order = distance, stable_subject_ref
limit = 1
```

无合法目标时，核心仍被消费、occurrence 仍成立，但不创建蔓生弹或伤害工作。目标在触发时锁定，之后不换目标。由扩散派生的雷元素命中时，使用该派生施加的稳定来源。

有目标时创建：

```text
SprawlingShotState
├── instance_ref
├── space_entity_ref
├── source_core_ref
├── trigger_occurrence_ref
├── trigger_source_ref
├── dynamic_scaling_basis
├── selected_target_ref
├── created_frame
└── revision
```

蔓生弹不声明固定飞行时长、速度、轨迹或转向。`SprawlingShotResolutionPort` 只接受 `ARRIVED | LOST`：

- `ARRIVED` 使用调用方提供的命中位置，在半径 `1m` 内对锁定目标产生超绽放伤害；
- `LOST` 只原子终结蔓生弹 State 和 Space Entity，不换目标、不造成伤害；
- 两种结果都由 `operation_id` 幂等处理；
- `ARRIVED` 时才读取雷触发者的当前等级、EM 和反应加成。

超绽放 Effect 使用：

```text
profile = reaction_profile.hyperbloom.incoming_electro_on_core
damage_profile = damage_profile.reaction.hyperbloom
damage_kind = reaction_damage.hyperbloom
```

怪物/角色倍率为 `3.0 / 0.15`，元素为零量草，使用剧变公式、不可暴击和近似单位防御。

## 10. 共享伤害与 Gate

三种终结伤害复用同一剧变公式：

```text
mastery_bonus = 16 * EM / (EM + 2000)
damage_before_resistance =
    level_multiplier * reaction_multiplier
    * (1 + mastery_bonus + reaction_bonus)
```

第九版 `reaction_bonus = 0.0`；实际受方草抗性独立结算。三种 Effect 保留专属 `reaction_damage.*` 分类，但 Gate 使用统一的 `bloom_family`：

```text
window_frames = 30
max_damage_instances = 2
scope = damage_source_ref + target_ref + bloom_family
gate = reaction_gate.bloom_family.damage
```

绽放爆炸来源为核心创建者，超绽放来源为雷触发者，烈绽放来源为火触发者。Gate 在每个候选目标实际准备伤害时检查；被 Gate 阻止只取消该目标的 Damage Effect，不撤销核心终态、occurrence、Space 移除或蔓生弹创建。

`reaction_damage.bloom_explosion`、`reaction_damage.hyperbloom`、`reaction_damage.burgeon` 只负责 Damage 分类和审计，不能被 `bloom_family` 统一 key 替代。

普通目标只得到 `DamageResult`；当前场上角色通过既有角色受伤协调器应用生命/护盾变化。Reaction 不直接扣血，也不为普通目标新增生命状态。

## 11. 复合顺序、事务与事实

感电目标同时存在正水和正雷时受到正草，按已确认顺序在同一 interaction 中执行：

```text
草 + 雷 -> 原激化
草 + 水 -> 第一个普通绽放
新激元素 + 剩余水 -> 第二个普通绽放
```

每个普通绽放 occurrence 都独立创建核心；只使用前一步的逻辑后值，不透支元素预算。

普通绽放与核心接触均遵循 `prepare -> validate -> commit`：Aura 后值、ReactionState、Space binding、到期工作、occurrence、Effect 和 Gate 预留在提交前完成校验，任何 stale 或证据不一致都不能留下部分写入。Commit 阶段不重新查询属性、空间或调用 handler。

使用通用事实记录已发生事件，包括：

```text
REACTION_OCCURRED
REACTION_STATE_CHANGED
DAMAGE_RESOLVED
ELEMENTAL_INTERACTION_RESOLVED
```

事实和终结 receipt 至少关联 reaction key、occurrence、来源、目标、核心/蔓生弹、终态原因、Effect、帧和是否被 Gate 阻止；不新增机制专属 EventType。

## 12. 月绽放

月绽放是独立反应，不归入本机制簇。其候选、参与者冻结、草露资源、月曜伤害和验收入口见[月绽放反应设计](./月绽放反应设计.md)。

## 13. 当前边界与验收入口

本版不实现丰穰之核、角色专属强制引爆、角色专属草露消费、草原核移动/聚集/碰撞/阻挡、蔓生弹真实运动、特殊目标索敌表、联机受方、非零专属反应加成、特殊暴击、削韧、硬直、击退和空间位移。

主要验收入口：

- `tests/unit/core/systems/reaction/test_bloom_mechanic.py`
- `tests/golden/reactions/test_quicken_and_bloom.py`

长期机制真值以本设计、对应契约、生产代码和 golden case 共同验证；第九版规划与临时记录只保留交付历史。
