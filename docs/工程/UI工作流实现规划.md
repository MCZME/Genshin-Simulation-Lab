## 1. 目标

- 工作流是 UI 产品面；CLI 不提供工作流的创建、校验或运行。
- 后端不实现工作流图引擎，只做工作流 JSON 不透明存档、已展开成员校验与批次运行。
- 前端拥有图语义：区域、节点、连线、校验、片段合并、变体展开、成员预览。
- 第一条纵向链路：根节点 → 配置区域（含枚举/区间）→ 模拟节点 → 结果摘要。

### 切片 1：后端批次执行模型（已完成）

- 落点：`application/batch/`、`application/services/`、`application/facade.py`。
- 内容：
  - 定义 `BatchMember`、批次状态视图与 `BatchRunService`。
  - 继续复用现有单任务 `SimulationJobRunner` 与 worker，批次层只做 `run_id -> member_id -> job_id` 映射、并发、取消和状态派生。
  - 支持 `POST /inputs/validate` 所需的已展开成员校验：结构校验、`item_id` 唯一、成员上限 200、资产存在性与可运行性。
  - facade 增加成员校验、提交批次、查询批次、取消批次能力。
- 验收：
  - 成员顺序与提交顺序一致。
  - 成功、部分失败、全部失败、取消均可通过状态视图表达。
  - 排队成员立即取消；运行中成员进入 `stopping`，跑完标 `cancelled`。
  - 任一份输入失败时批次不提交，并返回带 `item_id` 的诊断。
  - 超过 200 个成员被拒绝。
- 验证：批次服务专项测试、facade 批次集成测试，以及 application、任务 runner 和进程 worker 回归测试均已通过。

### 切片 9：区域运行与校验阶段（已完成）

- 落点：`frontend/src/workflow/runner.ts`、`frontend/src/workflow/asset_preflight.ts`（新增）、`frontend/src/state/run_state.ts`、`frontend/src/app/App.tsx`、`frontend/src/components/canvas/RegionNode.tsx`、`frontend/src/components/canvas/CanvasView.tsx`、`frontend/src/components/panels/RegionSummaryBar.tsx`。
- 内容（决策 2.40）：
  - 校验边界：节点校验（实时参数/路径诊断 + 加载时资产预检，不含槽位冲突等跨节点检查）；区域校验（跨节点统一校验，含冲突检测与成员展开）并入运行/校验流程的构建阶段，不再独立。
  - 区域运行只被目标区域内节点、连线及所连模拟节点的错误诊断阻断；其他区域节点错误（含失效资产）不阻断区域运行。
  - `planRegionRun`：区域范围运行计划（成员仅来自该区域，批次为连接该区域的模拟节点）；`planRegionCheck` 与独立检查流程移除。
  - 共用执行编排：全部运行与区域运行共用「构建限速动画 → 批次区域校验 → 提交 → 轮询 → 终态联动」；批次提交前区域校验（「校验中」步骤，失败标「失败」并附成员级聚合错误，「跳过」仍专指取消）。
  - 区域头部入口为「区域校验」+「区域运行」；「区域校验」是区域运行的子集，复用区域计划与构建动画，逐批校验后终止于「校验完成」，不提交批次、不创建结果；`regionChecks` 状态与区域摘要条检查展示移除。
  - 失败呈现：区域校验/构建阶段诊断（含跨节点错误与成员级校验诊断）进入问题面板并自动打开；顶部横幅只用于操作类错误；存在校验失败时运行结束不自动切换结果面板。
  - 加载/切换工作流时对全部资产引用批量预检，失效引用出 `ASSET_NOT_FOUND` 诊断并阻断运行。
- 验收：
  - 区域运行复用运行动画、置灰与取消交互；全部运行中某区域校验失败时该批失败、其余批次照跑。
  - 「区域校验」入口完成构建与逐批校验后停止，不触发模拟提交；通过批次显示「校验通过」。
  - 区域校验/构建失败在问题面板展示并自动打开，不显示顶部横幅。
  - 失效资产引用在工作流加载后出现于问题面板。
- 验证：`pnpm lint`（0 error；1 个既有 `initialize` hook 依赖警告）、`pnpm typecheck`、`pnpm test`（25 个文件 213 个用例）均通过。新增 `asset_preflight` 单元测试与 App 运行编排壳测试，覆盖资产引用收集/精确匹配/诊断生成、`planRegionRun` 批次构成、`scopedDiagnostics` 区域过滤、`validating`/`validated` 状态、节点级实时诊断不含跨节点槽位冲突、区域校验入口不提交模拟且不展示模拟进度、区域运行校验失败展示成员级诊断并进问题面板、构建阶段跨节点失败进问题面板且不显示顶部横幅、全部运行中某区域校验失败后其余批次照跑，以及其他区域失效资产不阻断目标区域运行。

## 5. 已确认结论

1. **批次状态生命周期**：第一版使用 `BatchRunService` 内存注册表，服务重启后旧批次不可查；后续若要求重启恢复，再独立设计批次库，不提前做。
2. **区间十进制实现**：区间序列使用十进制算术计算，避免 IEEE 754 浮点累积误差；“下一步 ≤ 终点即包含”；具体规则见[批量配置变体契约](../契约/批量配置变体契约.md)，保证成员顺序与 `item_id` 测试稳定。
3. **切片 4、5 连续开发**：切片 4 与 5 合并为同一开发阶段，内部保留“图语义编译”与“画布纵向链路”两个验收里程碑；工程搭建并入切片 4 第一项内容。合并只影响开发组织与排期，不改变代码边界——语义层保持纯 TypeScript 可单测，画布层只做展示与交互。

## 6. 主要风险

- 资产可运行性校验已在切片 1 接入资产仓库与内容注册表；对外诊断与 HTTP DTO 均不暴露 `handler_key`。
- 前端编译器与后端输入校验可能产生两套校验口径；以 `POST /inputs/validate` 为最终执行校验，前端诊断只负责提前反馈。
- 批次层复用单任务 runner 时不要跨进程共享 SQLite 连接或已组装运行时对象。
- 画布交互是产品复杂度较高的部分，切片 5 只覆盖第一条纵向链路，避免在 MVP 阶段铺开全部画布外围功能。
- 连续开发阶段内必须守住切片 4 的纯 TS 测试门槛：图语义、校验与变体编译先于画布组件完成并单测通过，避免语义逻辑与 React 组件耦合后回归成本上升。
