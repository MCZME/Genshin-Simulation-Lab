# 资产系统设计

本文档记录资产系统的架构边界、数据流和模块职责。资产数据库的字段、manifest 形状和校验规则见：[资产数据库契约](../契约/资产数据库设计.md)。

## 1. 定位

资产系统负责把外部静态数据转换为项目内部可验证、可分发、只读的资产库，并在仿真组装阶段提供资产读取能力。

资产系统不负责实现具体角色、武器、圣遗物机制。数据库只保存基础索引、等级属性、倍率表、效果参数和 `handler_key`，真实行为由 `content/` 中的 handler 实现。

## 2. 分层

资产系统分为五层：

```text
外部源站 raw JSON
-> source cache
-> 标准资产 manifest
-> SQLite 资产库
-> AssetRepository 协议
```

- 外部源站 raw JSON：来自 Project Amber / Yatta 当前默认 API。
- source cache：开发期本地缓存，用于调试转换器和追溯源字段。
- 标准资产 manifest：源站无关的资产导入边界。
- SQLite 资产库：正式运行时携带的只读生成产物。
- `AssetRepository`：应用和组装层读取资产的稳定协议。

正式发布和运行时只依赖 SQLite 资产库，不依赖 source cache。

## 3. 模块职责

### 3.1 `assets/`

`assets/` 保存资产领域对象与读取协议：

- `CharacterAsset`
- `CharacterLevelStats`
- `WeaponAsset`
- `WeaponLevelStats`
- `ArtifactSetAsset`
- `ArtifactSetBonus`
- `TalentScalingEntry`
- `EffectPayload`
- `AssetRepository`

`assets/` 不读取 SQLite，不抓取网络数据，也不实现导入流程。

### 3.2 `infrastructure/assets_project_amber/`

`assets_project_amber/` 是 Project Amber / Yatta 的源站适配层。

职责：

- 抓取源站当前默认 API 响应。
- 保存开发期 raw JSON cache。
- 把 raw JSON cache 转换为标准资产 manifest。

转换器按职责拆分：

```text
converter.py   -> manifest 构建编排与 meta
_common.py     -> JSON 读取、校验、曲线和文本数字通用工具
_indexes.py    -> 角色、武器、圣遗物基础索引
_characters.py -> 角色等级属性、天赋倍率、角色效果参数
_weapons.py    -> 武器等级属性、武器效果参数
_artifacts.py  -> 圣遗物套装效果参数
fetcher.py     -> 源站抓取与 source cache 写入
```

该层只认识源站字段，不直接写 SQLite。

### 3.3 `infrastructure/assets_sqlite/`

`assets_sqlite/` 是 SQLite 资产库适配层。

职责：

- 定义和初始化资产库 schema。
- 读取标准资产 manifest。
- 审计 manifest 数据质量。
- 把 manifest 原子化写入 SQLite。
- 校验 SQLite 资产库。
- 实现 `SQLiteAssetRepository`。

该层不实现具体游戏机制。

### 3.4 `application/`

`application/` 通过 `AssetRepository` 读取资产，并在仿真组装阶段解析资产引用。

组装阶段负责把：

```text
asset_key -> 资产对象 -> handler_key -> content handler
```

连起来。缺资产、缺 handler 或 JSON payload 不合法，应在组装阶段报错。

### 3.5 `content/`

`content/` 读取资产对象中的 `handler_key`、`TalentScalingEntry` 和 `EffectPayload`，实现真实机制。

`content/` 不访问 SQLite，也不从源站字段推断数据来源。

## 4. 数据构建流程

开发期完整流程：

```text
genshin-sim assets fetch-source
-> data/assets/sources/project_amber_yatta/...
-> genshin-sim assets build-manifest
-> data/assets/manifests/project_amber_yatta.json
-> genshin-sim assets audit-manifest
-> genshin-sim assets build --manifest
-> data/assets/assets.db
-> genshin-sim assets validate
```

`assets build --manifest` 先写临时数据库，校验通过后再替换目标库，避免留下半成品资产库。

`assets build` 无 `--manifest` 时只生成最小烟测库，用于开发闭环，不代表真实资产导入。

## 5. 数据来源边界

第一版正式数据来源为 Project Amber / Yatta 当前默认数据。

source cache 是开发期中间产物：

- 可以保存到本地用于调试。
- 不进入正式发布包。
- 不写入 SQLite 资产库表。
- 不作为运行时依赖。

SQLite 资产库通过 `source_name`、`source_version`、`source_language`、`data_version`、`importer_version`、`built_at` 和 `content_hash` 标识构建来源。

## 6. 导入范围

当前 Project Amber / Yatta 转换器导入：

- 角色基础索引。
- 角色 `1-90 + 95 + 100` 等级属性。
- 角色普通攻击、元素战技、元素爆发核心倍率。
- 角色固有天赋、特殊天赋和命座效果参数。
- 武器基础索引。
- 武器等级属性。
- 武器精炼效果参数。
- 圣遗物套装基础索引。
- 圣遗物套装件数效果参数。

未实现真实机制的效果参数使用显式 `*.unimplemented_*` handler 标记。这表示数据已入库，但机制尚未实现。

## 7. 运行时读取

运行时只通过 `AssetRepository` 读取资产：

```text
get_meta()
get_info()
list_characters()
get_character()
get_character_level_stats(..., ascended=True)
list_weapons()
get_weapon()
get_weapon_level_stats(..., ascended=True)
list_artifact_sets()
get_artifact_set()
get_artifact_set_bonuses()
get_talent_scalings()
get_effect_payloads()
```

`core/` 不依赖 `AssetRepository`。资产读取发生在 `application/assembly` 等组装阶段，组装完成后 `core/` 接收纯运行时对象。

## 8. 质量门

资产数据进入正式库前必须经过三层验证：

1. manifest loader：检查 JSON 结构、必填字段、未知字段和基础类型。
2. manifest audit：检查唯一键、引用关系、枚举、等级覆盖、倍率表和效果参数基础 schema。
3. SQLite validate：检查表结构、schema version、外键和 JSON payload 可解析性。

当前完整 raw cache 已验证通过：

```text
characters: 128
character_level_stats: 12544
weapons: 234
weapon_level_stats: 22244
artifact_sets: 61
artifact_set_bonuses: 118
talent_scalings: 2508
effect_payloads: 1421
issues: 0
```

这些统计表示当前导入链路可用，不表示对应角色、武器、圣遗物机制已经实现。

## 9. 后续扩展

后续新增数据源时，应新增源站适配层并输出同一个标准 manifest，不应让 SQLite writer 或 `AssetRepository` 直接认识源站字段。

后续实现具体机制时，应优先选择小范围 handler，使用 `handler_key` 绑定，并用测试或 golden case 验证数值行为。
