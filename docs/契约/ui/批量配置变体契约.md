# 批量配置变体契约

> 状态：正式规范。
> 本文定义配置区域展开为批成员的枚举、区间、叉乘、覆盖与成员上限规则。
> 最后更新：2026-08-29。

## 1. 目的

本文定义配置区域如何展开为一组模拟输入（批成员），以及枚举、区间、叉乘、覆盖和成员上限的规则。变体编译由 `frontend/` 完成；`application/batch/` 只接收已展开成员并编排任务。

## 2. 成员模型

- 每个成员拥有稳定 `item_id` 与确定展开顺序。
- 调整枚举顺序、区间参数后，已有连线按 `item_id` 保持指向；`item_id` 不得使用显示值或数组下标。
- 成员完成顺序不影响结果归属；每个成员对应一个仿真任务与一个 `session_id`。
- 单次模拟输入是成员数为 1 的批。

## 3. 枚举节点

```json
{
  "path": "team[0].character",
  "value_type": "asset",
  "values": [
    { "item_id": "e-1", "value": "character:barbara", "label": "芭芭拉" },
    { "item_id": "e-2", "value": "character:kaeya", "label": "凯亚" }
  ]
}
```

- `value_type`：`asset` / `number` / `string` / `json_fragment`。
- `item_id` 由编辑器在创建取值时生成，稳定不变。
- 成员投影端口按 `item_id` 暴露单个取值。

## 4. 区间节点

```json
{
  "path": "scene.targets[0].level",
  "start": 1,
  "end": 10,
  "step": 3,
  "label": null
}
```

取值规则（已确认）：

- 从 `start` 开始，只要下一步 `≤ end` 就继续生成；`start=1, end=10, step=3` 生成 `1, 4, 7, 10`。
- 数值使用十进制算术计算，避免浮点累积误差；前端不得用 IEEE 754 累加步长。
- `step <= 0`、`start > end` 为校验错误。
- `label` 为空时使用自动标签（如 `1..10/step3`）。

## 5. 组合规则

- 多个组输出相遇时按目标路径区分：
  - 目标路径不同：叉乘组合；
  - 目标路径相同：不叉乘，按[覆盖规则](../../架构/UI/配置区域设计.md)处理，后生效者覆盖先生效者并显示覆盖警告。
- 输入文档由根数据 + 片段链按顺序深合并生成。
- 覆盖只发生在同一叶子字段；配置区域边界输出展示应用后的最终文档与校验状态。
- 片段写入 `team[i]` 下任意字段后，若该条目缺少 `slot`，编译器按 `i + 1` 补齐（队伍槽位为 1 起始正整数），保证后端解析必填字段完整。

## 6. 成员上限

- 批次成员数量上限为 `200`（已确认）。
- 超过上限时配置区域边界输出直接报校验错误并阻止运行，同时展示最终成员数量供预览。
- 上限当前为固定常量；后续如需可配置，放入运行选项或应用设置，不进入 `SimulationInput`。

## 7. 编译与执行边界

- `frontend/`：变体编译，输出 `(item_id, SimulationInput)` 的有序集合；负责图校验、片段合并、叉乘/覆盖与成员预览。
- `application/batch/`：接收已展开成员，按批提交任务、跟踪成员状态、执行整批取消；不解析工作流图，不做变体编译，不持有 UI 状态。
- 每个成员提交为一个内部执行句柄（job）；成员状态为 `queued / running / stopping / completed / failed / cancelled`。
- 取消整批：排队成员立即取消，运行中成员跑完后标记取消；批次在全部成员到达终态后结束。批是内存调度实体，终态后不再追踪，规则见[批处理调度设计](../../架构/批处理调度设计.md)。
- 并发度默认 `min(4, CPU)`，成员小并行执行。
- 后端仍拒绝超过 200 个成员的批次，作为前端编译上限的第二道闸。

## 8. 结果归属

- 成员任务完成后，`session_id` 归属对应 `item_id`。
- 分析区域（后续）按成员展开会话组；聚合按成员顺序收拢。
- 结果库按 `session_id` 保存，工作流通过成员映射引用结果，不把结果内嵌进工作流文件。
