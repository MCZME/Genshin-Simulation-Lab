# 感电反应设计

> 状态：已实现。本文描述普通水雷感电、双 Aura 共存、周期脉冲和跨目标传导。

最后更新：2026-08-03

## 1. 定位

普通感电是由两种普通 Aura 支撑的周期状态反应。Reaction Rule 负责识别水雷方向、声明后手持久附着、捕获效果来源并建立或刷新 `ElectroChargedState`；帧协调器把到期状态物化为周期根；元素反应协调器统一结算每次脉冲的 Gate、Aura 消费、状态变化和 Damage。

代码落点：

```text
core/systems/reaction/mechanics/electro_charged/
core/systems/reaction/states.py
core/systems/reaction/scheduled.py
core/coordination/elemental_reaction/coordinator.py
```

感电伤害元素量为零，不施加雷 Aura，也不作为新的普通命中或元素反应入口。

## 2. 方向与双 Aura 建立

显式方向：

```text
incoming_hydro_on_electro
incoming_electro_on_hydro
```

感电 occurrence 本身不直接消费后手预算或先手 Aura。后手剩余预算通过 `PersistentIncomingAuraApplicationEffect` 按普通 `20%` 附着损耗形成持久 Aura，因此目标进入普通水、雷双 Aura 共存状态；两种 Aura 继续按各自贡献和衰减规则独立运行。

无伤害元素施加也能建立或刷新感电。ICD 后预算为零、缺少匹配 Aura 或同元素施加不形成普通感电。

## 3. 状态与来源刷新

`ElectroChargedState` 按目标占用共享 slot，保存：

```text
instance_ref
subject_ref
created_by_occurrence_ref
current_effect_owner
captured_scaling_basis
created_frame
next_tick_frame
next_tick_index
revision
```

水雷元素量的唯一真值仍在 Aura；状态不复制元素量，也不暂停 Aura 的自然衰减。

首次建立时创建状态，下一周期设为当前帧加 `60`，并在当前帧生成首次脉冲。活动期间再次成功附着正水或正雷时：

- 产生新的感电 occurrence；
- 保留状态实例、创建信息和周期游标；
- 将效果所有者与捕获式剧变基础替换为本次来源；
- 不额外生成当前帧脉冲，也不重置下一周期帧。

来源离场或切换到后台不会改用当前场上角色。未来脉冲继续使用状态已经捕获的来源、等级、元素精通和等级系数，直到合法再附着或传播接管来源。

## 4. 首次与周期脉冲

首次建立 occurrence 声明一个同帧下一 settlement round 的 `ReactionEffectGroup`。后续周期不创建伪 occurrence，而由 `ElectroChargedState.next_required_frame` 驱动：

```text
Aura 衰减到当前帧
-> 水雷完整性检查
-> 到期状态物化 ElectroChargedTickRootWork
-> 周期游标推进到 frame + 60
-> scheduled adapter 生成带 ScheduledStateTickCause 的 Effect Group
-> 进入统一感电脉冲结算
```

周期根使用状态实例、帧和 tick index 派生确定性身份。到期根在同帧原始 Action/Impact 前处理；同帧重复规范化不会再次生成根。

水或雷任一 Aura 在规范化后不存在时，状态被移除且不生成本次周期根。显式主体生命周期结束也会移除状态并取消未来工作。

## 5. 剧变伤害与 Gate

首次、周期和传导伤害共享以下公式：

```text
mastery_bonus = 16 * EM / (EM + 2000)

damage =
    level_multiplier
    * 2.0
    * (1 + mastery_bonus + reaction_bonus)
    * electro_resistance_multiplier
```

当前普通感电固定 `reaction_bonus = 0.0`。伤害为不可暴击、零元素量的雷元素剧变伤害，不读取攻击力、普通伤害加成、技能倍率或标准防御区。

基础倍率由每个 `GeneratedDamageImpactEffect.transformative_base_multiplier` 显式携带。协调器只适配 Effect 与 Damage Impact，不按 reaction key、damage kind 或 Damage Profile 推导倍率。

Damage Gate 使用来源、目标、Gate Definition 和 damage kind 分槽，`30` 帧内最多通过一次。Gate blocked 时不产生 Damage、不消费 Aura、不接管来源，但已经到期的周期游标继续推进。

## 6. Aura 消费与状态结束

一个目标只有同时满足以下条件才发生感电消费：

- 本次脉冲通过 Damage Gate；
- 目标存在有效 `ElectroChargedState`；
- 目标仍同时存在正水、正雷 Aura。

单次消费为：

```text
hydro_consumed = min(current_hydro, 0.4 GU)
electro_consumed = min(current_electro, 0.4 GU)
```

任一方不足 `0.4 GU` 时仍允许最后一次伤害，随后将剩余量消费到零并移除状态。其他反应或自然衰减导致任一 Aura 消失时，也移除状态；状态移除不修改仍存在的单一 Aura。

## 7. 传播与来源接管

每次脉冲以当前感电主体为主目标，并在 X/Z 平面半径 `13` 米的闭区间内查询其他正水 Aura 目标。主目标固定排在首位，其他候选按稳定主体引用排序；范围只冻结多个单体伤害目标，不把感电改成范围爆炸伤害。

仅有水 Aura 的传播目标：

- 通过自身 Gate 后受到一次单体雷伤；
- 不施加雷、不消费水、不创建感电状态。

已经感电的传播目标：

- 通过自身 Gate 后消费水雷各最多 `0.4 GU`；
- 消费后仍成立时，效果所有者和捕获基础替换为本次脉冲来源；
- 下一周期同步到当前帧加 `60`；
- 不产生新的感电 occurrence。

关系不适用或缺少 Damage capability 是目标级正常阻止。主目标失去合法伤害资格时移除其感电状态；传播目标被阻止不影响同组其他目标。

## 8. 多 Aura 候选

感电目录不调用其他反应 Runtime。水雷共存下的第三元素顺序由 Reaction 公共候选逻辑拥有：

- 火先对雷超载；雷被清空且仍有火预算时，再对水蒸发；
- 冰先对雷超导；雷被清空且仍有冰预算时，再对水冻结；同时完成两步时抑制超导独立伤害，但保留 occurrence 和物理减抗；
- 岩先对雷形成结晶候选，雷被清空且仍有岩预算时再对水形成第二候选；第二候选被同帧目标级结晶成立 Gate 阻止，因此最终只生成雷晶片并保留水 Aura；
- 风按雷后水形成已确认的双扩散；
- 草进入当前生产版本确认的原激化与普通绽放组合序列。

任一组合消费掉水或雷后，主交互投影会同步移除失效的感电状态。

## 9. 事务、事实与验证

一次感电脉冲冻结一个目标集合，并在第一次写入前准备和校验：

```text
逐目标 Gate
-> 条件 Aura 消费
-> State 移除或跨目标来源接管
-> Damage Impact
```

Aura 与 Reaction Store 计划统一预校验；Damage 记录也在提交前完整准备。技术失败阻止整个 Effect Group，Gate blocked、关系不适用和 capability 缺失是逐目标正常结果。周期 root、脉冲 Effect Group 和原始 Impact 是各自独立的 batch，已提交 batch 不由后续失败补偿回滚。

首次和再附着发布真实 `REACTION_OCCURRED`；周期脉冲只使用 `ScheduledStateTickCause`。状态变化、Aura 变化、Damage 和最终元素交互事实只在对应提交完成后发布。

长期验证覆盖两个方向、双 Aura 建立、首次与 `60` 帧周期、再附着刷新、显式 `2.0` 倍率、`30/1` Gate、`0.4 GU` 双消费、13 米传播、生命周期、火冰组合以及后续版本的风岩草组合。

稳定字段见[感电反应契约](../../../../契约/元素反应/反应/感电反应契约.md)。

## 10. 非目标

普通感电不实现月感电、特殊环境水体、角色自身感电、削韧、硬直、打断、击退、停滞、空间位移或 hitlag。后续反应对水雷共存状态的组合扩展不改变普通感电自身的状态、周期、Gate 和伤害契约。
