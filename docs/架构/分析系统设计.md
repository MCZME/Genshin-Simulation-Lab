# 分析系统设计

> 状态：正式规范。
> 本文描述分析系统：它把结果库真值加工成可展示、可比较的结果表，由取数/关系算子构成数据流，后端经节点运行时逐节点阶段执行；包括模块边界与稳定性规则。
> 最后更新：2026-09-05。

## 1. 定位

分析系统是结果存储系统的派生层：基于结果库真值加工出可展示、可比较的结果表。分析不写库、不改变结果库真值；所有派生结果可重建。

核心模型：

- **数据 = 结果库真值**：运行记录与事件记录是基础来源，事件载荷按声明的 JSON 路径提取成具名列。
- **入口 = 取数节点**：会话组约束行范围，`source` 切换运行记录 / 事件记录。
- **加工 = 关系算子**：条件筛选、投影、排序、分组聚合、限制行数、连接、计算列等组成数据流管道，表达力对标 SQL 查询的常用子集。
- **边界 = 后端拥有 SQL**：前端只提交结构化查询计划（不含 SQL 文本），后端负责校验、编译为参数化 SQL 并执行；安全边界是 prepared statement 语义加列名白名单。
- **会话维度是普通数据列**：逐场、跨场汇总、跨批对比都是显式列操作，框架不做隐式展开。

## 2. 模块边界

| 模块 | 职责 | 约束 |
| --- | --- | --- |
| `application/models.py` | 查询计划、节点执行、阶段与结果表的契约模型 | 声明级模型，不接触数据库实现 |
| `application/services/analysis_runtime.py` | 节点运行时用例门面（含取数编辑器 schema 聚合） | 声明级结构校验 + 委托执行协议 |
| `application/services/analysis_schema.py` | schema 聚合：固定表列、事件类型与输入快照树 | 只转发冻结清单，不另立真值 |
| `application/services/protocols.py` | 阶段执行器协议 | 应用层唯一依赖点 |
| `infrastructure/results_sqlite/analysis_query.py` | 共享编译核心：形状推导、CTE 编译、参数绑定、行数上限与聚合口径 | SQL 与结果库 schema 强耦合 |
| `infrastructure/results_sqlite/analysis_stage.py` | 节点运行时阶段执行器：阶段上下文、单节点执行、阶段读取与选择派生 | 复用共享编译核心的形状与聚合语义 |
| `server/` | schema 与节点运行时 HTTP 端点 | DTO 层，不直接访问 infrastructure |

依赖方向：`server / cli -> application -> 执行协议 <- infrastructure 实现`。应用层不接触 SQLite，基础设施层不越过协议向应用层暴露 SQL 文本。

节点种类、参数结构、表达式语言、形状推导与端点请求/响应形状是契约真值，见[分析系统契约](../契约/分析系统契约.md)，本文不重复维护。

## 3. 执行模型

分析执行以阶段化节点运行时为方向：前端创建阶段上下文后按拓扑序逐个提交节点，每个节点输出成为后端可寻址阶段（stage）并保留在上下文中，浏览器不充当中间表搬运工。

- 单节点执行：取数、关系算子与列值设置在同一编译语义上执行，节点输入来自已物化的阶段引用；阶段行集受统一行数上限约束。
- 选择派生：表格行、饼图扇区或柱状图柱体点击提交选择意图，后端在输入阶段上派生选择阶段，选择阶段驱动的下游分支只在用户选中时执行。
- 阶段生命周期：阶段只存在于运行时上下文，不写入结果库；响应携带阶段引用与可渲染行集。
- 失败语义：校验失败与节点执行错误按节点定位，单个节点失败即整次运行失败；具体端点与错误结构见[分析系统契约](../契约/分析系统契约.md)。

## 4. 稳定性规则

- 节点 kind、参数结构、操作符与聚合函数白名单、形状推导规则冻结：只增不改。
- 聚合口径、浮点除法语义、可空比较展开以后端实现为唯一真值，配 golden 断言。
- 形状推导由前端与后端各自实现，后端执行前防御性校验，不一致以契约校验失败拒绝。
- 对外端点形状是契约；变更走 API 版本升级。

## 5. 与结果存储系统的关系

- 真值层：运行记录、输入快照、初始快照、事件流（结果库）。
- 派生层：查询计划与阶段运行时的输出表；可重建，不落库。
- 物化只按性能需要建立，永远可重建，不改变真值层。
- 时间轴、区间配对、曲线等非关系代数加工不在当前节点集，后续扩展时同步登记契约。
