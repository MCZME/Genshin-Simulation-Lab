# 工作流定义契约

> 状态：正式规范。
> 本文定义画布工作流的持久化 JSON 格式、节点区域端口连线语义、片段合并、覆盖与边界输出规则。
> 最后更新：2026-08-29。

## 1. 职责与范围

本文定义画布工作流的持久化 JSON 格式与语义边界。它回答：

- 工作流文件里保存什么、不保存什么。
- 区域、节点、端口、连线的稳定身份与约束。
- 片段数据、根数据、覆盖与边界输出的语义。
- 校验结果的结构化形态。

不包含：编辑期瞬态（视口、选中、拖拽）、运行态（成员状态、任务句柄）、节点编辑器组件映射。前者归 `WorkflowEditorState`，后者归[前端工程规范](../../工程/前端工程规范.md)。

图语义的解析、校验与变体展开由 `frontend/` 完成。后端把本 JSON 当作不透明存档读写，不实现 `WorkflowValidator` 或图运行时。CLI 不读写、不运行本文件。

## 2. 顶层结构

```json
{
  "schema_version": 1,
  "meta": { "name": "示例工作流" },
  "regions": [],
  "nodes": [],
  "edges": [],
  "layout": {}
}
```

- `schema_version`：整型，递增；解析器只接受已声明版本。
- `meta.name`：用户可识别的显示名，不作为仿真识别依据。
- `regions`：区域对象列表。
- `nodes`：节点对象列表。
- `edges`：连线对象列表。
- `layout`：画布布局（区域矩形、节点坐标）；布局属于定义的一部分，随工作流保存。

存储位置：`<data_dir>/workflows/<workflow_id>.json`，一个文件一个工作流；保存由用户显式触发。后端存档服务不校验 `schema_version` 以外的图语义；完整校验在前端加载与运行前执行。

## 3. 区域模型

```json
{
  "id": "region-1",
  "kind": "configuration",
  "name": "主配置",
  "rect": { "x": 0, "y": 0, "width": 800, "height": 600 }
}
```

- `kind`：`configuration` / `analysis`。
- 配置区域固定拥有边界输出，分析区域固定拥有边界输入；配置区域没有独立输入端口，边界输出同时作为区域内节点链的汇入目标和连接模拟节点的输出源；边界端口属于区域，不作为独立节点。
- 区域是第一等画布对象，可移动、可调整尺寸；第一版不支持折叠与嵌套。
- 节点通过 `region_id` 获得归属；`region_id` 为空表示游离草稿，不能连接或参与运行。
- 区域 id 在工作流内稳定且唯一。

## 4. 节点模型

```json
{
  "id": "node-1",
  "kind": "character",
  "region_id": "region-1",
  "position": { "x": 40, "y": 80 },
  "size": { "width": 800, "height": 480 },
  "params": { "slot": 0 }
}
```

- `id`：工作流内稳定唯一，连线引用它；不得使用显示名或控件引用。
- `kind`：`node_kind`，与[节点与区域契约](./节点与区域契约.md)的注册表一致；未注册 kind 在加载/校验阶段报错。
- `params`：节点参数，按 kind 的 schema 校验。
- `size`（可选）：支持尺寸调节的视图节点画布几何（宽高像素），与 `position` 同类随工作流保存；缺省表示自适应宽度（内容自然宽夹持软上限，见[分析区域设计](../架构/UI/分析区域设计.md) 5.1）与默认高度 360px。存量定义缺省该字段时按默认语义处理，无需迁移。
- 端口不属于独立对象：端口由节点类型声明，连线用 `(node_id, port_id)` 定位。
- 模拟节点是画布级节点，不归属任何区域；输入侧只连接配置区域边界输出，输出侧只连接分析区域边界输入。

## 5. 端口与连线

```json
{
  "id": "edge-1",
  "source_node_id": "node-1",
  "source_port_id": "out",
  "target_node_id": "node-2",
  "target_port_id": "in"
}
```

- 端口有稳定 `port_id`；端口基数分单值输出与组输出。
- 组输出触发下游展开；成员投影端口绑定稳定 `item_id`，不绑定数组下标。
- 成员投影端口连线（`out:<item_id>`）只携带对应成员，编译按端口过滤变体；同一节点的不同成员分支互斥。
- 连线必须是 DAG；环检测由前端 `WorkflowValidator` 完成并标记环上连线。
- 数据语言随区域切换：配置区域为片段/输入文档，模拟节点为输入文档/会话，分析区域为会话/派生结果；不匹配的连线报错。
- 跨区域连线只允许连接区域边界端口与模拟节点。
- 多个上游按端口顺序应用，先连先应用；覆盖规则见第 6 节。
- 配置节点输入端口默认允许多条入线；多输入节点的片段合并由前端编译器隐式完成，单输入/单输出是特例。

## 6. 片段、根数据与覆盖

- 根数据：携带根身份的完整 JSON 文档，自根节点出发。
- 片段数据：节点直接产生、不携带根的修改内容；片段之间可深合并。
- 片段链按连线/端口顺序应用到根文档，产出新根数据。
- 覆盖只发生在同一叶子字段存在多个写入者；覆盖允许但必须警告：被覆盖节点与覆盖节点在界面上都给出明确提示。
- 生效顺序由端口顺序决定，后生效者覆盖先生效者。
- 配置区域边界输出始终展示应用后的最终文档、成员数量与校验状态。

## 7. 配置区域边界输出

- 边界输出收拢区域内有效输入，形成一组完整输入文档。
- 配置区域无独立输入端口；区域内节点链经各自尾节点直接汇入边界输出，多条汇入按连线顺序应用。
- 无有效数据汇入时输出为空并阻止运行。
- 边界输出承担最终输入数量、校验与预览，不执行模拟。
- 变体展开（枚举/区间、叉乘、成员上限）见[批量配置变体契约](./批量配置变体契约.md)。
- 设计说明见[配置区域设计](../../架构/UI/配置区域设计.md)。

## 8. 校验诊断

前端 `WorkflowValidator` 返回结构化诊断数组，每一项：

```json
{
  "severity": "error",
  "code": "REGION_MISMATCH",
  "message": "配置节点不能直接连接分析节点",
  "node_id": "node-3",
  "edge_id": null,
  "region_id": null,
  "path": null
}
```

- 校验覆盖：游离节点参与运行、区域不匹配、端口类型、环路、覆盖、路径语法、成员上限。
- 界面同时提供节点附近局部反馈与集中问题列表，两者都消费同一诊断模型。

## 9. 版本与演进

- `schema_version` 递增；旧版本可显式迁移，不支持静默改写。
- `node_kind` 与 `port_id` 冻结后只追加、不改名。
- 布局字段变更不影响运行语义；节点/连线身份变更必须走迁移。
