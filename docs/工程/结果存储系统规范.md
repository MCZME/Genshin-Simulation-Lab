# 结果存储系统规范

> 状态：正式规范（结果存储工程约定）。
> 本文规定结果存储系统相关的工作区目录与文件组织约定；系统职责、数据分层与边界见[结果存储系统设计](../架构/结果存储系统设计.md)，表结构、schema 版本与事件契约见[结果库契约](../契约/结果库契约.md)。
> 最后更新：2026-09-05。

## 1. 工作区目录与文件组织

- 项目配置 `config.toml` 位于项目根目录，使用 TOML（支持注释），程序写入采用 `tomlkit`；第一批配置项为 `schema_version` 与 `workspace.data_dir`，`kind`、`meta` 后续按需添加。`config.example.toml` 是提交到仓库的配置示例模板，`project init` 从示例复制生成 `config.toml`，后者不进入 git。
- 数据目录由 `workspace.data_dir` 指定，默认 `data/`；子目录按约定推导：`inputs/`、`results/`、`exports/`、`templates/`、`workflows/`、`logs/`，不逐个配置。
- 资产库位置独立（默认 `data/assets/`），不随 `data_dir` 搬迁；它是生成物，不视为用户数据。
- 模拟输入文件放在 `<data_dir>/inputs/`，一个 JSON 文件一个输入，平铺不嵌套；文件内 `input_key` 定身份，文件名仅作展示；发现方式为扫描目录，第一版不做索引。
- 工作流定义文件放在 `<data_dir>/workflows/`，一个 JSON 文件一个工作流，保存配置、模拟与分析节点定义及画布布局；后端按不透明存档读写，不解析图语义。批次与任务状态是内存调度数据，不落入工作区目录。
- 结果库位于 `<data_dir>/results/results.db`。
- 日志文件位于 `<data_dir>/logs/`，归日志系统所有；本规范只在目录约定上联动，不定义日志存储细节（见[日志系统设计](../架构/日志系统设计.md)）。
- `project init` 会创建上述工作区目录骨架并初始化结果库；后续命令使用目录时仍允许按需懒创建。
