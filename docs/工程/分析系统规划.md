# 分析系统规划

> 状态：生效，持续维护。
> 本文按[分析系统设计](../架构/分析系统设计.md)排定落地方案，登记分析算子化 v2 的范围与工程关注点。
> 最后更新：2026-08-25（同日 v2 定稿，v1 模板模型退役）。

## 1. 定位

分析能力按「数据 = 结果库内容、加工 = 关系算子」重做：两个取数节点 + 七个关系算子组成查询计划，后端在 `infrastructure/results_sqlite/analysis_query.py` 编译为 CTE 链一次执行；契约模型与用例在 `application/`，HTTP 端点在 `server/`。原 `analysis/` 顶层模块、v1 模板注册表（`templates.py`）与模板端点均已删除。

## 2. 已落地

- 查询计划模型（`AnalysisPlan` / `AnalysisPlanNode` / `AnalysisTableResult` 等）与执行协议（`AnalysisQueryExecutor`）。
- `AnalysisQueryService` 声明级结构校验（会话数与规模上限、ID 合法性、输出引用、事件类型与取数参数类型）。
- `SQLiteAnalysisQueryExecutor`：取数（运行/事件）+ 过滤/投影/排序/分组聚合/截断/连接/计算列，prepared statement 绑定、列名白名单、CTE 链一次执行、输出行上限 10000 与 `truncated` 标记。
- HTTP 端点：`POST /api/v1/analysis/query`、`GET /api/v1/analysis/schema`。
- 事件类型 schema 由 `application/services/analysis_schema.py` 从 core `EVENT_SPECS` 聚合，payload 字段映射当前登记伤害/治疗/Buff 四类，其余类型字段为空。
- 旧代码清理：v1 四张模板、模板目录与单模板执行端点、`processing` / `query_config` 节点 kind 全部退役；存量工作流加载时清除对应节点与连线。
- 测试：编译执行器集成测试（含 golden 断言：DPS 口径、stddev/p95、`ne` 可空展开）、空参数与参数类型校验、服务校验单测、HTTP 路由单测。

## 3. 后续增强

- 非关系代数逻辑（时间轴持续段配对等）扩展为专门处理节点。
- 条件列显示名解析（join 资产库或前端格式化层）。
- 结果超限/截断的后续处理（分页或查询级行限参数）。
- 事件类型 payload 字段映射随消费视图需求逐类登记。

## 4. 工程关注点

- 执行器与结果库 schema 强耦合：新增或修改结果库表/字段时，同步 `_RUN_TABLE_SCHEMA` / `_EVENT_TABLE_SCHEMA`，避免漂移。
- 口径一致性：聚合函数、除法与可空比较以后端实现为唯一真值，配 golden 断言；口径变化必须走契约新版本。
- 节点 `kind`、参数结构、操作符与聚合函数白名单、形状推导规则冻结：只增不改。
- 行数上限：输出 SQL 带 `LIMIT 10001` 下推，事件类查询仍建议用事件类型/帧范围参数收敛数据量。
- 安全：前端不传 SQL；字面量全部参数绑定，列名经白名单校验后引用。
