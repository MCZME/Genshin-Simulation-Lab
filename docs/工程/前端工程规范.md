# 前端工程规范

> 状态：正式规范。
> 本文定义 `frontend/` 的工程边界、技术选型、目录结构、状态数据流、组件与节点编辑器约定、画布实现、质量门禁和开发方式。
> 最后更新：2026-09-05。

## 1. 定位与边界

- `frontend/` 是仓库根目录下的独立 Web 前端工程，与 `backend/` 并列。
- 前端是纯客户端：只通过 `server/` 的 HTTP API 调用后端 application 能力，不 import 任何 Python 代码，不直接访问 SQLite，不组装仿真核心对象，不实现分析算法，不调用 CLI。
- UI 与 CLI 共享资产、仿真与结果等应用服务；CLI 不运行工作流。`application/` 不依赖前端实现；`core/` 不感知 UI 状态。
- Node.js 与 pnpm 只存在于开发/构建期；运行时由 Python 服务托管前端静态文件。
- 桌面形态与网页服务形态共用同一份前端构建产物；差异只在启动方式（server 入口 + 后置的桌面启动层）。

产品形态与画布语义由[画布设计](../架构/UI/画布设计.md)及各 UI 设计文档承载，本文只规定前端工程实现边界。

## 2. 技术选型

- React + TypeScript + Vite。
- 画布：React Flow（核心开源组件；Pro 商业组件未批准前不引入）。
- 包管理器：pnpm；提交 `pnpm-lock.yaml`。
- Node 版本通过 `package.json` 的 `packageManager` 与 `engines` 固定。
- 状态：`AppState`、`EditorState`、`RunState` 为纯 TypeScript 模块，不依赖 React。
- 类型：后端 OpenAPI -> `openapi-typescript` 生成 API 类型；不手写两套类型。
- 前端引入新依赖、切换组件库或接入 React Flow Pro 组件前，须人工确认并记录许可证结论；现有 ECharts 与 vis-timeline 的许可证结论见[UI与工作流决策](../决策/UI与工作流.md) D-038、D-045。

## 3. 目录结构

```text
frontend/
├── src/
│   ├── app/               # 应用外壳：导航、全局状态、错误反馈
│   ├── theme/             # 主题 token
│   ├── workflow/          # 定义模型、语义注册表、校验、变体编译
│   ├── state/             # AppState / EditorState / RunState
│   ├── api/               # HTTP API 客户端与类型
│   ├── components/
│   │   ├── canvas/        # 画布、区域、节点卡、连线层、框选、小地图
│   │   ├── nodes/         # 节点编辑器与 registry.tsx
│   │   ├── panels/        # 工具栏、对象面板、问题面板、结果面板（结果库浏览器）
│   │   ├── shell/         # 应用壳、设置弹窗、顶部栏、工具轨、状态栏
│   │   └── common/        # 输入框、资产选择器、表格、徽标等原语
│   └── views/             # 非画布页面：项目初始化
├── package.json
├── pnpm-lock.yaml
├── vite.config.ts
└── tsconfig.json
```

目录按功能域组织，不按组件类型建目录。`application/` 与 `infrastructure/` 的具体分层见[模块边界设计](../架构/模块边界设计.md)。

## 4. 状态与数据流

### 4.1 状态层

- `AppState`：当前项目/工作区、可用服务、当前视图。
- `EditorState`：只装语义状态——选中对象、节点已提交位置、连线、区域归属、已提交节点参数，以及按工作流独立的撤销/重做历史与最后保存引用；`dirty` 由当前定义与最后保存定义比较派生。
- `RunState`：运行期状态，不持久化。当前为「工作流运行」单块：`run` 为当前/最近一次工作流运行，含构建限速轨迹、按模拟节点索引的批次视图与终态。

分析区域运行态不进入上述持久/历史状态：schema 目录、按节点 id 的结果表与状态、视图 `selection`、区域运行阶段由应用层持有并经 Context 下发，不写入 `WorkflowDefinition`。

UI 私有状态不持久化；可单测的纯 TypeScript 状态集中在 `state/`，组件内瞬态留在组件层。

### 4.2 单向数据流

- 单向数据流：语义事件 -> `EditorState` -> 组件渲染；命令式只允许出现在高频瞬态与定制绘制组件内部。
- 业务状态只有一个更新入口：任何命令式代码不得绕过桥接层直接修改业务状态。
- 瞬态状态不进全局状态：拖拽中的位置、鼠标坐标等高频状态留在组件内部；只有拖拽结束、连线落定等语义事件才提交到 `EditorState`。
- 视口（缩放/平移）不进 `EditorState`，归画布组件持有；节点不因视口变化重建。
- 结果库原始内容不进入 `EditorState`/持久化状态：结果面板按 `session_id` 引用分页读取，单项详情按单行表中的 `session_id` / `frame` / `ordinal` 按需取数。
- 分析查询返回的派生结果表（单表硬上限 10000 行）是受限运行时数据，由应用层按节点 id 缓存并经 Context 下发；视图排序、高亮、列顺序与 `selection` 等查看瞬态只留在组件与桥接层，不随工作流 JSON 保存。
- 画布布局、节点位置等持久化内容通过工作流存档 API 保存；保存是显式动作。

### 4.3 桥接层

桥接层不依赖前端框架，可单测：

- `converters.ts`：EditorState 与 WorkflowDefinition 双向转换。
- `api/`：把 HTTP API 包装为页面可用的异步调用；配置预览走 `POST /inputs/validate`。
- `runtime_subscription.ts`：轮询 `GET /runs/{run_id}` 更新 RunState；SSE/WebSocket 后置。

组件不直接拼装 HTTP 请求，统一通过 API 客户端获取能力。具体端点与数据形状见[UI API 契约](../契约/ui/UI%20API%20契约.md)与[节点与区域契约](../契约/ui/节点与区域契约.md)。

## 5. 组件分类与生命周期

组件按功能域组织目录，不按组件类型建目录；每个组件在定义处标注类型。四类组件：

| 类型 | 职责 | 典型位置 |
| --- | --- | --- |
| 纯组件 | state 进、控件出，无内部状态 | 节点卡壳、区域框、状态徽标 |
| 编辑器组件 | 持有本地瞬态（文本、拖动、选择），提交语义事件 | 节点内编辑器、参数表单 |
| 实例组件 | 持有外部实例/焦点/绘制上下文，对外声明式 | 输入框包装、文件选择器、画布表面、连线绘制 |
| 桥接组件 | 对接异步（任务状态、查询结果），只转发数据与回调 | 运行状态展示、结果取数 |

实例组件契约：

- 自己持有控件实例（ref），自己管理焦点、IME、滚动位置等生命周期细节；
- 对外接口仍为声明式（数据 props + 语义回调）；
- 全局重渲染发生时不得重建自身或打断用户操作。

可复用的实例原语（输入框、文件选择器、画布表面等）收在 `ui/components/common/`，作为组件库基础件。

## 6. 节点注册表与编辑器

### 6.1 注册表分工

- 语义注册表在 `frontend/src/workflow/`：节点类型、片段形状、端口模型、参数 schema、区域约束与节点级校验。
- UI 注册表在 `frontend/src/components/nodes/registry.tsx`：`node_kind -> React 组件` 映射与展示元数据（图标、默认尺寸、面板排序）。
- 画布对象面板读语义注册表决定“当前区域有哪些对象”，再经 UI 注册表取编辑器组件；两侧以稳定 `node_kind` 为公共 key，互不循环依赖。
- 注册表显式注册，不自动扫描；WorkflowDefinition 中出现未注册 kind 时，加载/校验阶段报错，不静默忽略。
- 节点 `kind` 字符串冻结后只追加、不改名、不复用。

### 6.2 NodeKindSpec

每个节点类型是一个描述对象，至少包含：

- `kind` / `display_name`：稳定 key 与显示名。
- `region`：配置区域 / 分析区域 / 画布级（`null`，不归属区域）。
- 端口模型：输入输出端口、数据语言、单值/组输出、连接数约束。
- 片段形状：默认目标路径与参数形状；只声明路径，不读取 SimulationInput schema。
- 参数 schema：类型化节点参数，供编辑器生成表单与定义校验。
- 节点级校验规则。

展示元数据不进入语义注册表，不参与工作流校验、形状推导与变体展开。

### 6.3 特殊行为

纯描述性节点由 spec 与通用机制（片段应用、展开、查询）驱动。存在天生特殊行为的节点按 kind 显式绑定行为实现，不在 spec 中塞回调：

- 配置区域边界输出：收拢、校验、预览输入文档；属于区域模型，不进入节点类型注册表。
- 模拟节点：任务分发、按成员管理状态。
- 分析视图节点：展示节点，消费终端表；所有视图 `selection` 统一输出 `table`，表格行点击输出单行表，饼图/柱状图点击输出分组命中的行集表。
- 展示配置节点：数据链上的可选转发节点，输入 `table` 并原样转发给对应视图；不加工数据、不进入查询计划。
- 获取单行：无参数表算子，输入 `table` 并输出最多一行；单项详情节点：消费 0..1 行表，详情内容按需向结果库接口取数，不进入查询计划。

具体节点语义与参数契约见[节点与区域契约](../契约/ui/节点与区域契约.md)及对应区域设计。

### 6.4 编辑器与展示元数据

前端 UI 注册表为每个 `node_kind` 提供：

- 编辑器组件：`node_kind -> React 组件`。
- 图标与节点类别色：同类节点共享一个主色。
- 默认节点宽度与最小/最大尺寸。
- 画布对象面板排序与分组。
- 收起时的摘要渲染规则。

节点颜色按类别映射，不按具体类型平铺；类别色位于 `frontend/src/theme/tokens.ts` 的 `COLORS.nodeCategory`，画布对象面板、节点卡、拖拽预览与小地图共用同一套。未注册节点回落灰色；配置区域与分析区域使用区域色，不属于节点类别。具体类别划分与面板分组见[UI与工作流决策](../决策/UI与工作流.md) D-034、D-051–D-052。

### 6.5 节点卡与尺寸语义

- 节点卡统一采用「头部 + 内容区 + 底部」结构：头部承载类型标识、草稿徽标与节点级操作入口；底部承载输入顺序入口、成员投影开关与标签、组输出计数和端口点。
- 状态表达不得只依赖颜色：选中、草稿、运行置灰与应用中等状态同时提供文本或图形标识。
- 节点宽高为画布几何、按轴随工作流保存；尺寸语义常量与解析统一由 `frontend/src/workflow/view_size.ts` 持有。

具体节点的尺寸数值与交互语义由对应[配置区域设计](../架构/UI/配置区域设计.md)、[分析区域设计](../架构/UI/分析区域设计.md)与[工作流定义契约](../契约/ui/工作流定义契约.md)承载，本文不重复维护。

## 7. 画布实现约定

- React Flow 承载视口、节点、连线、选择与缩放；区域、端口命中、校验反馈为自定义组件。
- 区域在渲染层映射为 React Flow 父容器节点，区域内节点通过 `parentId` 作为子节点渲染；子节点位置在渲染层换算为区域内相对坐标，持久化契约仍保存画布绝对坐标。
- 区域只支持调整矩形尺寸，不做内容缩放；拖动区域标题栏移动区域时，内部节点绝对坐标同步平移。
- 该映射不改变语义模型：`regions` 仍独立于 `nodes`，区域边界端口属于区域。

区域边界、连线语义、运行与导航等产品规则见[画布设计](../架构/UI/画布设计.md)，本文不重复。

## 8. 质量门禁

```powershell
pnpm lint
pnpm typecheck
pnpm test
```

- `pnpm test` 使用 Vitest，覆盖状态、转换、图校验、变体编译与 API 客户端纯逻辑。
- 组件层使用壳测试与人工/截图验证。
- 前端与后端共享同一份契约文档；契约改动必须同步 OpenAPI 与类型生成。

## 9. 构建与开发

- 开发模式：`pnpm dev`，Vite 代理到本地后端（`/api` -> `http://127.0.0.1:<port>`）；后端单独以 `genshin-sim-server` 启动。
- 生产构建：`pnpm build`，产物由 server 入口启动时托管。
- 桌面安装包（PyInstaller + pywebview）后置；MVP 先保证 server 本地启动与网页服务两种模式。
