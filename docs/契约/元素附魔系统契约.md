# 元素附魔系统契约

> 状态：正式契约。六对异元素消耗规则、同元素不叠加与结算帧接入已确认；角色数值与部分外围语义仍待确认。标注“待确认”的项不进入生产实现。
> 最后更新：2026-08-10

## 1. 稳定 key

```text
ImpactKind.APPLY_INFUSION = "apply_infusion"
InfusionInstanceRef = "infusion:<sequence>"
```

definition key 使用稳定来源绑定与内容局部语义，例如：

```text
infusion.definition:character.chongyun:spirit_blade_field
infusion.definition:character.bennett:c6_field
infusion.definition:character.keqing:stellar_restoration
```

mechanic key 表达跨运行期稳定的机制语义，不包含槽位、精炼或参数版本。

## 2. 枚举

### 2.1 InfusionMode

```text
INFUSION     # 可覆盖武器附魔
CONVERSION   # 不可覆盖元素转化
```

### 2.2 RefreshPolicy

```text
ONCE       # 挂载一次，到 expires_at_frame 过期
PERIODIC   # 按 next_refresh_frame 周期重新挂载
```

### 2.3 原因码（EffectiveElementResolution.reason）

```text
no_active_source     # 无活动附魔/转化，使用攻击自身元素
conversion           # 有效元素转化强制
single_source        # 单一活动附魔
consumed             # 异元素消耗后的残留控制
freeze               # 冰水冻结残留，伤害元素为冰
electro_charged      # 雷水共存，伤害元素为水
```

## 3. 模型字段

### 3.1 InfusionDefinition

```text
definition_key
mechanic_key
handler_key
mode: InfusionMode
element: Element            # 不允许 PHYSICAL
applicable_attack_tags      # 默认：普通攻击/重击/下落攻击
refresh_policy: RefreshPolicy
period_frames: int | None   # PERIODIC 必填，且必须 <= duration_frames
duration_frames: int
weapon_gauge                # AuraAmount，必填正数；按来源配置，当前真实来源 1U，无衰减
target_kinds                # 第一版只支持 character
```

### 3.2 ApplyInfusionRequest

```text
request_id
frame
order
definition_key
character_ref
applier_ref
source_context
```

周期刷新由领域 Runtime 按定义推进，不要求 content 反复提交。

### 3.3 InfusionRecord

```text
instance_ref
definition
character_ref
applier_ref
source_context
mode
element
refresh_policy
created_frame
last_applied_frame
expires_at_frame
remaining_gauge              # 当前武器残留量；挂载时等于 weapon_gauge，被消耗后减少
frozen                       # 冻结标记：冻结载体记录为 True，伤害元素为冰
next_refresh_frame: int | None
lifecycle_state
removed_frame: int | None
removal_reason: str | None
```

半开生命周期：`created_frame <= frame < expires_at_frame`。
武器附着收敛以每条活动记录上的 `remaining_gauge` 为真值：同元素新挂载把其他同元素记录残留清零（刷新/顶替）；异元素按第 4 节规则消耗双方残留；冻结后由冻结载体记录标记，下一次挂载直接顶替。

### 3.4 EffectiveElementResolution

```text
frame
character_ref
element
mode: InfusionMode | None
reason: str
source_refs: tuple[RuntimeSourceRef, ...]   # 稳定排序
weapon_gauge: AuraAmount | None              # 控制来源配置的挂载量
```

### 3.5 有效元素查询

```text
resolve_effective_element(
    frame,
    character_ref,
    base_element,
    attack_tag: str | None = None,
) -> EffectiveElementResolution
```

- `attack_tag` 提供时只考虑 `applicable_attack_tags` 包含该标签的活动来源；无适用来源返回 `no_active_source` 与 `base_element`。
- 返回 `weapon_gauge` 为控制来源定义中的配置量；`no_active_source` 时为 `None`。

### 3.6 Damage 结算帧接入

- 结算帧按主攻击标签查询最终元素，命中附魔/转化时替换 `DamageImpactSpec.element`。
- 基础攻击无元素施加（物理、元素量为零）时，注入 `AuraStrength` 与 `weapon_gauge`；已有元素量的攻击只替换元素。
- ICD 标签/序列、AOE、倍率等其余字段不改变。
- 每次解析生成 `InfusionElementResolutionRecord` 审计记录（是否应用、来源与原因码）。

## 4. 六对消耗规则

约定：

- 武器侧每个来源挂载其定义中配置的 `weapon_gauge`（当前真实来源为 `1U` 弱元素），无自然衰减；来源按自身单次或周期生命周期过期。
- 消耗关系直接引用现有元素反应契约的消费公式，但只用于武器附着收敛，不产生 occurrence、伤害、效果或元素精通参与。
- 六对公式对任意正配置量成立；表中“等量 1U”是当前真实来源基准，非 1U 时残留按公式推导。
- 伤害元素判定只决定普攻/重击/下落的最终元素，与目标侧反应无关。
- 同一元素多来源不叠加：新挂载把同元素投影刷新为本次来源配置的 `weapon_gauge`，投影过期帧取 `max(当前, 本次)`，不缩短；任一来源活动期间投影保持，全部过期后移除；被消耗清空后不自动补满，等待下一次挂载。

| 组合 | 消费关系（引用现有契约） | 残留与伤害元素 | 依据 |
| --- | --- | --- | --- |
| 火 vs 冰 | 火打冰：`consumed = min(I, A/2)`，冰耗 `2×`；冰打火：`consumed = min(I, 2A)`，火耗 `consumed/2` | 等量 1U 时火残留、冰清空；伤害元素 = 火（双向） | [融化反应契约](./元素反应/反应/融化反应契约.md) |
| 水 vs 火 | 水打火：`consumed = min(I, A/2)`，火耗 `2×`；火打水：`consumed = min(I, 2A)`，水耗 `consumed/2` | 等量 1U 时水残留、火清空；伤害元素 = 水（双向） | [蒸发反应契约](./元素反应/反应/蒸发反应契约.md) |
| 冰 vs 水 | 双方 `1:1` 消费：`reaction_amount = min(I, A)` | 冻结残留；伤害元素 = 冰；后续施加直接顶替冻结 | [冻结反应契约](./元素反应/反应/冻结反应契约.md) |
| 雷 vs 冰 | 双方 `1:1` 消费：`consumed = min(I, A)` | 等量 1U 时双方清空；无残留 → 基础元素（物理空窗），等待下一轮刷新 | [超导反应契约](./元素反应/反应/超导反应契约.md) |
| 雷 vs 火 | 双方 `1:1` 消费：`consumed = min(I, A)` | 等量 1U 时双方清空；物理空窗，等待下一轮刷新 | [超载反应契约](./元素反应/反应/超载反应契约.md) |
| 雷 vs 水 | occurrence 不消费；后手按 `20%` 损耗保留，双方共存 | 共存期伤害元素 = 水；单侧消失后由残留侧控制 | [感电反应契约](./元素反应/反应/感电反应契约.md) |

补充规则：

- 多元素序列（如火进入水雷共存）按[感电反应契约](./元素反应/反应/感电反应契约.md)第 8 节顺序：火、冰先处理雷，预算剩余再处理水。
- 消耗后任一侧为零即移除该侧；双方都为零时武器回到无附着，使用攻击自身元素（通常物理）。
- 武器侧消耗不产生任何反应效果，不发布 `REACTION_OCCURRED`。
- 同元素施加按刷新/顶替处理：重新挂载该来源配置的 `weapon_gauge` 并刷新来源过期帧。

## 5. 事件

### 5.1 INFUSION_APPLIED

载荷包装 `InfusionApplicationResult`，序列化字段：

```text
result:
├── request_id / frame / order / outcome
├── instance_ref / definition_key / mechanic_key
├── mode / element / character_ref / applier_ref / source_context
├── expires_at_before / expires_at_after
├── next_refresh_frame_after
└── replaced_instance_refs
```

### 5.2 INFUSION_REMOVED

载荷包装 `InfusionRemovalResult`，序列化字段：

```text
result:
├── frame / instance_ref / definition_key / mechanic_key
├── mode / element / character_ref / reason
└── scheduled_expires_at_frame
```

替换时先发布移除事实，再发布应用事实；事件顺序按请求 order 与 instance ref 稳定排序。

## 7. 组装校验

- definition key 全局唯一，mechanic/handler key 非空。
- element 必须是合法非物理元素。
- PERIODIC 必须提供合法周期；时长必须为正。
- PERIODIC 要求 `period_frames <= duration_frames`，保证周期来源在到期前重新挂载。
- applicable_attack_tags 非空且已注册。
- content 声明 `infusion_definitions` 后必须提供对应 `APPLY_INFUSION` 入口。
- `infusion_definitions` 的 `handler_key` 必须与所属内容单元一致；第一版只允许角色内容单元声明。
- Damage 结算帧适配器与 `APPLY_INFUSION` 处理器必须随组装注入，缺任一适配器不得静默跳过附魔语义。
- 缺定义、缺 handler、非法字段在组装阶段报错，不延迟到仿真运行中。

## 8. 序列化

所有可持久化模型使用 JSON 兼容值对象，字段名与枚举值保持稳定；`Element` 使用 `core.elements.Element` 的稳定字符串值。

## 9. 当前未确认与不实现

- 同一元素多来源叠加：不实现（v1 冻结为刷新/顶替、不叠加；如角色实测出现反例再评审）。
- 同元素刷新/顶替的窗口恢复语义：v1 中旧同元素来源残留被新挂载清零后不随窗口到期恢复（“任一来源活动期间投影保持”按此简化），待角色案例复核。

- 具体角色来源的周期、时长、元素量、适用武器类型与离场保留规则：推迟到具体角色实现时确认。
- 具体来源的 `weapon_gauge` 数值由资产/内容配置，当前真实来源为 `1U`；数值随角色实现确认。
