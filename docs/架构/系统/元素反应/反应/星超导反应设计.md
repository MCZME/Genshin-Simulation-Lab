# 星超导反应设计

> 状态：正式规范。
> 本文固定与普通超导并列的独立星超导反应：星烁资格候选、极星辉域状态、队伍共享附着计数、4 秒周期结算与独立星烁伤害入口；契约见[星超导反应契约](../../../../契约/元素反应/反应/星超导反应契约.md)。
> 最后更新：2026-09-12。

## 1. 定位

星超导（`Stellar-Conduct`）是星烁反应（Stellar Reactions）体系首个落地的分支：冰雷交互在满足星烁资格时排他替代普通超导。它使用独立 `reaction.stellar_conduct` Definition、Rule、Profile、极星辉域状态与队伍共享计数状态，不归入 `mechanics/superconduct/` 机制目录，也不是普通超导 Rule 内的条件分支。

星超导 occurrence 本身不产生任何公共反应伤害（不存在"反应星烁伤害"分类），只按 `1:1` 消费冰雷并声明极星辉域（`Polestar Field`）状态与空间创建计划。星超导相关伤害属于角色技能提供的直伤星超导，由角色能力组装强类型输入后走独立星烁 Damage 公式。

辉映·星超导（`Radiance: Stellar-Conduct`）是共享会话在角色侧的投影：队伍每个角色持有一个辉映·星烁 Buff 实例，角色 content/ability 只读取自身 Buff 决定是否启用星超导技能逻辑。Buff 的统一创建、刷新与移除由跨系统协调承担，属后续接线切片。

## 2. 领域所有权

| 领域 | 星超导相关职责 |
| --- | --- |
| Aura | 冰、雷元素量与 `1:1` 消费后值 |
| Reaction | 独立 Definition 与候选、极星辉域 State、队伍共享计数 State、周期结算根 |
| Space | 极星辉域 `REACTION_OBJECT` 位置投影（圆心固定在触发反应的敌人当时位置）与生命周期声明 |
| Buff | 辉映·星烁 Buff 实例与物理减抗 Buff 的生命周期真值（当前切片未接线） |
| Damage | 独立星烁公式的结算与区间审计；不读取 Buff、ReactionState 或协调器 |
| Coordination | 领域创建/刷新/替换计划、附着记录条件判定、帧规范化物化结算根与到期移除；不实现星烁公式、不拥有长期状态 |

## 3. 稳定 Definition 与方向

```text
reaction.stellar_conduct / reaction_handler.stellar_conduct

stellar_incoming_cryo_on_electro
stellar_incoming_electro_on_cryo
```

候选要求请求同时携带 `reaction_capability:stellar_conduct`、上游确认的角色来源集合，并且当前触发来源属于该角色集合；只接受冰雷两个方向。`selection_priority` 为 `110`，高于普通超导默认 `0`；没有 capability 或合法角色触发来源时星候选不匹配，普通超导继续生效。capability 存在但后续计划缺少空间锚点、Profile 或 binding 不一致时视为技术错误，整批失败，不静默回退为普通超导。

两个方向都使用与普通超导相同的消费关系：

```text
consumed = min(incoming_amount, aura_amount)
```

## 4. 极星辉域状态

Reaction 拥有极星辉域 State，Space 拥有位置投影；两侧通过稳定 binding ref 原子创建、刷新和移除：

```text
PolestarFieldState
├── instance_ref             = reaction-state:polestar-field:{occurrence_ref}
├── space_entity_ref         = reaction_object:polestar_field:{occurrence_ref}
├── subject_ref              = 生成/刷新锚点主体
├── created_by_occurrence_ref
├── trigger_source_ref       = 创建 occurrence 的来源
├── team_ref                 = player_team
├── created_frame
├── expires_at_frame         = 最近一次触发帧 + 420
└── revision
```

触发星超导只影响生成和维持：

- 附近没有领域时，在触发目标当时位置创建新领域，圆心与角色位置无关；同时创建或继承队伍共享计数（见第 5 节）。
- 触发位置处于当前领域内（X/Z 距离 `<= 12`，忽略 Y 轴）时，保留同一实例和圆心，延展存在时间至 `frame + 420` 并递增 `revision`，同时通过 Space 实体更新入口同步空间实体的生命周期投影（保留创建帧与位置）；不重置计数窗口。
- 触发位置在领域外时，移除旧领域（State 与 Space 实体）并以新位置创建新领域；计数窗口继续继承，仅更新排除的触发攻击身份。
- 同一队伍同一时刻至多存在一个极星辉域。

领域到期时由 `PolestarFieldExpiryCoordinator` 原子移除 State、Space 实体与队伍共享计数，代表星超导共享会话结束。State 刷新与 Space 投影更新由 binding 校验强制一一对应：只有 State 刷新而没有 Space 更新（或更新后的生命周期与 State 不一致）时整批失败。领域水平半径 `12`、无限高度与 `420` 帧持续时间为当前实现基线，来源确认状态见契约第 9 节。

## 5. 队伍共享计数与 4 秒窗口

Reaction 拥有按队伍 scope 共享的计数 State：

```text
StellarConductCounterState
├── instance_ref             = reaction-state:stellar-conduct-counter:{team_ref}
├── subject_ref              = 会话创建时的锚点主体
├── team_ref                 = player_team
├── window_start_frame
├── next_settlement_frame    = window_start_frame + 240
├── window_index             = 从 1 连续递增
├── pending_count            = 当前窗口附着记录数
├── settled_stacks           = 最近一次结算的层数快照
├── recorded_record_refs     = 当前窗口已计数的 record_ref
├── excluded_attack_refs     = 新领域生成时排除的触发攻击身份
└── revision
```

计数按队伍共享，不绑定任何 Field 实例：领域替换、多个辉映角色都不会产生第二份计数。领域内敌人被施加冰/雷附着时，以一次攻击/判定事件为聚合单位形成 `StellarConductAttachmentRecord`（`record_ref`、`attack_ref`、`element`、`frame`、`target_refs`）；同一攻击对多个敌人产生附着只生成一条记录，被判定为双判的两次攻击生成两条记录。协调入口 `record_stellar_conduct_attachment` 按以下条件判定：

- 计数与领域 State 存在且领域未到期；
- 元素为冰或雷；
- `record_ref` 未在当前窗口记录（重放不重复计数）；
- `attack_ref` 不在排除集（新领域生成时，触发该次星超导的攻击不计入首个窗口）；
- 记录内至少一个目标处于领域内（X/Z 距离 `<= 12`）。

4 秒（`240` 帧基线）窗口到期时，帧规范化把结算冻结为 `StellarConductCounterSettlementRootWork` 并推进窗口：`settled_stacks = pending_count`、清空 `pending_count`、`recorded_record_refs` 与 `excluded_attack_refs`、`window_index += 1`、窗口前进 `240` 帧。scheduled root adapter 返回无 Effect 的 `prepared`，不生成公共反应伤害。系数查询按 `12` 层封顶，State 保留原始计数。

## 6. 辉映资格与直伤星烁入口

已确认的行为语义：

- 角色是否可以进入或执行星超导技能逻辑，只取决于该角色当前是否拥有辉映·星烁 Buff，不受新领域生成后前 4 秒的限制；不建立预热窗口。
- 直伤星超导在 `0` 层时星烁基础系数为 `1`，不因前 4 秒语义传入 `0`。
- 领域内冰/雷普通伤害增益由辉映 Buff 的属性修正实现，通过 `bonus.damage.cryo` 与 `bonus.damage.electro` 进入通用伤害增伤区；协调器和元素系统不直接修改伤害结果（待 Buff 接线切片）。

层数到系数的映射（`n` 为结算层数，查询时封顶 `12`）：

```text
直伤星烁基础系数：n = 0 -> 1；1 <= n <= 12 -> 1.4 + 0.05n；n > 12 -> 2
辉映冰/雷普通增伤：n = 0 -> 20%；1 <= n <= 12 -> 28% + 1%n；n > 12 -> 40%
```

星烁 Damage 使用独立 `damage_formula.stellar_reaction`，组织方式参考月曜公式但不复用月曜输入：角色能力在提交直伤计划时从自身 Buff 解析倍率、层数系数和星烁专属区间，组装为 `StellarReactionDamageInput(mode=character_direct)`；公式按区间顺序结算并生成独立审计，不读取 Buff、ReactionState 或协调器，不接受普通 `DamageModifierTerm` 与通用反应输入。`reaction_composite` 模式留待星扩散阶段启用。

## 7. 当前边界与验收入口

当前边界：

- 辉映·星烁 Buff 的统一创建/刷新/移除、离域约 1 秒延续与重置语义未接线；领域来源复用普通超导物理减抗 Buff 的申请/替换/移除编排未落地。
- 附着记录的上游事件接线（由攻击/Aura 施加事件聚合生成记录）未落地；当前由测试直接驱动协调入口。
- `damage_formula.stellar_reaction` 的 resolver 结算分支与角色直伤技能模组未接入；当前只有请求校验与无状态公式实现。
- `420` 帧、`240` 帧、半径 `12` 为实现基线；精确帧边界与半径来源待来源化确认，不作为正式数值 golden case。
