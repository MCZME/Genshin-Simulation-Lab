# 激化反应契约

> 状态：已实现
> 最后更新：2026-08-02
> 对应设计：[激化反应设计](../../../架构/系统/元素反应/反应/激化反应设计.md)

## 1. 稳定标识

| 类型 | 稳定键或值 |
| --- | --- |
| 原激化 | `reaction.quicken` |
| 原激化 Handler | `reaction_handler.quicken` |
| 雷命中草方向 | `incoming_electro_on_dendro` |
| 草命中雷方向 | `incoming_dendro_on_electro` |
| 原激化方向 Profile | `reaction_profile.quicken.<direction>` |
| 超激化 | `reaction.aggravate` |
| 超激化 Handler | `reaction_handler.aggravate` |
| 超激化方向 | `incoming_electro_on_quicken` |
| 超激化 Profile | `reaction_profile.aggravate.incoming_electro_on_quicken` |
| 蔓激化 | `reaction.spread` |
| 蔓激化 Handler | `reaction_handler.spread` |
| 蔓激化方向 | `incoming_dendro_on_quicken` |
| 蔓激化 Profile | `reaction_profile.spread.incoming_dendro_on_quicken` |
| 激化 Damage Profile | `damage_profile.reaction.catalyze_additive` |
| 激化公式 key | `damage_formula.catalyze_additive` |
| Aura | `AuraKind.QUICKEN` |
| State slot | `ReactionStateSlot.QUICKEN` |
| 超激化倍率 | `1.15` |
| 蔓激化倍率 | `1.25` |

本契约不定义激化专属 Reaction Gate；超激化和蔓激化受本次元素施加的 Aura ICD 限制。

## 2. Definition 与输入

三个 Definition 必须使用 `ReactionEntryKind.ELEMENTAL_INTERACTION`，并由生产 bootstrap 显式注册。Reaction 输入至少包含：

```text
interaction_id
target_impact_ref
frame / order
source_ref / subject_ref
incoming_element?
incoming_amount
observed_aura
observed_quicken_state?
current_damage_element?
catalyze_impact_qualification?
```

`incoming_amount` 必须是 Aura ICD 后的实际正预算。`observed_quicken_state` 必须与 `AuraKind.QUICKEN` 的 Link 投影一致；失配属于技术错误，不能降级为空反应。

## 3. 原激化契约

原激化只有两个方向：雷命中普通草、草命中普通雷。设先手 Aura 量为 `A`、ICD 后预算为 `T`：

```text
reaction_amount = min(A, T)
quicken_amount = reaction_amount
incoming_remaining = T - reaction_amount
aura_remaining = A - reaction_amount
```

约束：

- 消费系数为 `1:1`；
- 不应用普通附着 `20%` 损耗来计算 `quicken_amount`；
- `reaction_amount=0`、ICD blocked 或没有普通草/雷对手时不成立；
- 无伤害正草/正雷施加可以成立；
- 原激化不产生 Damage Effect、Damage Gate 或当前伤害调整；
- 后续步骤只能使用前置步骤留下的剩余预算。

## 4. QUICKEN Aura 与 State

每个主体最多有一个活动 `QuickenState`，并且必须与一份 `QUICKEN` Aura 和一条 Link 一一对应。

```text
QuickenState
├── instance_ref
├── subject_ref
├── quicken_aura_link_ref
├── created_by_occurrence_ref
├── last_updated_by_occurrence_ref
├── created_frame
└── revision
```

State 不保存 Aura amount、decay rate、来源等级、元素精通或 Damage 输入。`next_required_frame` 固定为 `None`。

激元素衰减档案必须满足：

```text
duration_seconds = 6 + 5Q
duration_frames = 60 * (6 + 5Q)
decay_per_frame = Q / (360 + 300Q)
```

其中 `Q` 是精确 `AuraAmount`，创建量和衰减率均不经过普通附着损耗。

建立、覆盖和终止使用三个强类型意图：

```text
QuickenStateEstablishmentIntent
QuickenStateCoverageIntent
QuickenStateTerminationIntent
```

对应 adapter 必须在组装阶段唯一注册。自然耗尽或主体失效时，State、Aura 和 Link 原子移除。

## 5. 覆盖与身份

在当前帧规范化后比较 `Q_old` 与 `Q_new`：

```text
Q_new > Q_old  -> amount=Q_new, decay_rate=R_new
Q_new <= Q_old -> amount=Q_old, decay_rate=R_old
```

覆盖必须：

- 保留 Aura instance、State instance、贡献引用、创建帧和 Link；
- 每次成功 occurrence 都更新 State `revision` 与 `last_updated_by_occurrence_ref`；
- 仅在新量严格更大时更新贡献来源、数量来源、衰减来源和档案；
- 新量较小或相等时保留旧贡献的来源与时间；
- 旧实例已在同帧归零时先完成终止，再新建实例。

Aura Store 保存唯一元素量和贡献账本；不得用普通 Aura 的无条件叠加替代本契约。

## 6. 超激化/蔓激化资格

附加反应资格证据由协调器提供 `CatalyzeImpactQualification`，至少证明：

```text
target_impact_ref == 当前目标 Impact
damage_element == trigger_element
has_positive_scaling_coefficient == True
```

并且：

- 交互开始时存在正 `QUICKEN` Aura 和对应 `QuickenState`；
- 本次 ICD 后正雷/正草元素施加成功；
- 当前关联 Damage Profile 选择 `damage_formula.catalyze_additive`；
- `DamageImpactSpec.scaling_terms` 至少有一个 `coefficient > 0`；
- 真实伤害、只有 flat base、只有零系数 term 或仅依赖后续 `BASE_DAMAGE_FLAT_ADD` 的命中不合格。

不合格时，普通元素交互和原激化仍可正常成立，但不得产生附加 occurrence 或 `CatalyzeCurrentImpactDamageAdjustment`。

## 7. 当前 Impact 调整协议

Reaction 只输出以下独立变体，不得复用 `CurrentImpactDamageAdjustment` 的增幅字段：

```text
CatalyzeCurrentImpactDamageAdjustment
├── adjustment_ref
├── target_impact_ref
├── occurrence_ref
├── reaction_profile_key
├── trigger_element
├── reaction_multiplier
└── reaction_bonus
```

同一目标 Impact 最多有一个最终适用的当前伤害调整；重复、冲突或 target 不一致时使用 `CatalyzeImpactAdjustmentConflictError` 失败。

协调器只转换为：

```text
CatalyzeReactionInput
├── target_impact_ref
├── occurrence_ref
├── reaction_profile_key
├── trigger_element
├── reaction_multiplier
└── reaction_bonus
```

该输入不能由 content、普通 Damage 请求或自由 metadata 直接填写。

## 8. Damage 公式与审计

Damage 必须使用主攻击标签唯一选中的 `damage_formula.catalyze_additive`，并拒绝将激化输入送入增幅反应区。设当前来源等级的共享系数为 `L`：

```text
mastery_bonus = 5 * EM / (1200 + EM)
base_damage_addition = L
                     * reaction_multiplier
                     * (1 + mastery_bonus + reaction_bonus)
```

本版超激化和蔓激化的 `reaction_bonus` 固定为 `0.0`。`EM` 和来源等级在 Damage 当前查询上下文读取；原激化创建者的属性不参与。

基础附加值进入 `BaseDamageAddition` 和 `DamageResult.base_damage_additions`，再按以下顺序结算：

```text
(ordinary scaling + base damage additions)
-> damage bonus
-> crit
-> general reaction zone
-> defense
-> resistance
```

DamageResult 必须保存 `CatalyzeReactionResolution`，至少审计 target、occurrence、profile、trigger element、来源等级、等级表 key、等级系数、EM、mastery bonus、反应倍率、反应加成、附加值和 EM 查询轨迹。

## 9. 复合顺序与燃烧链接

稳定顺序为：

```text
QUICKEN + DENDRO 被雷：Spread -> Quicken coverage
QUICKEN + ELECTRO 被草：Aggravate -> Quicken coverage
QUICKEN + CRYO 被雷：Superconduct 与 Aggravate 并行
DENDRO + CRYO 被雷：Superconduct -> 剩余雷预算 Quicken
```

`QUICKEN` 作为类草 Component 进入普通燃烧；双类草时每个 Component 各按 `1/150 GU/frame` 消费，同一 Link 不得导致重复消费。燃烧状态、火伤害和周期字段以[燃烧反应契约](./燃烧反应契约.md)为准。

## 10. 失败、事务与事实

以下情况必须在提交前稳定失败：

- Definition、Profile、Handler、Damage Profile 或 Quicken adapter 缺失；
- Aura/State/Link 主体、实例、revision 或前值冲突；
- 当前 Impact、伤害元素、Profile 或资格证据不一致；
- 已注册的绽放候选由绽放 Definition 和对应契约处理，不由激化契约重复消费 Aura；
- 雷扩散进入未实现激化扩散；
- Damage 公式输入非法或 Damage 预备失败。

ICD、Aura、Reaction、State、Link 和 Damage 计划必须在同一元素交互批次中完成 prepare/validate/commit；任何失败都不能留下部分 occurrence、Aura、State 或 Damage 调整。

激化只使用通用事实：`REACTION_OCCURRED`、`REACTION_STATE_CHANGED`、Aura 事实、`DAMAGE_RESOLVED` 和 `ELEMENTAL_INTERACTION_RESOLVED`，不新增机制专属事件。
