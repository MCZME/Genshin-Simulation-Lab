# 治疗系统实现规划

> 状态：持续维护的开放任务清单。阶段 A-C 与首个真实治疗能力已完成；范围治疗、更多角色 content 与快照/生存状态评审待推进。
> 架构职责见[治疗系统设计](../架构/系统/治疗系统设计.md)，公共数据与行为契约见[治疗系统契约](../契约/治疗系统契约.md)。
> 最后更新：2026-08-23。

## 1. 文档定位

本文只保留交付范围与开放任务，不重复架构职责、公式、事件契约与验收标准；这些以[治疗系统设计](../架构/系统/治疗系统设计.md)和[治疗系统契约](../契约/治疗系统契约.md)为准。通用治疗公式的机制来源已登记在[治疗系统契约](../契约/治疗系统契约.md)。旧项目实现只作覆盖范围参考，不直接迁移。

## 2. 已交付范围

| 阶段 | 交付 |
| --- | --- |
| A：模型与公式 | 多 component 治疗请求、结果与结构化错误；治疗基础值、治疗加成与受治疗加成公式；纯计算 `HealingResolver` |
| B：Resolver 与事件 | `HEALING_RESOLVED` 事件与通用 JSON 持久化 |
| C：生命系统接入 | `HealingRequestHandler`、生命系统 adapter 与 assembler 暴露；理论结算到生命提交闭环 |
| D（部分）：首个真实治疗能力 | `ImpactKind.HEAL` 接线、目标解析、芭芭拉环持续治疗与爆发治疗及纵向集成数值验证 |

第一轮未修改 `SimulationInput`、资产库 schema 或结果库 schema。

核心落位：`core/systems/healing/`、`core/events/`、`core/systems/health/`、`application/assembly/assembler.py`；纵向集成验证见 `tests/integration/content/barbara/`。

## 3. 开放任务

1. 范围治疗与更通用的多目标展开规则：单体与全队已由芭芭拉覆盖，范围治疗仍待定型。
2. 接入更多真实角色治疗 content：每个能力补充可信来源与数值验证（golden case）。
3. 治疗快照、生命之契和生存状态按后续需求单独评审（周期治疗已由芭芭拉环持续治疗覆盖）。

阶段验收口径不变：真实治疗能力必须能从运行时影响请求进入治疗 handler，数值具有可信来源并可由 golden case 复现。
