# 蒸发反应契约

> 状态：已实现。冻结普通水火蒸发的生产 key、方向、元素量和当前 Impact 增幅语义。

最后更新：2026-07-31

## 1. 稳定 key

```text
reaction_key = reaction.vaporize
handler_key = reaction_handler.vaporize
```

方向与 Profile：

| direction_key | profile_key |
| --- | --- |
| `incoming_hydro_on_pyro` | `reaction_profile.vaporize.incoming_hydro_on_pyro` |
| `incoming_pyro_on_hydro` | `reaction_profile.vaporize.incoming_pyro_on_hydro` |

上述 key 是生产契约，不得通过中文或其他显示名称替换。

## 2. 签名与基础倍率

| incoming_element | observed_aura_kind | direction_key | base_multiplier |
| --- | --- | --- | ---: |
| `hydro` | `pyro` | `incoming_hydro_on_pyro` | `2.0` |
| `pyro` | `hydro` | `incoming_pyro_on_hydro` | `1.5` |

Definition 必须同时注册两个方向，Profile 与签名方向一一对应。

## 3. 水触发火

前置条件：

```text
incoming_element = hydro
observed aura contains positive pyro amount A
incoming_amount I > 0
```

精确消费：

```text
incoming_consumed = min(I, A / 2)
aura_consumed = incoming_consumed * 2
incoming_remaining = I - incoming_consumed
aura_remaining = A - aura_consumed
```

Profile 基础倍率为 `2.0`。

## 4. 火触发水

前置条件：

```text
incoming_element = pyro
observed aura contains positive hydro amount A
incoming_amount I > 0
```

精确消费：

```text
incoming_consumed = min(I, A * 2)
aura_consumed = incoming_consumed / 2
incoming_remaining = I - incoming_consumed
aura_remaining = A - aura_consumed
```

Profile 基础倍率为 `1.5`。

## 5. 决议与 occurrence

反应成立时必须形成：

- 一个 `ReactionDecisionStep`；
- 一个 `ReactionOccurrence`；
- 一个 `ElementalTransitionEffect`；
- 零个 ReactionState、Gate、独立伤害或派生 Impact。

`transition.aura_kind` 分别为被消费的 `pyro` 或 `hydro`。不生成 `matched_component_ref`。

## 6. 当前伤害调整

只有当前 Damage Impact 的最终元素等于后手元素时才创建调整：

```text
reaction_profile_key = 当前方向 profile_key
trigger_element = incoming_element
base_multiplier = 当前方向 base_multiplier
reaction_bonus = 0.0
```

公式和审计遵守[增幅反应伤害契约](../增幅反应伤害契约.md)。

## 7. 后手剩余量

`incoming_remaining` 可以继续同一个 `ReactionDecisionSequence`，但序列结束后不自动写入 Aura。普通 Vaporize Rule 不输出持久后手附着 Effect。

## 8. 正常空结果

以下输入不形成普通蒸发 occurrence：

- 后手不是水或火；
- 没有对应的正普通火/水 Aura；
- ICD 后 `incoming_amount = 0`；
- 同元素施加；
- 不满足本契约两个明确签名的其他输入。

无当前伤害或伤害元素与后手不同，不否定蒸发本身，只是不创建 Damage 调整。

## 9. Golden case

至少长期覆盖：

| 方向 | Aura before | incoming before | incoming consumed | Aura consumed | 余量 |
| --- | ---: | ---: | ---: | ---: | --- |
| 水触发火 | 火 `0.8` | 水 `1.0` | 水 `0.4` | 火 `0.8` | 后手水 `0.6`，不持久化 |
| 火触发水 | 水 `0.8` | 火 `1.0` | 火 `1.0` | 水 `0.5` | 水 Aura `0.3` |

两个方向还必须覆盖 `EM = 0` 时的 `2.0` / `1.5` 伤害乘数和至少一个非零 EM 审计案例。
