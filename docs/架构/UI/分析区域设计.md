## 1. 产品定位（工作定义，待最终确认）

- 分析区域是用户对仿真结果进行查看、比较、解释并得出判断的画布空间：配置区域回答“模拟什么”，模拟节点回答“跑这批”，分析区域回答“跑出来说明什么”。
- 分析区域的产出是答案和结论：不是新的模拟输入，也不是新的仿真；不改动结果库真值。
- 分析区域随工作流保存，是画布的一部分，不是脱离画布上下文的独立报告页。
- 结果即时变化：视图配置或数据变化后，结果立即重新求值；分析区域不能做成配置区域那样的“方法式”处理链。

## 2. 已确认结论

### 2.1 区域模型

- 区域是数据语言的边界；边界端口是跨区域数据的唯一出入口；**数据只沿连线流动**（该规则适用于配置区域与分析区域）。
- 分析区域边界输入是区域内数据的唯一输入源，提供整个区域的数据来源。
- 区域内任何节点必须沿连线从边界输入取得数据；未连接节点是草稿，不能获得数据。
- 边界输入的上游只能是画布级源节点：模拟节点、数据提供节点。
- 边界输入**允许多源合并**：模拟节点与数据提供节点可同时连入，会话组按连线顺序合并。
- 数据提供节点是画布级节点，不属于分析区域内部；历史结果经它连入边界输入。
- 分析区域不关心数据来源；来源归属由源节点（模拟节点 / 数据提供节点）负责。
- 会话组 = 会话 ID 的有序列表，不携带来源标签或其它元数据。
- 区域本身不承担会话数、来源、成功/失败状态的汇总展示（批次状态在模拟节点，历史选择状态在数据提供节点）。

### 2.2 已废弃的旧条款

- “分析区域的边界输入可以不连接；此时可由区域内的数据提供节点选择历史结果。边界输入与内部数据提供节点是两个明确数据源，不互相替代或隐式合并。”——数据提供节点作为区域内独立数据源的表述不再成立。

### 2.3 执行模型

- 分析区域是声明式的视图空间：改配置即重新提交查询计划，单次查询开销小；缓存键（数据源指纹 + 配置）后置。
- 运行粒度为区域级一次查询（见 2.5 与契约 v2），不做逐节点限速推进；节点状态按响应着色，错误定位到具体节点。
- 端口语言见 2.8：`会话组` / `结果表` / `展示配置`。
- 每个视图有独立状态（加载中 / 有数据 / 空 / 错误 / 过期）。
- 分析区域头部提供「运行分析」入口，按 2.17 的三阶段执行；运行期间复用现有批次编排（构建动画、进度、取消与编辑锁），分析节点状态由查询响应驱动。
- 定义变化自动重算：取数/算子/展示配置、区域连线、数据源会话等影响结果的快照变化后，前端防抖重新查询（见 2.18）；自动重算无副作用，缺会话或会话过期时不查询只提示。

### 2.4 展示形式

- 需要图表形式（如饼图）作为视图的展示方式之一；具体图表种类与范围待定。

### 2.5 数据入口与算子节点族

- **数据处理不是一种节点，而是一族节点**：一个取数节点（「获取数据」，`source` 切换双来源）+ 七个关系算子。用户以连线组合表达 SQL 常用子集的查询与加工；表达力的扩展方向是算子种类，不是成品模板。
- **取数节点是会话组的唯一消费点**：单一「获取数据」节点（`fetch`）以 `source` 切换：
  - `运行记录`：读 `simulation_runs`，支持从输入快照按路径提取条件列（变体身份）；
  - `事件记录`：读 `simulation_events`，支持事件类型多选、帧范围谓词下推与载荷路径提取成具名列。
- **七个算子**（结果表进、结果表出）：过滤、投影、排序、分组聚合（sum / count / avg / max / min / stddev / p95）、限制行数、等值连接（inner / left）、受限计算列（数值四则）。
- 表达能力边界冻结于契约：过滤条件为单层条件组 + 操作符白名单；文本匹配、嵌套条件 AST、跨列比较后置；时间轴持续段配对等非关系代数逻辑留待专门处理节点扩展。
- 参数安全线不变：字面量全部 prepared statement 绑定，列名经白名单校验后引用，不拼接 SQL。
- 形状静态可推：每个节点的输出形状由输入形状与参数唯一确定；前端推导驱动校验诊断与列下拉选择器（列引用一律下拉，不允许自由文本），后端执行前独立防御性校验，靠契约测试对齐。
- 执行模型：前端把区域内从边界可达的子图编译为结构化查询计划，`POST /api/v1/analysis/query` 一次提交；后端编译 CTE 链在库内执行，中间结果不出后端；响应只携带视图终端表（≤10000 行截断标记）。分析区域运行为区域级单次查询，错误定位到具体节点。
- 后端落点：`infrastructure/results_sqlite/analysis_query.py` 计划编译执行器，`application/` 提供计划模型与用例门面，`server/` 出计划执行与 schema 端点；原模板注册表 `templates.py` 与模板服务删除。

### 2.6 配置节点的作用域

- **查询参数配置节点取消**：算子与取数节点的标量参数在节点卡内直接编辑；原「配置节点提供参数」路线随模板层退役。
- **展示配置保留**（四种 kind，各对应一种视图）：给视图节点提供列绑定——表格配置（条件列/数据列）、时间轴配置（轨道列/起点列/终点列/值列/标签列）、饼图配置（分组列/值列/标签列）、柱状图配置（X 轴列/Y 轴列/系列列）。列选项来自视图输入表的形状推导（前端沿「配置节点 → 视图 → 上游链」解析）；一个视图必须且只能连一个对应展示配置节点（缺失报错）。
- 会话选择只通过会话组（边界输入 / 数据提供节点）。

### 2.7 节点模型原则（上下文无关）

- **节点是上下文无关的输入→输出单元**：节点不关心输入从哪来、输出被谁用；只声明“接收什么输入、提供什么输出”。
- 节点允许**多输入、多输出**；处理节点之间**允许串联**，处理节点的输出可以分支给多个下游。
- 图的连通性、端口语言匹配、无环等由前端图校验器负责，节点自身不感知图结构。
- 分析区域是**声明式数据流图**：每个节点是纯函数，输出由输入派生；依赖变化自动向下游传播，结果即时更新。这区别于配置区域的“方法式”（节点作为方法、按拓扑序应用、有构建轨迹）。

### 2.7.1 交互原则（节点内状态节点内交互）

- **节点内的状态在节点内交互，其它状态在节点外。**
- 列顺序是视图节点内部状态：在节点内直接调整（拖列头调整顺序）。
- **列显隐不是视图职责**：视图显示收到的全部数据；需要隐藏或重命名列时，在取数/投影阶段用 `project` 算子完成，不再需要模板列选择参数。
- **数据消费方式（哪些列是条件列/数据列）属于配置节点**：视图节点不知道列归属，只按配置节点提供的绑定渲染。

### 2.8 端口语言与数据集

- 分析区域端口语言三套：
  - `会话组`：会话 ID 列表；边界输入与数据提供节点输出；只能进取数节点的选场过滤。
  - `结果表`：取数节点与算子的输出（列名 + 类型）；可进视图数据输入与下游算子输入；列可被投影、排序、分组、连接、计算列与过滤条件引用。
  - `展示配置`：展示配置节点输出（按视图种类区分）；只进对应视图的配置输入。
- 视图数据输入是**单表语义**：允许一条或多条同结构入线，行拼接为一张表后按同一套绑定渲染；不同结构的表连入由校验器拒绝。视图不设“来源”概念。
- 连接规则按语言 + 形状匹配；不匹配由前端校验器报错。
- **会话维度显式化**：所有源表携带 `session_id` 列——逐场查看是过滤/投影保留 `session_id`，跨场汇总是聚合不把它放进分组列，跨批对比是多条链靠身份列区分；框架不做任何隐式按会话展开（`per_value` 出局）。

### 2.9 视图节点划分

- 视图节点按具体形态拆成节点种类，不做带模式参数的通用视图节点。已设计：`成员指标表`、`单场时间轴`、`占比饼图`、`指标柱状图`；其余（汇总统计表等）后续设计。
- 饼图与柱状图**拆成两个节点种类**，不通过“图表类型”配置节点区分。
- 视图节点是纯渲染终端：数据来自数据处理节点输出，展示来自配置节点。

### 2.10 对比

- **对比不是独立节点或独立视图**。
- **视图不设“多来源”能力**：同结构的数据是同一份数据，视图按单表语义消费（多条同结构入线行拼接）；需要区分批次/场次时，由结果表里的身份列（`session_id`、变体条件列）承担，并经配置节点绑定（条件列、X 轴、系列列等）。
- 不同结构的数据无法被同一套展示配置覆盖，不能进同一视图；需要并置/对比时由连接/聚合等算子合并为带来源列的输出表（数据层能力），不进入视图职责。
- 产品决策“多结果对比第一版不强制包含”继续有效。

### 2.11 数据提供节点与模拟节点的会话保留

- 数据提供节点是画布级源节点，参数只有 `session_ids`（有序去重字符串数组，≤1000，随工作流保存）；顺序即用户选择顺序；空数组合法。
- 名称/状态/时间筛选、分页、“加载更多”、刷新与失效会话提示均为编辑器瞬态交互，不进入工作流 JSON；筛选能力由 `GET /api/v1/results` 的 `q` / `state` / `created_from` / `created_to` / `ids` 参数提供（见[UI API 契约](../../契约/ui/UI API 契约.md)）。
- 交互形态：节点卡只显示摘要（已选数量、名称 chips、失效提示），历史会话选择在锚定节点的画布内弹层完成；弹层内已选列表顺序即输出顺序，支持上移/下移。
- 数据提供节点**只提供会话级历史列表**：不做批次展示、不做“批次 → 成员”展开。
- 已选会话在结果库中缺失时执行不报错（查询自然无行）；编辑器打开时提示“N 场已不存在”并提供一键清除。
- 模拟节点**保存最近一次批次产生的会话 ID**；需要整批数据时，只能经模拟节点的最近一次批次获取（连入分析区域边界输入）。
- 模拟节点最近一次会话 ID **随工作流持久化**：写入模拟节点参数 `last_sessions`（会话 ID 列表），重开工作流后分析区域仍可读取。
- 模拟节点随批次同时保存 **`last_input_fingerprint`**（本次批次的有序来源区域 + 有序成员输入 JSON 的稳定哈希）：用于判断 `last_sessions` 是否随配置区域参数变化而过期。未记录指纹的存量定义视为无法核对（自动重算沿用旧会话并提示；「运行分析」默认补跑）。
- 分析区域边界合并后的总会话数 ≤1000，超限由前端校验报错（与[分析系统契约](../../契约/分析系统契约.md) 6.2 对齐）。
- “结果详情暴露输入摘要/成员标签”仍为结果 API 后置能力，不阻塞分析区域第一版。

### 2.12 具体视图：成员指标表

- 作用：参数扫描 / 批结果总览，回答“每个成员表现如何、哪个条件组合最优”。
- 行 = 会话；列分两类：
  - **条件列**：该会话的输入条件（如武器类型、等级、精炼等变体参数），说明这一行是什么配置。
  - **数据列**：需要分析的指标（DPS、总伤害、最高/平均伤害、总治疗等）。
- 条件列来自会话的输入摘要（变体身份），经获取数据节点（运行记录来源）的快照提取列获得（快照提取列即 `asset_key` 原始值）；显示名解析后置。会话组本身仍只有 session ID。
- **条件列与数据列绑定由表格配置节点指定**（节点外内容），不是算子链声明；取数/算子链只输出通用行表；视图节点不知道列归属，按绑定渲染（条件列与数据列分区显示）。
- 视图功能只包含：**排序、列内最大/最小高亮**；列绑定由配置节点提供；不做“哪一行最优”的判断（那是用户的结论）。
- 视图按单表语义消费：多条同结构入线行拼接后按同一套绑定渲染；不设来源标签。
- **绑定编辑形态（2026-08-26 确认）**：绑定编辑在表格配置节点卡片内完成——两个分区列表（条件列、数据列），每行列名下拉选择，支持上移/下移/移除；列选项来自所连视图输入表的形状推导（前端沿「配置节点 → 视图 → 上游链」解析）。视图节点卡不承载任何绑定控件；缺少配置时视图内容区显示“缺少表格配置”空态，点击只做导航（选中并平移到对应配置节点），不在视图卡内编辑。
- **节点卡形态（2026-08-26 确认）**：头部（类型标识 + 状态徽标）+ 内容区（结果表本身，不出现参数表单）+ 底部（`in` / `config` 输入端口与“共 N 行”）。默认宽约 560px、高约 360px，可拖拽调整大小。
- **内容区状态（2026-08-26 确认）**：六态直接呈现在表格区域——未连接数据源、缺少表格配置、上游为空、加载中（骨架）、错误（区域内错误信息）、有数据（“共 N 行”）。其中“缺少表格配置”与“上游为空”提供可点击修复入口：前者导航到配置节点，后者定位到问题列表。
- **持久化边界（2026-08-26 确认）**：绑定（配置节点参数）随工作流保存；排序状态、最大/最小高亮、列显示顺序均为瞬态查看状态，不随工作流保存，重新打开回到默认（无排序、无高亮、按绑定顺序显示）。
- **排序规则**：
  - 数据列：单列排序（点表头切换升/降），不做多列组合排序。
  - 条件列：支持多列组合排序，**组合顺序 = 用户点击表头的顺序**（先点击的列为主排序键，后点击的列为次级排序键）；例如先点武器类型、再点等级，与先点等级、再点武器类型结果不同；每列方向可切换。
  - 表头呈现：条件列表头显示组合序号（①②…）与方向箭头；数据列表头显示方向箭头。提供“清除排序”小操作，一次清除全部排序状态。
  - 效果：按主排序键分组、组内按次级排序键排序，**分组是排序的自然结果，不需要显式分组功能**。
  - 默认无排序：按数据集行序显示，排序完全由用户点击驱动。
- 显式分组表头（组内排序、组间比较）后置。
- **列顺序**：拖列头调整显示顺序，允许跨区调整显示位置，但跨区不改变绑定角色（分区由配置节点绑定决定，显示顺序由节点内拖拽决定）。
- **视觉分区**：条件列固定在左侧、数据列在右侧，中间分隔线 + 数据区轻微底色差异；表头滚动时吸顶。
- **高亮（2026-08-26 确认）**：数据列表头下拉菜单提供“高亮最大 / 高亮最小 / 清除高亮”；只对数值列开放，非数值数据列不提供；高亮不影响排序。
- **大批量呈现**：节点卡内滚动 + 窗口化渲染，不搞分页；底部常驻“共 N 行”；后端返回 `truncated` 时显示“仅显示前 10000 行”提示；节点可调整大小以改变展示区域。

### 2.16 具体节点 UI：获取数据（2026-08-26 确认）

- 节点显示名「获取数据」，kind `fetch`，`source ∈ runs | events`；**节点卡只做摘要**，配置进入大弹层（与数据提供节点的会话选择弹层同构，不改变画布形式）。
- 卡片结构：默认宽度 360px（其余节点 260px）；摘要显示来源徽标、数据范围（输入条件列数 / 事件范围）与输出列表格（列名 / 类型 / 来源），底部保留会话组输入端口；卡片内提供「编辑数据…」入口打开配置弹层。
- **配置弹层**：分「数据范围」与「输出列」两区；草稿式编辑，完成才写回节点参数，取消丢弃；弹层内校验（列名规范、重名、缺事件类型）即时提示。
- **数据范围**：来源切换「运行记录 / 事件记录」（另一来源已有参数时二次确认）。取数节点不承担行级筛选（帧范围等归下游过滤算子，`frame` 是固定输出列）；事件范围不再单独出现选择器，由输出列目录统一控制。
- **输出列（运行记录）**：结构树勾选——左侧展示输入快照结构树（对象 / 列表 / 标量，来自 schema `snapshot_tree`），列表节点（队伍[]、目标[]、套装[]）只出现一次、不枚举位置；勾选列表叶子时由用户输入位置编号（显示 1 基、路径 0 基），非列表叶子直接勾选；右侧为已选输出列（列名可改、类型角标、可移除），提供常用入口与「手动添加列」（路径 + 列名 + 类型）。
- **输出列（事件记录）**：左侧按事件类型展开字段（业务名 + 类型，字段来自 schema `event_types`），目录顶部显示事件范围状态（全部（未筛选）/ 已选 N 类）；**类型名前的勾选框控制事件范围**，**字段勾选框生成输出列**并自动补齐事件范围；右侧已选输出列可改列名/移除，提供常用入口与「手动添加列」（事件类型 + 路径 + 列名 + 类型）。`event_type` 随 `payload_columns` 持久化（契约必填，见[分析系统契约](../../契约/分析系统契约.md) 3.1）。
- 术语：界面使用「输入条件列 / 输出列 / 事件范围」等用户语言，不再暴露表名、JSON 路径与「快照 / 载荷 / 提取列」内部术语（参数名与契约保持不变）。

### 2.17 运行入口与三阶段执行（2026-08-26 确认）

- 分析区域头部提供「运行分析」按钮（与配置区域的「区域校验 / 区域运行」并列）；运行分三阶段：**获取输入 → 数据处理 → 视图加载**，任一阶段失败即整次中止。
- **获取输入**：逐个检查边界输入连接的源节点——模拟节点满足任一条件即补跑：`last_sessions` 缺失或为空、未记录 `last_input_fingerprint`、或指纹与当前配置区域展开结果不一致（配置已变更）；补跑完成的新会话写回 `last_sessions` 与 `last_input_fingerprint` 并随工作流保存。数据提供节点直接使用 `session_ids`，永不触发模拟。多源按连线顺序合并去重（同 2.1）。
- 补跑的模拟节点未连接任何配置区域时，运行报错中止并提示先连接配置区域；分析区域边界完全未连接源节点时同样报错中止，不发空查询。
- 补跑复用现有批次运行编排：构建动画、批次进度、取消、全局编辑锁与「逐批校验 → 提交 → 轮询」链路；补跑任一失败或取消，不进入查询阶段，旧结果保留并标 stale。
- **数据处理**：区域级图校验通过后，把从边界可达的子图编译为查询计划，`POST /api/v1/analysis/query` 一次执行；错误定位到具体节点（同 2.3/2.5）。
- **视图加载**：终端表落入视图节点并更新状态；「运行分析」运行期间区域标题显示当前阶段（获取输入… / 查询… / 加载视图…），按钮禁用。
- 会话过期判定与自动重算见 2.18；结果缓存键仍后置。

### 2.18 自动重算与数据源指纹（2026-08-26 确认）

- 前端对每个分析区域维护**可重算快照指纹**：查询计划请求（会话组 + 表节点）、区域内全部节点参数（覆盖视图与展示配置，v1 统一触发）、区域内/边界连线顺序、边界输入就绪状态。
- 快照变化后防抖 300ms 自动重算：仅重新提交查询计划并更新视图，不触发模拟；相同快照跳过请求（结果缓存后置）。
- 竞态：自动重算带递增序号，过期响应丢弃；查询前保留旧表并标 `stale`（无旧表标 `loading`），完成后替换，避免闪空。
- **缺会话或会话过期时不查询**：边界连接的模拟节点未就绪时，视图显示可操作提示（「模拟数据未运行 / 配置已变更或输入指纹缺失，请点击运行分析」），由用户显式「运行分析」补跑。
- 图校验错误时不自动重算，错误继续由问题面板呈现；schema 未加载时跳过。
- 模拟节点 `last_input_fingerprint` 是数据源真值的一部分：配置区域参数变化会使期望指纹变化 → 会话过期 → 自动重算停止查询并提示；该字段随批次写回并随工作流保存。

### 2.19 分析模板（节点组）方向（2026-08-26 确认骨架，未定稿）

- 目标：把「获取数据范围 → 处理数据 → 查看结果」的用户心智翻译成现有节点图，避免用户直接面对结果库结构与 SQL/算子语义。
- 模板是**前端代码中一组节点的定义**（节点 kind + 默认参数 + 节点间连线），不是新节点 kind，不进入工作流持久化；拖入分析区域时按定义生成一组普通节点，参数预填，生成后与模板无关联，可自由编辑、删除、重连。
- **模板不包括视图**：只生成数据范围 + 处理链（取数、过滤、聚合、连接等），输出结果表；视图（成员指标表 / 时间轴 / 饼图 / 柱状图）与展示配置由用户后续自行添加连接。
- 裸算子节点（`fetch` / `filter` / `project` / `aggregate` / `join` / `compute` 等）保留在画布对象面板，作为「高级 / 自定义分析」入口；模板是默认引导，不替代高级能力。
- 模板目录维护在前端（与节点注册表同层），指标/口径需配 golden 测试或明确注释；不新增后端端点。
- 尚未确定（依赖后续节点设计讨论）：模板清单与每个模板生成的子图、模板输出形态（单输出/多输出）、拖入交互细节（是否自动接区域边界输入、是否弹参数选择）、命名（分析模板 / 数据处理模板 / 节点组）。
- **模板设计暂停**：先完成分析区域节点设计讨论，再回头定模板清单与生成规则。

### 2.20 具体节点 UI：过滤（2026-08-27 确认）

- 卡片形态：**卡片直编**，不弹层。过滤节点只是少量条件行，直接编辑比弹层更顺；取数节点因目录大、勾选复杂才用弹层。卡片内为「条件组合」（满足全部 / 满足任一分段控件）+ 条件行 + 添加按钮，节点卡加宽至 340px。
- 操作符：界面用中文口语（等于 / 不等于 / 大于 / 大于等于 / 小于 / 小于等于 / 属于 / 不属于 / 为空 / 不为空），**按列类型过滤可选集合**——数值列才有大小比较，文本列才有属于/不属于，布尔列只有等于/不等于/为空判断；参数仍为契约 `op` 原值。
- 值输入类型化：数值列数字输入（int 限整数）、布尔列真/假下拉、属于/不属于多值 chips（回车或逗号添加、退格删除最后一个、chip 内移除）、为空/不为空不出现值输入。chips 修正旧编辑器把 `in` 数组字符串化后一改即坏的问题。
- 行内即时校验：缺列、空值、空数组、值类型与列类型不匹配（含存量错误数据）逐行提示（提示不阻断编辑，整体形状校验仍由问题面板承担）；切换列/操作符时自动重置为与列类型兼容的值形态。
- 语义保持契约：`ne` / `not_in` 沿用可空语义（SQL 常识），`is_null` / `is_not_null` 参数不携带 `value`；本节点不改任何参数结构与后端行为。
- 列名暂用原名，业务中文标签作为整个分析流程的统一调整后置（见第 3 节）。

### 2.21 具体节点 UI：分组聚合（2026-08-27 确认）

- 卡片形态：**卡片直编**，不弹层（与过滤节点一致）；节点卡加宽至 340px。卡片分「统计维度」与「统计指标」两区（对应契约 `group_by` 与 `aggregates`），避免 SQL 术语。
- 统计维度：checkbox 清单（列名 + 类型提示），保持清单顺序输出；v1 不支持拖拽排序。
- 统计指标行：聚合函数下拉（求和 / 计数 / 平均 / 最大 / 最小 / 标准差 / 95% 分位，参数仍为契约 `fn` 原值）+ 列下拉（带类型）+ 结果列名；**函数按列类型过滤**——计数对所有列开放，其余仅数值列。
- 结果列名：选择函数和列后自动填入默认名 `fn_column`（如 `sum_dps`，与契约自动命名一致），用户可改；改动后切换函数/列保留自定义名；留空时按契约自动命名。
- 行内校验：函数/列未选、非数值列使用数值函数、结果列名不合法或重名逐行提示；统计维度与统计指标皆空时提示至少选择其一。
- 参数与契约保持一致（`group_by` / `aggregates`，`as` 可选），不改变后端行为；列名暂用原名。

### 2.22 具体节点 UI：投影（2026-08-27 确认）

- 显示名保持「投影」（候选「选择列」被否，沿用现名）；**卡片直编**，不弹层，节点卡加宽至 340px。

### 2.23 具体节点 UI：排序（2026-08-27 确认）

- **卡片直编**，不弹层，节点卡加宽至 340px；每行 = 排序键序号（①②…）+ 列下拉（带类型）+ 方向（**升序 / 降序**，参数仍为 `asc / desc`）+ 上移/下移 + 移除；「＋ 添加排序键」追加。

- 排序键顺序即优先级（第一行为主排序键），v1 支持行内上移/下移调整；首行上移、末行下移按钮禁用。

- 参数与契约保持一致（`keys`），不改变后端行为；列名暂用原名。

### 2.24 具体节点 UI：限制行数（2026-08-27 确认）
