# 护盾系统后续实现计划

> 状态：核心运行时已完成；本文只记录尚未实现的真实护盾 content、结晶和扩展工作。
> 正式行为与架构见[护盾系统设计](../架构/护盾系统设计.md)，稳定字段见[护盾系统契约](../契约/护盾系统契约.md)。

最后更新：2026-07-13

## 1. 已有基线

当前已经具备：

- 机制实例身份、半开生命周期、活动索引和受控命令。
- 护盾创建公式、全部授予策略和原生容量 Store。
- 动态护盾强效、元素倍率和多盾并行吸收。
- 护盾到生命提交闭环。
- Impact、application assembly、事件、快照和结果 JSON 往返。
- 单元测试、集成测试和测试专用 content 纵向链路。

测试专用 content 只证明工程链路，不代表任何真实角色护盾已经完成。

## 2. 真实护盾 content

### 2.1 目标

至少选择一个规则简单、资料充分的真实角色护盾，完成：

```text
资产与 handler_key
-> content action / impact
-> ShieldGrantRequest
-> ShieldRuntime
-> 角色来伤
-> HealthRuntime
-> 事件与结果持久化
```

### 2.2 实现前输入

- 当前版本技能描述和资产倍率。
- 等级、天赋等级和创建属性。
- 持续时间、元素、授予策略和 conflict key。
- 长按、命座、固有天赋或特殊倍率是否影响原生容量。
- 是否授予抗打断及其后续系统依赖。
- 至少一个可复现的创建与承伤 golden case。

### 2.3 验收

- 使用真实资产输入，不在测试中硬编码替代正式数据链路。
- 创建公式中间量和最终原生容量可审计。
- 切换场上角色后动态护盾强效正确。
- 刷新、替换和过期行为与来源一致。
- handler 缺失或数据错误在组装阶段失败。
- 事件和结果库记录可复现完整过程。

## 3. 结晶反应

### 3.1 前置条件

结晶开始实现前必须先确认：

- 元素附着和反应归属协议。
- 反应触发帧与晶片创建帧。
- 结晶等级表和元素精通公式的数据来源。
- CreatedObjectRuntime 与 Space 的晶片实体模型。
- 拾取目标、拾取范围和拾取帧顺序。
- 新晶片替换旧结晶盾的明确规则。

### 3.2 目标链路

```text
元素附着与岩反应
-> 结晶反应结果
-> 晶片 created object
-> 当前场上角色进入拾取范围
-> 晶片消耗
-> active_team ShieldGrantRequest
-> 结晶盾授予
```

### 3.3 验收

- 等级表、精通公式和元素结果有当前版本来源。
- 不同元素晶片使用明确 ShieldElement。
- 晶片创建、拾取、消耗和护盾授予事件顺序稳定。
- 新旧结晶盾替换规则有 golden case。
- 15 秒等持续时间不凭记忆写入，必须由来源确认。
- 多晶片、切人和过期边界可复现。

## 4. 后续扩展

以下事项不与真实护盾或结晶默认捆绑：

- 护盾存在条件查询协议。
- 完整抗打断、韧性和击退系统。
- 固定角色保护、联机和多队伍 protection。
- owner 被移除时的跨系统清理协议。
- 专用护盾结果投影和 analysis 模型。
- UI 有效盾量展示与指定来伤元素查询。

每项扩展必须先确认状态所有者、查询入口、事件顺序和测试基线。
