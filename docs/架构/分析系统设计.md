# 分析系统设计

> 状态：正式规范。
> 本文定义分析系统的模块边界、查询计划编译执行、可读 schema 与节点契约。
> 最后更新：2026-08-29。

## 1. 定位

分析系统是结果存储系统的派生层：基于结果库真值加工出可展示、可比较的结果表。分析不写库、不改变结果库真值；所有派生结果可重建。

核心模型：

- **数据 = 结果库内容**：`simulation_runs`、`simulation_events` 两张主表 + JSON 字段。
- **入口 = 取数节点**：单个 `fetch` 节点以 `source` 切换运行记录 / 事件记录；会话组约束行范围，从结果库读出基础表，事件载荷经声明的 JSON 路径提取成具名列。
- **加工 = 关系算子**：过滤、投影、排序、分组聚合、截断、等值连接、受限计算列；用户在画布上把算子连成管道，表达力对标 SQL 查询的常用子集。
- **边界 = 后端拥有 SQL**：前端只提交结构化查询计划（不含 SQL 文本），后端负责编译为参数化 SQL 并执行；安全边界是 prepared statement 语义加列名白名单，不是字符串过滤。
- 会话维度是普通数据列（`session_id`）：逐场、跨场汇总、跨批对比全部是显式列操作，框架不做隐式展开。

## 2. 模块边界

| 模块 | 职责 | 约束 |
| --- | --- | --- |
| `infrastructure/results_sqlite/analysis_query.py` | 查询计划编译执行器：计划校验（无环、输入数量、形状推导、列白名单）、CTE 编译、参数绑定、行数上限 | SQL 与结果库 schema 强耦合，实现自洽于此文件 |
| `application/models.py` | 查询计划与结果表的契约模型（`AnalysisPlan`、`AnalysisTableResult` 等） | 只做声明级校验，不接触数据库实现 |
| `application/services/analysis_query.py` | 用例门面 `AnalysisQueryService`（计划执行、schema 目录） | 声明级校验 + 委托执行协议 |
| `application/services/protocols.py` | `AnalysisQueryExecutor` 协议 | 入口层唯一依赖点 |
| `server/` | `POST /api/v1/analysis/query`、`GET /api/v1/analysis/schema` | DTO 层，不直接访问 infrastructure |

依赖方向：`server / cli -> application -> 执行协议 <- infrastructure 实现`。v1 的 `templates.py`、`AnalysisTemplatesService` 与模板目录端点删除。

## 3. 节点契约

节点种类、端口语言、表达式语言、算子参数与形状推导规则统一见[分析系统契约](../契约/分析系统契约.md)第 2 至 5 节，本文不重复维护细节。要点：

- 取数节点只有一个（`fetch`，`source` 切换运行记录 / 事件记录），是会话组唯一消费点；
- 七个算子均为「结果表进、结果表出」的上下文无关单元，输出形状由输入形状与参数静态可推；
- 形状推导规则前后端各自实现：前端驱动编辑器与校验诊断，后端执行前防御性校验，靠契约测试对齐。

## 4. 执行模型

- 前端把分析区域内从边界可达的子图编译为查询计划（可达性 + 拓扑序 + 参数收集），一次提交 `POST /api/v1/analysis/query`。
- 后端将各节点编译为 CTE 链在结果库上一次执行；中间结果不出后端，浏览器不充当搬运工。
- 响应只携带 `outputs` 声明的终端表（视图输入）；每表硬上限 10000 行，超出置 `truncated: true`。
- 校验失败以 `400 / validation_failed` 返回，`details` 定位到具体节点；单个节点失败则整图失败。
- 改参数即重新提交计划；单查询开销小，草案中的缓存键（数据源指纹 + 配置）可以后置而不吃亏。
- 分析区域的运行粒度是「区域一次查询」，不再做逐节点限速推进；节点状态按响应着色，错误定位到具体节点（对决策 2.34 在分析区域适用范围的修订）。

## 5. 稳定性规则

- 节点 kind、参数结构、操作符与聚合函数白名单、形状推导规则冻结：只增不改。
- 聚合口径、浮点除法语义、可空比较展开以后端实现为唯一真值，配 golden 断言。
- 对外端点形状是契约；变更走 API 版本升级。

## 6. 与结果存储系统的关系

- 真值层：运行记录、输入快照、初始快照、事件流（结果库）。
- 派生层：查询计划的输出表；可重建，不落库。
- 物化（跳变表等）只按性能需要建立，永远可重建。
- 区间配对、曲线等非关系代数逻辑留待专门处理节点扩展，登记时同步本文件与契约。
