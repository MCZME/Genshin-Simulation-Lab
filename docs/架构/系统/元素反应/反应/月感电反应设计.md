# 月感电反应设计

> 状态：已实现（第一条纵向切片）
> 最后更新：2026-08-03

## 1. 定位

月感电是与普通感电机制簇并列的独立反应，使用独立 `reaction.lunar_electro_charged` Definition、Rule、Profile、雷暴云状态、周期攻击根和月曜伤害路径，不归入 `mechanics/electro_charged/` 机制目录。

月感电在满足队伍 capability、角色触发来源和严格水雷元素签名时排他选中；本次交互只产生月感电 occurrence，不同时产生普通感电 occurrence。没有 capability 或合法角色触发来源时，月候选不匹配，普通候选继续生效。

月感电 occurrence 本身不产生伤害，也不消耗水、雷元素量；它只创建或刷新雷暴云，并让本次后手元素以普通损耗形成持久 Aura，使水雷保持共存。伤害来自雷暴云的独立周期攻击，属于反应月曜伤害。

## 2. 领域所有权

| 领域 | 月感电相关职责 |
| --- | --- |
| Aura | 水、雷元素量、逐来源贡献账本、攻击时 `0.4 GU` 精确消费与后值 |
| Reaction | 独立 Definition、严格水雷候选、参与者冻结、雷暴云 State、攻击计划和逐目标 Damage Gate |
| Space | 雷暴云 `REACTION_OBJECT` 的位置投影、生命周期与创建/销毁声明 |
| Damage | 反应月感电复合月曜伤害的组分结算、排序加权和审计 |
| Coordination | 帧规范化物化攻击根、逐目标检查水雷 Aura、冻结参与者、Gate/消费/伤害的批次提交；不实现月感电公式 |

## 3. 稳定 Definition 与方向

```text
reaction.lunar_electro_charged / reaction_handler.lunar_electro_charged

lunar_incoming_hydro_on_electro
lunar_incoming_electro_on_hydro
```

候选要求请求同时携带 `reaction_capability:lunar_electro_charged`、上游确认的角色来源集合，并且当前触发来源属于该角色集合；只接受严格水雷两个方向，不接受其他元素共存签名。

月感电 occurrence 不消费水雷：

```text
incoming_consumed = 0
aura_consumed = 0
```

后手元素通过 `PersistentIncomingAuraApplicationEffect` 以标准 `20%` 损耗形成持久 Aura，水雷继续各自自然衰减。

## 4. 雷暴云状态

Reaction 拥有队伍级雷暴云 State，Space 拥有位置投影；两侧通过稳定 binding ref 原子创建、刷新和移除：

```text
LunarStormCloudState
├── instance_ref             = reaction-state:lunar-storm-cloud:{occurrence_ref}
├── subject_ref              = 生成/刷新锚点主体
├── space_entity_ref         = reaction_object:lunar_storm_cloud:{occurrence_ref}
├── created_by_occurrence_ref
├── trigger_source_ref       = 创建 occurrence 的角色来源（Gate 身份与伤害 owner 使用）
├── team_ref                 = player_team
├── created_frame
├── expires_at_frame         = 创建/刷新帧 + 360
├── next_attack_frame        = 创建帧 + 15（首次）
├── next_attack_index        = 从 1 连续递增
├── attack_interval_frames   = 15
└── revision
```

资料基线：雷暴云存在 `6` 秒，首次攻击约 `0.25~0.3` 秒；当前冻结确定值为 `15` 帧。触发月感电只影响生成和维持：附近没有雷暴云时在目标位置创建一朵；附近已有雷暴云时刷新其存在时间至 `frame + 360`，保留实例身份、触发来源和攻击游标。

同一队伍、同一时刻附近存在多朵雷暴云时（`5` 米半径），保留存在时间最长的一朵（并列时取 `instance_ref` 较小者），销毁其余云：State 移除且对应 Space 实体删除。本切片把云间排斥与生成锚点都使用 `5` 米半径的确定性最小可行规则，精确数值仍待人工确认。

雷暴云到期时由 `LunarStormCloudExpiryCoordinator` 原子移除 State 与 Space 实体。当前最小可行边界：刷新只延展 State 到期时间，不更新 Space 实体生命周期投影；到期移除以 State 为准。

## 5. 周期攻击

帧规范化把本帧 due 的雷暴云攻击冻结为 `LunarStormCloudAttackRootWork`，并推进 `next_attack_frame += 15`、`next_attack_index += 1`。scheduled root adapter 把根工作投影为下一 settlement round 的范围攻击 Effect group：

- 以雷暴云位置为中心、`5` 米半径的 `AreaAroundPositionSelection`；
- 每个合法敌对目标分别准备攻击：
  1. 目标必须同时存在正水、正雷 Aura；
  2. 目标 Aura 贡献中至少一个活动贡献来自角色；
  3. 逐目标 Damage Gate（`120` 帧窗口、每次至多 `1` 次）；
  4. 消费前从水雷正贡献冻结角色参与者（同一角色去重）；
  5. 对目标水、雷 Component 分别消费 `0.4 GU`；
  6. 以 `LunarReactionDamageInput(mode=REACTION_COMPOSITE)` 进入统一 Damage Impact。

Gate 阻止时该目标不消费、不受伤。雷暴云攻击不是角色元素施加，不额外加入创建云的触发方；每次攻击都从当时消费前的水雷正贡献重新冻结参与者。

## 6. 反应月曜伤害

雷暴云攻击伤害使用月曜生产公式的 `REACTION_COMPOSITE` 模式：每个角色组分独立完成等级基数、精通、暴击、擢升和抗性结算，再按完整组分伤害排序并使用 `0.60 / 0.30 / 0.05` 加权。

当前基线参数：

```text
等级基数：80=1077.4，90=1446.9，95=1561.5，100=1674.8
月曜精通系数 = 6 × EM / (EM + 2000)
反应倍率 = 3.0（采用角色月感电基线，反应月感电独立倍率待人工确认）
伤害元素 = 雷（DamageElement.ELECTRO）
可暴击 = true
```

伤害分类使用 `damage_profile.reaction.lunar_electro_charged`，Damage kind 使用 `reaction_damage.lunar_electro_charged`，与普通感电 `reaction_damage.electro_charged` 互不混淆。

## 7. 当前边界与验收入口

当前边界：

- 正式角色 content 的 capability 绑定仍待角色内容设计；golden case 使用临时 capability 端口。
- 首次攻击间隔、周期攻击间隔、攻击半径、云间排斥半径和生成锚点采用上述冻结基线，精确数值待人工确认。
- 雷暴云刷新不更新 Space 实体生命周期投影（见第 4 节）。
- 角色月感电伤害入口（`CHARACTER_DIRECT`）待角色内容设计，本切片只实现反应月感电（雷暴云攻击）。
- 雷暴云移动、阻挡、复杂碰撞和其他需要完整空间几何的规则不由当前 `Space` 最小模型推测；岩造物干扰和角色专属雷暴云强化属于后续 content/Space 切片。
- 反应月曜伤害继续使用注入式暴击决策；可回放随机输入的统一协议尚未冻结，不能在本机制中自行引入全局随机源。

主要验收入口：

- `tests/unit/core/systems/reaction/test_lunar_electro_charged.py`
- `tests/unit/core/coordination/elemental_reaction/test_lunar_storm_cloud_planning.py`
- `tests/golden/reactions/test_lunar_electro_charged_storm_cloud.py`

资料基线：[月曜反应通论](https://www.miyoushe.com/ys/article/73142429)。长期机制真值以本设计、契约、生产代码和 golden case 共同验证。
