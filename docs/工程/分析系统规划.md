# 分析系统规划

> 状态：生效，持续维护。
> 本文按[分析系统设计](../架构/分析系统设计.md)排定落地方案，登记分析能力重做后的第一版范围与工程关注点。
> 最后更新：2026-08-25

## 1. 定位

分析能力按“数据 = 结果库内容、处理 = SQL 模板”重做：模板注册表（声明 + SQL + 行变换）在 `infrastructure/results_sqlite/templates.py`，契约模型与用例在 `application/`，HTTP 端点在 `server/`。原 `analysis/` 顶层模块及其 processors（状态还原、路径寻址、序列、指标、对比）已删除。

## 2. 已落地

- 模板契约模型（`TemplateDeclaration` / `TemplateResult` / `RelationTable` 等）与执行协议（`AnalysisTemplateExecutor`）。
- `AnalysisTemplatesService` 声明级校验（模板存在、参数必填与类型、关系形状、行数上限）。
- `SQLiteAnalysisTemplateExecutor`：四张 v1 模板（`session_metrics`、`share_rows`、`timeline_rows`、`metric_summary`），prepared statement 绑定、关系临时表拼装、结果行上限 10000 与 `truncated` 标记。
- HTTP 端点：`GET /api/v1/analysis/templates`、`POST /api/v1/analysis/templates/{template_id}/execute`。
- 旧代码清理：`analysis/` 模块、`GET /results/{session_id}/metrics` 端点、`ResultsService` 的折叠/查询/指标/对比方法、相关冻结测试与 helpers 全部移除；`GET /results/{session_id}/events`（仓库直读）保留。
- 测试：模板执行器集成测试（含 golden 断言：`session_metrics` 聚合数值与 DPS 口径）、服务校验单测、HTTP 路由单测。

## 3. 后续增强

- 模板扩展：原始事件查询、状态折叠（曲线）等模板，待有消费视图（复盘视图、曲线）时登记。
- 条件列显示名解析（join 资产库或前端格式化层）与模板可选列参数（任意列隐藏）。
- 结果超限/截断的后续处理（分页或模板级行限）。
- 视图节点落地后按前端需求回填模板声明（如时间轴多场叠加的“身份列”角色）。

## 4. 工程关注点

- 模板与结果库 schema 强耦合：新增或修改结果库表/字段时，同步模板 SQL 与声明，避免漂移。
- 口径一致性：指标公式（总伤害、DPS 等）以模板实现为唯一真值，配 golden 断言测试；口径变化必须走新模板或版本。
- 模板集只增不改：新增模板登记到[分析系统契约](../契约/分析系统契约.md)第 4 节。
- 行数上限：事件类模板靠帧范围/事件类型参数收敛数据量；v1 不做分页。
- 安全：前端不传 SQL；参数与关系输入由执行器安全拼装。
