# 文档入口

本目录保存项目架构、稳定契约、决策、工程规范和必要的历史资料。文档正文、目录和文件名使用中文，路径引用使用相对链接。

仓库级 Codex/AI 协作入口见根目录 [AGENTS.md](../AGENTS.md)。本目录保存正式设计、契约和工程规范；`AGENTS.md` 只保留硬规则、必读路径和验证入口，不重复展开详细方案。

## 1. 文档分区

| 分区 | 职责 |
| --- | --- |
| `架构/` | 当前系统职责、领域模型、依赖、流程和不变量 |
| `契约/` | 稳定 key、配置、数据结构、公式输入、失败边界和序列化要求 |
| `决策/` | 已确认的高层选择、原因、替代方案和冻结结论 |
| `工程/` | 开发规范、测试要求、迁移策略、实施计划和历史交付资料 |

正式文档不保存实施时间线。第一版、第二版等交付过程、历史评估和临时资料必须明确标记状态，不能作为当前生产真值。

## 6. 维护规则

- 改动架构边界、配置契约、资产 schema、结果模型或迁移策略时同步更新对应文档。
- 新增正式文档前先确定其唯一职责，避免同一规则由多个文件共同拥有。
- 尚未确认的机制明确标注草案、待确认或临时资料。
- 历史文档冻结后不继续追踪当前实现状态。
- 删除被替代文档前，先迁移唯一内容并修正全部引用。
- 文档与代码冲突时，根据已确认资料、正式契约和 golden case 判断正确行为，再修正错误的一侧。
