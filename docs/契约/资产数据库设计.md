# 资产数据库设计

> 本文档记录新项目第一版资产数据库的设计决策。
> 资产数据库用于保存角色、武器、圣遗物、技能倍率与效果参数等基础资产数据。

## 1. 设计目标

新项目的资产数据库用于替代旧项目中的 MySQL 静态资产库。

第一版目标：

- 使用本地数据库，便于离线运行与随应用分发。
- 保存角色、武器、圣遗物等仿真所需基础数据。
- 支持技能倍率、武器特效、命座、天赋、圣遗物效果等半结构化数据。
- 为 UI 提供资产列表与基础展示数据。
- 为仿真组装阶段提供稳定、明确的数据读取接口。
- 避免让仿真核心直接依赖 SQLite、SQL 或 UI 层。

## 2. 非目标

第一版暂不处理：

- 敌人基础抗性/等级信息。
- 多语言文本。
- 用户自定义资产。
- 在线资产更新。
- 复杂数据库迁移系统。
- 原始抓取数据归档表。

原始抓取数据不写入主资产库。如需追溯，可由导入流程在库外保存文件或缓存。

## 3. 数据库选型

第一版主资产库使用 SQLite。

资产库文件作为只读生成产物存在，例如：

```text
data/assets/assets.db
```

应用运行时只读使用该数据库，不直接修改主资产库。

## 4. 总体分层

资产库采用“结构化索引表 + JSON 半结构化负载”的混合模型。

核心分为两层：

- Index 层：保存 UI 和仿真经常查询的稳定字段。
- Payload 层：保存技能倍率、武器效果、命座、天赋、圣遗物效果等非标准结构。

数据库保存数据、参数和处理器标识；复杂行为逻辑仍由仿真代码实现。

## 5. 第一版表结构

第一版暂定表：

```text
asset_db_meta
asset_import_runs
characters
character_level_stats
weapons
weapon_level_stats
artifact_sets
artifact_set_bonuses
talent_scaling_entries
effect_payloads
```

### 5.1 `asset_db_meta`

保存当前资产库元信息。

建议字段：

```text
key    TEXT PRIMARY KEY
value  TEXT NOT NULL
```

建议内容：

```text
schema_version
data_version
importer_version
built_at
source_name
source_version
content_hash
```

### 5.2 `asset_import_runs`

记录资产库生成过程。

建议字段：

```text
id
source_name
source_version
schema_version
data_version
importer_version
imported_at
note
```

第一版每次整体重建资产库，因此该表不承担原始数据归档职责。

### 5.3 `characters`

角色基础索引表。

建议字段：

```text
asset_key    TEXT PRIMARY KEY
source_id    TEXT NOT NULL
name         TEXT NOT NULL
element      TEXT NOT NULL
weapon_type  TEXT NOT NULL
rarity       INTEGER NOT NULL
handler_key  TEXT NULL
```

### 5.4 `character_level_stats`

角色等级属性表。

建议字段：

```text
character_key     TEXT NOT NULL
level             INTEGER NOT NULL
ascension_phase   INTEGER NOT NULL
base_hp           REAL NOT NULL
base_atk          REAL NOT NULL
base_def          REAL NOT NULL
ascension_stat    TEXT NULL
ascension_value   REAL NULL
```

### 5.5 `weapons`

武器基础索引表。

建议字段：

```text
asset_key    TEXT PRIMARY KEY
source_id    TEXT NOT NULL
name         TEXT NOT NULL
weapon_type  TEXT NOT NULL
rarity       INTEGER NOT NULL
handler_key  TEXT NULL
```

### 5.6 `weapon_level_stats`

武器等级属性表。

建议字段：

```text
weapon_key       TEXT NOT NULL
level            INTEGER NOT NULL
ascension_phase  INTEGER NOT NULL
base_atk         REAL NOT NULL
secondary_stat   TEXT NULL
secondary_value  REAL NULL
```

### 5.7 `artifact_sets`

圣遗物套装基础索引表。

建议字段：

```text
asset_key    TEXT PRIMARY KEY
source_id    TEXT NOT NULL
name         TEXT NOT NULL
handler_key  TEXT NULL
```

### 5.8 `artifact_set_bonuses`

圣遗物一件套、二件套或四件套效果参数表。

建议字段：

```text
artifact_set_key  TEXT NOT NULL
piece_count       INTEGER NOT NULL
handler_key       TEXT NOT NULL
params_json       TEXT NOT NULL
```

### 5.9 `talent_scaling_entries`

技能倍率条目表。

建议字段：

```text
id              INTEGER PRIMARY KEY
character_key   TEXT NOT NULL
talent_key      TEXT NOT NULL
entry_key       TEXT NOT NULL
label           TEXT NOT NULL
scaling_json    TEXT NOT NULL
tags_json       TEXT NULL
```

`talent_key` 示例：

```text
normal_attack
charged_attack
plunging_attack
elemental_skill
elemental_burst
passive
```

`entry_key` 为同一技能内的稳定条目键，不作为显示文本使用。

### 5.10 `effect_payloads`

通用效果参数表。

建议字段：

```text
effect_key   TEXT PRIMARY KEY
owner_type   TEXT NOT NULL
owner_key    TEXT NOT NULL
effect_kind  TEXT NOT NULL
unlock_key   TEXT NULL
handler_key  TEXT NOT NULL
params_json  TEXT NOT NULL
```

`owner_type` 示例：

```text
character
weapon
artifact_set
passive
constellation
talent
```

## 6. 资产身份规则

不使用 SQLite 自增 ID 作为资产身份。

不使用显示名称作为资产身份。

配置文件与仿真组装统一引用 `asset_key`。

`asset_key` 使用 `{asset_type}:{source_id}` 格式，例如：

```text
character:75
weapon:11512
artifact_set:15032
```

`name` 只用于 UI 展示与人类阅读。

`display_name` 可以写入配置作为辅助缓存，但不能作为仿真识别依据。

## 7. `asset_key` 与 `handler_key`

`asset_key` 与 `handler_key` 分离。

- `asset_key`：资产身份，数据库与配置使用。
- `handler_key`：代码实现绑定键，由仿真代码注册表解析。

示例：

```text
asset_key   = character:75
handler_key = character.furina
```

当前阶段按三档理解 `handler_key`：

- `handler_key = NULL`：资产已入库，但尚无行为实现。UI 可以展示，组装阶段不会创建 content。
- `handler_key = generic.noop` 或 `generic.test_*`：仅用于测试、占位或本地最小闭环验证，不代表真实游戏机制已经实现。
- `handler_key = character.*`、`weapon.*` 或 `artifact.*`：已有真实 content 实现，应有对应测试或 golden case 支撑。

真实资产若对应行为尚未实现，默认保持 `handler_key` 为空，不使用占位 handler 假装已实现。

## 8. 技能倍率 `scaling_json`

`scaling_json` 只保存随技能等级变化的倍率/数值表，不保存技能行为逻辑。

百分比统一存储为小数倍率：

```text
7.864% -> 0.07864
48.3862% -> 0.483862
```

第一版使用组件式结构：

```json
{
  "schema_version": 1,
  "mode": "level_table",
  "level_min": 1,
  "level_max": 15,
  "components": [
    {
      "kind": "stat_ratio",
      "stat": "hp",
      "values": [0.07864, 0.084538, 0.090436]
    }
  ]
}
```

`mode` 第一版支持：

```text
level_table
constant
```

`components.kind` 第一版支持：

```text
stat_ratio
flat
plain_ratio
plain_value
```

混合治疗示例：

```json
{
  "schema_version": 1,
  "mode": "level_table",
  "level_min": 1,
  "level_max": 15,
  "components": [
    {
      "kind": "stat_ratio",
      "stat": "hp",
      "values": [0.048, 0.0516, 0.0552]
    },
    {
      "kind": "flat",
      "values": [462.2253, 508.4543, 558.5355]
    }
  ]
}
```

复杂行为、内容创建空间实体的生命周期与行为调度、持续时间、攻击间隔、元素附着等不进入 `scaling_json`。

## 9. 效果参数 `params_json`

`effect_payloads.params_json` 用于保存武器、天赋、命座、圣遗物等复杂效果的参数。

数据库只保存效果参数，不保存效果行为。

顶层固定包含：

```text
schema_version
params
```

示例：

```json
{
  "schema_version": 1,
  "params": {
    "modifiers": [
      {
        "target": "self",
        "stat": "hp_percent",
        "op": "add",
        "value": 0.2
      }
    ]
  }
}
```

精炼变化示例：

```json
{
  "schema_version": 1,
  "params": {
    "damage_bonus_by_refinement": [0.12, 0.15, 0.18, 0.21, 0.24],
    "duration_frames": 600,
    "stack_limit": 3
  }
}
```

简单效果可以使用通用 handler：

```text
generic.static_modifiers
generic.conditional_modifiers
```

复杂效果使用专用 handler：

```text
character.furina.c2
weapon.some_weapon.passive
artifact.some_set.4pc
```

## 10. 导入与版本管理

资产库是可重建的生成产物。

建议生成流程：

```text
读取源数据
-> 清洗/标准化
-> 生成临时 assets.tmp.db
-> 校验数据完整性
-> 校验通过后替换 assets.db
```

第一版本地导入入口使用资产 manifest JSON 文件，作为“已标准化数据 -> SQLite 资产库”的边界。

manifest 顶层固定包含：

```text
schema_version = 1
kind = asset_manifest
meta
characters
character_level_stats
weapons
weapon_level_stats
artifact_sets
artifact_set_bonuses
talent_scalings
effect_payloads
```

CLI 构建命令：

```powershell
uv run genshin-sim assets build --manifest path/to/assets.json --db data/assets/assets.db
```

无 `--manifest` 时，`assets build` 仍只生成本地最小烟测资产库，用于开发闭环和测试，不代表真实资产导入。

开发期允许从 Project Amber / Yatta 当前默认 API 抓取本地 raw JSON cache，用于调试转换器和追溯源字段：

```powershell
uv run genshin-sim assets fetch-source --source project-amber-yatta --out data/assets/sources/project_amber_yatta/default
```

该命令默认抓取角色、武器、圣遗物套装索引和成长曲线。需要详情数据时显式指定：

```powershell
uv run genshin-sim assets fetch-source --source project-amber-yatta --character-id 10000075 --weapon-id 11512 --artifact-set-id 15032 --out data/assets/sources/project_amber_yatta/default
```

若需要开发期完整 raw cache，可使用 `--all-details`，但全量角色、武器和圣遗物套装详情请求较多，耗时和源站偶发失败风险都更高。

raw cache 转标准 manifest：

```powershell
uv run genshin-sim assets build-manifest --source project-amber-yatta --source-cache data/assets/sources/project_amber_yatta/default --out data/assets/manifests/project_amber_yatta.json
```

manifest 转 SQLite 前应先执行数据验收：

```powershell
uv run genshin-sim assets audit-manifest --manifest data/assets/manifests/project_amber_yatta.json
```

`audit-manifest` 会读取标准 manifest 并输出导入摘要。存在重复键、孤儿引用、非法枚举或等级覆盖不完整时，命令返回非零退出码；通过后再执行 `assets build --manifest`。

第一版 Project Amber / Yatta 转换器生成角色、武器与圣遗物套装基础索引、已有详情文件对应的等级属性、角色核心战斗天赋倍率、角色固有天赋、特殊天赋与命座效果参数、武器精炼效果参数，以及圣遗物套装效果参数：

- 角色基础索引来自 `avatar/index.json`。
- 武器基础索引来自 `weapon/index.json`。
- 圣遗物套装基础索引来自 `reliquary/index.json`。
- 角色等级属性需要 `avatar/{id}.json` 与 `static/avatarCurve.json`，覆盖 `1-90` 每级以及 `95`、`100`。
- 武器等级属性需要 `weapon/{id}.json` 与 `static/weaponCurve.json`。3 星及以上武器覆盖 `1-90` 每级；1 星与 2 星武器按源数据最高突破等级覆盖到 `70`。
- 可突破等级 `20, 40, 50, 60, 70, 80` 写入突破前与突破后两条记录。
- 角色天赋倍率来自 `avatar/{id}.json` 的 `talent` 字段，第一版只转换普通攻击、元素战技、元素爆发三类核心战斗天赋。
- 天赋倍率按源站 `description` 行生成 `TalentScalingEntry`，保留 `source_talent_key`、`source_skill_id`、`source_line_index`、`source_template`、`source_param` 与格式标记，便于后续 handler 与源字段对照。
- 角色固有天赋效果来自 `avatar/{id}.json` 的 `talent` 字段中 `type=2` 且没有 `promote` 的条目，写入 `effect_payloads`，`owner_type=character`。
- 固有天赋效果按描述文本初步分为 `effect_kind=passive` 与 `effect_kind=passive_exploration`；空名称且空描述的源站占位条目会被跳过。
- 角色特殊天赋效果来自 `avatar/{id}.json` 的 `talent` 字段中有 `promote`、但不属于普通攻击/元素战技/元素爆发倍率转换范围的条目，写入 `effect_payloads`，`owner_type=character`。
- 特殊天赋效果按描述文本初步分为 `effect_kind=alternate_sprint`、`effect_kind=special_movement` 或 `effect_kind=special_talent`；替代冲刺等单级参数保存在 `promote_entries` 中。
- 角色命座效果来自 `avatar/{id}.json` 的 `constellation` 字段，写入 `effect_payloads`，`owner_type=character`，`effect_kind=constellation`，`unlock_key=c1` 到 `c6`。
- 角色固有天赋、特殊天赋与命座效果第一版只保留源 key、源 id、名称、原始描述和按文本顺序解析出的数字参数，不在导入阶段解释为真实机制。
- 武器效果参数来自 `weapon/{id}.json` 的 `affix` 字段，写入 `effect_payloads`，`owner_type=weapon`，`effect_kind=passive`。
- 武器效果参数第一版只提取精炼描述中的高亮值，保留完整 `source_templates`、`raw_values` 和解析后的 `values`；高亮文本可能是百分比、普通数字、斜杠分组数字或平台限定文本。
- 圣遗物套装效果来自 `reliquary/index.json` 的 `affixList` 字段，写入 `artifact_set_bonuses`。
- 常规圣遗物套装按源站 `affixList` 排序生成 2 件和 4 件效果；只有一个效果的祭礼冠类套装按 1 件效果写入。
- 圣遗物套装效果第一版只保留源 `source_affix_id`、`source_template` 和按文本顺序解析出的数字参数，不在导入阶段解释为真实机制。
- 没有 `affix` 的 1 星与 2 星普通武器不写效果参数。
- 不存在详情文件的资产只写基础索引，不写等级属性。
- 角色、武器、圣遗物套装索引行的 `handler_key` 默认保持为空，不在导入阶段绑定真实机制实现。
- 角色固有天赋、特殊天赋、命座、武器效果与圣遗物套装效果等参数行因 schema 要求必须有 `handler_key`，当前使用显式的 `*.unimplemented_*` 标记；这些键不代表真实机制已经实现，后续应由具体 content handler 替换。

raw cache 只作为开发期中间产物，不进入正式发布包，不进入运行时用户数据目录，也不写入资产数据库表。正式使用只携带生成后的 `data/assets/assets.db`。资产库元信息中保留 `source_name`、`source_version`、`data_version`、`importer_version`、`built_at` 和 `content_hash`，用于标识本次构建来源。

版本拆分：

```text
schema_version
data_version
importer_version
```

当 `schema_version` 不兼容时，优先重新生成或替换 `assets.db`。

当 `data_version` 较旧但 `schema_version` 兼容时，应用可以继续运行，并由 UI 提示数据版本较旧。

未来若支持用户自定义资产，再考虑 `user_assets.db` 或正式迁移系统。

## 11. 导入校验

导入校验至少包含：

- `asset_key` 唯一。
- `source_id` 存在。
- `name` 不为空。
- 等级属性覆盖必要等级。
- `scaling_json` 符合当前 schema。
- 百分比已经转换为小数倍率。
- `handler_key` 要么为空，要么能在代码注册表中找到；`generic.noop` 与 `generic.test_*` 只用于测试或占位资产。
- `effect_payloads.params_json` 是合法 JSON。
- 不存在孤儿外键。

当前 `audit-manifest` 已覆盖：

- 角色、武器、圣遗物套装基础键唯一性。
- 角色等级属性、武器等级属性、圣遗物套装效果、技能倍率、效果参数的引用关系。
- 角色元素、武器类型、稀有度与属性枚举的基础合法性。
- 角色 `1-90 + 95 + 100` 等级覆盖；3 星及以上武器 `1-90` 等级覆盖，1 星与 2 星武器覆盖到 `70`。
- 可突破等级 `20, 40, 50, 60, 70, 80` 的突破前后双 phase 覆盖。
- 圣遗物套装效果 `piece_count` 只允许 `1`、`2` 或 `4`，并检查 `params` 的基础 schema。
- 技能倍率 `scaling` 的基础 schema、组件列表和值表长度。
- 效果参数 `params` 的基础 schema、精炼范围和组件值表长度。
- 角色命座效果的 `unlock_key` 必须为 `c1-c6`，角色固有天赋效果的 `unlock_key` 必须使用 `passive:*` 形状，特殊天赋效果的 `unlock_key` 必须使用 `talent:*` 形状。

效果参数的语义 schema 会在实现具体武器、天赋、命座或圣遗物 handler 时继续细化。

## 12. 与仿真核心的接口

`sim-core` 不直接依赖 SQLite。

`sim-core` 不直接执行 SQL。

资产数据库只在仿真组装阶段被读取；仿真运行时尽量不再查询资产库。

新项目通过 `AssetRepository` 协议暴露资产读取能力。

SQLite 的具体实现放在 `SQLiteAssetRepository` 一类的基础设施实现中。

建议接口能力：

```text
get_meta()
list_characters()
get_character(character_key)
get_character_level_stats(character_key, level, ascended=True)
list_weapons(weapon_type)
get_weapon(weapon_key)
get_weapon_level_stats(weapon_key, level, ascended=True)
list_artifact_sets()
get_artifact_set(artifact_set_key)
get_talent_scalings(character_key, talent_key)
get_effect_payloads(owner_key, effect_kind)
```

`ascended` 用于在可突破等级选择突破前或突破后属性，默认 `True` 保持读取最高突破阶段。该参数只对可突破等级生效：

```text
20, 40, 50, 60, 70, 80
```

示例：

```text
get_character_level_stats("character:10000002", 20, ascended=False) -> 20/0
get_character_level_stats("character:10000002", 20, ascended=True)  -> 20/1
get_character_level_stats("character:10000002", 37, ascended=False) -> 37/1
```

仓库返回明确的数据对象，例如：

```text
CharacterAsset
WeaponAsset
ArtifactSetAsset
TalentScalingEntry
EffectPayload
```

不向核心层传递 SQL row。

## 13. Handler 注册表

`handler_key` 由代码注册表解析。

示例：

```text
character.furina -> Furina
character.furina.c2 -> FurinaC2Handler
generic.static_modifiers -> StaticModifierHandler
artifact.viridescent_venerer.4pc -> ViridescentVenerer4pcHandler
```

缺资产、缺 handler、JSON 格式错误应在组装阶段报错，不应延迟到仿真运行中。

当前验证阶段只要求确认“资产 -> `handler_key` -> content contribution -> runtime 注入”的链路正确，不以 `generic.noop` 或测试 handler 验证真实伤害、治疗、Buff、反应或属性修饰数值。
