# 月结晶反应契约

> 状态：正式规范。
> 本文固定月结晶独立反应的稳定标识、候选与元素消费、月笼 State、共享累计器、谐奏攻击与反应月曜伤害及事务边界。
> 最后更新：2026-09-05。

## 1. 稳定标识

| 类型 | 稳定键或值 |
| --- | --- |
| 月结晶 | `reaction.lunar_crystallize` |
| 月结晶 Handler | `reaction_handler.lunar_crystallize` |
| 水岩方向 | `lunar_incoming_geo_on_hydro` |
| 水岩 Profile | `reaction_profile.lunar_crystallize.incoming_geo_on_hydro` |
| 谐奏攻击 Profile | `reaction_profile.lunar_crystallize.harmony_attack` |
| 月笼 State | `reaction_state.lunar_cage` |
| 累计器 State | `reaction_state.lunar_crystallize_accumulator` |
| 月笼空间 Profile | `reaction_spatial_profile.lunar_cage` |
| 月结晶 Damage Profile | `damage_profile.reaction.lunar_crystallize` |
| 月结晶 Damage Kind | `reaction_damage.lunar_crystallize` |
| 月结晶 capability | `reaction_capability:lunar_crystallize` |
| 月笼队伍作用域 | `player_team` |

月结晶 Definition 必须由 `create_default_reaction_bootstrap()` 组合进生产 bundle；Damage Profile 由生产组装器 `lunar_crystallize_damage_profiles()` 注册。月结晶没有独立 Damage Gate（谐奏无冷却，只按次数触发）；月笼飞行冷却由月笼 State 保存。缺失注册在组装阶段失败。

## 2. 候选与元素消费

月结晶只匹配以下条件同时满足的交互：

1. 请求携带 `reaction_capability:lunar_crystallize`；
2. 请求携带上游确认的角色来源集合 `character_source_refs`；
3. 当前触发来源 `source_ref` 属于该角色集合；
4. 后手岩命中正水 Aura，且目标没有活动冻结状态。

月结晶 `selection_priority` 为 `100`，高于普通结晶默认 `0`；无 capability 或合法角色触发来源时月候选不匹配，普通水结晶继续生效。火、雷、冰结晶方向不进入月候选。

元素消费与普通结晶一致：

```text
geo_consumed = min(入射岩元素量, 水 Aura 量 × 2)
aura_consumed = geo_consumed / 2
```

月结晶不使用普通结晶成立 Gate，不创建水晶片。occurrence 保存消费前冻结的 `participant_refs`（正水贡献角色 + 后手岩触发角色，去重排序）。

水雷共存目标沿用公共水雷复合候选：雷步骤先以普通结晶成立（受普通成立 Gate 约束），岩预算仍有剩余时，水步骤按月结晶候选继续成立。月结晶不受普通成立 Gate 约束，因此同一批内可以同时出现雷结晶晶片与月结晶月笼/累计记录。

## 3. 月笼 State

月笼 State 字段：

```text
instance_ref / subject_ref / space_entity_ref
created_by_occurrence_ref / trigger_source_ref / team_ref
created_frame / last_harmony_frame / next_attack_frame
expires_at_frame / attack_index / revision
```

约束：

- `instance_ref = reaction-state:lunar-cage:<occurrence_ref>:<0..2>`，`space_entity_ref = reaction_object:lunar_cage:<occurrence_ref>:<0..2>`，均由 occurrence_ref 与序号确定性派生；
- `expires_at_frame = last_harmony_frame + 540`（9 秒）；
- 创建时 `last_harmony_frame = created_frame`、`next_attack_frame = created_frame`；
- 发射后 `next_attack_frame = fire_frame + 21`、`last_harmony_frame = fire_frame`、`attack_index += 1`；
- 场上同时最多 3 枚月笼；触发目标附近（`12` 米半径、`5` 米高圆柱，Y 差 `≤ 5`）无月笼时，销毁旧月笼并在目标周围 `3.25` 米圆周上等距生成 3 枚；有则不生成；
- 到期帧由 `LunarCageExpiryCoordinator` 原子移除 State 与 Space 实体。

当前最小可行边界：生成半径冻结为 `3.25` 米（资料区间 `3~3.5`）；岩造物干扰忽略；刷新不更新 Space 实体生命周期投影，移除以 State 到期帧为准。

## 4. 共享累计器

累计器 State 字段：

```text
instance_ref / team_ref / subject_ref
pending_records / max_layers = 4 / revision
```

- `pending_records` 按 `(frame, order, occurrence_ref)` 排序，每条记录保存 `occurrence_ref`、`frame`、`order` 与 `participant_refs`；
- 每次月结晶追加一条记录，超过 4 层时丢弃最旧记录；
- 累计达到 3 条且存在合法谐奏目标时，消费前 3 条并发射谐奏；
- 谐奏无独立冷却，只按次数触发；受月笼飞行冷却或月笼销毁影响无法发射时记录继续累计（溢出）。

## 5. 谐奏攻击与反应月曜伤害

谐奏目标为当前受角色攻击的**一个**目标，且必须同时处于三枚月笼索敌范围（每枚月笼 `12` 米半径、`5` 米高圆柱）内；候选目标按距月笼集合锚点最近选择，并列取稳定 subject ref 较小者。三枚月笼必须全部未在飞行冷却且未到期。

每枚月笼各发射一枚投射物：

- 三枚月笼分别创建独立 `LunarReactionDamageImpactEffect`，使用同一参与者并集；
- 每个角色组分独立暴击，每枚月笼之间重新判定；
- 各月笼独立排序并 `0.60 / 0.30 / 0.05` 加权；
- 伤害立即结算（`NEXT_SETTLEMENT_ROUND`），投射物飞行只作为月笼冷却状态；
- 元素量恒为 `0`，不产生元素附着，不触发后续普通反应，不消费谐奏目标元素量。

月曜公式参数（已注册默认值）：

```text
等级基数：{80: 1077.4, 90: 1446.9, 95: 1561.5, 100: 1674.8}
精通系数 = 6 × EM / (EM + 2000)
反应系数 = 1.6（未折入口径，与角色月结晶倍率同值）
伤害元素 = 岩（GEO），可暴击
```

反应系数与分配权重是**一对口径**：本仓库采用未折入写法（系数 `1.6`、权重 `0.60 : 0.30 : 0.05`），最高组分实际系数为 `1.6 × 0.60 = 0.96`；资料里的另一套折入写法「反应倍率 `0.96` 配 `1 : 1/2 : 1/12` 分配」与本写法逐组分等价。换口径时两者必须同时改，只改一边会重复计入或漏计 `0.60`。数值出处：米游社《元素反应(高等元素论)》(`article/25901063`)、《月结晶伤害公式》与《月曜反应》(`article/77019346`)，适用版本月之八；等价关系由 golden `tests/golden/damage/test_lunar_reaction_coefficient.py` 钉住。

## 6. 事务、事实与错误边界

月结晶候选、月笼集合替换、累计器追加与消费、谐奏 Effect 和 Aura 消费均使用 `prepare -> validate -> commit`。Aura、ReactionState、Space 和事实的前值/版本任一 stale 时，整批失败且不得部分提交。

必须记录通用 `REACTION_OCCURRED`、`REACTION_STATE_CHANGED` 和 `ELEMENTAL_INTERACTION_RESOLVED`；谐奏伤害复用统一 Damage Impact 流程，不伪造 occurrence。

组装阶段缺少 Definition、Profile、Damage Profile、State/Space adapter 或月笼到期协调器时失败；运行时 capability 缺失、角色来源不匹配、版本冲突、空间绑定不一致或月笼冷却未结束也必须显式失败。

## 7. 当前非目标与验收入口

契约不包含：

- 正式角色 content 的 capability 绑定（golden case 使用临时 capability 端口）；
- 岩造物干扰月笼生成位置；
- 月笼投射物阻挡与命中延迟结算；
- 随机选笼/选目标的可回放随机协议（当前按距离 + 稳定 ref 确定性选择）；
- 角色月结晶 `CHARACTER_DIRECT` 伤害入口（直伤倍率资料基线 `1.6`，与第 5 节反应系数同值）。
- 角色或追加攻击专属的随机规则；当前组分暴击继续使用注入式 `CriticalDecisionProvider`。

主要验收入口：

- `tests/unit/core/systems/reaction/test_lunar_crystallize.py`
- `tests/unit/core/coordination/elemental_reaction/test_lunar_crystallize_planning.py`
- `tests/golden/reactions/test_lunar_crystallize_harmony.py`
- `tests/golden/damage/test_lunar_reaction_coefficient.py`（反应系数口径与权重）

资料基线：[月曜反应通论](https://www.miyoushe.com/ys/article/73142429)。长期机制真值以本契约、对应设计、生产代码和 golden case 共同验证。
