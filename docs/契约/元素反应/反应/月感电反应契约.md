## 2. 候选与元素消费

月感电只匹配以下条件同时满足的交互：

1. 请求携带 `reaction_capability:lunar_electro_charged`；
2. 请求携带上游确认的角色来源集合 `character_source_refs`；
3. 当前触发来源 `source_ref` 属于该角色集合；
4. 严格水雷方向：水触发正雷 Aura，或雷触发正水 Aura。

月感电 `selection_priority` 为 `100`，高于普通感电默认 `0`；无 capability 或合法角色触发来源时月候选不匹配，普通感电继续生效。

月感电 occurrence 不消费任何元素量：`incoming_consumed = 0`、`aura_consumed = 0`。后手元素通过持久 Aura Effect 以标准 `20%` 损耗保留，水雷继续各自自然衰减。

## 3. 雷暴云 State

雷暴云 State 字段：

```text
instance_ref / subject_ref / space_entity_ref
created_by_occurrence_ref / trigger_source_ref / team_ref
created_frame / expires_at_frame / next_attack_frame
next_attack_index / attack_interval_frames / revision
```

约束：

- `instance_ref` 与 `space_entity_ref` 必须由 occurrence_ref 确定性派生；
- `expires_at_frame = 创建帧 + 360`，刷新只能延展不能缩短；
- `next_attack_frame = 创建帧 + 15`，`attack_interval_frames = 15`；
- `next_attack_index` 从 `1` 连续递增；
- 刷新必须保留 `instance_ref`、`subject_ref`、`space_entity_ref`、`trigger_source_ref`、创建帧和攻击游标，只延展存在时间并递增 revision。

创建/刷新规则：

- 目标位置（Space 实体锚点）`5` 米内没有同队伍雷暴云时创建一朵；
- 已有时刷新存在时间至 `frame + 360`，不重置攻击游标；
- 同一批次内同时存在多朵过近雷暴云时保留存在时间最长者（并列取 `instance_ref` 较小者），其余 State 与 Space 投影原子移除；
- 到期帧由 `LunarStormCloudExpiryCoordinator` 原子移除 State 与 Space 实体。

当前最小可行边界：生成锚点、云间排斥半径和攻击半径均冻结为 `5` 米；刷新不更新 Space 实体生命周期投影，移除以 State 到期帧为准。

## 4. 周期攻击与 Gate

雷暴云攻击使用 `LunarStormCloudAttackRootWork` 作为 scheduled root，由唯一 `LunarStormCloudScheduledRootAdapter` 投影为 `LunarStormCloudAttackEffect` Effect group：

- 攻击范围：以云位置为中心 `5` 米半径 X/Z 圆形；
- 合法目标：正水 + 正雷 Aura，且至少一个活动贡献来自角色；
- 逐目标 Gate：`reaction_gate.lunar_electro_charged.damage`，窗口 `120` 帧，每次窗口至多 `1` 次伤害；
- 有效攻击对目标水、雷 Component 分别消费 `0.4 GU`；
- 消费前按贡献账本冻结角色参与者，同一角色去重；
- 攻击不产生元素施加，不额外加入创建云的角色。

Gate 阻止时该目标不消费、不受伤。雷暴云自身生命周期不受目标 Aura 是否存在影响。

## 5. 反应月曜伤害

雷暴云攻击使用 `LunarReactionDamageInput(mode=REACTION_COMPOSITE)`，通过统一 Damage Impact 结算：

```text
等级基数：{80: 1077.4, 90: 1446.9, 95: 1561.5, 100: 1674.8}
精通系数 = 6 × EM / (EM + 2000)
反应倍率 = 3.0（基线，独立倍率待人工确认）
权重 = 最高 0.60、第二 0.30、其余 0.05
伤害元素 = 雷，可暴击
```

组分独立完成结算后排序加权；结果保存于 `DamageResult.lunar_reaction_resolution`。该路径没有独立的 Reaction 专用伤害端口。

## 6. 事务、事实与错误边界

月感电候选、雷暴云 State/Space 创建与刷新、攻击根、Gate、Aura 消费和伤害均使用 `prepare -> validate -> commit`。Aura、ReactionState、Gate、Space、Damage 和事实的前值/版本任一 stale 时，整批失败且不得部分提交。

必须记录通用 `REACTION_OCCURRED`、`REACTION_STATE_CHANGED`、`AURA_INTERACTION_RESOLVED` 和 `ELEMENTAL_INTERACTION_RESOLVED`；周期攻击不伪造 occurrence。

组装阶段缺少 Definition、Profile、Gate、Damage Profile、State/Space adapter 或 scheduled root adapter 时失败；运行时 capability 缺失、角色来源不匹配、版本冲突、空间绑定不一致也必须显式失败。

## 7. 当前非目标与验收入口

契约不包含：

- 正式角色 content 的 capability 绑定（golden case 使用临时 capability 端口）；
- 角色月感电 `CHARACTER_DIRECT` 伤害入口；
- 首次攻击/周期间隔、攻击半径、云间排斥半径与生成锚点的精确数值确认（当前使用上述冻结基线）；
- 雷暴云 Space 实体生命周期在刷新时的投影更新；
- 雷暴云移动、阻挡、复杂碰撞、岩造物干扰和角色专属强化；
- 反应月曜伤害的可回放随机输入协议；当前继续使用注入式 `CriticalDecisionProvider`。
- 月结晶。
