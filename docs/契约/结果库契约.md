# 结果库契约

> 状态：正式规范。
> 本文定义结果库 SQLite 表结构、事件持久化契约、写入读取协议与错误语义。
> 最后更新：2026-08-29。

## 1. 定位

结果库是结果存储系统的 SQLite 实现，保存运行记录、输入快照、初始快照与事件流。派生查询由分析模板执行器在读取侧完成（见[分析系统设计](../架构/分析系统设计.md)），结果库不承担投影表职责。

## 2. 术语

- 结果库 schema 版本：结果库自身的结构版本（库级）。
- 输入 schema 版本：某次运行输入快照的格式版本（运行级）。
- 输入快照：进入仿真的不可变输入副本。
- 初始快照：第 0 帧状态基线。

## 3. schema 版本规则

- `result_db_meta.schema_version` 是结果库结构版本，存整数文本。
- `simulation_runs.input_schema_version` 是本次运行输入快照的格式版本。
- 事件契约不设独立版本：事件类型名冻结 + payload 只增不改。
- 开发阶段（未发布正式版）：版本不兼容时明确报错，由用户显式重建结果库，不静默覆盖。
- 发布正式版后：逐级迁移，迁移前备份、单事务执行；第一版仅允许兼容变更。

## 4. 表结构（目标 schema v2）

### 4.1 `result_db_meta`

```text
key    TEXT PRIMARY KEY
value  TEXT NOT NULL
```

必需元信息：`schema_version`、`created_at`。

### 4.2 `simulation_runs`

```text
session_id            TEXT PRIMARY KEY
state                 TEXT NOT NULL      -- completed | failed | cancelled
name                  TEXT NOT NULL      -- 展示名，来自输入 meta.name
input_schema_version  INTEGER NOT NULL
input_snapshot_json   TEXT NOT NULL
initial_snapshot_json TEXT NULL          -- 成功运行必有；失败/取消可空
created_at            TEXT NOT NULL
started_at            TEXT NULL
finished_at           TEXT NULL
stop_reason           TEXT NULL
end_frame             INTEGER NULL
frames_run            INTEGER NULL
event_count           INTEGER NOT NULL DEFAULT 0
error_code            TEXT NULL
error_message         TEXT NULL
asset_version         TEXT NULL          -- provenance，与资产库 meta 对齐
content_version       TEXT NULL          -- provenance，内容版本
seed                  TEXT NULL          -- 随机种子，格式随模拟输入契约确定
```

约束：

- 成功运行：`state = completed`；`stop_reason`、`end_frame`、`frames_run` 非空；`event_count` 等于事件行数；`error_code` / `error_message` 为空；`initial_snapshot_json` 非空。
- 失败/取消运行：`state = failed | cancelled`；元摘要列留空或 0；`input_snapshot_json` 必有；`initial_snapshot_json` 可空（取决于失败阶段）；不写事件行。
- 同一 `session_id` 写入后状态不可变更，不允许重复写入。

### 4.3 `simulation_events`

```text
session_id  TEXT NOT NULL
ordinal     INTEGER NOT NULL
frame       INTEGER NOT NULL
event_type  TEXT NOT NULL
data_json   TEXT NOT NULL

PRIMARY KEY (session_id, ordinal)
FOREIGN KEY (session_id) REFERENCES simulation_runs(session_id) ON DELETE CASCADE
```

约束：

- `ordinal` 从 0 起连续递增，表达会话内全局事实顺序。
- `event_type` 必须是冻结的 `EventType.name`。
- `data_json` 是 `payload.to_dict()` 的 JSON object。
- 不持久化 `source_type` 与事件分类元信息。

### 4.4 索引

```text
idx_runs_created_at  ON simulation_runs(created_at DESC)
idx_events_frame     ON simulation_events(session_id, frame, ordinal)
idx_events_type      ON simulation_events(session_id, event_type)
```

连接开启：`PRAGMA foreign_keys = ON`；结果库启用 WAL。

## 5. 事件持久化契约

- 事件类型名冻结：只允许追加，不允许改名或复用；语义变化走新事件类型。
- payload 序列化：字段只增不改，未知字段读取方忽略；破坏性变更必须走新事件类型。
- 状态变化事件必须携带 `before/after` 或稳定引用证据（HP、能量、Buff、护盾、Aura 等逐领域核对），保证“初始快照 + 事件折叠”可还原任意帧状态。
- `frame` 为查询维度；事件在帧内先后顺序由 `ordinal` 保证，不设帧内子序号。

### 5.1 第一版逐领域证据核对表

| 领域/内容 | 初始快照 provider | 变化证据（事件） | 还原结论 |
| --- | --- | --- | --- |
| 队伍与角色身份 | `team`（`active_slot` + 角色 `current_hp`/`current_energy`） | `TEAM_SWITCHED`、`CHARACTER_HEALTH_CHANGED`、`CHARACTER_ENERGY_CHANGED`、`CHARACTER_MAX_HP_CHANGED` | 可折叠还原 |
| 属性面板 | `attributes`（第 0 帧完整面板 + `applied_terms`） | `ATTRIBUTE_PANEL_CHANGED` | 可折叠还原 |
| 冷却 | `cooldown` | `COOLDOWN_CHANGED`（`before_record`/`after_record` 完整记录快照） | 可折叠还原 |
| Buff | `buff` | `BUFF_APPLIED`（`instance_after` 完整实例）、`BUFF_REMOVED` | 可折叠还原 |
| 护盾 | `shield` | `SHIELD_GRANTED`（`instance_after`）、`SHIELD_CAPACITY_CHANGED`、`SHIELD_REMOVED` | 可折叠还原 |
| 附魔/转化 | `infusion` | `INFUSION_APPLIED`（`instance_after`）、`INFUSION_REMOVED` | 可折叠还原 |
| 元素附着 | `aura` | `AURA_APPLIED`、`AURA_DEPLETED`、`AURA_INTERACTION_RESOLVED` | 快照基线；第一版折叠未接入，标记 `baseline` |
| 附着 ICD | `aura_icd` | `AURA_ICD_RESOLVED` | 快照基线；第一版折叠未接入，标记 `baseline` |
| 元素反应 | `reaction` | `REACTION_STATE_CHANGED`、`REACTION_OCCURRED`、`ELEMENTAL_INTERACTION_RESOLVED` | 证据可支持持续状态还原；第一版折叠未接入，标记 `baseline`；Gate 记录（窗口/计数/就绪帧）显式排除 |
| 元素共鸣 | `resonance` | `RESONANCE_ACTIVATED` | 快照基线；第一版折叠未接入，标记 `baseline` |
| 月兆 | `moonsign` | `MOONSIGN_LEVEL_SET`、`MOONSIGN_BONUS_APPLIED`、`MOONSIGN_BONUS_EXPIRED` | 快照基线；第一版折叠未接入，标记 `baseline` |
| 能量 | `energy` | `CHARACTER_ENERGY_CHANGED`、`ENERGY_PICKUP_SPAWNED`、`ENERGY_PICKUP_SETTLED`、`DIRECT_ENERGY_CHANGE_RESOLVED` | 快照基线；角色能量变化经 `team` provider 折叠 |
| 空间 | `space` | `SPACE_ENTITY_CREATED`、`SPACE_ENTITY_REMOVED` | 创建/移除证据可支持还原；第一版折叠未接入，标记 `baseline`；位置与生命周期更新（跟随、刷新、延长）显式排除 |
| 内容状态 | `content_state` | `CONTENT_STATE_CHANGED` | 快照基线；第一版折叠未接入，标记 `baseline` |
| 移动 | 无快照 provider | `MOVEMENT_COLLIDED`、`MOVEMENT_LANDED` | 垂直状态（高度/速度/重力）显式排除 |
| 伤害/治疗/受伤 | 无 | `DAMAGE_RESOLVED`、`HEALING_RESOLVED`、`DAMAGE_APPLIED` | 事实可查询，不作为状态折叠 |

状态折叠模板后置（待曲线/状态视图消费时登记）；`fold_status` 语义随折叠模板实现定义。新增或移除 provider、改变证据事件或调整排除边界时，必须同步本表与[事件类型](../架构/事件系统/事件类型.md)。

### 5.2 属性面板事件与初始快照形状（自旧分析系统契约迁移）

属性面板属于结果存储契约，不依赖分析层：

初始快照 `attributes` provider（第 0 帧完整面板）：

```json
{
  "frame": 0,
  "subjects": {
    "character:slot_1": {
      "stat.atk_total": { "value": 1500.0, "applied_terms": [] }
    }
  }
}
```

`applied_terms` 每项含 `provider_key`、`source_ref`、`stage`、`value`、`audit_tags`（“属性被什么影响”的证据）。第一版不存 `rejected_terms` 与 `dependency_trace`。

`ATTRIBUTE_PANEL_CHANGED`（默认记录，仅有效变化发布）载荷：

```json
{
  "frame": 120,
  "subject_ref": "character:slot_1",
  "changes": [
    {
      "attribute_key": "stat.atk_total",
      "before_value": 1500.0,
      "after_value": 1800.0,
      "after_terms": []
    }
  ]
}
```

### 5.3 DAMAGE_RESOLVED 完整审计（2026-08-29）

`DAMAGE_RESOLVED` 的 `data_json` 固定为：

```json
{
  "result": {},
  "audit": {}
}
```

- `result` 保持 `DamageResult.to_dict()` 摘要形状，字段语义不得改变。
- `audit` 是完整伤害公式审计，必填；当前开发阶段旧运行缺失 `audit` 视为与当前契约不兼容。

`audit` 结构：

```json
{
  "component_results": [
    {
      "component_key": "skill_1",
      "attribute_key": "stat.atk.total",
      "attribute_value": 1800.0,
      "original_coefficient": 1.2,
      "final_coefficient": 1.2,
      "damage": 2160.0
    }
  ],
  "base_damage_additions": [
    {
      "addition_key": "...",
      "value": 120.0,
      "source_ref": {},
      "audit_tags": []
    }
  ],
  "damage_bonus": {
    "element_bonus": 0.466,
    "modifier_bonus": 0.2,
    "multiplier": 1.666
  },
  "critical": {
    "can_crit": true,
    "crit_rate": 0.8,
    "effective_crit_rate": 0.8,
    "crit_damage": 1.5,
    "outcome": "crit",
    "multiplier": 2.5
  },
  "defense": {
    "source_level": 90,
    "target_level": 90,
    "defense_reduction": 0.0,
    "defense_ignore": 0.0,
    "multiplier": 0.5
  },
  "resistance": {
    "resistance": 0.1,
    "multiplier": 0.9
  },
  "reaction": null,
  "applied_terms": [],
  "rejected_terms": [],
  "source_attribute_trace": [],
  "target_attribute_trace": [],
  "trace_metadata": {}
}
```

字段要求：

- `component_results`：按结算顺序或稳定排序输出，不省略。
- `base_damage_additions`：固定基础伤害加值完整输出。
- `applied_terms`、`rejected_terms`：沿用 `DamageModifierTerm` 的稳定序列化字段。
- `source_attribute_trace`、`target_attribute_trace`：沿用 `AttributeResolution` 结构，递归依赖完整保存，不截断。
- `trace_metadata`：JSON 兼容映射。
- 序列化来源为 `DamageResult.to_audit_dict()`，模型定义见[伤害系统设计](../架构/系统/伤害系统设计.md)第 9 节。

- `initial_snapshot_json` 保存第 0 帧状态基线（角色运行态、属性、能量、HP、空间、目标等），由 `core/snapshots` 导出。
- 内容由各领域快照 provider 契约保证；结构变更遵守“只增不改”。
- `core/snapshots` 已统一为一条导出链路：`Simulator -> SnapshotRuntime -> FrameSnapshot`；帧 0 快照随运行记录保存，作为任意帧状态查询基线。

### 6.1 第一版 provider 登记

执行链路在第 0 帧注册 14 个 provider：`energy`、`buff`、`infusion`、`content_state`、`resonance`、`moonsign`、`cooldown`、`shield`、`reaction`、`space`、`aura`、`aura_icd`、`team`（含角色生命与能量）、`attributes`（第 0 帧属性面板 + `applied_terms`）；移动状态按首版显式排除。

`initial_snapshot_json` 保存第 0 帧 `FrameSnapshot` 的 JSON（含 `providers`；`events` 字段是第 0 帧事件的冗余视图）。第 0 帧事件行全部进入事件流，读取侧折叠只使用 `providers` 与事件流，不使用快照内的 `events` 字段。provider key 稳定且只增不改；新增或移除 provider 时同步 §5.1 核对表。

## 7. 写入协议

- `session_id` 由调用方在运行开始前分配（`uuid.uuid4().hex`），写入器不自行生成。
- 成功写入：一次事务写入运行记录与全部事件。
- 失败/取消写入：最小运行记录，不含事件行。
- 重复写入同一 `session_id` 必须报错，禁止覆盖。
- 写入前不执行 schema 迁移（开发期由用户显式重建）。

## 8. 读取协议

`ResultRepository` 至少提供：

```text
list_runs(limit, state=None, name_query=None, created_from=None,
          created_to=None, session_ids=None) -> tuple[RunListItem, ...]
get_run(session_id)          -> RunDetail（运行记录 + 输入快照 + 初始快照）
get_events(session_id, frame_min=None, frame_max=None,
           event_type=None, offset=None, limit=None) -> tuple[RecordedEvent, ...]
get_event(session_id, ordinal) -> RecordedEvent | None
```

- `name_query`：`name` 列子串匹配，大小写不敏感；`%`、`_`、`\` 按字面匹配，不解释为 SQL 通配符。
- `created_from` / `created_to`：`created_at` 时间范围，ISO-8601 UTC（`+00:00`），两端含端点。
- `session_ids`：会话 ID 限定集合；空集合返回空。按请求顺序回显（缺失会话省略）由服务层完成；HTTP 层提供 `ids` 时不再传其它筛选。

帧状态折叠执行器由读取侧用例实现，不在结果库新增逐帧快照表。结果库读取协议提供运行记录、事件分页、单事件读取等原始读取，结果库不直接提供状态查询 SQL；帧状态响应由应用层基于初始快照和事件折叠生成。将来物化跳变表后，可增加“取该帧前最后一次变化”的读取接口。

## 9. 事件流归档（预留）

- 触发类型：单次运行超限（写时判定）、结果库总体积超限（存量归档）、批量/长仿真模式（按模式判定）。
- 文件：`<data_dir>/results/events/<session_id>.jsonl`（可压缩），不可变，带校验哈希。
- 读取透明：仓库接口统一，调用方不感知事件在表内还是文件内。
- 删除结果时联动删除归档文件。
- 阈值参数化，待实测校准；第一版不实现。

## 10. 与任务系统的关联

- 任务侧持有 `session_id`；结果库不存 `job_id`。
- 失败/取消运行由任务系统在适当时机调用失败写入入口。
- 结果库错误信息只留摘要；完整堆栈与调度细节归任务系统与日志。

## 11. 错误与失败语义

- 结果不存在：`ResultNotFoundError`。
- schema 版本不兼容：明确报错并提示重建（开发期）。
- JSON 损坏：明确报错，不静默跳过。
- 写入违反不可变规则：报错，不覆盖。

## 12. 测试要求

- 成功运行写-读往返。
- 失败/取消最小记录（状态、时间、输入快照、错误，无事件行）。
- 重复写入与覆盖防护。
- 事件契约稳定性（`EventType.name` 冻结测试）。
- payload 兼容（未知字段可忽略）。
- 状态折叠：初始快照 + 事件 → 任意帧值。
- 开发期版本不兼容的重建行为。
- 归档预留接口（如实现）。
