# 扩散反应契约

> 状态：已实现
> 最后更新：2026-08-01
> 对应设计：[扩散反应设计](../../../架构/系统/元素反应/反应/扩散反应设计.md)

## 1. 稳定标识

| 类型 | 稳定键 |
| --- | --- |
| 反应 | `reaction.swirl` |
| Handler | `reaction_handler.swirl` |
| 伤害 Profile | `damage_profile.reaction.swirl` |
| 附着 Profile | `aura_application_profile.reaction.swirl` |
| 目标策略 | `reaction_target.swirl_emission` |

反应方向 Profile 使用 `reaction_profile.swirl.<direction>`：

| `direction` | 输出元素 |
| --- | --- |
| `incoming_anemo_on_pyro` | `Element.PYRO` |
| `incoming_anemo_on_hydro` | `Element.HYDRO` |
| `incoming_anemo_on_electro` | `Element.ELECTRO` |
| `incoming_anemo_on_cryo` | `Element.CRYO` |
| `incoming_anemo_on_frozen` | `Element.CRYO` |

## 2. 伤害键

| 输出元素 | `reaction_damage_kind` | Gate Definition |
| --- | --- | --- |
| 火 | `reaction_damage.swirl.pyro` | `reaction_gate.swirl.pyro.damage` |
| 水 | `reaction_damage.swirl.hydro` | `reaction_gate.swirl.hydro.damage` |
| 雷 | `reaction_damage.swirl.electro` | `reaction_gate.swirl.electro.damage` |
| 冰 | `reaction_damage.swirl.cryo` | `reaction_gate.swirl.cryo.damage` |

每个扩散 `GeneratedDamageImpactEffect` 必须显式携带 `transformative_base_multiplier=0.6`。协调器不得根据 `reaction_key` 补推倍率。

## 3. 消耗与发射元素量

对通过 ICD 的风元素量 `W` 和反应前 Aura 量 `A`：

```text
incoming_consumed = min(W, 2 * A)
aura_consumed = incoming_consumed / 2
remaining_incoming = W - incoming_consumed
remaining_aura = A - aura_consumed
```

派生元素量：

```text
2 * A > W  => 1.25 * W + 0.95
2 * A <= W => 1.25 * A + 0.95
```

等量边界必须进入 `2 * A <= W` 分支。

## 4. 派生批次

一次普通扩散必须同时产出中心 `ReactionEffectGroup` 和范围 `ReactionGeneratedImpactBatch`。双扩散可以让一个范围 batch 引用两个 occurrence。

中心 Effect group 必须包含 `GeneratedDamageImpactEffect`；范围 batch 至少包含：

- 一个或多个 `ReactionGeneratedImpact`；
- occurrence 因果信息；
- 来源观察值；
- 目标选择请求。

目标选择契约：

- `geometry="circle_xz"`；
- XZ 平面半径 `6`；
- 排除 anchor；
- 不限制数量；
- 结果按 `subject_ref` 稳定排序。

范围组件契约：

| 输出元素 | Damage | Aura |
| --- | --- | --- |
| 火 | 必须 | 必须 |
| 水 | 禁止 | 必须 |
| 雷 | 必须 | 必须 |
| 冰 | 必须 | 必须 |

派生 Aura 必须使用 `aura_application_profile.reaction.swirl`，且不请求 ICD 许可。

## 5. 目标资格

每个派生命中的关系、Damage 能力和 Aura 能力必须分别判定：

- 非敌对关系：存在的 Damage、Aura 分量均记为 `blocked_relation`；
- 缺少 Damage 能力：只阻止伤害分量；
- 缺少 Aura 能力：只阻止 Aura 分量；
- Damage 分量不得依赖目标同时具有 Aura 能力。

水扩散没有范围 Damage 分量，因此不得产生范围伤害提交或伤害门控请求。

## 6. 伤害与门控

扩散伤害必须：

- 使用 `damage_profile.reaction.swirl`；
- 使用发生时捕获的来源等级、精通与扩散专属加成；
- 读取输出元素对应的目标抗性；
- 不暴击；
- 元素量为 `0`；
- 使用 `SECONDARY_AMPLIFYING` 派生伤害语义。

四个伤害门控分别使用对应 Gate Definition，窗口参数为 `30/2`。中心与范围扩散伤害共享来源、目标和元素相同的门控状态。门控失败只设置伤害结果，不得阻止同一派生命中的 Aura 或后续反应。

## 7. 双扩散

固定顺序：

| 中心状态 | 顺序 | 输出 |
| --- | --- | --- |
| 雷 + 水 | 雷、再水 | 雷、水 |
| 水 + 冻结 | 水、再冻结 | 水、冰 |
| 隐藏冰 + 冻结 | 单次冰 occurrence | 冰 |

第二步只能在第一步完全耗尽对应 Aura 且风元素仍有余量时发生。雷水与水冻结的两个 occurrence 必须共享按第二步反应前状态计算出的发射元素量。

无 Aura 目标上的同时应用只允许以下策略：

- `simultaneous_application.no_aura_electro_hydro_coexistence`；
- `simultaneous_application.no_aura_hydro_cryo_frozen`。

其他同时应用组合必须返回稳定错误，不得静默改写为普通顺序附着。

## 8. 事务与错误

- 每个派生命中批次必须经过 prepare、validate、commit；
- 同一批次的伤害、Aura 与反应计划必须原子提交；
- 后续批次失败不得回滚已经提交的独立批次；
- 派生队列超过 64 轮必须稳定失败；
- 缺失 Profile、Gate、目标策略、来源观察值或元素映射时必须在准备阶段失败。
