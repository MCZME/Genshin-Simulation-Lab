# 星扩散反应设计

> 状态：正式规范。
> 本文固定与普通扩散并列的独立星扩散反应：星辉风旋状态、伤害源与参与者账本、星扩散·风/冰两类反应星烁伤害、辉映·星扩散状态；契约见[星扩散反应契约](../../../../契约/元素反应/反应/星扩散反应契约.md)。
> 最后更新：2026-09-14。

## 1. 定位

星扩散（`Stellar-Swirl`）是星烁反应（Stellar Reactions）体系第二个落地的分支：风元素命中冰元素 Aura 在满足星烁资格时排他替代普通扩散。它使用独立 `reaction.stellar_swirl` Definition、Rule、Profile 与星辉风旋（Stellar-Swirl Vortex）状态，不归入 `mechanics/swirl/` 机制目录，也不是普通扩散 Rule 内的条件分支。

星扩散包含两类反应星烁伤害：

- 星扩散·风：反应触发时立即对触发目标造成的风元素伤害，单体、可暴击、不附着元素；
- 星扩散·冰：风旋爆炸时对范围内目标造成的冰元素伤害，可暴击，并附着 `1U` 冰元素（可触发融化、星超导等后续反应）。

两类伤害都使用独立星烁公式 `damage_formula.stellar_reaction` 的 `reaction_composite` 模式：逐参与者结算、按折前伤害稳定排序、`0.60/0.30/0.05/0.05` 固定权重聚合。

辉映·星扩散（`Radiance: Stellar-Swirl`）是触发星扩散·风后的角色侧资格状态：具备资格的角色在 `8` 秒内可进入，直伤星扩散的星烁基础系数固定为 `1`。星扩散与星超导可以同时存在、同时反应；同一角色同时满足两种辉映状态条件时，只有辉映·星超导生效。

本期范围明确排除：风元素自附着方向（冰元素攻击风自附着敌人反向触发）、风旋爆炸命中角色跳跃能力的**量化口径**、角色 content 技能模组、爆炸冲击 Impact 语义的生产接线。

爆炸命中角色的跳跃能力 Buff 本身已落地为位置级标记 Buff（见第 10 节）：`ACTIVE_CHARACTER` 位置级主体、`marker_only`、`360` 帧；消耗归角色跳跃动作自身（读取 `ActionInterpretationContext.buff_reader`、以 `ImpactKind.REMOVE_STATUS` 显式移除，见 D-071 / D-073），Movement 不建跳跃能力模型、不认识 Buff；但"提高跳跃能力"具体如何提高、命中范围与精确持续帧仍无来源，也不接任何角色的起跳动作。

## 2. 领域所有权

| 领域 | 星扩散相关职责 |
| --- | --- |
| Aura | 冰元素 Aura 的普通扩散语义消费（`min(incoming, aura×2)`，aura 侧减半）；冰贡献观察随交互请求冻结 |
| Reaction | 独立 Definition 与候选、星辉风旋 State、参与者账本、风伤害去重 Gate 定义 |
| Space | 星辉风旋 `REACTION_OBJECT` 位置投影（锚定首个反应目标位置）与生命周期 |
| Buff | 辉映·星扩散 Buff 的生命周期真值 |
| Damage | 星烁复合公式的逐参与者结算与区间审计；不读取 Buff、ReactionState 或协调器 |
| Movement（`core/movement`，运行时设施） | 只提供位移入口：`ImpactKind.MOVEMENT` 的 `movement.jump.upward_velocity` → `start_jump`，随后推进垂直运动并发布落地/碰撞事实；不建跳跃能力模型、不内置任何起跳数值、不认识 Buff |
| Coordination | 风旋创建/升级/爆炸计划、参与者判定与账本写入、爆炸 Effect 物化、辉映 Buff 编排、到期移除、爆炸命中角色的跳跃能力 Buff 申请；不实现星烁公式、不拥有长期状态、不承担起跳消耗 |

## 3. 稳定 Definition 与方向

```text
reaction.stellar_swirl / reaction_handler.stellar_swirl

stellar_incoming_anemo_on_cryo
```

本期只注册风触发冰一个方向；风元素自附着敌人被冰攻击反向触发的方向（`stellar_incoming_cryo_on_anemo`）依赖当前 Aura 模型不支持的风元素附着（`AuraKind` 无 ANEMO），明确不纳入本期，方向 key 仅作预留。

候选要求与星超导同构：

1. 请求携带 `reaction_capability:stellar_swirl`；
2. 请求携带上游确认的角色来源集合 `character_source_refs`；
3. 当前触发来源 `source_ref` 属于该角色集合；
4. 方向：风元素命中正冰 Aura。

`selection_priority` 为 `110`，高于普通扩散默认 `0`；无 capability 或合法角色触发来源时星候选不匹配，普通扩散继续生效。capability 存在但后续计划缺少空间锚点、binding 不一致等技术前提缺失时整批失败，不静默回退为普通扩散。

元素消费与普通扩散一致：

```text
incoming_consumed = min(incoming_amount, aura_amount × 2)
aura_consumed = incoming_consumed / 2
```

## 4. 星辉风旋状态

Reaction 拥有星辉风旋 State，Space 拥有位置投影；两侧通过稳定 binding 原子创建、更新和移除：

```text
StellarSwirlVortexState
├── instance_ref             = reaction-state:stellar-swirl-vortex:{创建 occurrence_ref}
├── space_entity_ref         = reaction_object:stellar_swirl_vortex:{创建 occurrence_ref}
├── subject_ref              = 创建锚定目标
├── level                    = 1~6
├── last_reaction_source_ref = 生命周期内最后一次星扩散·风的触发者（爆炸伤害源）
├── last_reaction_occurrence_ref
├── participants             = 参与者账本（见第 5 节）
├── created_frame
├── expires_at_frame         = created_frame + 180
└── revision
```

- 全场唯一：作用域为战斗级 `battle`（非 `player_team`），同一时刻至多一个活动风旋；
- 首次创建锚定在第一个反应目标当时位置，锚点与角色位置无关；后续升级不移动锚点；
- 等级 `1~6`：已有风旋时每次星扩散·风等级 `+1`，不刷新爆炸计时（实现基线，待来源化确认）；
- 未达到 `6` 级时最晚在生成后 `180` 帧（约 `3` 秒基线）自动爆炸；达到 `6` 级立即爆炸；
- 爆炸（无论到期还是 6 级提前）原子终结 State 与 Space 实体，并向下一结算轮物化冰爆炸 Effect group；
- 6 级提前爆炸后，同一批次内仍成立的后序目标事件看到无风旋，创建等级 `1` 的新风旋并锚定该目标；新风旋的账本、伤害源窗口与旧风旋无任何继承。

State 变更与 Space 投影由 binding 校验强制对应：创建/移除一一对应，升级不改变生命周期时只递增 `revision`。校验入口为 `validate_stellar_swirl_vortex_space_bindings` / `validate_stellar_swirl_vortex_space_terminalizations`。

## 5. 伤害源与参与者账本

星扩散语境下"伤害源"与"伤害计算参与者"是两个概念：

- **伤害源**：每段星扩散伤害恰好一个，承担命中、附着施加与后续反应触发的全部归因；
- **伤害计算参与者**：每段星烁伤害至多 `4` 名，只参与星烁公式计算并出现在逐参与者审计中，不产生任何归因，不触发只允许伤害源触发的效果。

**参与判据（统一原则）**：以反应发生层为真值。风不附着，风侧参与反应的唯一形态是触发；冰侧参与反应的判据是——反应发生时该角色的冰贡献仍是目标冰 Aura 上的活跃贡献（剩余量大于 `0`）且被本次反应消费。在本项目的消耗模型中，消费量会同步扣减所有活跃贡献，因此"反应发生时贡献活跃"与"被本次反应消费"等价。仅施加附着但未参与反应的角色不是参与者；冰被融化、星超导等其他反应消耗不产生参与者资格。

**星扩散·风**：

- 伤害源 = 本次反应触发者（施加风元素的角色）；
- 参与者 = 触发者 ∪ {其冰贡献在本次反应发生时活跃且被消费的角色}；集合语义去重；
- 参与者不要求持有星烁 capability；
- 参与者天然限于队伍角色，结构性至多 `4` 名；契约保留"按首次参与帧升序保留前 4"的确定性兜底。

**星扩散·冰**：

- 没有反应触发者；
- 伤害源 = 本风旋生命周期内、爆炸前最后一次星扩散·风的触发者。被风伤害去重挡掉的风事件与 6 级同帧引发爆炸的那次风事件都是合格候选；同帧多次风按稳定处理顺序取最后一条；
- 参与者 = 生命周期内所有星扩散·风参与者集合的并集。

账本随 State 持有、随爆炸终结：

```text
StellarSwirlParticipantEntry
├── participant_ref
├── first_reaction_frame
└── last_reaction_frame
```

每次星扩散·风在协调器计划时从请求内的 AuraView 冻结冰贡献观察、计算本次参与者集合，同批次写入账本并更新 `last_reaction_*`。风伤害的参与者输入 = 触发者 + 本次冰贡献者（冻结进 Effect）；冰爆炸的参与者输入 = 账本并集、伤害源 = `last_reaction_source_ref`。

爆炸 AOE 的命中目标由空间范围查询决定，与参与者集合互不关联；爆炸附着的 `1U` 冰元素归因于伤害源。

## 6. 星扩散·风伤害与去重

- 触发时立即对触发目标（`CurrentSubjectSelection`）结算一段风元素反应星烁伤害，星烁基础系数 `0.75`，可暴击（逐参与者独立决策），不附着元素；
- 去重走 `ReactionDamageGate`（`reaction_gate.stellar_swirl.wind`，damage kind `reaction_damage.stellar_swirl_wind`，窗口 `30` 帧基线、至多 `1` 次）：同一敌人在窗口内至多承受一次风伤害；
- 去重是伤害结算层规则：不影响反应发生、元素消费、风旋等级累加、参与者计入与"最后一次星扩散反应"的认定；
- 多目标同帧按稳定 `subject_ref` 顺序逐目标处理：每个目标事件独立执行去重判定与风旋等级累加；
- 伤害 Effect 物化为星烁复合伤害 Effect（与月曜复合通道同构），经主攻击标签 `reaction.stellar_swirl.wind` 的 DamageProfile 映射进入 `damage_formula.stellar_reaction`。

## 7. 星扩散·冰爆炸与冰附着

- 爆炸不被视为触发反应，不发 `REACTION_OCCURRED`；伤害源与参与者按第 5 节认定；
- 爆炸中心为风旋 Space 实体锚点位置；目标选择为 `AreaAroundPositionSelection`：
  - 等级 `1~2`：圆柱半径 `6`、高度 `4`（星辉风旋小）；
  - 等级 `3~6`：圆柱半径 `8`、高度 `4`（星辉风旋大）；
  - 当前 Space 查询将圆柱投影为 X/Z 圆，高度仅作强类型资料记录，不参与范围判定；
- 范围内全部有效目标承受一段冰元素反应星烁伤害，星烁基础系数：等级 `1~2` 为 `2`，等级 `3~6` 为 `3`；可暴击；
- 爆炸对命中目标附着 `1U` 冰元素（走 ReactionGeneratedImpactBatch → AuraApplicationRequest 通道），归因于伤害源；由此触发的融化、星超导等后续反应的触发者即该伤害源，无需特殊接线；
- 爆炸 Effect group 以 `NEXT_SETTLEMENT_ROUND` 轮次执行：到期爆炸由风旋到期协调器物化，6 级提前爆炸在交互批次内物化，两条路径产出同一 Effect 形态。

命中目标分流（两条互不相干的通道，不共用一次目标遍历的写结果）：

- **敌对目标 → 伤害/附着**：`AreaAroundPositionSelection` 显式声明 `reaction_target.hostile_effect` 资格策略，不继承 `bloom_damage` 默认值。这样"爆炸不自伤"由资格意图表达，而不是依赖 `StellarReactionDamageImpactEffect` 恰好不在 bloom 自伤白名单的 Effect 类型联合里；
- **范围内角色 → 跳跃能力 Buff**：角色在 Effect 循环内按 `SELF` 关系被挡下（`blocked_relation`），不受冰伤害、不被附着。爆炸范围内确实存在角色时，协调器在 Effect 循环**外**走独立通道补一条 `ACTIVE_CHARACTER` 主体的跳跃能力 Buff 申请（与 `1U` 冰附着同构，见第 10 节）。命中判定用的是空间范围，挂载身份用的是位置级队伍作用域，二者分离。

资料另记录爆炸冲击的 Impact 语义（削韧 `60/80`、`Air,100,600` 冲击、初始停滞 `0`、韧性影响停滞为否、停滞时间流速 `0.01`、远程类型、`HitDirection` 备注）；这些属于 Impact/命中层语义，与星烁 Damage 公式和冰附着来源分层表达，首期接线范围见契约非目标。

## 8. 反应星烁复合伤害

星扩散·风与星扩散·冰共用 `damage_formula.stellar_reaction` 的 `reaction_composite` 模式（本阶段启用，星超导继续使用 `character_direct`）：

1. 逐参与者以单人公式结算：`scaling_value` 替换为该参与者的 `reaction_base_value`（按参与者自身等级查等级系数表，观察期冻结）；星烁基础系数取反应侧常量（风 `0.75`，冰 `2/3`）；
2. 每名参与者使用独立 DamageRequest 与独立结算会话，元素精通、暴击（注入式 `CriticalDecisionProvider` 逐参与者决策）与目标抗性实时读取并生成独立审计；同一目标的各参与者组分共享同一抗性区；
3. 按折前伤害从高到低稳定排序（同值按参与者主体 id），最多保留 `4` 名；
4. 权重按名次固定分配 `0.60/0.30/0.05/0.05`，不按参与人数重归一化（与月曜复合实现同构）；
5. 聚合结果与逐参与者组分（区间、暴击、权重）写入 `StellarReactionDamageResolution`，`DamageResult.stellar_reaction_resolution` 承载完整审计。

公式不读取 Buff、ReactionState 或协调器；星烁基础增伤、星烁增伤、星烁大权区、反应星烁羽毛区与星烁擢升作为强类型输入字段（或参与者字段）进入公式，不接受普通 `DamageModifierTerm`。

## 9. 辉映·星扩散

- 队伍中角色触发星扩散·风后，具备辉映·星扩散资格的角色在 `480` 帧（约 `8` 秒基线）内进入辉映·星扩散；每次触发在同一交互批次内统一申请或刷新（`REFRESH` + `REPLACE_LATEST`，至多 `1` 层）；
- Buff 携带直伤星扩散基础系数词条（`stellar.swirl.direct_base_multiplier`，固定值 `1.0`），角色 content/ability 读取该 Buff 启用直伤星扩散技能逻辑（第三阶段接入）；
- 目标集合由辉映·星扩散资格证据决定，经 capability 证据模型承载；机制首期由测试构造资格证据，具体角色与资格 key 粒度在角色资产接入阶段定案；
- 与辉映·星超导可同时存在（两个 Buff 各自独立）；同一角色同时满足两种辉映状态条件时，只有辉映·星超导生效——由角色侧启用逻辑的读取优先级执行，Buff 层不做跨 Definition 互斥；
- 辉映·星扩散无领域依赖，纯计时状态。

## 10. 风旋爆炸命中的跳跃能力 Buff

- 爆炸范围内存在角色时，协调器在 Effect 循环外的独立通道申请 `buff.reaction.stellar_swirl.jump_boost`：位置级队伍作用域主体 `AttributeSubjectKind.ACTIVE_CHARACTER`（挂载身份是队伍稳定作用域 id `player_team`），`REFRESH` + `REPLACE_LATEST`、至多 `1` 层，`360` 帧（约 `6` 秒基线）；
- 主体选位置级而非精确角色：跳跃只有前台角色能执行，谁在前台谁享受，切人后由新前台自然接管；空间侧也只有 `SpatialEntityKind.ACTIVE_CHARACTER` 一种角色实体，二者自洽；
- `marker_only`，不声明任何属性词条——"提高跳跃能力"没有来源化的量化口径，位移设施也没有跳跃能力模型可写；
- 消耗链路归属**角色跳跃动作自身**：动作解析时读到该 Buff → 据此确定本次跳跃的位移参数 → 对该主体上的活动记录发起显式移除（`BuffRemovalReason.CONSUMED`）。位移设施只接受 `ImpactKind.MOVEMENT` 意图（`movement.jump.upward_velocity` → `start_jump`）并推进运动，不认识 Buff、不发布起跳事实，也不经过任何起跳消耗协调器；
- 起跳初速度由调用方给出，位移设施不内置任何角色跳跃数值；本期**未接线**：角色跳跃动作与其 impact factory 未建，消费实际不发生；读取（`ActionInterpretationContext.buff_reader`）与消费（`ImpactKind.REMOVE_STATUS`）两条通道已可用。

## 11. 当前边界与验收入口

当前边界：

- `180` 帧、`480` 帧、`360` 帧、去重窗口 `30` 帧为实现基线；爆炸 AOE 半径 `6/8`、高度 `4`、系数 `0.75/2/3`、四项权重与 `1U` 附着为来源化数值，正式 golden case 冻结前按契约第 11 节记录来源与适用版本；
- 风元素自附着方向、跳跃能力 Buff 的消耗接线（角色跳跃动作与对应 impact factory）与量化口径、角色直伤技能模组、爆炸冲击 Impact 语义接线均不在本期；
- 跳跃落地记录的 `fall_height` 是**起跳点高度而非顶点**：位移设施尚未建模"上升转下落"的顶点，`start_jump` 沿用起跳点作为下落起始高度。接下落伤害或受击逻辑前需要补顶点跟踪；
- 风旋升级不刷新爆炸计时为暂定基线。
