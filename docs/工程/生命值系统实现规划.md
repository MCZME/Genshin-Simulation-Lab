## 1. 文档定位

生命值系统已经完成第一轮实现。本规划作为实施记录和后续接入清单，不再重复以下正式架构内容：

- `HealthState`、请求、结果和错误模型的完整字段。
- `HealthRuntime` 的计算公式、提交顺序和数值不变量。
- 生命变化与最大生命同步事件的详细契约。
- 与属性、伤害、治疗、护盾和生存状态的长期边界。

上述内容统一维护在[生命值系统设计](../架构/系统/生命值系统设计.md)和[事件类型](../架构/事件系统/事件类型.md)中。

## 2. 第一轮目标与范围

第一轮只建立角色当前生命的稳定运行时边界：

- 角色以 frame 0 的最终 `stat.hp.max` 满血进入仿真。
- `CharacterRuntimeState.health` 保存当前生命。
- `CharacterHealthStore` 按角色主体索引生命状态。
- `HealthRuntime` 提供查询、角色承伤、恢复量应用和直接扣血入口。
- 生命变化返回统一结果，并对有效变化发布事件。
- 最大生命变化可以按原生命比例同步当前生命。

生命值系统第一轮自身不包含：

- 场景目标生命、击败、移除和索敌过滤。
- 治疗公式、治疗 modifier 和治疗 resolved 事件；这些能力已由治疗系统阶段 A-C 独立接入。
- 敌方或环境伤害产生角色承伤结果的 adapter。
- 护盾、减伤、生命之契、死亡、复活和免死。
- 真实角色生命消耗机制和对应 golden case。
- 初始残血配置、UI 生命条或结果库专用生命表。

第一轮不修改 `SimulationConfig`、资产库 schema 或结果库 schema。

## 4. 实施阶段

### 阶段 A：角色生命状态

状态：已完成。

- 增加 `HealthState` 和数值校验。
- 挂接 `CharacterRuntimeState.health`。
- 增加 `CharacterHealthStore`。
- 保持目标运行态不变。

验收结果：角色当前生命成为明确运行态，目标未进入生命系统。

### 阶段 B：生命提交运行时

状态：已完成。

- 增加伤害应用、恢复量应用和直接扣血三类请求。
- 实现当前生命、最大生命、生命比例和零生命查询。
- 返回统一 `CharacterHealthChangeResult`。
- 增加最大生命同比同步入口。
- 对非法请求、主体和状态使用结构化错误。

验收结果：无需具体 content 即可独立验证角色生命变化语义。

### 阶段 C：组装接入

状态：已完成。

- 在 frame 0 解析每个角色的最终 `stat.hp.max`。
- 默认以满血创建角色运行态。
- 在 `SimulationContext` 注册 `HealthRuntime`。
- 通过 `AssembledSimulation.health_runtime` 暴露稳定入口。

验收结果：所有已组装角色都有合法生命状态，目标组装流程未改变。

### 阶段 D：事件与持久化

状态：已完成。

- 增加 `CHARACTER_HEALTH_CHANGED` 状态变化事件。
- 增加 `CHARACTER_MAX_HP_CHANGED` 审计事件。
- 零变化不发布普通生命变化事件。
- 使用现有通用事件 JSON 完成结果库往返。

验收结果：有效生命变化可记录和复盘，无需升级结果库 schema。

### 阶段 E：上游系统接入

## 5. 验收标准

第一轮完成标准如下：

1. 每个已组装角色的初始当前生命等于 frame 0 的最终最大生命。
2. `HealthRuntime` 和 `CharacterHealthStore` 只接受角色主体。
3. 伤害应用、恢复量应用和直接扣血统一通过 `HealthRuntime` 提交。
4. 当前生命始终位于 `[0, stat.hp.max]`。
5. 结果能够区分请求量、有效量和未应用量。
6. 满血恢复、零伤害和完全受限的扣血不发布生命变化事件。
7. 最大生命同比同步不伪装为治疗或普通生命变化。
8. 当前生命为零不触发死亡、击败、索敌或停止行为。
9. 当前角色对目标的伤害仍只产生 `DAMAGE_RESOLVED`。
10. 目标配置、目标运行态和结果库 schema 不因本系统改变。

## 7. 资料依据

- [KQM 护盾机制](https://library.keqingmains.com/combat-mechanics/damage/shields)：护盾吸收位于角色生命扣减之前，护盾不是额外生命。

- [KQM 夜兰 C4 证据](https://github.com/KQM-git/TCL/blob/master/docs/evidence/characters/hydro/yelan.md)：最大生命增加导致的当前生命同步不是治疗。
- [KQM 逐影猎人证据](https://github.com/KQM-git/TCL/blob/master/docs/evidence/equipment/artifacts.md)：仅最大生命变化不触发要求当前生命变化的效果。

具体角色的扣血比例、最低生命限制和特殊恢复规则仍需独立来源或 golden case。
