# 分析系统契约

> 状态：已确认（2026-08-25 分析能力重做定稿）。本文定义模板目录、模板执行端点、v1 模板清单与稳定性规则。旧版 StateQuery / EventQuery / 序列 / 指标 / 对比 / 属性面板还原模型已随 analysis 模块删除，不再构成对外契约；属性面板的初始快照 provider 与 `ATTRIBUTE_PANEL_CHANGED` 事件形状仍属结果存储契约，登记在[结果库契约](./结果库契约.md)第 5.1 节。
> 系统设计见[分析系统设计](../架构/分析系统设计.md)。

## 1. 术语

- **模板**：后端拥有的查询单元 = SQL + 参数声明 + 关系输入声明 + 输出形状声明。
- **展开参数**：绑定类别为 `session_group` 的参数；v1 只有 `union` 模式（一句 SQL 带 IN 列表执行一次）。
- **关系输入**：下游 SQL 把上游结果表当作输入关系（连接级临时表语义），SQL 用 `{{名称}}` 占位。
- **结果表**：模板执行输出，= 列（名称 + 类型）+ 行 + 截断标记。

## 2. 模板目录

### `GET /api/v1/analysis/templates`

返回模板声明列表，前端据此生成处理节点卡表单与校验连线：

```json
{
  "items": [
    {
      "template_id": "session_metrics",
      "display_name": "每会话指标",
      "params": [
        {
          "name": "session_ids",
          "type": "string[]",
          "required": true,
          "binding": ["session_group", "upstream_column"]
        },
        { "name": "frame_min", "type": "int", "required": false, "binding": ["static", "config"] }
      ],
      "relations": [],
      "output": {
        "columns": [{ "name": "session_id", "type": "string" }]
      }
    }
  ]
}
```

`binding` 允许的取值：`static`、`config`、`session_group`、`upstream_column`。

## 3. 模板执行

### `POST /api/v1/analysis/templates/{template_id}/execute`

请求：

```json
{
  "params": { "session_ids": ["a1b2c3"], "frame_min": 0 },
  "relations": {
    "source": {
      "columns": ["total_damage", "dps"],
      "rows": [[123.0, 61.5]]
    }
  }
}
```

响应：

```json
{
  "columns": [{ "name": "session_id", "type": "string" }],
  "rows": [["a1b2c3"]],
  "truncated": false
}
```

约束：

- 展开参数 `session_ids` 就是 `params` 里的普通 `string[]`，没有单独的展开请求形状。
- 值链：上游结果表某一列的值直接放进下游 `params`。
- 关系输入：`columns` + `rows` 原样传输；后端校验“声明所需列 ⊆ 提供列”，超出的列忽略。
- 行集硬上限 10000 行，超出置 `truncated: true`；关系表上限 5000 行，超限拒绝；v1 不分页。
- 错误：未知模板 `404 / not_found`；参数缺失/类型不符/未知参数、关系缺失/列不匹配/超限 `400 / validation_failed`。

## 4. v1 模板清单

v1 模板按视图需求驱动，共四张，只增不改：

| 模板 | 输出列 | 消费视图 |
| --- | --- | --- |
| `session_metrics` 每会话指标 | `session_id`、`run_name`、`frames_run`、各槽位变体列（`char_{n}_key/level/constellation`、`weapon_{n}_key/level/refinement`）、`total_damage`、`dps`、`highest_hit`、`average_hit`、`total_healing`、`damage_count`、`healing_count` | 成员指标表、指标柱状图 |
| `timeline_rows` 时间轴行 | `session_id`、`track`、`start_frame`、`end_frame`（可空）、`value`（可空）、`label`（可空） | 单场时间轴 |
| `share_rows` 占比行 | `group`、`value`（百分比由视图计算） | 占比饼图 |
| `metric_summary` 指标汇总 | `metric`、`avg`、`max`、`min`、`stddev`、`p95` | 关系链消费样例 |

要点：

- `timeline_rows` 的 `event_types` 参数缺省为全部支持类型；点行映射固定为“伤害/治疗”，持续段 v1 只做 Buff（`BUFF_APPLIED` + `BUFF_REMOVED` 按实例配对），其余选中类型输出通用点行（`track` = 事件类型）。
- `share_rows` 的 `dimension` 取值：`source`（伤害按来源）、`damage_kind`（伤害按类型）、`healing_source`（治疗按来源）。
- `metric_summary` 的关系输入 `source` 所需列：`total_damage`、`dps`、`highest_hit`、`average_hit`、`total_healing`。
- 指标口径（整场 DPS = 总伤害 ÷ (frames_run ÷ 60) 等）以模板实现为唯一真值，配 golden 断言测试。
- 条件列 v1 输出 `asset_key` 原始值；显示名解析与可选列参数后置。

## 5. 稳定性规则

- 模板 `template_id`、参数声明、关系输入声明、输出列名与类型冻结；只追加、不改名、不改变语义。
- 对外端点形状是契约；变更走 API 版本升级。
- 删除模板必须走新版本并提供迁移。
