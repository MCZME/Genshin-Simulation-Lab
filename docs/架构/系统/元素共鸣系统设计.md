# 元素共鸣系统设计

> 状态：静态切片与全部动态效果（附着时长、冷却、双雷微粒、双草精通、
> 双冰暴击、双岩增伤/减抗）已实现。
> 稳定 key、激活条件、静态修饰与装配规则见[元素共鸣契约](../../契约/元素共鸣契约.md)。
> 最后更新：2026-08-10

## 1. 定位

`core/systems/resonance/` 是元素共鸣领域。它唯一拥有：

- 队伍元素构成到活跃共鸣集合的纯判定。
- 共鸣定义注册表与激活集合的真值。
- 激活后对全部角色展开的静态属性修饰 provider。
- 首次帧推进时发布的 `RESONANCE_ACTIVATED` 事实与快照。

共鸣的具体数值（元素计数阈值、属性倍率、触发反应清单等）属于内容规则，位于
`content/team/resonance.py`，不进入 `core/`。

## 2. 激活规则

- 队伍满员（角色数不少于 4）时才判定共鸣；不满员不激活任何共鸣。
- 某元素角色不少于 2 名时激活对应元素共鸣；多个共鸣可以同时生效。
- 4 名不同元素角色激活「交织之护」。
- 无元素角色不参与任何计数；无元素角色与 3 名不同元素角色组队不触发交织之护。

## 3. 结构

```text
core/systems/resonance/
├── models.py        ResonanceRequirement / ResonanceDefinition /
│                    ResonanceStaticModifier / ResonanceAuraDurationRule /
│                    TeamElementComposition / ResonanceActivation
├── definitions.py   ResonanceDefinitionRegistry
├── evaluator.py     evaluate_resonances()：构成 -> 激活集合
├── store.py         ResonanceStore：激活集合、构成快照与双雷冷却认领
├── runtime.py       ResonanceRuntime：只读查询、快照、一次性激活事实
├── ports.py         Aura 时长 / 冷却时长窄端口实现
├── providers.py     build_resonance_static_providers()：按槽位展开静态属性
├── snapshots.py     ResonanceSnapshot
└── errors.py        领域错误
```

反应触发的跨系统响应由协调层承载：

```text
core/coordination/resonance_reaction/
└── stage.py         ResonanceReactionStage：FACT_RESPONSE 反应意图阶段
```

`core/systems/resonance` 不依赖其他领域 Runtime/Store，只使用 `core/attributes`
的值对象与 `core/elements` 的中立元素语义。

## 4. 静态效果

第一版已接线的静态效果（数值见[元素共鸣契约](../../契约/元素共鸣契约.md)）：

| 共鸣 | 属性修饰 |
| --- | --- |
| `resonance.pyro` | `stat.atk.total` percent +25% |
| `resonance.hydro` | `stat.hp.max` percent +25% |
| `resonance.geo` | `bonus.shield.strength` flat +15% |
| `resonance.dendro` | `stat.elemental_mastery` flat +50 |
| `resonance.intertwined` | 全部 `resistance.*` flat +15% |

静态 provider 在组装期按每个队伍槽位构造并绑定角色主体，与角色、武器的静态
modifier 一样由属性系统统一聚合；水共鸣在初始最大生命解析前生效，因此角色
初始生命直接包含 25% 提升。

交织之护要求角色主体可以查询 `resistance.*`，因此[属性系统契约](../../契约/属性系统契约.md)
已将全部 `resistance.*` 的主体扩展为 `character`、`target`。

## 5. 附着时长与冷却修正

- 火/水/雷/冰共鸣分别缩短角色主体上的冰/火/水/雷 Aura 持续时间 40%：
  `ResonanceAuraDurationTermProvider` 通过 `CharacterAuraDurationTermPort`
  向角色附着入口提供 `AuraDurationTerm`，衰减档案按倍率缩放。
- 双风共鸣为全队元素战技/元素爆发冷却提供 ×0.95 时长 term：
  `ResonanceCooldownDurationTermProvider` 通过 `CooldownDurationTermPort`
  在 `TimedImpactAction` 开始冷却时合并进请求。

## 6. 反应触发效果

`ResonanceReactionStage`（位于 `core/coordination/resonance_reaction/`）
注册在 `FACT_RESPONSE` 阶段，消费
`REACTION_OCCURRED` 事实并为下一结算轮次入队强类型意图：

- 双雷：触发清单命中且冷却可认领（间隔 >= 300 帧）时，产生
  `ImpactRequest(ENERGY, spawn_pickup, electro)` 意图。
- 双草：按触发反应组别为全队每个角色产生
  `ApplyBuffRequest`（+30 或 +20 元素精通，360 帧），两组独立计时。
- 双冰：`ResonanceCryoCritDamageProvider` 在目标冰附着/冻结时写入
  `CRIT_RATE_ADD` +15%。
- 双岩：`ResonanceGeoDamageProvider` 在护盾庇护或存在月笼时写入
  `DAMAGE_BONUS_ADD` +15%；`ResonanceReactionStage` 消费 `DAMAGE_RESOLVED`
  为目标施加 15 秒岩抗 -20% Buff。

双冰与双岩的只读端口（`TargetAuraFrozenReadPort`、
`CharacterShieldPresenceReadPort`、`LunarCagePresenceReadPort`）在装配期由
`application/assembly/ports.py` 适配器绑定 Aura、Reaction、Shield 与队伍
运行态；月笼判定第一版按存在即生效。

## 7. 事件与快照

- `RESONANCE_ACTIVATED`：分类 `FACT`、默认记录。激活集合在组装期确定，
  Runtime 在首个模拟帧（第 1 帧）时间推进阶段发布一次，载荷包含
  `active_keys`、`team_size` 与 `established_frame`。
- `ResonanceSnapshot`：每帧导出活跃 key、队伍人数与建立帧，供快照 provider
  使用；快照同时包含双雷微粒最近掉落帧。

## 8. 装配

```text
RuntimeAssetBundle（角色资产含 element）
-> application/assembly/resonance.py build_resonance_bundle()
   -> TeamElementComposition
   -> ResonanceDefinitionRegistry(create_resonance_definitions())
   -> evaluate_resonances()
   -> ResonanceStore / ResonanceRuntime / 静态 provider / Aura 与冷却端口
-> RuntimeAssembler
   -> 静态 provider 注入属性运行时（含初始最大生命解析）
   -> Aura 端口注入 CharacterAuraImpactRequestHandler
   -> 双草 Buff 定义进入 Buff 注册表
   -> 动作冷却端口注入 TimedImpactAction
   -> core/coordination/resonance_reaction/ResonanceReactionStage
      注册 FACT_RESPONSE 与快照
   -> ResonanceRuntime 注册到 context、FramePipeline(TIME_ADVANCE) 与快照
```

角色元素不是七种元素之一、共鸣定义重复、激活集合引用缺失定义等错误在组装
阶段以 `InvalidRuntimePayloadError` 报出，不延迟到仿真运行中。

## 9. 当前不实现

- 双岩月笼「附近」：第一版按「存在月笼即生效」近似，距离判定未实现。
