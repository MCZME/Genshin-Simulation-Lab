# 动作系统契约

> 状态：正式。
> 本文档是动作系统的机器可验证契约：内容包、解释器、Action 实现与组装方必须
> 遵守的稳定接口与规则。设计意图、边界与模块划分见
> [动作系统设计](../架构/动作系统设计.md)。

最后更新：2026-08-08

## 1. 适用范围

本契约覆盖：

- 解释器返回边界（`ActionInterpretationResult`）。
- 动作启动与控制请求（`PreparedAction` / `ControlActionRequest`）。
- 解释器注册与绑定（`ActionInterpreterRegistry` / `InterpreterBinding`）。
- `action_key` 与 `ActionRegistry`。
- 动作准入、具名锁与中断（`ActionAdmissionPolicy` / `ActionInterruptPolicy` /
  `ActionDecision`）。
- `ActionInstance` 生命周期与每帧处理顺序。
- `ActionImpactPoint` 契约。
- `TargetingSpec` 索敌契约。
- `TimedImpactAction` 固定/动态时间线与垂直位移契约。
- 动作独占空间位置写入口（`SpaceRuntime.apply_displacement`）。
- 切人动作与停止条件。

以下内容由其他正式契约维护，本契约不重复：

- 输入 trace、按键映射、输入会话与输入事件 payload：[按键输入契约](./按键输入契约.md)。
- Damage Impact 字段、AOE 与元素流程：[伤害系统设计](../架构/系统/伤害系统设计.md)、
  [元素反应协调器设计](../架构/协调/元素反应协调器设计.md)。
- 内容包文件结构与组装：[内容包结构约定](../工程/内容/内容包结构约定.md)与
  [内容系统设计](../架构/内容系统设计.md)。

## 2. 解释器返回边界

`ActionInterpretationKind` 固定为：

```text
wait
reject
start_action
control_action
```

`InputSessionPolicy` 固定为：

```text
keep_listening
detach
cancel
```

规则：

- `wait` 不改变会话控制状态。
- `reject` 必须携带非空 `reason`，并按 `session_policy` 更新会话。
- `start_action` 必须携带非空 `prepared_action`。
- `control_action` 必须携带非空 `control_request`。
- 一次解释只返回一个主指令；一个动作的多个机制结果通过多个 impact 表达。

## 3. PreparedAction

```text
PreparedAction
├── action_key
├── owner
├── requested_start_frame
├── params
├── source_session_id?
├── bind_session_on_accept
├── continue_on_reject
├── interrupt_kind?
└── metadata
```

规则：

- `action_key` 必须非空，且必须在 `ActionRegistry` 中已注册。
- `requested_start_frame` 必须是非负整数，且不得早于当前仿真帧。
- `bind_session_on_accept`：动作接受后，HOLD/RELEASE 是否继续路由到该实例。
- `continue_on_reject`：管理器拒绝后，会话是否继续等待后续判断。
- `interrupt_kind`：本次请求用于判断能否中断冲突实例的语义标识。
- `params` 与 `metadata` 在构造时拷贝，后续解释器/管理器不得共享可变引用。

## 4. ControlActionRequest

```text
ControlActionRequest
├── target_instance_id
├── command
└── params
```

规则：

- `target_instance_id` 必须是正整数。
- `command` 是动作语义命令（如 `continue`、`enter_stage`、`release`、`cancel`、
  `finish`），不携带物理按键语义。
- 通用 `TimedImpactAction` 至少支持 `finish` 与 `cancel`。
- 解释器通过控制命令影响动作实例，不能直接修改 `action_state`。

## 5. 解释器注册与绑定

- 同一输入键在 `ActionInterpreterRegistry` 中只能注册一个 selector，不允许
  重复注册或隐藏优先级责任链。
- selector 在 PRESS 时解析一次并写入 `RuntimeInputSession.interpreter_binding`；
  HOLD、RELEASE 与 CANCEL 始终回到同一解释器，不因 `active_slot` 变化重新路由。
- `InterpreterBinding` 固定为 `interpreter_id` / `interpreter` / `owner` /
  `scope`。
- `ActionOwnerRef` 固定为 `team` 或 `character(slot)`。

组装校验：

- 配置允许出现的每个输入键都必须存在 selector。
- 同一个键不能重复注册 selector。
- 真实角色槽位必须存在角色解释器；测试解释器不能作为真实角色的默认降级。
- 找不到解释器或动作实现时在组装阶段报错，不延迟到仿真运行中。
- 角色不支持某个输入时，由已解析的解释器返回结构化拒绝，而不是解释器缺失。

## 6. action_key 与 ActionRegistry

- `action_key` 是运行时动作实现身份；非空、全局唯一，不等于资产 `asset_key`
  或装配入口 `handler_key`。
- 解释器只返回 `action_key` 与参数，不直接构造任意 `Action` 对象。
- 组装阶段检查：解释器声明的 `supported_action_keys` 全部已注册；动作声明的
  impact key 已注册 factory，或明确不产生 impact。

## 7. 动作准入、锁与中断

`ActionAdmissionPolicy`：

```text
ActionAdmissionPolicy
├── action_tags
├── required_locks
├── interrupt_policy
└── concurrency_policy
```

- `required_locks` 为空或 `concurrency_policy=allow_parallel` 时不与其他实例冲突。
- 冲突判定：新请求的 `required_locks` 与 scheduled/running 实例的
  `required_locks` 有交集。
- 所有冲突实例都必须允许被当前 `interrupt_kind` 中断，才原子地先取消旧实例、
  再创建新实例；不允许部分取消。

`ActionInterruptPolicy`：

```text
ActionInterruptPolicy
├── allowed_interrupt_kinds
├── active_from_frame
├── active_until_frame?
└── cancel_policy
```

- `cancel_policy` 当前支持 `reject_new` 与 `cancel_current`。
- `queue_new`、`truncate_current` 与 `allow_parallel` 后续按真实需要扩展，当前
  不是契约值。

`ActionDecision` 拒绝原因固定为：

```text
invalid_start_frame
invalid_owner
session_not_active
session_already_bound
lock_conflict
interrupt_not_allowed
instance_not_found
invalid_command
unsupported_action
```

同帧动作请求按输入边界原始顺序处理；前一个请求产生的实例和锁对后一个请求
立即可见。

## 8. ActionInstance 生命周期与每帧处理顺序

生命周期：

```text
scheduled
running
completed
canceled
```

- 被拒绝的动作请求不创建实例，只记录 `ActionDecision`。
- `Action` 不直接修改生命周期；它接收只读 `ActionExecutionContext` 并返回
  `ActionExecutionResult`，由 `ActionManager` 应用
  `next_state` / `emitted_impacts` / `lifecycle_directive` / `records`。
- `lifecycle_directive` 固定为 `continue` / `finish` / `cancel`。

每帧处理顺序：

```text
1. 启动此前预约在本帧开始的实例
2. 按原始顺序处理本帧 PRESS / RELEASE 边界
3. 每次解释后立即应用动作请求或控制命令
4. 按 session_id 处理仍为 held/listening 的 HOLD
5. 推进此前已经运行的 ActionInstance
6. 完成或取消到期实例
7. ImpactRuntime 处理本帧影响点
```

规则：

- 当前帧接受且 `start_frame=N` 的动作立即调用 `on_start()`，同帧后续输入可见
  其状态变化。
- 本帧刚执行 `on_start()` 的实例不再执行 `on_update()`。
- 控制命令立即调用 `on_command()`；仍运行的实例可在推进阶段再执行 `on_update()`。
- RELEASE 帧不再调用 HOLD。
- 输入边界先于 HOLD，保持“显式输入先处理、运行态随后推进”的帧语义。

## 9. ActionImpactPoint

```text
ActionImpactPoint
├── impact_point_id
├── source_instance_id
├── owner
├── action_key
├── impact_key
├── scheduled_frame
├── targeting?
├── params
├── cancel_with_action
└── status
```

- `scheduled_frame` 必须是非负整数；影响点在到期帧由 `ImpactRuntime` 分发。
- `status` 固定为 `pending` / `dispatched` / `canceled`。
- 动作取消时：已 `dispatched` 的影响点不回滚；`pending` 且
  `cancel_with_action=true` 的影响点取消；`cancel_with_action=false` 的继续。

## 10. TargetingSpec 索敌契约

```text
TargetingSpec
├── origin
├── radius
├── search_area?
├── selection_policy_key?
├── kinds
├── exclude_entity_ids
├── snapshot_policy
└── snapshot_entity_ids
```

```text
SearchAreaSpec
├── shape
├── radius
└── height?
```

- 提供 `search_area` 时，运行时用 `search_area.radius` 作为 X/Z 查询半径；
  否则用 `radius`。当前空间模型忽略高度（圆柱投影为同半径圆）。
- `selection_policy_key="分数"` 时，在查询结果中按
  `distance_xz, stable_entity_id` 选择最近目标（并列取稳定实体 id 较小者）。
- `snapshot_policy` 固定为 `resolve_on_impact` / `snapshot_on_emit`；
  `snapshot_on_emit` 使用 `snapshot_entity_ids`，不再重新查询。
- 索敌只选择瞄准目标与攻击方向，不等同于最终伤害范围；实际 AOE 由 Damage
  Impact 在影响点到期时按空间状态解析。

## 11. TimedImpactAction 时间线契约

- `duration_frames` 必须是正整数。
- `impact_frame_offsets` 的偏移必须是非负整数，影响点在
  `start_frame + offset` 到期。
- 时间线在注册期固定；启动期可变时间线的动作（如下落攻击）不使用本契约，
  改由 MovementSystem 事实事件驱动（见第 12 节）。

## 12. 位移契约（MovementSystem）

- 位移由 `MovementSystem` 统一拥有：空中实体（`position.y > 0`）从速度 0
  开始受重力自然下落，落地时 Y 归零并同步 `Space`。
- 位置写入口由 MovementSystem 独占：`SpaceRuntime.apply_displacement(
  entity_id, position)` 只供 Movement 领域使用；动作不再直接写 `Space` 位置，
  需要位移时通过 `ImpactKind.MOVEMENT` 请求表达意图（当前支持
  `params.movement = {entity_id, vertical_velocity}`）。
- 下落攻击等事件驱动动作：`FallPlungeAction` 读取 Movement 当前帧事实
  （`MOVEMENT_COLLIDED` / `MOVEMENT_LANDED`），在碰撞/落地帧当场发出影响点，
  不预排影响帧，也不写位移。
- 下坠碰撞使用实体碰撞箱：角色碰撞箱与目标碰撞箱 X/Z 与 Y 区间重叠时产生
  碰撞事实；`position.y` 视为实体基座高度，碰撞箱从基座向上延伸。

## 13. 切人动作契约

- 切人动作 key 固定为 `team.switch`，参数 `target_slot` 必须是与数字键
  `keyboard.1`~`keyboard.4` 对应的正整数槽位。
- 切人必须创建 `ActionInstance`；`TeamSwitchAction.on_start()` 切换
  `TeamRuntimeState` 并同步 `player:active.active_slot`。
- 切人动作通常不产生 impact。

## 14. 停止条件

模拟器只有在以下条件全部满足时才能自然结束：

- 所有输入会话计划已经完成。
- 没有 held/listening 的运行时输入会话。
- 没有 scheduled/running 动作实例。
- 没有待处理 `ActionImpactPoint`。
- 没有待分发或待结算的机制请求、运行中的空间对象或其他机制任务。
