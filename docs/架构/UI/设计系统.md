# 设计系统

> 状态：正式规范。
> 最后更新：2026-10-13。
> 本文规定前端 UI 的视觉语言与组件规范：设计令牌、色彩语义、排版阶梯、图标与组件状态。产品形态与交互规则见[画布设计](./画布设计.md)及各区域设计，工程边界见[前端工程规范](../../工程/前端工程规范.md)。

## 1. 令牌架构与单一事实源

- 唯一事实源是 `frontend/src/theme/tokens.ts`（TypeScript，供组件引用）。
- `frontend/src/theme/tokens.css` 是令牌的 CSS 自定义属性镜像（`:root`，供样式表引用）；`frontend/src/theme/tokens.test.ts` 断言两侧完全一致——无缺失、无多余、无漂移，改动任何一侧而不同步即测试失败。
- 消费规则：样式与组件只允许引用令牌，不得硬编码新色值、字号、圆角与阴影；新增视觉语义必须先加令牌，再在两侧同步。
- 分层：当前直接落地语义层（表面/文本、交互、过程色、身份色、间距、排版、圆角、阴影、层级）；不单独维护原色层，语义值即唯一定义。
- 暗色是当前唯一模式。令牌按语义角色命名（如 `panel` / `text` / `severity`），不按亮暗命名，为将来多模式预留。
- `app.css` 已于 2026-10-13 全量令牌化（第 7 节 Phase 1）；经评估有意保留的存量字面量登记在 §4 保留清单，不得新增。

## 2. 色彩

| Band | 令牌 | 含义 |

### 2.5 色彩硬规则

1. 身份 band 与过程 band 不共享精确色值（`tokens.test.ts` 断言，新增任一侧色值都会触发检查）。
2. 同一 band 内允许语义复用：`status.running` 与 `severity.info` 同为蓝、`selection` 与 `warningText` 同为琥珀，属有意的过程语义复用。
3. 状态不得只依赖颜色：错误、警告、运行中、选中等状态必须同时提供图标、文本或图形标识（前端工程规范 6.5）。
4. 身份色只作身份标识（类别圆点、区域描边、拖拽预览、小地图），不得用于表达状态或严重度。
5. 半透明叠加层（焦点环、悬停光晕、条纹纹理、渐变过渡）允许 `rgba()` 字面量，但基色必须从令牌派生；旧强调蓝 `rgba(59,130,246,·)` 已随 Phase 1 迁至 `rgba(56,189,248,·)`。
6. 领域装饰色（资产稀有度金、暴击/层数琥珀、正向增益绿、验证状态徽标）不属于两个 band，允许保留字面量，但须在 §4 保留清单登记；纳入令牌体系前排期统一。

### 2.6 2026-10-12 语义修正

- `displayView` 由 `#ef4444` 改为 `#f43f5e`：原与错误红同值，红色节点卡会被误读为报错节点。
- `teamConfig` `#f59e0b`→`#facc15`、`targetConfig` `#22c55e`→`#4ade80`、`dataSource` `#3b82f6`→`#60a5fa`、`displayConfig` `#ec4899`→`#d946ef`、`itemDetail` `#eab308`→`#22d3ee`：让出过程色精确值，同时拉开数据流相邻类色的区分度。
- 元素配色统一：`elements.ts` 的 `ELEMENT_COLORS`（Tailwind 系配色，与 tokens 双轨维护）退役，全量改用 `COLORS.element`；`pyro` 由 `#ef4444` 改为 `#ef7938`，同时消除元素色与错误红的撞值。
- 未知节点回落色由 `#64748b` 改为 `#475569`：原与 `status.cancelled` 同值。
- 图表分类色（`echartsCore.ts` 的 `VIEW_CHART_PALETTE`）是数据编码色，不属于两个 band；其首位与 `displayView` 类别色对齐，已同步更新。
- 按键轨迹调色板（`workflow/inputKeys.ts` 的按键色）暂归「输入标识」band 维持现状，统一归位列后置（第 7 节 Phase 3）。
- 表格最大/最小高亮定向（2026-10-13，视觉批 3）：`hl-max` 由完成绿改 `selection` 琥珀系（与暴击高光同族的「庆祝」语义）；`hl-min` 原取 `severity.error` 红，与错误语义冲突（红色会被读成异常而非「最小值」），改中性冷灰（`fillNeutral` 16% 底 + `textMuted`）。高亮仍同时加重字重，不只依赖颜色（规则 3）。

## 3. 字体与排版

字体栈沿用 `FONT.body`（`"Segoe UI", "Microsoft YaHei", system-ui, sans-serif`）与 `FONT.mono`（等宽，用于数值、路径、按键、哈希）。

| 阶梯 | 值 | 用途 |
| --- | --- | --- |
| `caption` | 11px / 行高 1.4 | 徽标、刻度、辅助说明（全局字号下限） |
| `bodySmall` | 12px / 行高 1.4 | 密集界面正文（节点编辑器、面板列表） |
| `body` | 13px / 行高 1.5 | 默认界面正文、卡标题 |
| `title` | 14px / 行高 1.4 | 分区标题、顶栏控件 |
| `heading` | 16px / 行高 1.5 | 弹窗标题、空态标题 |
| `display` | 20px / 行高 1.5 | 空态主标题 |

规则：

- 禁止 9px / 10px 字号；11px 仅用于徽标与刻度（存量 9/10px 随 Phase 1 消除）。
- 数值、路径、按键、指纹等等宽内容用 `FONT.mono` 并开启 `font-variant-numeric: tabular-nums`，保证列对齐。
- 标题字重用 600；仅顶栏品牌标识可用 700。
- 中文正文不斜体；强调用字重或颜色，不用斜体。

## 4. 间距、圆角、阴影、层级

间距（4px 基网）：`xs` 4（图标与文字间距）、`sm` 8（卡内分组）、`md` 12（卡内区块、列表项）、`lg` 16（面板留白）、`xl` 24（页面分区）。

圆角四档，层级递增：`control` 4（按钮、字段、徽标）< `overlay` 6（下拉、浮层）< `card` 8（节点卡、工具面板）< `container` 12（区域框、弹窗）。

阴影三级：`card`（节点卡，`0 4px 12px rgba(0,0,0,.35)`）< `overlay`（下拉、菜单，`0 8px 24px rgba(0,0,0,.45)`）< `modal`（弹窗、拖拽幽灵，`0 16px 48px rgba(0,0,0,.5)`）。浮层阴影只表达「浮起」，不表达选中；选中一律用 2.2 的焦点/选中环。

层级（样式禁止魔法数）：`toolPanel` 20 < `dropdown` / `resizeHandle` 30 < `popover` 40 < `dragGhost` 50 < `modal` 100。

## 5. 图标

现状问题（已解决，2026-10-13）：界面曾混用 Unicode 符号与 emoji（`↶ ↷ ▾ ✎ 🗑 ⚙ × ✓ ＋`），渲染随平台字体漂移，且无法统一描边与尺寸。

选型标准：线性风格、24 网格、1.5px 描边、圆角线帽、单色 `currentColor`；许可证可商用；支持按需引入。候选 Lucide（ISC）与 Tabler（MIT）。

**已确认引入 Tabler Icons（2026-10-13，用户确认）**：`@tabler/icons-react` 3.49.0，MIT 许可证（Copyright (c) 2020-2026 Paweł Kuna），结论见[前端工程规范](../../工程/前端工程规范.md)第 2 节。引入层为 `frontend/src/components/common/icons.tsx`：锁定 1.5px 描边与 16px 控件默认尺寸，包声明 `sideEffects: false`，命名引入可 tree-shake（14 个图标约 +4.6 kB）；行内 caret 与表头指示 12px，侧轨 20px，在调用点显式传 `size`。字符图标已按 shell → 面板 → 画布 → 节点顺序全量替换；`×N` 计数与伤害公式中的 `×` 是文本不是图标，保留。

状态矩阵（每个原语都必须有，禁止只做 default）：

| 状态 | 期望表现 |
| --- | --- |
| default | 第 2.1/2.2 节令牌值 |
| hover | 描边 `borderStrong`，或表面 `panelRaised` |
| active | 表面 `panelRaised` + 描边 `accent` |
| focus-visible | 1px `accent` 描边外环（见 2.2） |
| disabled | 透明度 0.5，`cursor: not-allowed` |

## 7. 迁移计划

逐步套到现有界面，每阶段独立可评审，门禁为 `pnpm lint` / `pnpm typecheck` / `pnpm test`：

- **Phase 0（已完成，2026-10-12）**：令牌落地（`tokens.ts` 规范化、`tokens.css` 镜像、一致性测试）；语义色修正与元素配色统一（2.6）；未知回落色修正。
- **Phase 1（已完成，2026-10-13）**：`app.css` 全量令牌化——现存 1017 处 `var(--…)` 引用（同值直换 + 选择器级分流：`#3b82f6` 旧强调蓝 29 处迁至 `accent`，`status-running` 等过程语义按选择器走状态令牌）；消除 9/10px 字号（143 处收敛至 `caption` 11px）；圆角入四档（2/3/4/5→`control`、6→`overlay`、7/8→`card`、10→`container`）；阴影按几何家族归位三级；z-index 八处跨组件层切入令牌；旧蓝焦点环光晕迁至新强调色 `rgba(56,189,248,·)`。保留字面量见 §4 保留清单。新增 `fillNeutral` 令牌（中性填充）。
- **Phase 2（已完成，2026-10-13）**：图标库人工确认（Tabler，MIT）与引入层落地；字符图标按 shell → 面板 → 画布 → 节点顺序全量替换（`×N` 计数等文本符号除外）；`focus-visible`（按钮原语 1px `accent` 外环）与 `loading`（保存/运行按钮 `aria-busy` + 文案「…」）补全；运行按钮运行中保持可双击取消（决策 2.38），以 `aria-busy` 表达繁忙。
- **视觉批 1–3（已完成，2026-10-13，分支 `feat/canvas-visual-polish`）**：美术层打磨，全程不触碰节点几何与连线锚点（禁 transform 位移/缩放，动效只作用于 stroke / box-shadow / background / dashoffset）。
  - 批 1 氛围层与连线状态语言：`.canvas-atmosphere` 视口固定区域色径向微光（落实画布设计既定「动态氛围背景层」）；连线四态经 `--xy-edge-stroke` 整体换色，运行中挂库内 `animated` dash 流动；连线标签 `×N` 的 fill/字号/字串归位令牌。
  - 批 2 运行高光时刻：批次进度条 running 段微光、构建推进节点呼吸环、批次完成徽章一次性脉冲（限定 `.simulation-editor` 作用域）；新增 `prefers-reduced-motion` 总开关。
  - 批 3 状态层级与空态：节点类别色带（`--node-category` 驱动 `::before`）；画布空态落地；批次计数 / 组徽标 / 伤害乘法链统一 `tabular-nums`；表格 max/min 高亮定向修正（见 2.6）；小地图修正库默认浅色遮罩并仪表化；拖拽落点合法内发光 + 错误类型区域红色虚线劝阻（`invalidDropRegionId`，仅区域归属类节点参与判定）。
- **Phase 3**：视觉验收与截图回归（覆盖三批视觉改动：氛围层 / 连线四态 / 运行高光 / 色带 / 空态 / 小地图 / 落点反馈）；按键轨迹调色板（`inputKeys.ts`）归位到身份色 band；评估 `app.css` 按域拆分（后置，有明确需求再动）。

约束：不做大爆炸重写；每阶段只碰令牌与该段样式，不顺手改结构；存量工作流与节点契约不受任何阶段影响。
