月绽放 Definition 必须由 `create_default_reaction_bootstrap()` 组合进生产 bundle；Damage Profile 由生产组装器 `bloom_damage_profiles()` 和 `lunar_bloom_damage_profiles()` 共同注册。缺失注册在组装阶段失败。

## 2. 候选与元素消费

月绽放只匹配以下条件同时满足的交互：

1. 请求携带 `reaction_capability:lunar_bloom`；
2. 请求携带上游确认的角色来源集合 `character_source_refs`；
3. 当前触发来源 `source_ref` 属于该角色集合；
4. 严格水草 Aura 方向：水触发普通草，或草触发水，不接受 `QUICKEN`。

水草消费关系与普通绽放一致：

```text
incoming_hydro_on_dendro:
hydro_used = min(T, 2 * A)
dendro_like_used = hydro_used / 2

incoming_dendro_on_hydro:
dendro_used = min(T, A / 2)
hydro_used = dendro_used * 2
```

两侧实际消费均为正才产生月绽放 occurrence。月绽放 `selection_priority` 为 `100`，高于普通绽放的默认 `0`；无 capability 或合法角色触发来源时月候选不匹配，普通候选继续生效。

## 3. 草原核共享创建

月绽放每次 occurrence 生成的 `DendroCoreState` 字段、生命周期、容量、终态和事务流程与普通绽放完全一致，遵守[绽放反应契约](./绽放反应契约.md)第 3 节“草原核契约”。草原核后续爆炸、超绽放和烈绽放使用普通剧变伤害，不属于月曜伤害类别。

## 4. 参与者

月绽放 occurrence 在消费前从实际使用的 Aura Component 贡献和当前触发角色冻结 `participant_refs`，来源去重后按稳定顺序保存。capability provider 若没有实际贡献且不是触发者，不自动进入参与者集合。

参与者快照用于反应审计，不生成伤害 Effect。角色月绽放伤害的属性与来源由施放技能的角色决定，不从参与者快照读取。

## 5. 草露资源

Reaction 持有队伍级 `LunarBloomDewState`，字段：

```text
team_ref
current_value: Fraction
capacity: Fraction = 3
recovery_rate_per_frame: Fraction = 1/150
recovery_expires_at_frame: int
normalized_through_frame: int
resource_revision: int
```

触发月绽放时先规范化到当前帧，再保留已有 Fraction 进度并刷新恢复截止帧为 `frame + 150`。规范化只向前投影，不回到过去。资源计划与 Aura、ReactionState 和 Gate 使用同一 Store version 校验提交。

草露消费接口：

```text
consume(team_ref, amount: int) -> LunarBloomDewState
```

- `amount` 必须是正整数；不足、未生成或非法数量直接拒绝；
- 消费前规范化到当前帧；
- 消费后 `current_value` 减去 `amount`，恢复窗口与规范化游标不变；
- 消费结果随资源计划原子提交，不独立成立事务。

角色技能侧的具体消费时机、最低值、最大消费量和回退顺序待角色内容设计实现。

## 6. 角色月曜伤害

月绽放没有反应伤害。角色月绽放伤害由角色技能消费草露后构造 `LunarReactionDamageInput(mode=CHARACTER_DIRECT)` 进入统一 Damage Impact。

月曜公式参数（已注册默认值）：

```text
等级基数：{80: 1077.4, 90: 1446.9, 95: 1561.5, 100: 1674.8}
精通系数 = 6 × EM / (EM + 2000)
角色月绽放倍率 = 1.0
```

伤害结果使用 `DamageResult.lunar_reaction_resolution` 保留组分、排序、权重和审计；该路径没有独立的 Reaction 专用伤害端口。角色技能侧的具体伤害构造、暴击决策和属性来源待角色内容设计实现。

## 7. 事务、事实与错误边界

月绽放候选、草原核创建和草露资源计划均使用 `prepare -> validate -> commit`。Aura、ReactionState、Space、Gate、资源和事实的前值/版本任一 stale 时，整批失败且不得部分提交。Commit 不重新查询 Attribute、Space 或调用 handler。

必须记录通用 `REACTION_OCCURRED`、`REACTION_STATE_CHANGED` 和 `ELEMENTAL_INTERACTION_RESOLVED`，并保存 occurrence、来源、目标、Effect 和帧。

组装阶段缺少 Definition、Handler、Profile、State/Space adapter 或资源计划时失败；运行时 capability 缺失、角色来源不匹配、版本冲突也必须显式失败，不能降级为普通绽放。

## 8. 当前非目标与验收入口

契约不包含：

- 角色 content 的正式 capability 绑定（当前使用临时 capability 端口）；
- 角色技能侧对草露的消费与角色月绽放伤害入口（Reaction 侧消费接口已提供）；
- 动态角色 capability、具体角色名单和角色专属草露/山月草露/诳言之核资源；
- 月感电、月结晶。

主要验收入口：

- `tests/unit/core/systems/reaction/test_lunar_bloom.py`
- `tests/golden/reactions/test_lunar_bloom_damage_boundary.py`
