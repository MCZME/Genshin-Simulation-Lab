# 蒸发反应设计

> 状态：已实现。本文描述普通水火蒸发的两个明确方向。

最后更新：2026-08-03

## 1. 定位

普通蒸发是无状态增幅反应。它消费普通火或普通水 Aura，形成一个 `ReactionOccurrence`，并在当前关联伤害具备资格时输出 `CurrentImpactDamageAdjustment`。

代码落点：

```text
core/systems/reaction/mechanics/vaporize/mechanic.py
```

公共判定、事务和事实规则见：

- [系统边界与领域模型](../系统边界与领域模型.md)
- [判定与执行流程](../判定与执行流程.md)
- [事务、事实与验证](../事务、事实与验证.md)

## 2. 稳定身份

| 类型 | 值 |
| --- | --- |
| Reaction key | `reaction.vaporize` |
| Handler key | `reaction_handler.vaporize` |
| 水触发火方向 | `incoming_hydro_on_pyro` |
| 火触发水方向 | `incoming_pyro_on_hydro` |
| 水触发火 Profile | `reaction_profile.vaporize.incoming_hydro_on_pyro` |
| 火触发水 Profile | `reaction_profile.vaporize.incoming_pyro_on_hydro` |

一个 Reaction key 包含两个显式方向，不拆成两个反应，也不通过显示名称识别。

## 3. 方向与倍率

| 先手 Aura | 后手元素 | 基础倍率 | 消费关系 |
| --- | --- | ---: | --- |
| 普通火 | 水 | `2.0` | `1` 水最多消费 `2` 火 |
| 普通水 | 火 | `1.5` | `1` 火最多消费 `0.5` 水 |

基础倍率来自方向 Profile。Reaction 不在 Rule 中读取元素精通。

## 4. 精确元素量

设：

- `I` 为 ICD 后完整后手元素预算；
- `A` 为匹配先手 Aura 当前量。

水触发火：

```text
incoming_consumed = min(I, A / 2)
aura_consumed = incoming_consumed * 2
incoming_remaining = I - incoming_consumed
aura_remaining = A - aura_consumed
```

火触发水：

```text
incoming_consumed = min(I, A * 2)
aura_consumed = incoming_consumed / 2
incoming_remaining = I - incoming_consumed
aura_remaining = A - aura_consumed
```

所有元素量使用 `AuraAmount` 精确计算，不使用浮点数决定消费与归零。

## 5. 示例

| 方向 | 初始 Aura | 后手预算 | 结果 |
| --- | ---: | ---: | --- |
| 水触发火 | 火 `0.8` | 水 `1.0` | 消耗水 `0.4`、火 `0.8`；后手剩余水 `0.6` |
| 火触发水 | 水 `0.8` | 火 `1.0` | 消耗火 `1.0`、水 `0.5`；剩余水 Aura `0.3` |

后手剩余量可以继续当前 `ReactionDecisionSequence` 的后续步骤，但序列结束后不自动形成持久 Aura。

## 6. 伤害关联

蒸发成立后：

- `current_damage_element` 与后手元素一致时，创建当前 Impact 调整；
- 无伤害元素施加仍产生 occurrence 和 Aura 消费，但不产生 Damage 调整；
- `reaction_bonus` 当前生产值固定为 `0.0`；
- Damage 使用后手来源当前帧的 `stat.elemental_mastery`；
- 最终增幅乘数由 Damage 计算，而不是 Vaporize Rule 计算。

## 7. 状态与生命周期

普通蒸发不创建：

- ReactionState；
- Damage Gate 或成立 Gate；
- 独立反应伤害；
- 周期根、传播或空间实体；
- 后续 settlement round 工作。

Damage 最终为零或被后续防护完全吸收，不撤销蒸发 occurrence 和已提交 Aura 消费。

## 8. 验证

当前验证包括：

- 两个方向的签名、基础倍率和精确消费单测；
- 无 Aura、同元素、零后手预算等空决议；
- 无伤害施加只反应不增伤；
- 元素精通与反应区公式测试；
- 两个方向的完整生产纵向 golden case；
- Damage 预检失败时 ICD、Aura、Reaction 和 Damage 零提交。
