# 元素共鸣系统设计

> 状态：正式规范。
> 本文说明 `core/systems/resonance/` 元素共鸣领域的职责：队伍构成到共鸣集合的激活判定、静态属性修饰、附着与冷却时长修正、反应触发效果，以及装配与端口绑定。
> 最后更新：2026-09-05。

共鸣 key、激活条件、数值、领域模型与事件载荷以[元素共鸣契约](../../契约/元素共鸣契约.md)为真值，本文不重复维护。

## 1. 定位

`core/systems/resonance/` 是元素共鸣领域。它唯一拥有：

- 队伍元素构成到活跃共鸣集合的纯判定。
- 共鸣定义注册表与激活集合的真值。
- 激活后对全部角色展开的静态属性修饰 provider。
- 首次帧推进时发布的 `RESONANCE_ACTIVATED` 事实与快照。
- 共鸣附着时长与冷却时长修正的窄端口实现。

共鸣的具体数值（元素计数阈值、属性倍率、触发反应清单等）属于内容规则，位于 `content/`，不进入 `core/`。

## 2. 激活规则

激活判定在组装期完成，运行期不改变：

- 队伍满员（角色数不少于 4）时才判定共鸣；不满员不激活任何共鸣。
- 某元素角色不少于 2 名时激活对应元素共鸣；多个共鸣可以同时生效。
- 4 名不同元素角色激活「交织之护」。
- 无元素角色不参与任何计数；无元素角色与 3 名不同元素角色组队不触发交织之护。

激活集合固定后按 key 稳定排序，进入 `ResonanceStore`。

## 3. 结构

```text
core/systems/resonance/
├── models.py        ResonanceRequirement / ResonanceDefinition /
│                    ResonanceStaticModifier / ResonanceAuraDurationRule /
│                    TeamElementComposition / ResonanceActivation
├── definitions.py   ResonanceDefinitionRegistry
├── evaluator.py     evaluate_resonances()：构成 -> 激活集合
├── store.py         ResonanceStore：激活集合、构成快照与双雷冷却认领
├── runtime.py       ResonanceRuntime：只读查询、快照、一次性激活事实
├── ports.py         Aura 时长 / 冷却时长窄端口实现
├── providers.py     build_resonance_static_providers()：按槽位展开静态属性
├── snapshots.py     ResonanceSnapshot
└── errors.py        领域错误
```

反应触发的跨系统响应由协调层承载：

```text
core/coordination/resonance_reaction/
└── stage.py         ResonanceReactionStage：FACT_RESPONSE 反应意图阶段
```

`core/systems/resonance` 不依赖其他领域 Runtime / Store，只使用 `core/attributes` 的值对象与 `core/elements` 的中立元素语义。

## 4. 静态效果

激活共鸣的静态属性修饰对队伍每个角色各展开一份，按槽位绑定角色主体，与角色、武器的静态 modifier 一样由属性系统统一聚合。静态 provider 在组装期构造并注入属性运行时；水共鸣在初始最大生命解析前生效，因此角色初始生命直接包含其提升。

静态修饰的属性目标、阶段、值与审计标签见[元素共鸣契约](../../契约/元素共鸣契约.md)。

交织之护要求角色主体可以查询 `resistance.*`，因此属性契约已把全部 `resistance.*` 的主体扩展为 `character`、`target`。

## 5. 附着与冷却时长修正

- 火 / 水 / 雷 / 冰共鸣分别缩短角色主体上的对应 Aura 持续时间：`ResonanceAuraDurationTermProvider` 通过 `CharacterAuraDurationTermPort` 向角色附着入口提供 `AuraDurationTerm`，衰减档案按倍率缩放。
- 双风共鸣为全队元素战技 / 元素爆发冷却提供时长 term：`ResonanceCooldownDurationTermProvider` 通过 `CooldownDurationTermPort` 在动作开始冷却时合并进请求。

目标 Aura、倍率与冷却系数见[元素共鸣契约](../../契约/元素共鸣契约.md)。

## 6. 反应触发效果

`ResonanceReactionStage`（位于 `core/coordination/resonance_reaction/`）注册在 `FACT_RESPONSE` 阶段，消费 `REACTION_OCCURRED` / `DAMAGE_RESOLVED` 事实并为下一结算轮次入队强类型意图：

- 双雷：触发清单命中且冷却可认领时，产生雷元素能量微粒意图。
- 双草：按触发反应组别为全队角色产生元素精通 Buff 意图，两组独立计时。
- 双冰：攻击处于冰附着或冻结状态的目标时写入暴击率加成，经只读端口查询目标状态。
- 双岩：处于护盾庇护或存在活动月笼时写入伤害加成，并对受击目标施加岩元素抗性降低 Buff。

双冰与双岩的只读端口（目标冻结、护盾存在、月笼存在）在装配期由 `application/assembly/ports.py` 适配器绑定 Aura、Reaction、Shield 与队伍运行态。触发反应清单、数值、时长与 Buff 定义键见[元素共鸣契约](../../契约/元素共鸣契约.md)。

## 7. 事件与快照

- `RESONANCE_ACTIVATED`：分类 `FACT`、默认记录。激活集合在组装期确定，Runtime 在首个模拟帧时间推进阶段发布一次，载荷包含 `active_keys`、`team_size` 与 `established_frame`。
- `ResonanceSnapshot`：每帧导出活跃 key、队伍人数与建立帧，并包含双雷微粒最近掉落帧，供快照 provider 使用。

## 8. 装配

```text
RuntimeAssetBundle（角色资产含 element）
-> application/assembly/resonance.py build_resonance_bundle()
   -> TeamElementComposition
   -> ResonanceDefinitionRegistry(create_resonance_definitions())
   -> evaluate_resonances()
   -> ResonanceStore / ResonanceRuntime / 静态 provider / Aura 与冷却端口
-> RuntimeAssembler
   -> 静态 provider 注入属性运行时（含初始最大生命解析）
   -> Aura 端口注入 CharacterAuraImpactRequestHandler
   -> 双草 Buff 定义进入 Buff 注册表
   -> 动作冷却端口注入 TimedImpactAction
   -> core/coordination/resonance_reaction/ResonanceReactionStage
      注册 FACT_RESPONSE 与快照
   -> ResonanceRuntime 注册到 context、FramePipeline(TIME_ADVANCE) 与快照
```

角色元素不是七种元素之一、共鸣定义重复、激活集合引用缺失定义等错误在组装阶段以 `InvalidRuntimePayloadError` 报出，不延迟到仿真运行中。

## 9. 不实现

- 双雷触发清单中的星超导：确认不接入。
- 双岩月笼「附近」：按「存在月笼即生效」近似，距离判定未实现。
