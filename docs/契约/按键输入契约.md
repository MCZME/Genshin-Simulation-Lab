# 按键输入契约

> 状态：正式契约。本文档定义 `SimulationConfig.input_trace` 的按键输入事实格式、校验规则，以及它到动作系统输入会话计划的跨层数据边界。

最后更新：2026-07-11

## 1. 适用范围

本文档只回答：“配置和输入会话这批数据长什么样，跨模块怎么传，哪些信息不能泄露。”

包含范围：

- `SimulationConfig.input_trace` 的 JSON 结构。
- 第一版支持按键集合。
- 配置与编译阶段校验规则。
- `InputTraceCompiler` 的输入输出边界。
- `InputSessionTrace`、`InputSessionPlan`、`InputSessionBoundary` 的数据结构。
- 解释器可见的 `InputSessionView` 暴露规则。
- 输入事实与会话边界事件类型及 payload。

不包含范围：

- 具体按键如何解释为普通攻击、战技、爆发、切人、跳跃或冲刺。
- 角色动作帧数、动作锁、中断窗口、资源消耗或冷却规则。
- 伤害、治疗、命中、索敌、元素附着、反应或其他机制结算。
- UI 编辑方式、键位设置界面或手柄映射策略。

运行时协作关系见：[按键输入系统设计](../架构/按键输入系统设计.md)。

## 2. 配置数据结构

`input_trace` 记录玩家在某一帧按下或松开了哪些键，不直接记录动作语义。

```text
InputTrace = list[KeyInputFrame]

KeyInputFrame
├── frame: int
└── events: list[KeyEvent]

KeyEvent
├── key: string
└── phase: press | release
```

示例：

```json
[
  {
    "frame": 120,
    "events": [
      {"key": "keyboard.e", "phase": "press"},
      {"key": "mouse.left", "phase": "press"}
    ]
  },
  {
    "frame": 145,
    "events": [
      {"key": "keyboard.e", "phase": "release"}
    ]
  },
  {
    "frame": 150,
    "events": [
      {"key": "mouse.left", "phase": "release"}
    ]
  }
]
```

`frame` 使用仿真帧号。第 0 帧保留为初始化帧，因此配置中的输入帧号必须从正整数开始。

## 3. 支持按键集合

第一版支持键盘和鼠标按钮：

```text
keyboard.e
keyboard.q
keyboard.space
keyboard.1
keyboard.2
keyboard.3
keyboard.4
mouse.left
mouse.right
```

默认控制含义：

| 按键 | 默认控制含义 |
| --- | --- |
| `keyboard.e` | 战技按钮 |
| `keyboard.q` | 爆发按钮 |
| `keyboard.space` | 跳跃按钮 |
| `keyboard.1` ~ `keyboard.4` | 切换到对应队伍槽位 |
| `mouse.left` | 攻击按钮 |
| `mouse.right` | 冲刺按钮 |

默认控制含义不是最终动作。具体动作由解释器根据输入会话、owner、角色状态和动作运行态判断。

第一版不支持：

- 手柄输入。
- 自定义键位映射。
- 鼠标移动、镜头、视角或准星变化。
- 移动键功能；默认角色无法通过 `W/A/S/D` 移动。

实际位移由动作或空间系统处理，不由按键输入轨迹直接计算。

## 4. 校验规则

- `frame` 必须是正整数。
- `KeyInputFrame` 按 frame 严格递增。
- 同一个 frame 只能出现一次；同帧事件合并到同一个 `events` 列表。
- `events` 必须至少包含一个 `KeyEvent`；空帧没有语义，不写入配置。
- `phase` 只允许 `press/release`。
- `key` 只允许使用第一版支持按键。
- 同一帧内同一个 key 不能重复出现。
- 同帧事件按列表顺序处理，不设置隐藏优先级。
- 每一个 press 必须有且只有一个后续 release。
- 未按下的 key 不能 release。
- 已按下的 key 不能再次 press。
- 轨迹结束时不能存在仍未 release 的 key。
- 不允许同一个 key 在同一帧 press 后 release；同键最短保持时间为一帧。

配置模型和 `InputTraceCompiler` 都应执行防御性校验。配置错误必须在组装或运行前暴露。

## 5. InputTraceCompiler 边界

`InputTraceCompiler` 在组装阶段完成按键输入事实配对：

```text
KeyInputFrame / KeyEvent
-> InputSessionPlan
-> InputSessionBoundary
-> InputSessionTrace
```

输入：

- 来自 `SimulationConfig.input_trace` 的 `KeyInputFrame` 序列。
- 每个输入帧已经具备帧号和同帧事件顺序。

输出：

- 不可变 `InputSessionPlan` 集合。
- 便于 `ActionManager` 按帧读取的 `InputSessionBoundary` 索引。
- 封装两者的 `InputSessionTrace`。

职责：

- 校验帧号、按键、阶段、顺序和按键生命周期。
- 配对每个 `press/release`。
- 保留同帧事件原始顺序。
- 按 press 出现顺序稳定分配 `session_id`。
- 生成 `InputSessionTrace`。

非职责：

- 不作为每帧运行对象。
- 不调用动作解释器。
- 不决定动作是否发生。
- 不创建动作实例或修改运行态。

## 6. 输入会话数据结构

### 6.1 InputSessionTrace

```text
InputSessionTrace
├── sessions: tuple[InputSessionPlan, ...]
├── boundaries: tuple[InputSessionBoundary, ...]
├── get_session(session_id)
├── boundaries_at(frame)
└── has_pending_after(frame)
```

`InputSessionTrace` 是 `ActionManager` 的输入计划载体。它可以持有完整未来计划，但解释器只能看到当前帧视图。

### 6.2 InputSessionPlan

```text
InputSessionPlan
├── session_id
├── key
├── press_frame
├── release_frame
├── press_order
├── release_order
└── held_frames
```

规则：

- `session_id` 按 press 出现顺序稳定分配。
- `press_order/release_order` 保存各自所在帧的原始列表序号。
- `held_frames = release_frame - press_frame`。

### 6.3 InputSessionBoundary

```text
InputSessionBoundary
├── frame
├── order
├── session_id
└── phase
```

`phase` 只表示外部输入事实边界：

```text
press
release
```

`ActionManager` 使用边界索引恢复每帧的 PRESS/RELEASE 顺序。会话化不能改变同帧输入语义。

## 7. InputSessionView 暴露规则

`ActionManager` 私有持有完整 `InputSessionTrace`，但解释器只接收当前帧只读视图。

```text
InputSessionView
├── session_id
├── key
├── trigger
├── press_frame
├── current_frame
├── held_frames
├── physical_state
├── owner
├── bound_instance?
└── release_frame?
```

`trigger` 是运行时解释触发：

```text
press
hold
release
cancel
```

暴露约束：

- PRESS 和 HOLD 阶段不能暴露计划中的 future release frame。
- RELEASE 到达时才写入并暴露 `release_frame`。
- PRESS 时 `held_frames=0`。
- HOLD 时 `held_frames=current_frame-press_frame`。
- RELEASE 时 `held_frames=release_frame-press_frame`。
- `bound_instance` 只作为只读视图暴露。
- 解释器生成的动作开始帧不得早于当前仿真帧。
- 禁止在 release 时回溯创建已经错过运行阶段的动作。

这些规则保证完整输入计划不会向解释器泄露未来信息。

## 8. 输入事件类型与 payload

输入事实、会话边界和动作判断属于不同层级：

```text
KeyEvent
InputSessionBoundary
ActionInterpretationResult
ActionDecision
ActionInstance lifecycle
```

按键输入契约只定义输入事实与会话边界事件。

### 8.1 INPUT_KEY_RECEIVED

`INPUT_KEY_RECEIVED` 是输入事实事件。

```text
InputKeyReceivedPayload
├── key
├── phase
├── order
└── session_id
```

`GameEvent.frame` 表示该输入事实发生帧，payload 不重复记录 `frame`。该事件只记录原始按键事实和编译后关联的 `session_id`，不记录 `held_frames`，避免把派生会话信息混入输入事实层。

### 8.2 INPUT_SESSION_BOUNDARY_REACHED

`INPUT_SESSION_BOUNDARY_REACHED` 是输入会话边界事件。

```text
InputSessionBoundaryPayload
├── session_id
├── key
├── phase
├── order
├── press_frame
├── held_frames
├── physical_state
├── control_state
├── owner_kind
├── owner_slot
├── interpreter_id
├── binding_scope
├── will_interpret
└── skip_reason
```

该事件记录 `ActionManager` 处理会话边界时看到的会话状态、解释器 binding 和是否会调用解释器。`will_interpret=false` 时，`skip_reason` 记录跳过原因，例如 `detached` 或 `canceled`。

这些输入事件只用于复盘、审计和结果记录，不作为动作机制的驱动来源。发布顺序和运行时语义见：[按键输入系统设计](../架构/按键输入系统设计.md)。

## 9. 待细化事项

以下事项保留为后续扩展，不影响当前正式契约：

- 输入会话在快照和结果库中的持久化格式。
- CANCEL 回调当前仅保留枚举和契约位置；是否启用回调等待具体角色或机制需求确认。
- 动作解释结果、动作决策和动作生命周期事件仍由动作系统文档细化。
- 自定义键位、手柄、移动和视角输入的扩展契约。
