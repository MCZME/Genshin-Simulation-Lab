# 月结晶反应设计

> 状态：已实现（第一条纵向切片）
> 最后更新：2026-08-03

## 1. 定位

月结晶是与普通结晶机制簇并列的独立反应，使用独立 `reaction.lunar_crystallize` Definition、Rule、Profile、月笼状态、共享累计器和月曜伤害路径，不归入 `mechanics/crystallize/` 机制目录。

月结晶在满足队伍 capability、角色触发来源和严格水岩元素签名时排他选中水结晶方向；本次交互只产生月结晶 occurrence，不同时产生普通结晶 occurrence。火、雷、冰结晶方向不受影响，保持普通结晶。没有 capability 或合法角色触发来源时，月候选不匹配，普通水结晶候选继续生效。

月结晶成立时按普通结晶的岩水 `2:1` 消费元素量，不创建水晶片，不产生反应伤害本身；伤害来自月笼的谐奏攻击，属于反应月曜伤害。月结晶不使用普通结晶目标级成立 Gate，可以高频触发。

## 2. 领域所有权

| 领域 | 月结晶相关职责 |
| --- | --- |
| Aura | 水元素量、逐来源贡献账本与 `2:1` 消费后值 |
| Reaction | 独立 Definition、严格水岩候选、参与者冻结、月笼 State、队伍级共享累计器、谐奏发射计划与 Effect 声明 |
| Space | 月笼 `REACTION_OBJECT` 的位置投影、生命周期与创建/销毁声明 |
| Damage | 反应月结晶复合月曜伤害的组分结算、排序加权和审计 |
| Coordination | 月笼集合生成/复用、累计器追加与消费、谐奏目标选择、冷却推进和批次提交；不实现月结晶公式 |

## 3. 稳定 Definition 与方向

```text
reaction.lunar_crystallize / reaction_handler.lunar_crystallize

lunar_incoming_geo_on_hydro
```

候选要求请求同时携带 `reaction_capability:lunar_crystallize`、上游确认的角色来源集合，并且当前触发来源属于该角色集合；只接受后手岩命中正水 Aura 的严格水岩方向，冻结目标不进入候选。

元素消费与普通结晶一致：

```text
geo_consumed = min(入射岩元素量, 水 Aura 量 × 2)
aura_consumed = geo_consumed / 2
```

## 4. 月笼集合

Reaction 拥有队伍级月笼 State，Space 拥有位置投影；两侧通过稳定 binding ref 原子创建、替换和移除。

```text
LunarCageState
├── instance_ref            = reaction-state:lunar-cage:<occurrence_ref>:<0..2>
├── subject_ref             = 生成锚点目标
├── space_entity_ref        = reaction_object:lunar_cage:<occurrence_ref>:<0..2>
├── created_by_occurrence_ref
├── trigger_source_ref
├── team_ref                = player_team
├── created_frame
├── last_harmony_frame      初始 = created_frame
├── next_attack_frame       初始 = created_frame
├── expires_at_frame        = last_harmony_frame + 540
├── attack_index            从 0 开始，每次发射 +1
└── revision
```

场上同时最多且常态只有 3 枚月笼。每次月结晶 occurrence：

1. 触发目标附近（`12` 米半径、`5` 米高圆柱）没有月笼时，销毁场上旧月笼（若有）并在该目标周围 `3.25` 米半径圆周上等距生成 3 枚新月笼；附近已有月笼时不生成。
2. 追加一条参与者记录到共享累计器。
3. 累计达到 3 条且存在合法谐奏目标时，消费前 3 条并发射谐奏。

月笼是不可移动、无碰撞模型、不占角色岩造物公共上限的岩元素创造物。岩造物干扰生成位置在首切片忽略；投射物阻挡属于当前 Space 模型边界。

月笼超过 9 秒（`540` 帧）没有进行谐奏攻击时销毁：`expires_at_frame = last_harmony_frame + 540`，由 `LunarCageExpiryCoordinator` 原子移除 State 与 Space 实体。三枚月笼一起生成、一起发射，生命周期天然同步。

## 5. 共享累计器与溢出

月结晶累计属于队伍侧机制实例，不按反应目标保存。因为下一次谐奏需要知道被消费的三次月结晶分别有哪些反应参与者，必须保存按 occurrence 顺序排列的记录：

```text
LunarCrystallizeAccumulatorState
├── instance_ref            reaction-state:lunar-crystallize-accumulator:<team_ref>
├── team_ref
├── subject_ref             首个记录的锚点（稳定）
├── pending_records         按 (frame, order, occurrence_ref) 排序，最多 4 层
├── max_layers = 4
└── revision

LunarCrystallizeOccurrenceRecord
├── occurrence_ref / frame / order
└── participant_refs（消费前冻结，去重排序）
```

每次月结晶追加一条记录；超过 4 层时丢弃最旧记录。累计达到 3 条时尝试发射谐奏；受月笼飞行冷却或月笼销毁影响无法发射时，记录继续累计（溢出）。延迟发射消费前 3 条后，剩余 1~2 层记录会让后续只触发 1~2 次月结晶就再次谐奏，直到溢出耗尽。

## 6. 谐奏攻击

谐奏没有独立冷却，只按累计次数触发；每 3 次月结晶触发一轮。

### 6.1 目标与月笼选择

- 谐奏目标为当前受角色攻击的**一个**目标，且必须同时处于三枚月笼的索敌范围（每枚月笼 `12` 米半径、`5` 米高圆柱，Y 差 `≤ 5`）内。
- 候选目标按距月笼集合锚点最近选择，并列时取稳定 subject ref 较小者；目标不要求等于触发月结晶的目标。
- 三枚月笼必须全部未在飞行冷却（`next_attack_frame ≤ frame`）且未到期；否则本次不消费记录，累计溢出。

### 6.2 发射与冷却

每枚月笼发射后进入投射物飞行冷却：`next_attack_frame = fire_frame + 21`（`0.35 秒 × 60`），冷却结束前该月笼不能再攻击。谐奏伤害立即结算（下一 settlement round），不模拟投射物命中延迟；投射物飞行只作为月笼冷却状态。

发射时刷新月笼存活窗口：`last_harmony_frame = fire_frame`、`expires_at_frame = fire_frame + 540`、`attack_index += 1`。

### 6.3 谐奏伤害

只要角色参与了本次谐奏所消费的三次月结晶中的任意一次附着记录，就参与三枚月笼的全部谐奏伤害组分。三枚月笼分别创建独立复合伤害请求：

- 使用同一参与者集合。
- 每个角色组分分别判定暴击。
- 每枚月笼之间重新判定组分暴击。
- 每枚月笼完成各组分计算后独立排序和 `0.60 / 0.30 / 0.05` 加权。

谐奏伤害属于反应月曜伤害，使用月曜生产公式的 `REACTION_COMPOSITE` 模式。当前基线参数：

```text
等级基数：80=1077.4，90=1446.9，95=1561.5，100=1674.8
月曜精通系数 = 6 × EM / (EM + 2000)
反应倍率 = 1.6（采用角色月结晶基线）
伤害元素 = 岩（GEO），可暴击
元素量 = 0，不产生元素附着，不触发后续普通反应
```

谐奏不消费谐奏目标上的元素量。月反应伤害统一不产生元素附着、不携带元素量，角色月曜伤害与反应月曜伤害均适用。

## 7. 当前边界与验收入口

当前边界：

- 正式角色 content 的 capability 绑定仍待角色内容设计；golden case 使用临时 capability 端口。
- 月笼生成半径冻结为 `3.25` 米（资料区间 `3~3.5` 米）；岩造物干扰生成位置未实现。
- 索敌圆柱半径 `12` 米、高 `5` 米按资料冻结；目标与月笼的 Y 差判定使用 `≤ 5`。
- 反应月结晶独立倍率采用角色月结晶基线 `1.6`；独立倍率资料确认前不改变生产注册。
- 月笼投射物阻挡、月笼随机选择的可回放随机协议未进入本切片（当前按距离 + 稳定 ref 确定性选择）。
- 月笼强化和其他角色专属效果属于后续 content/Space 切片。
- 月曜组分继续使用注入式暴击决策；随机选笼、随机选目标或追加攻击的可回放随机协议必须由 Damage/仿真随机基础设施统一定义，不能由月结晶机制自行引入全局随机。
