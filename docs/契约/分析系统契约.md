# 分析系统契约

> 状态：正式规范。
> 本文定义分析系统取数、关系算子、查询计划与节点执行、可读 schema 的契约。
> 最后更新：2026-09-05。

## 1. 术语

- **取数节点**：分析子图的数据入口，按会话组从结果库读出一张基础表；`fetch` 节点以 `source` 切换运行记录（`simulation_runs`）与事件记录（`simulation_events`）。
- **算子节点**：对输入表做纯关系变换的节点（条件筛选、投影、排序、分组聚合、限制行数、连接表、新增计算列、设置列值）。
- **会话组**：会话 ID 的有序去重列表；唯一语义是约束取数节点的行范围，算子节点不感知会话概念。
- **条件组**：过滤节点的结构化条件列表，结构见第 4.1 节。
- **形状**：某节点输出表的列清单（列名 + 类型），由第 5 节规则静态推导。
- **查询计划**：节点清单 + 参数 + 输入关系 + 输出清单的结构化计划，是共享编译核心（形状推导与 CTE 编译）的编译单元，不含任何 SQL 文本；前端按拓扑序逐节点提交执行请求，不再提交整图计划。
- **节点执行请求**：向节点运行时提交单个 `fetch` / 算子的执行请求（`kind` + `params` + 有序输入阶段引用）。
- **阶段**：节点运行时上下文中的可寻址结果（列清单 + 行集 + 截断标记），由节点执行或选择派生产生，可被后续节点引用。

## 2. 节点种类与端口

| kind | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `fetch` | 无（会话组经区域边界注入） | `table` | 按 `source` 读 `simulation_runs` / `simulation_events` |
| `filter` | `table` ×1 | `table` | 条件筛选 |
| `project` | `table` ×1 | `table` | 选列 + 可选重命名 |
| `sort` | `table` ×1 | `table` | 多列排序 |
| `aggregate` | `table` ×1 | `table` | 分组聚合 |
| `limit` | `table` ×1 | `table` | 限制行数 |
| `single` | `table` ×1 | `table` | 获取单行（输出最多一行） |
| `join` | `table` ×2 | `table` | 连接表（inner / left 等值连接） |
| `compute` | `table` ×1 | `table` | 新增计算列 |
| `derive` | `table` ×1 | `table` | 设置列值：新增列，或把同类型输入列改写为指定值 |

- 端口数据语言只有两套：`session_group`（仅区域边界 → 取数节点）与 `table`（其余全部连线）。`single` 是普通表算子，全部视图 `selection` 输出 `table`，单项详情节点消费 0..1 行表；详情数据由[UI API 契约](./ui/UI%20API%20契约.md)第 8 节定义的帧状态与事件详情接口读取。
- 会话维度不是隐式机制：所有源表携带 `session_id` 列，逐场、跨场汇总、跨批对比都是 `session_id` 与普通列上的显式操作。
- 节点参数随工作流定义保存（前端拥有）；算子的参数结构与形状规则是本契约（后端拥有），两端各自实现、靠契约测试对齐。
- 时间轴持续段配对（Buff 施加/移除按实例配对）、区间与曲线等非关系代数逻辑不在当前节点集，留待专门处理节点扩展。

## 3. 取数节点

### 3.1 `fetch`（来源切换）

```json
{
  "source": "runs",
  "snapshot_columns": [
    { "path": "team.0.character.asset_key", "name": "char_1_key", "type": "string" }
  ]
}
```

- `source` 必填：`runs` 读取运行记录（`simulation_runs`），`events` 读取事件记录（`simulation_events`）。来源决定固定输出列与可用参数集合；跨来源参数（如 `source=runs` 携带 `event_types`）校验拒绝。
- 所有具名列与输出列名（提取列 `name`、投影 `as`、聚合 `as` / 自动命名、计算列 `name`）必须匹配 `^[A-Za-z0-9_\u4e00-\u9fff]{1,64}$`（允许中文、字母、数字与下划线，≤64 字符）；列名唯一约束见各算子规则。
- `source = runs` 时：
  - `snapshot_columns` 可省略，会话组是唯一行范围约束。
  - 固定输出列 = `simulation_runs` 全部列（见[结果库契约](./结果库契约.md)第 4.2 节）**除去** `input_snapshot_json` 与 `initial_snapshot_json` 两列（大 JSON 整体不进入分析管道）；类型映射 `TEXT→string`、`INTEGER→int`。
  - `snapshot_columns`（≤ 64 个）从 `input_snapshot_json` 按点分路径提取具名列，规则同事件提取列；成员指标的条件列（变体身份）经此获得，路径清单来自输入快照契约文档（数组下标用数字段，如 `team.0.character.asset_key`；后端兼容方括号形式 `team[0].character.asset_key`）。
- `source = events` 时：

```json
{
  "source": "events",
  "event_types": ["DAMAGE_RESOLVED", "HEALING_RESOLVED"],
  "payload_columns": [
    { "event_type": "DAMAGE_RESOLVED", "path": "result.final_damage", "name": "damage", "type": "float" }
  ]
}
```

  - `event_types` / `payload_columns` 均可省略：`event_types` 缺省为全部事件类型。取数节点只负责「提供哪一种数据」；帧范围等行级筛选由下游过滤算子承担（`frame` 为固定输出列，可在过滤节点按列引用）。
  - 固定输出列：`session_id`、`ordinal`、`frame`、`event_type`，其后依次接提取列。
  - 提取列 ≤ 64 个；每项必填 `event_type`（事件类型名，编辑器来自 schema 目录），`path` 为 `data_json` 内的点分路径；提取按声明事件类型作用域取值——非该事件类型的行该列一律为 `NULL`，同路径字段跨事件类型不会混合；值按声明类型转换，路径缺失或无法转换置 `NULL`；`type ∈ string | int | float | bool`。
  - 提取列的 `event_type` 不在 `event_types` 筛选（缺省为全部时除外）中时，前端校验给 warning：该列整列为 `NULL`。
  - 事件类型名与 payload 字段的稳定性继承结果库契约（类型名冻结、字段只增不改），本契约不重复维护清单；编辑器可选项来自第 6.3 节 schema 端点。

## 4. 表达式语言

### 4.1 条件组（过滤节点参数）

```json
{
  "mode": "all",
  "conditions": [
    { "column": "dps", "op": "gte", "value": 50000 },
    { "column": "weapon_1_key", "op": "in", "value": ["a", "b"] },
    { "column": "end_frame", "op": "is_not_null" }
  ]
}
```

- `mode ∈ all | any`，单层条件列表，不支持嵌套。
- 空条件组（`conditions` 缺省或 `[]`）按恒真语义编译为透传，不报错。
- 操作符白名单：

| 操作符 | 编译形态 | 适用类型 | 备注 |
| --- | --- | --- | --- |
| `eq` | `col = ?` | string / int / float / bool | |
| `ne` | `(col != ? OR col IS NULL)` | 同上 | 采用符合直觉的可空语义 |
| `not_in` | `(col NOT IN (?) OR col IS NULL)` | 同上 | 空数组校验报错 |
| `in` | `col IN (?, ...)` | 同上 | 空数组校验报错 |
| `gt` / `gte` / `lt` / `lte` | `col > ?` 等 | 仅 int / float | 字符串字典序无分析意义，校验拒绝 |
| `is_null` / `is_not_null` | 一元 | 全类型 | 无 `value` 载荷 |

- 文本匹配（LIKE 类）、`between`、正则、列与列比较全部不进白名单。
- 所有字面量以绑定参数执行（prepared statement 语义）；列名必须存在于该节点输入形状中才允许引用。排除明确不做拼接 SQL。

### 4.2 新增计算列表达式（新增计算列节点参数）

```json
{ "name": "dps", "expr": {
  "op": "/",
  "left": { "col": "total_damage" },
  "right": { "op": "/", "left": { "col": "frames_run" }, "right": { "lit": 60 } } } }
```

- `op ∈ + - * /`；叶子只能是 `{ "col": 列名 }` 或 `{ "lit": 数值字面量 }`；深度上限 16。
- `/` 一律按浮点语义执行（不发生整数截断）；除数为 0 结果为 `NULL`。
- 表达式中引用的列必须存在且为数值类型。

## 5. 算子参数与形状推导

每个算子的输出形状由输入形状与参数唯一确定；规则在本节冻结，前端（编辑器与校验）与后端（执行前防御性检查）各自实现同一套推导，不一致的计划以 `400 / validation_failed` 拒绝。

### 5.1 条件筛选 `filter`

- 参数：第 4.1 节条件组。输出形状 = 输入形状。

### 5.2 投影 `project`

```json
{ "columns": [ { "name": "total_damage", "as": "damage" }, { "name": "session_id" } ] }
```

- 输出 = 按列出顺序的子集；`as` 可省略；输出列名不得重复；类型随源列。
- `columns` 至少一列，空数组校验失败。

### 5.3 排序 `sort`

```json
{ "keys": [ { "column": "dps", "direction": "desc" }, { "column": "session_id", "direction": "asc" } ] }
```

- 至少一列；`direction ∈ asc | desc`；输出形状 = 输入形状。

### 5.4 分组聚合 `aggregate`

```json
{
  "group_by": ["session_id"],
  "aggregates": [
    { "fn": "sum", "column": "damage", "as": "sum_damage" }
  ]
}
```

- 聚合函数白名单：`sum` / `count` / `avg` / `max` / `min` / `stddev` / `p95`；除 `count` 外要求源列为数值类型。
- `group_by` 与 `aggregates` 至少提供其一；两者皆空校验失败。
- 输出形状 = 分组列（原名原序）+ 聚合列；聚合列命名：`as` 省略时自动为 `<fn>_<column>`，输出列名不得重复。
- 类型映射：`count → int`；`min / max / sum → 随源列`；`avg / stddev / p95 → float`。
- 语义约定：`count` 为该列非空计数；`stddev` 为**总体标准差**（除以 n）；`p95` 为线性插值分位数；口径以后端实现为唯一真值并配 golden 断言。

### 5.5 限制行数 `limit`

- 参数 `{ "count": n }`，`1 ≤ n ≤ 10000`；输出形状 = 输入形状。

### 5.6 连接表 `join`

```json
{ "left_key": "session_id", "right_key": "session_id", "mode": "left" }
```

- 仅按键等值连接；`mode ∈ inner | left`（左表保留全部行）。多输入口的第一个输入为左表。
- 输出形状 = 左表全部列 + 右表中与左表不重名的列；右表需要保留的重名列应先经投影改名。左连接时右表列补 `NULL`。

### 5.7 新增计算列 `compute`

- 参数：第 4.2 节表达式数组（≥1）；输出形状 = 输入形状 + 计算列（追加在末尾）；表达式列类型恒为 `float`（`+ - *` 在两侧均为 int 时结果为 int）。

### 5.8 设置列值 `derive`

- 参数：`columns`（≥1），每项 `{ "name": 列名, "type": 类型, "value": 字面量 }`；类型限定 `string | int | float | bool`，字面量必须与类型匹配。
- 输出形状 = 输入形状 + 新增列（追加在末尾）；新增列不能与输入列或前列重名。
- 若 `name` 与输入列同名且类型一致，视为把该列整列改写为指定值，不产生重复列。
- 用途：给描述符行补固定角色、帧号或属性聚焦等字段，或把已有列统一改成某个指定值。

### 5.9 获取单行 `single`

- 无参数；输出形状 = 输入形状。
- 语义：输入有行时保留第一行，输入为空时输出空表（0..1 行）；后端编译为 `SELECT * FROM 输入 LIMIT 1`。
- 不承诺行的业务含义；需要稳定定位时由上游 filter/sort 确定行序。

## 6. 节点执行

### 6.1 上限

- 会话组 ≤ 1000（有序去重，超限校验拒绝），经上下文创建注入取数行范围。
- 每张返回表与每个物化阶段硬上限 10000 行，超出置 `truncated: true`；不分页。
- 行数上限在节点运行时逐阶段生效：某阶段被截断后，下游节点消费截断后的行集。

### 6.2 节点运行时接口

节点运行时按阶段执行：前端创建分析阶段上下文，按拓扑序逐节点提交，每个节点输出成为可寻址阶段（stage），阶段保留在上下文中供后续节点引用与前端读取。

- 创建上下文：`POST /api/v1/analysis/runtime/contexts`，请求携带 `session_ids`。
- 单节点执行：`POST /api/v1/analysis/runtime/contexts/{context_id}/nodes/execute`，参数结构与查询计划中的单个 `fetch` / 算子一致，输入为已物化阶段引用。
- 阶段读取：`GET /api/v1/analysis/runtime/contexts/{context_id}/stages/{stage_id}`。
- 分组/行选择派生：`POST /api/v1/analysis/runtime/contexts/{context_id}/stages/{stage_id}/select`（`kind=row` 取单行、`kind=group` 取分组命中行集）。
- 同结构阶段行拼接：`POST /api/v1/analysis/runtime/contexts/{context_id}/merge`。
- 上下文关闭：`DELETE /api/v1/analysis/runtime/contexts/{context_id}`。
- 阶段只存在于运行时上下文，不写入结果库；阶段行集受统一行数上限约束（见第 6.1 节）。

### 6.3 `GET /api/v1/analysis/schema`

取数节点编辑器的可读 schema 数据源：

```json
{
  "tables": {
    "simulation_runs": { "columns": [ { "name": "state", "type": "string", "description": "运行状态", "value_kind": "enum:run_state" } ] }
  },
  "event_types": [
    { "name": "DAMAGE_RESOLVED", "fields": [ { "path": "result.element", "type": "string", "description": "伤害元素", "value_kind": "enum:element" } ] }
  ],
  "snapshot_tree": {
    "key": "root",
    "label": "输入快照",
    "kind": "object",
    "children": [
      { "key": "team", "label": "队伍", "kind": "list", "children": [
        { "key": "character", "label": "角色", "kind": "object", "children": [
          { "key": "asset_key", "label": "资产", "kind": "scalar", "type": "string", "value_kind": "asset:characters", "default_name_template": "char_{0}_key" }
        ] }
      ] }
    ]
  }
}
```

内容来自结果库契约的冻结清单、事件类型文档与输入快照契约，端点只做聚合转发，不另立真值。事件类型清单以 core `EVENT_SPECS` 为真值源完整聚合；payload 字段映射当前只登记已有明确消费需求的事件类型（`DAMAGE_RESOLVED` / `HEALING_RESOLVED` / `BUFF_APPLIED` / `BUFF_REMOVED`），其余事件类型 `fields` 为空，编辑器允许手动填写载荷路径，映射随视图需求登记。`DAMAGE_RESOLVED` 载荷同时包含 `result` 与 `audit`：audit 字段映射随伤害事件详情消费登记，存储载荷见[结果库契约](./结果库契约.md)第 5.3 节。

`snapshot_tree` 是运行记录来源的结构树（镜像《模拟输入契约》第一版字段）：节点 `kind ∈ object | list | scalar`，`object` 为对象节点、`list` 为列表节点（**不枚举位置**，队伍/目标等集合可能是变长）、`scalar` 为可提取叶子；列表叶子经 `default_name_template` 用 `{0}/{1}...` 按列表祖先顺序占位，由前端在用户输入位置后替换（显示 1 基、路径 0 基）。目录外路径（如契约后续新增字段）编辑器仍允许手动填写。

`value_kind` 声明该列 / 字段 / 叶子的**单元格值显示类别**：`asset:characters` / `asset:weapons` / `asset:artifact-sets` 表示值是资产库 `asset_key`（显示名经 `POST /api/v1/assets/resolve` 解析）；`enum:element` / `enum:weapon_type` / `enum:run_state` / `enum:event_type` / `enum:formula_key` 表示封闭词表值（前端按词表翻译）；空串为普通值（按原文显示）。查询计划与结果仍只携带原始值，显示名解析是前端展示层职责，解析失败回退原文，不影响查询与排序。

## 7. 错误语义

- 节点执行请求或参数校验失败：`400 / validation_failed`，`details` 数组逐项给出 `node_id` 与原因码（未知列、类型不匹配、输入数量不符、超限等）。
- 其余沿用仓库通用错误结构。

## 8. golden 断言

- 聚合函数口径（含 `p95` 插值）、`/` 浮点语义与除零置 `NULL`、`ne` 可空展开、形状推导规则，均以后端实现为唯一真值，配最小 golden 用例锁定。

## 9. 稳定性规则

- 节点 `kind`、参数结构、操作符与聚合函数白名单、形状推导规则冻结：只增不改，不改名不改语义；破坏性变更走契约新版本。
- 校验规则（含列名规则）与 schema 响应模型字段只增不改；收紧或变更走契约新版本。
- 事件类型与 payload 字段稳定性继承[结果库契约](./结果库契约.md)，本文不重复声明。
- 对外端点形状是契约；变更走 API 版本升级。
