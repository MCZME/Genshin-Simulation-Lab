# 后续实现计划

> 状态：持续维护的开放任务清单。
> 本文汇总当前已进入实现阶段但尚未闭合的领域后续任务；正式行为、字段与契约以对应架构设计与契约为准，本文不重复稳定真值。
> 最后更新：2026-09-06。

## 1. 文档定位

本文只记录“还需要做什么”，不记录“已经做到什么”；已完成内容由各系统架构/契约与生产代码承载。任务完成或范围关闭后，从本文移除或标记为完成。

通用验收口径：真实内容接入必须走“资产 -> handler_key -> content contribution -> 运行时注入”链路，具备可信来源并由 golden case 复现；测试 content 不代替真实机制完成声明。

本文不维护生产覆盖状态矩阵；各领域当前基线以生产 bootstrap、测试目录与对应架构/契约文档为准。

## 2. 动作系统

1. **解释与决策审计字段**：结构化 reason code 与 evidence 如何进入动作解释/决策审计；正式字段落地前 `reason` 保持字符串，不得把中文显示文本作为机器判断依据。
2. **动作领域事件类型与 payload**：动作解释结果、动作决策与动作生命周期的最终事件类型与载荷待确认。
3. **`action_state` 快照协议**：快照序列化结构与恢复边界待确认，纳入结果还原链路。
4. **真实角色 action 清单**：具体角色 `action_key`、控制命令与参数 schema 随真实角色 content 接入确定。
5. **下落攻击精确数值**：低空/高空分档与重力时序仍为临时值，需可信来源后锁定；二维 Box / 扇形 AOE 随真实范围技能接入补齐。
6. **MovementSystem 第二位移来源**：出现击退、投射物或敌人移动等第二个位移来源时再扩展，不在当前契约内提前搭建。
7. **同帧机制结算顺序**：多个机制请求同帧出现时的结算顺序按真实角色能力需求确认。
8. **冷却写路径扩展**：冷却开始帧之外的减秒、重置、多充能消费等写路径按真实能力逐项接线。
9. **停止条件协作校验**：停止条件与运行中空间对象、待处理机制请求之间的最终协作校验。
10. **动作能力扩展评估**：多影响点之外的动态参数、多阶段时间线等动作能力按真实角色需求逐项评估，不提前预建。

## 3. 属性系统

1. **真实内容属性 golden case**：真实角色、武器、圣遗物与队伍共鸣等属性链路（资产基础值、静态 modifier、运行期 provider）需可信来源与 golden case 锁定；当前 Buff 工程闭环使用测试 content 验证，不代表真实游戏机制数值完成。
2. **跨顶层缓存与 revision token**：第一版只实现 session 内 memo；只有性能数据证明必要时再引入跨顶层缓存。
3. **属性快照与审计持久化**：属性快照、审计结果的结果库 schema 与读取协议待后续结果侧接入时确定。
4. **属性消费契约**：伤害、治疗、反应等系统消费属性查询的正式口径随各系统真实能力接入登记；已消费侧（如生命值查询 `stat.hp.max`）以对应契约为准。
5. **UI 属性面板**：面板展示与审计需求确认后按前端工程推进。

## 4. 战场空间

1. **非圆形状边界语义**：CircleSector 与定向 Box 的稳定边界包含、排序与数值容差，以及胶囊范围，待具体机制提出需求后评审并锁定契约。
2. **空间快照与结果库接入**：空间状态如何进入快照与结果库、按帧还原范围待结果存储侧确定。
3. **创建物参与默认候选**：内容创建空间实体是否参与某些动作的默认候选解析，随真实动作需求确认。

## 5. 批处理调度

1. **细粒度运行中取消**：在仿真帧循环引入可选的取消检查协议（每 N 帧或按阶段检查）；协议定义保持在 application 与 core 的边界层，不把调度或 UI 细节渗入 `core/`。
2. **细粒度进度回传**：逐帧进度、实时事件流与 UI 回放后置；当前展示粒度即成员状态。

## 6. 按键输入

1. **输入会话持久化**：输入会话在快照与结果库中的持久化格式、还原与读取规则待结果侧确定。
2. **CANCEL 回调语义**：解释器 CANCEL 触发当前只保留枚举与契约位置；是否启用回调、payload 与审计规则待真实角色或机制需求确认。
3. **输入扩展契约**：自定义键位、手柄、移动与视角输入的扩展契约在对应能力进入前定义。

## 7. 日志系统

1. **批量任务 worker 日志**：多进程批量任务运行时，为 worker 提供独立日志文件并定义命名与关联约定（当前过渡策略为主进程记录任务状态、worker 只记录简要边界）。
2. **UI 日志能力**：UI 方案确定后补充默认日志目录、默认启用与“导出诊断日志”能力。
3. **清理参数校准**：日志清理参数（保留天数、文件数上限）按真实运行实测校准。

## 8. 结果存储

1. **事件流文件化归档**：单次运行超限（写时判定）、结果库总体积超限（存量归档）、批量 / 长仿真模式（按模式判定）的归档实现；阈值参数化，待实测校准。
2. **批量扫描事件直写**：批量 / 长仿真场景下事件直写文件模式与结果、任务关联规则。
3. **检查点快照**：仅当“任意帧查询”性能需要时建立，作为可重建物化，不改变真值层。
4. **任务状态持久化**：由任务系统独立实现，结果侧不立项。

## 9. 治疗

1. **范围治疗与多目标展开**：范围治疗的目标展开规则尚未定型。前置：真实角色范围治疗能力或独立规则评审。验收：范围治疗从运行时请求进入治疗 handler 并完成生命提交的纵向链路，且有可信来源 golden case。
2. **更多真实角色治疗 content**：接入更多真实角色治疗能力。验收：每个能力具备可信来源、真实资产链路与 golden case。
3. **治疗快照、生命之契与生存状态**：按后续需求单独评审。

## 10. 生命值

1. **真实角色生命消耗最小可复现案例**：需要可信来源。验收：golden case 可复现。
2. **角色生存状态机**：确有动作、复活或战斗结束需求时单独评审。

## 11. 护盾

1. **真实 Buff golden case（收尾）**：因缺少可信资料待补充；测试 content 不代表真实机制完成。
2. **Buff 与护盾共享评审**：基于两者实际实现比较身份、生命周期与提交不变量，不只比较字段名称；只有存在相同且稳定的不变量才提取中立原语，否则保持领域实现独立。
3. **触发与后续命令**：真实触发型内容接入前评审同帧后续命令队列、稳定排序键、结算轮次、最大轮次与循环检测、事实到后续命令的 adapter、未来帧工作与仿真终止条件。
4. **真实护盾 content**：选择一个规则简单、资料充分的真实角色护盾，打通资产与 handler_key 到创建、承伤、事件与结果持久化的完整链路。验收：使用真实资产输入；创建公式中间量与最终原生容量可审计；切换场上角色后动态护盾强效正确；刷新/替换/过期与来源一致；handler 缺失或数据错误在组装阶段失败；至少一个可复现的创建与承伤 golden case。
5. **领域迁移收尾**：完成领域聚合与角色受伤协调器迁移后的剩余一致性校验；ShieldRemovalReason `owner_removed` 命名评审。
6. **结晶物理拾取流程**：结晶晶片的物理碰撞、距离与实际拾取资格流程。
7. **护盾存在查询与抗打断**：护盾存在查询、抗打断贡献等能力待正式抗打断系统设计后接入。

暂缓范围：正式抗打断、韧性与击退系统；联机和多队伍保护；队伍/角色移除时的护盾领域清理命令；专用护盾结果投影与 analysis 模型；UI 有效盾量展示；护盾 grant 策略固化到组装期定义。

## 12. 元素反应

1. **正式角色 content 的 capability 接入**：角色 Content 设计稳定后，把正式 capability provider 接入 assembler，并验证真实角色绑定。
2. **月反应角色技能入口**：接入角色技能对草露的消费与 `CHARACTER_DIRECT` 月曜伤害入口（月绽放）；按需补充月感电所需的跨目标贡献读取。前置：角色 Content 设计稳定。
3. **精确数值待确认项**：随角色 content 推进，继续按对应反应契约的“当前边界/非目标”核对，不在本文重复记录。

## 13. 分析区域

1. **表达式类派生（非字面量）**：当前 `derive` 覆盖列值改写，表达式类派生为后续扩展。

## 14. UI 画布与区域

1. **性能目标与节点规模基准**：画布与分析区域的性能目标、节点规模基准待实际负载验证后确定。
2. **分析能力扩展设计**：状态曲线、自定义指标、导出节点与多结果对比等分析能力的设计待消费需求确认。
3. **资产筛选**：资产选择器按资产类型、来源、可用性等条件的筛选能力后续扩展。
4. **连线手动路径调整**：画布连线当前为自动布线，手动路径调整待产品需要时实现。

## 15. 冷却系统

1. **冷却事实接入公共事件与结果库**：`COOLDOWN_CHANGED` 载荷、事件语义与结果库持久化已按当前实现落地；后续新增冷却事实类别或字段需同步契约与事件类型文档。
2. **Impact / 后续命令队列适配冷却 mutation**：真实触发型内容（如减 CD、重置、临时获得次数）接入时，定义 Impact 或后续命令到 `ReduceRemainingCooldownRequest` / `ResetActiveCooldownRequest` 的适配与阶段。
3. **剩余冷却与仿真停止条件**：确认剩余冷却是否影响整体仿真停止条件及与动作、机制任务的协作校验。
4. **临时获得次数并无视 CD 命令**：魈 C6 等“临时获得次数并无视 CD”语义不能用普通 reset 近似，待真实角色 content 需求确认后单独设计命令。

## 16. 伤害系统

1. **`DamageRequest.tags` 主 / 附加标签独立**：恢复独立字段后再明确 request 层主次语义，同步契约与审计序列化。
2. **`strike_type` / `range_type` 审计边界**：当前由 Impact 与 Reaction 消费，尚未进入单目标请求与 `DAMAGE_RESOLVED` 审计；如需要显式增加字段。
3. **伤害属性快照契约**：独立、显式的伤害属性快照尚未设计，不能复用目标选择快照字段；由需要快照的真实机制驱动。
4. **直接伤害 golden case**：直接伤害回归待正式契约来源重新建立。
5. **随机暴击与回放**：生产环境带种子随机 `CriticalDecisionProvider` 与回放契约尚未确认；当前仅注入式固定决策。
6. **动态伤害 provider 接入**：Buff 等领域运行时的活动实例向伤害索引暴露只读 provider 查询接口，随动态机制消费需求接入。

## 17. 状态效果（Buff）

1. **真实 Buff 全生命周期 golden case**：从真实资产出发，覆盖「真实 Buff 全生命周期 + 属性查询 + 事件 + 覆盖区间」的独立 golden case；测试夹具与开发者测试内容不代替真实机制覆盖。
2. **驱散 / 免疫规则**：驱散类别、不可驱散与免疫规则待真实驱散机制需求确认；驱散类移除接入状态效果最大生命协调器的显式移除路径。
3. **每层独立期限与部分层消费**：当前为单记录统一期限模型；需要独立层期限或部分层消费的机制出现时单独设计。
4. **动态作用域记录**：始终跟随当前场上角色的动态作用域需先评审窄 active-character scope reader，或在切换事实后按稳定规则迁移状态。
5. **Buff 覆盖投影**：覆盖区间投影（半开区间并集）随 analysis 曲线 / 状态视图消费需求实现。

## 18. 内容

1. **generic 第一批正式能力名单**：普攻、重击、天赋等级、命座各自的最小通用骨架，以及武器、圣遗物侧通用构成如何与角色侧并列设计。前置：角色 Content 设计稳定。
2. **资产参数进入 content 的编译细则**：天赋倍率、CD、能量等参数编译到哪一层，哪些必须在 factory 期冻结，角色私有参数与通用参数的表达方式。
3. **武器/圣遗物内容状态的宿主形态**：挂在角色下含所有权限制，还是各自运行时对象。
4. **event_hook 进入正式 content 的分工**：允许的 hook 模式与领域强类型命令/Buff 的分工继续按真实需求收敛。
5. **解释器状态与可快照性**：哪些必须进入内容状态、哪些允许留在 interpreter 临时字段，以及与快照 provider 的验收关系。
6. **运行期接线遗留**：`PredicateContext.facts` 事实过滤谓词、`has_buff` 默认端口与 `modifier_commands` 意图直出。
