# 战场空间设计

> 状态：正式规范。
> 本文描述 `core/space` 战场空间：它保存场上的轻量空间实体并提供 X/Z 范围查询，供动作索敌与伤害 AOE 获取候选；包括实体模型、创建对象与目标协作、查询边界和模块组织。
> 最后更新：2026-09-05。

## 1. 定位与目标

`Space` 用于描述一次仿真中的战场空间实体，回答“某个位置附近有哪些候选空间实体”。

职责：

- 保存当前场上角色、多个目标点位和内容创建的带生命周期空间实体。
- 提供 X/Z 平面的 Circle、CircleSector 与定向 Box 范围查询。
- 支持按实体类型、生命周期和排除列表过滤查询结果。
- 为动作层提供候选空间实体 id，供索敌与伤害 AOE 展开。

非目标：

- 真实 3D 物理、刚体碰撞、目标挤压、复杂敌人体型与多 hitbox。
- 真实索敌优先级。
- 命中、伤害、反应或元素附着结算。
- 内容创建对象的 tick 行为或机制结算逻辑。

## 2. 空间实体

`Space` 统一保存轻量空间实体：

```text
SpatialEntity
├── entity_id
├── kind
├── position
├── lifecycle
├── collision_box
├── facing
├── active_slot
├── owner_key
├── source_key
└── tags
```

实体类型：

```text
ACTIVE_CHARACTER
TARGET
CREATED_OBJECT
REACTION_OBJECT
```

`Space` 只保存空间实体与查询所需的通用字段。角色、目标、内容创建对象等复杂战斗状态由对应领域运行态持有；`SpatialEntity.lifecycle` 复用 `core/entity_states` 的通用生命周期值对象，`collision_box` 默认圆柱（底半径 0.5、高 1.0），`position.y` 视为实体基座高度。当前命中判定只使用 X/Z，碰撞箱高度保留给下落攻击等高度敏感机制。

位置写入口由 `MovementSystem` 独占：`SpaceRuntime.apply_displacement` 只供 Movement 领域写入实体位置，动作不再直接修改空间实体位置，需要位移时通过 `ImpactKind.MOVEMENT` 意图表达。

`REACTION_OBJECT` 不属于 `CreatedObjectRuntime`，也不获得 Target、Damage 或 Aura capability；它只表示由 Reaction State 拥有机制语义、由 Space 拥有位置和活动投影的实体。

## 3. 当前场上角色与目标

### 3.1 当前场上角色

只创建一个当前场上角色空间实体：

```text
entity_id = "player:active"
kind = ACTIVE_CHARACTER
active_slot = 当前场上槽位
```

后台角色默认没有独立空间实体。切人时不创建新位置，也不为后台角色保留单独位置；切人成功后同步 `player:active.active_slot`。

完整角色运行态由 `CharacterRuntimeState` 表示，归 `TeamRuntimeState` 持有。角色的属性、能量、技能状态、Buff、动作状态等不进入 `Space`；`CharacterRuntimeState.combat_entity_id` 是角色战斗身份，`Space` 中的 `player:active` 是当前场上角色空间实体，两者通过 `active_slot` 关联。

### 3.2 目标点位

配置中的多个 `scene.targets` 在组装阶段映射为空间实体：

```text
entity_id = "target:<target_id>"
kind = TARGET
position = scene.targets[].position
```

目标的等级、抗性等战斗参数不属于 `Space`，由 `TargetRuntimeState` 保存，并由 `TargetRuntimeCollection` 管理多个目标。`SpaceRuntime` 直接持有该集合，用于把空间候选实体解析成目标运行态引用。`TargetRuntimeState.spatial_entity_id` 默认使用 `target:<target_id>`。

## 4. 内容创建空间实体

动作影响通过 `ImpactRequest(kind=create_entity)` 请求创建内容定义的空间实体。该链路不引入独立 `summons` 模块：游戏语义上的召唤物、场地物或临时造物只要存在于战场空间中，都按带生命周期的空间实体处理。

```text
ActionImpactPoint
-> ImpactRequest(kind=create_entity)
-> ImpactRequestDispatcher 转交 CreatedObjectRuntime
-> CreatedObjectRuntime 创建或刷新 CreatedObjectRuntimeState
-> CreatedObjectRuntime 通过 SpaceRuntime 将 state.entity 同步到 Space
```

`CreatedObjectRuntime` 负责对象创建、刷新、实例数量上限、生命周期过期、时长延长与 tick 请求生成；它由 `SpaceRuntime` 持有。`Space` 只负责登记空间实体，并在查询时按当前帧过滤未创建或已过期实体。对象身份（`object_key`、`behavior_key`、tick 间隔）与对象参数保存在 `CreatedObjectRuntimeState`，不进入 `Space`。

无空间位置、不参与空间查询的持续逻辑不应放入 `Space` 或 `CreatedObjectRuntime`，应归机制、状态或 hook 处理。

## 5. 与动作系统的协作

`SpaceRuntime` 是空间运行态的直接入口，持有：

- `Space`：空间实体、生命周期过滤与范围查询。
- `TeamRuntimeState`：`player:active` 对应的队伍共享角色运行态引用。
- `TargetRuntimeCollection`：多个目标运行态集合。
- `CreatedObjectRuntime`：内容创建空间实体的运行态。

`SpaceRuntime` 不按 `(actor_entity_id, action_key)` 消费普通动作实例。动作实例由 `ActionManager` 拥有；需要空间查询、位置同步或创建空间对象时，Action 或机制请求通过 `SpaceRuntime` 的受控接口协作。切人由 `TeamSwitchAction` 实例执行：

```text
TeamSwitchAction.on_start()
-> TeamRuntimeState.switch_to(target_slot)
-> SpaceRuntime.update_active_character_slot(active_slot)
```

`SpaceRuntime` 不判断切人是否允许，也不持有切人动作生命周期。

## 6. 配置映射

`scene.player` 描述当前场上角色的初始空间实体：

```json
{
  "player": {
    "position": { "x": 0, "y": 0, "z": 0 },
    "facing": { "x": 0, "y": 0, "z": 1 }
  }
}
```

省略 `scene.player` 时默认位置 `(0, 0, 0)`、朝向 `(0, 0, 1)`。

`scene.targets` 描述多目标战场：

```json
{
  "targets": [
    {
      "id": "target_1",
      "level": 90,
      "position": { "x": 0, "y": 0, "z": 5 },
      "resistance": {}
    }
  ]
}
```

内容创建空间实体不直接写入 `scene`；它们由运行期 `create_entity` 请求创建并同步到 `Space`。

## 7. 查询语义

普通范围查询只使用 X/Z 平面：

```text
distance_xz(query_center, entity.position) <= radius
```

`position.y` 可以保留在空间实体记录中，但不参与命中判定。统一 Damage Impact 的二维 AOE 语义提供 `OrientedBox` / `Circle` / `CircleSector`：Box 使用完整边长、Circle/Sector 使用半径与圆心角，Sphere 与圆柱在 X/Z 模型中投影为同半径圆，高度不参与查询；本地偏移与朝向随索敌确定的攻击方向旋转。

`entities_in_radius` 转换为 `CircleArea` 查询；`entities_in_area` 按排除列表、生命周期、实体类型与形状包含过滤：

```text
entity_id 不在 exclude_entity_ids
entity.lifecycle 在 Space 当前帧处于 active
kinds 为空或 entity.kind 属于 kinds
area.contains(entity.position)
```

查询只返回满足几何与类型过滤的候选空间实体；Impact 在冻结目标集合后形成最终目标级 interaction：

```text
Action targeting query
-> 瞄准目标与攻击方向
-> Damage Impact AOE query
-> candidate targets
-> 冻结 target interactions
-> 元素与伤害结算
```

`ActionImpactPoint` 的 `TargetingSpec` 只负责索敌、选择瞄准目标和确定攻击方向，不等同于 Damage Impact 的实际 AOE。实际受击目标在 Impact 到期时由 AOE 重新查询并冻结。`CREATED_OBJECT` 与 `REACTION_OBJECT` 可以按空间实体类型查询，但不会自动成为目标运行态引用。

空间实体如何转换为可结算目标，由消费侧按窄端口/规则处理（如元素反应的候选资格转换），不通过 Space 猜测阵营、关系或 capability；通用 Space 容器只返回几何候选。

## 8. 跨领域实体变更

跨领域需要原子提交的空间实体变更（如反应对象的创建与到期）走 `SpaceEntityMutationPlan`：

- 计划只支持实体创建与删除，同一 id 不能同时出现在两类变更中；移动或任意 update 不进计划。
- 计划携带帧、预期实体 version 与 operation id；validate 无副作用，commit 只替换内存投影，不查询、不计算、不回调、不发布事实。
- 非空计划只增加一次实体 version；直接 add / update / remove 的真实变更也走同一 version，避免绕过 stale 检查。
- `SpaceSnapshot` 保存帧、实体 version 与按 `entity_id` 稳定排序的实体，不保存反应真值或内容状态。

## 9. 模块边界

`core/space` 属于纯核心运行时。

允许：

- 依赖 `core` 内部纯数据结构，复用 `core/entity_states` 的通用生命周期值对象。
- 作为 `SimulationContext.space_runtime` 挂载，并按帧推进当前查询帧。
- 持有 `TargetRuntimeCollection` 并提供目标运行态解析。
- 持有 `CreatedObjectRuntime` 并同步内容创建空间实体。

禁止：

- 依赖 `assets`、`content`、`application` 或访问 SQLite / 文件系统。
- 持有武器、圣遗物、结果库对象或内容层贡献对象。
- 持有内容创建对象的 tick 行为、机制结算逻辑或内容专属状态。
- 定义具体原神机制或直接结算伤害、治疗、反应、Buff。

## 10. 代码组织

```text
core/space/
├── geometry.py         # Vector3、CircleArea、CircleSectorArea、OrientedBoxArea、ImpactAreaSpec
├── entities.py         # SpatialEntityKind、SpatialEntity、CollisionBox
├── errors.py           # 空间实体计划冲突错误
├── mutations.py        # SpaceEntityMutationPlan、SpaceEntityCommitReceipt
├── snapshots.py        # SpaceSnapshot
├── created_objects.py  # CreatedObjectRuntime、CreatedObjectRuntimeState 等
├── runtime.py          # SpaceRuntime：运行态持有与受控同步接口
├── space.py            # Space 容器与查询、SpaceEntityMutationPlanner
└── __init__.py         # 对外导出稳定入口
```

外部模块优先从 `genshin_sim.core.space` 导入公开类型，不直接依赖具体文件路径。
