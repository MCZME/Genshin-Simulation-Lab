# 设计系统

> 状态：正式规范。
> 最后更新：2026-10-13。
> 本文规定前端 UI 的视觉语言与组件规范：设计令牌、色彩语义、排版阶梯、图标与组件状态。产品形态与交互规则见[画布设计](./画布设计.md)及各区域设计，工程边界见[前端工程规范](../../工程/前端工程规范.md)。

## 1. 令牌架构与单一事实源

- 唯一事实源是 `frontend/src/theme/tokens.ts`（TypeScript，供组件引用）。
- `frontend/src/theme/tokens.css` 是令牌的 CSS 自定义属性镜像（`:root`，供样式表引用）；`frontend/src/theme/tokens.test.ts` 断言两侧完全一致——无缺失、无多余、无漂移，改动任何一侧而不同步即测试失败。
- 消费规则：样式与组件只允许引用令牌，不得硬编码新色值、字号、圆角与阴影；新增视觉语义必须先加令牌，再在两侧同步。
- 分层：当前直接落地语义层（表面/文本、交互、过程色、身份色、间距、排版、圆角、阴影、层级）；不单独维护原色层，语义值即唯一定义。
- 暗色是当前唯一模式。令牌按语义角色命名（如 `panel` / `text` / `severity`），不按亮暗命名，为将来多模式预留。
- `app.css` 全量令牌化；经评估有意保留的存量字面量登记在 §4 保留清单，不得新增。

## 2. 色彩

色彩分两个 band，规则见 2.5：

| Band | 令牌 | 含义 |
| --- | --- | --- |
| 过程色 | `severity` / `status` / `selection` | 严重度、运行状态、选择语义 |
| 身份色 | `nodeCategory` / `region` / `element` / `fallback` | 对象身份（节点类别、区域、元素、未知回落） |

### 2.2 交互色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `accent` | `#38bdf8` | 品牌/交互强调：焦点环、数据端口、品牌标识、连线高亮 |

### 2.5 色彩硬规则

1. 身份 band 与过程 band 不共享精确色值（`tokens.test.ts` 断言，新增任一侧色值都会触发检查）。
2. 同一 band 内允许语义复用：`status.running` 与 `severity.info` 同为蓝、`selection` 与 `warningText` 同为琥珀，属有意的过程语义复用。
3. 状态不得只依赖颜色：错误、警告、运行中、选中等状态必须同时提供图标、文本或图形标识（前端工程规范 6.5）。
4. 身份色只作身份标识（类别色带、区域描边、拖拽预览、小地图），不得用于表达状态或严重度。
5. 半透明叠加层（焦点环、悬停光晕、条纹纹理、渐变过渡、氛围层）允许 `rgba()` 字面量，但基色必须从令牌派生。
6. 领域装饰色（资产稀有度金、暴击/层数琥珀、正向增益绿、验证状态徽标）不属于两个 band，允许保留字面量，但须在 §4 保留清单登记；纳入令牌体系前排期统一。
7. 表格最大/最小高亮定向：`hl-max` 取 `selection` 琥珀系（与暴击高光同族的「庆祝」语义），`hl-min` 取中性冷灰（`fillNeutral` 16% 底 + `textMuted`）。最小值禁用 `severity.error` 红——红色会被读成异常而非「最小值」；高亮同时加重字重，不只依赖颜色（规则 3）。

## 3. 字体与排版

字体栈沿用 `FONT.body`（`"Segoe UI", "Microsoft YaHei", system-ui, sans-serif`）与 `FONT.mono`（等宽，用于数值、路径、按键、哈希）。

| 阶梯 | 值 | 用途 |
| --- | --- | --- |
| `caption` | 11px / 行高 1.4 | 徽标、刻度、辅助说明（全局字号下限） |
| `bodySmall` | 12px / 行高 1.4 | 密集界面正文（节点编辑器、面板列表） |
| `body` | 13px / 行高 1.5 | 默认界面正文、卡标题 |
| `title` | 14px / 行高 1.4 | 分区标题、顶栏控件 |
| `heading` | 16px / 行高 1.5 | 弹窗标题、空态标题 |
| `display` | 20px / 行高 1.5 | 空态主标题 |

规则：

- 禁止 9px / 10px 字号；11px 仅用于徽标与刻度。
- 数值、路径、按键、指纹等等宽内容用 `FONT.mono` 并开启 `font-variant-numeric: tabular-nums`，保证列对齐；运行中会变动的数值（批次计数、组徽标、伤害乘法链、进度计数）同样开启。
- 标题字重用 600；仅顶栏品牌标识可用 700。
- 中文正文不斜体；强调用字重或颜色，不用斜体。

## 4. 间距、圆角、阴影、层级

间距（4px 基网）：`xs` 4（图标与文字间距）、`sm` 8（卡内分组）、`md` 12（卡内区块、列表项）、`lg` 16（面板留白）、`xl` 24（页面分区）。

圆角四档，层级递增：`control` 4（按钮、字段、徽标）< `overlay` 6（下拉、浮层）< `card` 8（节点卡、工具面板）< `container` 12（区域框、弹窗）。

阴影三级：`card`（节点卡，`0 4px 12px rgba(0,0,0,.35)`）< `overlay`（下拉、菜单，`0 8px 24px rgba(0,0,0,.45)`）< `modal`（弹窗、拖拽幽灵，`0 16px 48px rgba(0,0,0,.5)`）。浮层阴影只表达「浮起」，不表达选中；选中一律用 2.2 的焦点/选中环。

层级（样式禁止魔法数）：`toolPanel` 20 < `dropdown` / `resizeHandle` 30 < `popover` 40 < `dragGhost` 50 < `modal` 100。

| 领域装饰色 | `#fbbf24` ×6（稀有度/暴击/层数）、`#4ade80` ×2（正向值）、`#7dd3fc` ×3 / `#93c5fd` / `#bfdbfe`（浅蓝强调）、`#bbf7d0` / `#86efac`（浅绿）、`#8fa3bd`（弱化值）、`#34d399` / `#38bdf8`（验证状态徽标） | 见 2.5 规则 6，待纳入令牌体系 |

## 5. 图标

选型标准：线性风格、24 网格、1.5px 描边、圆角线帽、单色 `currentColor`；许可证可商用；支持按需引入。

选型结论：**Tabler Icons**（`@tabler/icons-react` 3.49.0，MIT，Copyright (c) 2020-2026 Paweł Kuna），引入前经人工确认，许可证结论见[前端工程规范](../../工程/前端工程规范.md)第 2 节。引入层为 `frontend/src/components/common/icons.tsx`：锁定 1.5px 描边与 16px 控件默认尺寸，包声明 `sideEffects: false`，命名引入可 tree-shake；行内 caret 与表头指示 12px，侧轨 20px，在调用点显式传 `size`。字符图标已全量替换；`×N` 计数与伤害公式中的 `×` 是文本不是图标，保留。

节点类别 → 图标映射（节点卡当前用类别色圆点 + 顶部 3px 类别色带，图标映射表预留给注册表元数据）：

| 类别 | 图标语义 | 类别 | 图标语义 |
| --- | --- | --- | --- |
| 运行设置 | sliders 滑块 | 数据获取 | database 数据库 |
| 队伍配置 | users 队伍 | 数据加工 | filter 过滤 |
| 目标配置 | crosshair 目标 | 展示配置 | palette 配置 |
| 操作输入 | keyboard 键盘 | 展示视图 | table 表格 |
| 参数扫描 | scan 扫描 | 单项详情 | file-search 检索 |
| 模拟执行 | play 运行 | | |

Shell 图标映射：保存 save、全部运行 play、撤销 undo、重做 redo、设置 settings、删除 trash、重命名 pencil、切换工作流 chevron-down、新建 plus、刷新 refresh。

规则：控件内图标 16px，顶栏与侧轨 20px；纯图标按钮必须配 `aria-label` 或 tooltip；禁止再引入 emoji 作功能图标。

## 6. 组件规范

### 6.1 原语清单

| 原语 | 位置 | 说明 |
| --- | --- | --- |
| 按钮 | `app.css` `.action-button` / `.text-button` / `.icon-button` | 主操作 / 文字 / 图标三型 + danger 变体 |
| 字段 | `components/common/fields.tsx` | 文本、数值（点击显编辑、滑块变体）、下拉、复选 |
| 徽标 | `app.css` `.node-output-badge` 等 | 严重度、状态、类别圆点、草稿、组计数、数据语言 |
| 浮层 | `.asset-dropdown` / `.workflow-menu` 等 | 下拉、菜单、popover，统一 `overlay` 圆角与阴影 |
| 进度 | 模拟节点卡批次监控 | 分段进度条按 `status` 着色，配计数行文本 |
| 连线 | `app.css` `.react-flow__edge` | 见 6.4 |
| 氛围层 | `app.css` `.canvas-atmosphere` | 见 6.4 |
| 空态 | `app.css` `.canvas-empty` 等 | 画布空态见 6.3；面板内空态同 6.3 规范 |
| 表格 | 结果面板、视图节点 | 表头 12px `textMuted`，数值列右对齐等宽 |

### 6.2 状态矩阵

每个原语都必须有，禁止只做 default：

| 状态 | 期望表现 |
| --- | --- |
| default | 第 2.1/2.2 节令牌值 |
| hover | 描边 `borderStrong`，或表面 `panelRaised` |
| active | 表面 `panelRaised` + 描边 `accent` |
| focus-visible | 1px `accent` 描边外环（见 2.2） |
| disabled | 透明度 0.5，`cursor: not-allowed` |
| invalid | 描边 `severity.error` + 行内错误文本（`errorTextStrong`） |
| loading | 按钮文案后加「…」并禁用，不做全局遮罩 |

### 6.3 空态规范

空态由图标（或类别圆点）+ 一句中文说明 + 一个主操作按钮构成；禁止只有一句灰字。

画布空态（无区域且无节点时）：「拖入区域开始」+「从左侧对象面板拖入」+ 配置 → 模拟 → 分析三阶段 chips（圆点取区域色与模拟节点类别色）；纯文字引导，不放置位插画。

### 6.4 画布视觉规范

节点卡：`panel` 底 + 1px `border` 描边 + `card` 圆角与阴影；顶部 3px 类别色带（`--node-category` 驱动 `::before`，取色规则见 2.4）；头部 36px 承载类别圆点、标题、输出徽标、草稿徽标与删除按钮（悬停显示）；底部承载输入顺序、成员投影、组计数与端口。

节点卡状态：

| 状态 | 表现 |
| --- | --- |
| 选中 | 2px `accent` 外环（`box-shadow`） |
| 草稿（区域外游离） | 虚线边框 + 「草稿」徽标 |
| 运行未参与（dimmed） | 透明度 0.45 + `saturate(0.4)` |
| 构建推进中（step-running） | `accent` 描边 + 呼吸环 + 抬升层级 |

视图节点（表格/饼图/柱状图）与可调宽节点（伤害详情、角色状态详情、按键轨迹）悬停/选中时宽高手柄常驻；尺寸语义见各视图设计与 D-046。

连线：默认降噪（`fillNeutral` 50% 透明度、1.5px）、悬停提亮 `accent`、选中 `accent`、运行中 `status.running` + dash 流动、未参与运行置灰（18% 透明度）；经 `--xy-edge-stroke` 派生变量整体换色，路径与箭头同步。组输出连线携带 `×N` 标签（`caption` / mono / `textMuted`）。跨区域连线只连接区域边界端口与画布级源节点（配置区域设计 §2）。

氛围层：视口固定的区域色低透明度径向微光（配置蓝 12% / 分析紫 9%），纯装饰不接收指针事件；点阵网格（24px）由 React Flow Background 承担。

区域：2px 区域色描边 + `container` 圆角 + 半透明面板底；顶栏 32px 可拖动；最小 400×240，不可折叠；缩放手柄选中时常驻。

小地图：右下角，可平移缩放；深色半透明底 + `card` 圆角边框；节点填类别色/区域色并加深色描边分隔；视口矩形用 `accent` 描边，非可见区深色遮罩。

拖拽落点：合法目标（同类区域）显示 `accent` 虚线 outline + 内发光；错误类型区域（区域归属类节点拖到异类区域，如配置节点到分析区域）显示 `severity.error` 虚线 outline 劝阻；画布级节点与新建区域不参与劝阻判定。拖拽预览为跟手幽灵（`dragGhost` 层级）。

执行轨迹着色（D-028）：运行期间节点按步骤状态着色（等待/应用中/已应用/跳过），运行中对象的连线高亮，未参与本次运行的对象（游离草稿、未连接区域）置灰，执行路径一眼可辨。模拟节点批次监控（D-029）：状态徽章 + 计数行 + 按成员状态着色的分段进度条。

### 6.5 动效规范

- 节点卡与区域禁用 `transform` 位移/缩放类效果：连线锚点定位于节点边界，位移会扯断连线。
- 动效只作用于 `stroke`、`box-shadow`、`opacity`、`background`、`stroke-dashoffset`、`color`，不得改变任何元素的几何位置与尺寸。
- 现行动效：进度条 running 段微光（1.6s 循环）、构建推进呼吸环（1.2s 循环）、批次完成徽章脉冲（640ms 一次性）、连线 dash 流动（库内 0.5s 循环）。
- `prefers-reduced-motion: reduce` 时全部动效关闭。
