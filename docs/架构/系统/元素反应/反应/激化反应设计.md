# 激化反应设计

> 状态：已实现
> 最后更新：2026-08-02
> 对应契约：[激化反应契约](../../../../契约/元素反应/反应/激化反应契约.md)

## 1. 定位

激化是一个共享激元素状态的机制簇，包含三个 Reaction Definition：

- 原激化 `Quicken`：消耗普通草/雷并建立或覆盖 `QUICKEN` Aura；
- 超激化 `Aggravate`：雷命中活动激元素时，为当前合格雷伤害增加基础伤害；
- 蔓激化 `Spread`：草命中活动激元素时，为当前合格草伤害增加基础伤害。

原激化、超激化和蔓激化不能拆成互相调用的机制目录：三者读取同一次交互的元素投影，原激化拥有激元素生命周期，两个附加反应只拥有当前 Impact 调整。实现位于 `core/systems/reaction/mechanics/catalyze/`。

## 2. 领域所有权

| 领域 | 激化相关职责 |
| --- | --- |
| Reaction | 元素签名、消费关系、`QuickenState`、覆盖决策、附加反应资格和当前 Impact 调整 |
| Aura | `QUICKEN` 当前量、唯一派生贡献、精确衰减档案和 Link 投影 |
| Damage | 激化完整公式、实时等级/精通读取、基础伤害增加值和审计结果 |
| Coordination | ICD 后预算、步骤顺序、状态计划 adapter、Link 校验、Damage 输入转换和原子提交 |
| Burning | 将 `QUICKEN` 作为类草 Component 与普通草共同接入 `BurningState` |

Reaction 不读取 Attribute Runtime，不直接构造 `DamageRequest`，不保存 Aura 当前量，也不直接调用 Aura、Damage 或 Burning Runtime。协调器只转换强类型协议。

## 3. Definition、Profile 与注册

`quicken_definition()`、`aggravate_definition()` 与 `spread_definition()` 由 `create_default_reaction_bootstrap()` 组合进当前生产 Registry；Damage 侧同时注册 `catalyze_damage_profile()`。

### 3.1 原激化

```text
reaction_key: reaction.quicken
handler_key: reaction_handler.quicken

incoming_electro_on_dendro
incoming_dendro_on_electro
```

两个方向使用 `StateReactionProfile`，分别声明草 Aura 或雷 Aura 的消费方向。原激化本身没有 Damage Profile、Damage Effect 或 Reaction Gate。

### 3.2 附加反应

```text
reaction.aggravate / reaction_handler.aggravate
reaction.spread    / reaction_handler.spread
```

超激化方向为 `incoming_electro_on_quicken`，触发元素为雷，倍率 `1.15`；蔓激化方向为 `incoming_dendro_on_quicken`，触发元素为草，倍率 `1.25`。两者使用 `AdditiveReactionProfile`，不保存等级系数、元素精通或最终伤害。

## 4. 原激化建立

协调器先通过 Aura ICD 得到实际后手预算 `T`，Reaction 读取目标当前普通草或雷 Aura 量 `A`：

```text
reaction_amount = min(A, T)
quicken_amount = reaction_amount
remaining_origin_aura = A - reaction_amount
remaining_incoming = T - reaction_amount
```

规则：

- 草和雷按 `1:1` 消费；
- 使用完整 ICD 后预算，普通 `20%` 附着损耗不提前扣除；
- 激元素不使用普通附着损耗；
- 无伤害的正草/正雷施加也可以建立原激化；
- 原激化本身不产生 Damage Effect；
- 前置候选已经消费预算时，只使用步骤后的剩余预算；
- 交互结束后未被明确持久化的后手剩余量不会自动形成普通 Aura。

成功结果包含一个 `ReactionOccurrence`、一个建立或覆盖意图，以及一条普通草/雷的 `ElementalTransitionEffect`。

## 5. 激元素 Aura 与 QuickenState

激元素使用 `AuraKind.QUICKEN`，Aura Store 是当前量、贡献和衰减的唯一真值。一个连续激元素实例只保留一条 Reaction 创建的派生贡献，并携带唯一 `Quicken Link`。

`QuickenState` 保存：

```text
instance_ref
subject_ref
quicken_aura_link_ref
created_by_occurrence_ref
last_updated_by_occurrence_ref
created_frame
revision
```

State 不保存元素量、衰减率、来源等级、元素精通或伤害来源；没有周期游标和 `next_required_frame`。激元素自然衰减由 Aura 帧规范化推进，归零后由协调器同步清理 State、Aura 和 Link。

### 5.1 精确衰减

设创建/覆盖得到的激元素量为 `Q` GU：

```text
duration_seconds = 6 + 5 * Q
duration_frames  = 60 * (6 + 5 * Q)
decay_per_frame  = Q / (360 + 300 * Q)
```

项目使用 `AuraAmount` 和精确有理数保存衰减档案，不通过浮点持续时间反推速率。`Q = 0.8 GU` 时持续 `600` 帧。

### 5.2 建立与自然终止

`QuickenStateEstablishmentIntent` 原子创建 State、`QUICKEN` Aura 和 Link；`QuickenStateTerminationIntent` 处理激元素耗尽或主体失效。State、Aura 与 Link 任一前值或主体不一致时，整个批次在提交前失败。

自然归零不延长仿真；下一次真实必需帧到来前，帧协调器必须先清理已经归零的激元素及其 State，后续请求看到无活动激元素。

## 6. 激元素覆盖

每次新的原激化都先把旧激元素规范化到当前帧，再比较 `Q_old` 与 `Q_new`：

```text
Q_new > Q_old  -> 采用 Q_new 及其衰减率
Q_new <= Q_old -> 保留 Q_old 及其衰减率
```

覆盖规则：

- 保留 Aura instance、State instance、贡献引用、创建帧和 Quicken Link；
- 所有成功原激化都保留 occurrence，并更新 State 的 `last_updated_by_occurrence_ref` 与 `revision`；
- 只有新量严格更大时，才更新贡献来源、数量来源、衰减来源和衰减档案；
- 新量较小或相等时保留旧贡献来源和时间字段；
- 旧实例在同帧规范化为零时，先完整终止，再按首次建立创建新实例。

激元素不复用普通 Aura 的无条件同元素叠加和衰减率继承规则。

## 7. 超激化与蔓激化资格

两个附加反应都读取交互开始时已经存在的正激元素投影。后续同一交互新建或覆盖的激元素不能反向为当前 Impact 提供资格。

### 7.1 超激化

必须同时满足：

- 活动 `QUICKEN` Aura 和 `QuickenState` 均存在；
- 本次 ICD 后成功施加正雷元素；
- 当前目标级 Impact 存在稳定关联伤害；
- 关联伤害元素为雷；
- 主攻击标签选出的 Damage Profile 为 `damage_formula.catalyze_additive`；
- `DamageImpactSpec.scaling_terms` 至少有一个 `coefficient > 0`。

### 7.2 蔓激化

蔓激化条件与超激化相同，但关联伤害元素和本次元素必须为草。

不满足资格时，原激化或普通 Aura 消费仍可成立；只是不产生附加反应 occurrence 和当前 Impact 调整。只有没有已注册候选的正常组合才返回空决议；水进入激元素时由绽放 Definition 接管，雷扩散进入激化扩散仍属于未迁移候选并在写入前稳定失败。

两个附加反应不消费激元素、不改变其衰减率或持续时间，也不使用独立 Reaction Gate；连续合法的草/雷施加只受 Aura ICD 限制。

## 8. Damage 接入

Reaction 输出独立的 `CatalyzeCurrentImpactDamageAdjustment`：

```text
adjustment_ref
target_impact_ref
occurrence_ref
reaction_profile_key
trigger_element
reaction_multiplier
reaction_bonus
```

协调器将它转换为 Damage 的 `CatalyzeReactionInput`。协调器不读取等级或元素精通，也不计算附加值；Damage 在准备阶段再次校验 target、Impact、触发元素和公式 Profile。

Damage Profile 由主攻击标签唯一选择：

```text
damage_profile.reaction.catalyze_additive
    -> damage_formula.catalyze_additive
    -> DamageType.CATALYZE_REACTION
```

激化完整公式的计算顺序是：

```text
普通 scaling
 + 激化基础伤害增加值
 -> damage bonus
 -> crit
 -> general reaction zone
 -> defense
 -> elemental resistance
```

设来源等级共享表系数为 `level_multiplier`，当前查询元素精通为 `EM`：

```text
mastery_bonus = 5 * EM / (1200 + EM)
addition = level_multiplier
         * reaction_multiplier
         * (1 + mastery_bonus + reaction_bonus)
```

本版 `reaction_bonus = 0.0`。附加值以 `BaseDamageAddition` 进入基础 scaling 区，可暴击，并继续受到对应元素增伤、防御和抗性影响。DamageResult 同时保存 `CatalyzeReactionResolution` 与 `base_damage_additions` 投影。

原激化的创建者等级、元素精通和后续属性变化不参与；超激化/蔓激化使用当前关联伤害来源的等级和实时元素精通。

## 9. 复合候选顺序

复合候选由 Reaction 公共组合逻辑保存为 `ReactionDecisionSequence`，不依赖 Registry 或机制目录顺序。

```text
激雷 + 草：先蔓激化，再用剩余草/雷预算原激化
激草 + 雷：先超激化，再用剩余雷/草预算原激化
激冰 + 雷：超导与超激化并行，超激化不消费激元素
冰草 + 雷：先超导，剩余雷预算再尝试原激化
```

激冰与冰草是两条不同规则：前者的超激化资格来自交互开始时的激元素和成功雷施加；后者的原激化必须使用超导之后的剩余预算。

## 10. 与燃烧集成

激元素可以作为类草 Component 参与普通燃烧：

- 火命中仅激元素时建立一个 `BurningState` 和一份燃元素 Aura；
- 激草共存时，普通草与激元素共同链接同一 `BurningState`，但每个 Component 独立按 `1/150 GU/frame` 消费；
- 任一类草 Component 耗尽不重复消费另一 Component；
- 激元素耗尽时同步结束其 `QuickenState`，燃烧在仍有其他类草时可以继续；
- 燃烧终止或类草 Link 移除后，剩余激元素恢复其正常精确衰减档案。

燃烧的伤害、周期和来源快照仍由[燃烧反应设计](./燃烧反应设计.md)与对应契约拥有；激化文档只说明 `QUICKEN` 的类草 Link 参与。

## 11. 协调、事务与事实

一个元素交互批次可同时准备：

```text
ICD plan
普通 Aura transition
QuickenState/Aura/Link plan
Reaction occurrence 与 DecisionSequence
CatalyzeCurrentImpactDamageAdjustment
其他 Reaction Effect
Damage prepared record
```

协调器先准备并校验所有计划，再按既有顺序无回调提交；Aura、ReactionState、Damage 输入或 Link 校验任一 stale 时不留下部分状态。Damage 预备失败也阻止当前批次提交。

激化不新增专属 EventType。使用通用 `REACTION_OCCURRED`、`REACTION_STATE_CHANGED`、Aura 事实、`DAMAGE_RESOLVED` 和 `ELEMENTAL_INTERACTION_RESOLVED`；附加值通过 occurrence、adjustment、`target_impact_ref` 和 DamageResult 审计关联。

## 12. 第八版历史边界

第八版不实现：

- 水与激元素的绽放候选（现由第九版绽放 Definition 处理）；
- 雷扩散命中激元素的激化扩散；
- 真实伤害、只有固定 flat base 或基础 scaling 全为零的附加反应；
- 角色、武器、圣遗物和命座对激化的专属改写；
- 未确认的激化专属反应加成来源；
- 击退、硬直、削韧和空间位移。

第八版交付时这些候选必须稳定失败或返回无附加反应，不得静默消费 Aura 或提交部分 Damage；当前绽放稳定语义以[绽放反应设计](./绽放反应设计.md)及[绽放反应契约](../../../../契约/元素反应/反应/绽放反应契约.md)为准。
