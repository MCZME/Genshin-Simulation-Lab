# 超导反应设计

> 状态：已实现。本文描述普通冰雷超导、范围冰伤与物理减抗。

最后更新：2026-08-03

## 1. 定位

普通超导是即时剧变反应。它按 `1:1` 消费普通冰/雷，在当前元素交互中形成 occurrence，并冻结一个包含 Damage 与 Status 两个 Effect 的同帧后续 group。

代码落点：

```text
core/systems/reaction/mechanics/superconduct/mechanic.py
core/coordination/elemental_reaction/status.py
```

## 2. 方向与元素变化

显式方向：

```text
incoming_cryo_on_electro
incoming_electro_on_cryo
```

两个方向都使用 `consumed = min(incoming_amount, aura_amount)`。无伤害元素施加也能产生 occurrence、独立伤害和减抗；超导不修正原始 Impact 的关联伤害。

## 3. 剧变伤害

```text
damage element = cryo
base multiplier = 1.5
elemental amount = 0
can crit = false
strike type = none
```

来源缩放基础在 occurrence 时捕获，Damage 使用共享剧变公式和目标冰抗。超导不因为与超载共用 Effect 模型而继承钝击语义。

## 4. 共享范围 Effect Group

一个 group 包含：

```text
GeneratedDamageImpactEffect
ReactionStatusEffect
```

二者共享以 occurrence 主体为中心的 X/Z 平面 5 米查询、冻结候选和 `target_order`，但 capability 独立：

- `damage` 决定能否结算冰伤；
- `attribute_status` 决定能否施加物理减抗；
- 一个 Effect 被正常阻止不撤销另一个 Effect。

## 5. Damage Gate

超导 Gate 使用 30 帧最多两次的半开计数窗口。每个来源、目标和 damage kind 独立分槽；第三次及以后 blocked 不推进 Gate，也不阻止减抗计划。

## 6. 物理减抗与所有权

ReactionStatusEffect 声明：

```text
resistance.physical += -0.40
duration = 720 frames
```

Reaction 拥有数值、持续时间和 Status Profile，但不 import Buff Runtime/Store。协调器的显式 adapter 转换为 Buff 请求；BuffStore 是 Debuff 实例、冲突、替换、过期、事件和快照的唯一真值。

同一目标上的超导减抗跨来源共享 conflict slot，使用 `replace`：旧实例原子移除，新实例携带最新 occurrence 来源并获得完整 720 帧。它不叠加成 `-0.80`，但可与其他 conflict key 的物理减抗按属性系统规则加算。

## 7. 事务与事实

round 1 在任何写入前统一准备和校验目标资格、Gate、Buff、Damage 及角色受伤计划。提交后，replace 先发布 `BUFF_REMOVED` 再发布 `BUFF_APPLIED`，随后发布 `DAMAGE_RESOLVED` 和最终元素交互事实。

Gate blocked 是正常结果；缺 Status adapter、Buff Definition、Damage Profile 或无效计划是技术错误，阻止整个 Effect group 提交。

## 8. 非目标

当前超导不实现削韧、硬直、击退、停滞、空间位移、特殊暴击或特殊目标减抗免疫。超导 Damage Effect 不携带打击类型。

## 9. 验证

当前验证覆盖两个方向、`1:1` 消费、零精通公式、5 米范围、`30/2` Gate、Gate 与 Buff 解耦、跨来源 replace、720 帧到期、物理减抗属性读取和事实写保护。

稳定字段见[超导反应契约](../../../../契约/元素反应/反应/超导反应契约.md)。
