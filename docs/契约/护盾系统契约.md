# 护盾系统契约

> 状态：核心运行时契约已实现。
> 本文冻结护盾系统的稳定枚举、强类型模型、Impact payload、事件载荷、快照和验证规则。运行流程与游戏行为见[护盾系统设计](../架构/护盾系统设计.md)。

最后更新：2026-07-13

## 1. 适用范围

本契约覆盖：

- `core/systems/shield/` 的公共模型。
- 护盾创建公式和授予策略。
- 角色来伤、并行吸收与生命提交结果。
- `ImpactKind.SHIELD` 的 `params.shield` payload。
- 护盾事件 payload 与快照序列化。
- 结构化错误和数值验证。

不覆盖真实角色倍率、结晶等级表、敌方盾条或 UI 模型。

## 2. 通用数值规则

- 数值接受 `int | float`，拒绝 `bool`。
- 所有数值必须为有限数。
- 容量、来伤和倍率按字段要求校验非负或正数。
- `abs(value) <= 1e-12` 的容量残差归一化为 `0.0`。
- `frame` 为非负整数；instance id 和持续帧数为正整数。
- tags 归一化为 `frozenset[str]`，每项必须是非空字符串。

## 4. ShieldProtectionRef

字段：

```text
kind: ShieldProtectionKind
protection_id: str
```

默认队伍保护引用：

```json
{"kind": "active_team", "protection_id": "team:player"}
```

稳定 Store owner key：

```text
{kind}:{protection_id}
```

`character` 类型的 protection id 必须与来伤目标 entity id 一致；`active_team` 来伤目标必须是当前场上角色。

## 5. 创建公式

### 5.1 ShieldScalingTerm

```text
component_key: str
attribute_key: AttributeKey
coefficient: float
```

- `component_key` 在单个公式内唯一。
- `attribute_key` 必须是公共属性。
- coefficient 为有限非负数。

### 5.2 ShieldNativeMultiplierTerm

```text
multiplier_key: str
multiplier: float
source_context: RuntimeSourceRef
```

- `multiplier_key` 在单个公式内唯一。
- multiplier 为有限非负数。
- source context 保存该护盾自身倍率来源。

### 5.3 ShieldCapacityFormula

```text
scaling_terms: tuple[ShieldScalingTerm, ...]
flat_absorption: float
native_multipliers: tuple[ShieldNativeMultiplierTerm, ...]
```

scaling term 按 component key 排序，native multiplier 按 multiplier key 排序。固定值为有限非负数。

### 5.4 ShieldCapacityFormulaResult

保存：

- 每个 `ShieldCapacityComponentResult`。
- flat absorption。
- base absorption。
- 每个 `ShieldNativeMultiplierResult`。
- 合并后的 native multiplier。
- 最终 native absorption。

最终 native absorption 必须为有限正数。

## 6. ShieldGrantRequest

```text
grant_id: str
frame: int
mechanic_key: str
handler_key: str
protection_ref: ShieldProtectionRef
creator_ref: AttributeSubjectRef(character)
source_context: RuntimeSourceRef
element: ShieldElement
duration_frames: int
grant_formula: ShieldCapacityFormula
grant_policy: ShieldGrantPolicy
conflict_key: str
capacity_limit_formula: ShieldCapacityFormula | None
grants_interruption_resistance: bool
tags: frozenset[str]
```

约束：

- `grant_id`、mechanic key、handler key 和 conflict key 非空。
- creator 必须是角色主体。
- duration 为正整数。
- 只有 `add_capped_refresh` 可以且必须提供 capacity limit formula。

## 7. ShieldGrantResolution

Resolver 输出：

```text
grant_id
frame
creator_ref
protection_ref
component_results
flat_absorption
native_multiplier_results
granted_absorption
capacity_limit?
attribute_trace
source_context
```

`granted_absorption` 和非空 `capacity_limit` 必须为有限正数。属性 trace 保存创建时查询结果，不包含动态护盾强效。

## 8. ShieldGrantResult

Runtime 提交结果：

```text
resolution: ShieldGrantResolution
outcome: ShieldGrantOutcome
instance_id: int
replaced_instance_id: int | None
remaining_before: float
remaining_after: float
maximum_after: float
expires_at_before: int | None
expires_at_after: int
```

约束：

- 授予后的 remaining 和 maximum 为正数。
- `remaining_after <= maximum_after`。
- `replaced_instance_id` 只在替换创建时存在。
- 刷新策略保留 instance id。

## 9. ShieldComponent

活动护盾组件字段：

```text
instance_id
mechanic_key
handler_key
protection_ref
creator_ref
source_context
element
maximum_native_absorption
remaining_native_absorption
conflict_key
grants_interruption_resistance
grant_snapshot_ref
tags
```

活动组件必须满足：

```text
0 < remaining_native_absorption <= maximum_native_absorption
```

组件不保存 created frame 和 expires at frame；二者由关联的 `MechanicInstance` 拥有。

## 10. 容量变化与移除结果

### 10.1 ShieldCapacityChangeResult

```text
frame
instance_id
mechanic_key
protection_ref
reason: ShieldChangeReason
native_before
native_after
maximum_before
maximum_after
```

容量字段为有限非负数。耗尽时 `native_after == 0`，随后发布移除结果。

### 10.2 ShieldRemovalResult

```text
frame
instance_id
mechanic_key
protection_ref
reason: ShieldRemovalReason
native_remaining
```

耗尽移除的 remaining 为零；过期、替换和显式移除可以保存未消耗完的原生剩余量。

## 11. CharacterIncomingDamage

```text
damage_id: str
frame: int
protection_ref: ShieldProtectionRef
target_ref: AttributeSubjectRef(character)
mitigated_amount: float
element: DamageElement
source_ref: AttributeSubjectRef | None
source_context: RuntimeSourceRef | None
tags: frozenset[str]
```

`mitigated_amount` 是护盾前防御、抗性和伤害减免已经完成后的非负来伤量。兼容属性 `amount` 返回同一数值，不表示护盾前理论伤害。

## 12. ShieldHitResult

每个活动护盾保存：

```text
instance_id
mechanic_key
element
native_before
native_cost
native_after
element_multiplier
shield_strength
shield_strength_multiplier
effective_multiplier
absorbable_incoming_damage
depleted
```

容量字段非负，effective multiplier 为正数，`depleted` 必须与 `native_after == 0` 的计算结果一致。

## 13. ShieldAbsorptionResult

```text
damage_id
frame
protection_ref
target_ref
mitigated_amount
element
active_character_shield_strength
shield_hits
protected_damage
health_bound_damage
had_active_shield_before
has_active_shield_after
depleted_instance_ids
```

不变量：

```text
mitigated_amount == protected_damage + health_bound_damage
```

`shield_hits` 按 instance id 稳定顺序保存；depleted id 排序。无盾或零来伤时 hits 为空，protected 为零。

## 14. IncomingDamageApplicationRecord

```text
incoming_damage: CharacterIncomingDamage
shield_result: ShieldAbsorptionResult
health_application: CharacterDamageApplication
health_result: CharacterHealthChangeResult
```

`health_application.amount` 必须等于 `shield_result.health_bound_damage`。完全吸收时 amount 为零，但仍形成完整记录。

## 15. ShieldComponentStore

Store 以 mechanic instance id 保存活动组件，并维护单调递增 version。

公共能力：

- `get()`、`require()`。
- `add()`、`replace()`、`remove()`、`discard()`。
- `active_for()`、`conflicts()`。
- `apply_batch()`。

### 15.1 ShieldComponentUpdate

```text
instance_id
expected_remaining
remaining_after
maximum_after
remove_after
```

约束：

- `remove_after` 必须与 `remaining_after == 0` 一致。
- remaining after 不大于 maximum after。
- batch 内 instance id 不重复。
- expected version 和每个 expected remaining 必须精确匹配当前状态。
- 任一校验失败时不得应用部分更新。

## 16. ImpactKind.SHIELD

`ImpactRequest.kind` 为 `shield`，并要求 `params.shield` 为对象。

### 16.1 必填字段

```json
{
  "shield": {
    "mechanic_key": "example.shield",
    "handler_key": "example.shield.handler",
    "conflict_key": "example.shield",
    "duration_frames": 600,
    "grant_formula": {
      "scaling_terms": [],
      "flat_absorption": 1000,
      "native_multipliers": []
    }
  }
}
```

`owner_slot` 必填，用于从 SpaceRuntime 的 team state 解析创建者。

### 16.2 可选字段

```text
protection_ref          # 默认 active_team:team:player
element                 # 优先使用 ImpactRequest.element，否则默认 none
grant_policy            # 默认 replace
capacity_limit_formula  # 仅 add_capped_refresh
grants_interruption_resistance  # 默认 false
tags                    # 默认空数组
```

formula 中 scaling term 字段为 `component_key`、`attribute_key`、`coefficient`；native multiplier 字段为 `multiplier_key`、`multiplier`。来源上下文由 handler 根据 ImpactRequest 构造，不由 payload 任意覆盖。

## 17. 事件契约

| EventType | Category | Payload | 发布条件 |
| --- | --- | --- | --- |
| `SHIELD_GRANTED` | `STATE_CHANGE` | `ShieldGrantedPayload(result)` | 创建、替换、刷新、叠加或保留 |
| `SHIELD_CAPACITY_CHANGED` | `STATE_CHANGE` | `ShieldCapacityChangedPayload(result)` | 吸收或刷新导致容量变化 |
| `SHIELD_REMOVED` | `STATE_CHANGE` | `ShieldRemovedPayload(result)` | 耗尽、过期、替换或显式移除 |
| `SHIELD_ABSORPTION_RESOLVED` | `FACT` | `ShieldAbsorptionResolvedPayload(result)` | 非零来伤且有活动护盾参与 |
| `DAMAGE_APPLIED` | `STATE_CHANGE` | `DamageAppliedPayload(record)` | 角色来伤完成护盾与生命提交 |

事件分类和全局默认记录规则以[事件类型](../架构/事件系统/事件类型.md)为准。所有 payload 的 `to_dict()` 返回 JSON-compatible 数据。

## 19. 错误类型

```text
ShieldSystemError
├── ShieldValidationError
├── ShieldAttributeError
├── ShieldCapacityError
├── ShieldPolicyError
├── ShieldProtectionNotFoundError
├── ShieldTargetMismatchError
├── ShieldInstanceNotFoundError
├── ShieldStateConflictError
└── ShieldAtomicCommitError
```

调用方应按领域错误处理，不能把非法公式、目标不匹配或提交冲突静默视为“没有护盾”。

## 20. 序列化规则

- 枚举序列化为稳定字符串 value。
- tags 序列化为排序 tuple。
- 主体引用序列化为 `kind` 和 `entity_id`。
- RuntimeSourceRef 序列化为 `kind`、`source_key` 和 `instance_id`。
- protection ref 序列化为 `kind` 和 `protection_id`。
- 结果保留中间量，不只保存最终伤害或最终容量。
- 新增或删除字段属于契约变化，必须同步事件持久化测试和本文。

## 21. 测试要求

契约测试至少覆盖：

- 非有限数、负数、布尔数值和非法枚举被拒绝。
- 公式 key 唯一性和公共属性限制。
- grant policy 与 capacity limit 的组合约束。
- 活动组件容量不变量。
- 吸收守恒不变量。
- batch version、前值、重复 id 和缺失组件冲突。
- Impact payload 必填字段和默认值。
- 事件 payload 与快照稳定序列化。
- 通用结果数据库 JSON 往返。
