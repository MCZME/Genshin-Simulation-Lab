# 资产数据库契约

本文档记录当前已经实现并验证的资产数据库、资产 manifest、导入规则和读取协议契约。资产系统的分层和模块职责见：[资产系统设计](../架构/资产系统设计.md)。

## 1. 基本原则

- 资产库是只读生成产物。
- 正式运行时携带 SQLite 资产库，不携带开发期 raw JSON cache。
- 仿真配置、资产库和组装逻辑统一使用 `asset_key` 引用资产。
- 显示名称只用于 UI 展示和人工阅读，不作为仿真识别依据。
- `handler_key` 是代码实现绑定入口，与 `asset_key` 分离。
- 数据库保存参数，不保存具体机制行为。
- `core/` 不直接访问资产库。

## 2. 资产身份

`asset_key` 使用 `{asset_type}:{source_id}` 形状。

当前资产类型：

```text
character
weapon
artifact_set
```

示例：

```text
character:10000002
weapon:11512
artifact_set:15032
```

`source_id` 保留源站资产 id。资产模型会校验 `asset_key` 中的 `source_id` 必须与字段 `source_id` 一致。

## 3. SQLite Schema

当前资产库 schema version 为：

```text
2
```

资产库是可再生的只读产物，不提供就地 schema 迁移。`assets init` 仅初始化新库，若目标已存在表结构，则会先验证其表、必需列和 `schema_version`；不兼容的 v1 库必须通过 manifest 重新构建，不能只修改元数据版本号。

必需表：

```text
asset_db_meta
asset_import_runs
characters
character_level_stats
weapons
weapon_level_stats
artifact_sets
artifact_set_bonuses
talent_scaling_entries
effect_payloads
```

### 3.1 `asset_db_meta`

```text
key    TEXT PRIMARY KEY
value  TEXT NOT NULL
```

必需元信息：

```text
schema_version
data_version
importer_version
built_at
source_name
source_version
content_hash
```

Project Amber / Yatta 导入还会写入：

```text
source_language
source_fetched_at
```

### 3.2 `asset_import_runs`

```text
id                INTEGER PRIMARY KEY AUTOINCREMENT
source_name       TEXT NOT NULL
source_version    TEXT NOT NULL
schema_version    TEXT NOT NULL
data_version      TEXT NOT NULL
importer_version  TEXT NOT NULL
imported_at       TEXT NOT NULL
note              TEXT NULL
```

该表记录资产库整体生成过程，不归档 raw JSON。

### 3.3 `characters`

```text
asset_key    TEXT PRIMARY KEY
source_id    TEXT NOT NULL
name         TEXT NOT NULL
element      TEXT NOT NULL
weapon_type  TEXT NOT NULL
rarity       INTEGER NOT NULL
burst_energy_cost REAL NOT NULL
handler_key  TEXT NULL
```

`burst_energy_cost` 的运行时语义、`cost = 0` 行为和组装失败规则见[元素能量系统契约](./元素能量系统契约.md)。

### 3.4 `character_level_stats`

```text
character_key    TEXT NOT NULL
level            INTEGER NOT NULL
ascension_phase  INTEGER NOT NULL
base_hp          REAL NOT NULL
base_atk         REAL NOT NULL
base_def         REAL NOT NULL
ascension_stat   TEXT NULL
ascension_value  REAL NULL

PRIMARY KEY (character_key, level, ascension_phase)
FOREIGN KEY (character_key) REFERENCES characters(asset_key) ON DELETE CASCADE
```

### 3.5 `weapons`

```text
asset_key    TEXT PRIMARY KEY
source_id    TEXT NOT NULL
name         TEXT NOT NULL
weapon_type  TEXT NOT NULL
rarity       INTEGER NOT NULL
handler_key  TEXT NULL
```

### 3.6 `weapon_level_stats`

```text
weapon_key       TEXT NOT NULL
level            INTEGER NOT NULL
ascension_phase  INTEGER NOT NULL
base_atk         REAL NOT NULL
secondary_stat   TEXT NULL
secondary_value  REAL NULL

PRIMARY KEY (weapon_key, level, ascension_phase)
FOREIGN KEY (weapon_key) REFERENCES weapons(asset_key) ON DELETE CASCADE
```

### 3.7 `artifact_sets`

```text
asset_key    TEXT PRIMARY KEY
source_id    TEXT NOT NULL
name         TEXT NOT NULL
handler_key  TEXT NULL
```

### 3.8 `artifact_set_bonuses`

```text
artifact_set_key  TEXT NOT NULL
piece_count       INTEGER NOT NULL
handler_key       TEXT NOT NULL
params_json       TEXT NOT NULL

PRIMARY KEY (artifact_set_key, piece_count, handler_key)
FOREIGN KEY (artifact_set_key) REFERENCES artifact_sets(asset_key) ON DELETE CASCADE
```

### 3.9 `talent_scaling_entries`

```text
id             INTEGER PRIMARY KEY AUTOINCREMENT
character_key  TEXT NOT NULL
talent_key     TEXT NOT NULL
entry_key      TEXT NOT NULL
label          TEXT NOT NULL
scaling_json   TEXT NOT NULL
tags_json      TEXT NULL

UNIQUE (character_key, talent_key, entry_key)
FOREIGN KEY (character_key) REFERENCES characters(asset_key) ON DELETE CASCADE
```

### 3.10 `effect_payloads`

```text
effect_key   TEXT PRIMARY KEY
owner_type   TEXT NOT NULL
owner_key    TEXT NOT NULL
effect_kind  TEXT NOT NULL
unlock_key   TEXT NULL
handler_key  TEXT NOT NULL
params_json  TEXT NOT NULL
```

`effect_payloads.owner_key` 按 `owner_type` 引用资产。SQLite 层不为该表声明外键，manifest audit 负责检查 `character`、`weapon`、`artifact_set` owner 是否存在。

## 5. 标准 Manifest

manifest 是“标准化资产数据 -> SQLite 资产库”的导入边界。

顶层字段：

```text
schema_version
kind
meta
characters
character_level_stats
weapons
weapon_level_stats
artifact_sets
artifact_set_bonuses
talent_scalings
effect_payloads
```

固定值：

```text
schema_version = 1
kind = asset_manifest
```

manifest loader 会拒绝未知字段，并校验每个对象的必填字段、类型和未知字段。

### 5.1 `meta`

`meta` 是字符串键值表。缺省规则：

- `schema_version` 缺省为当前 SQLite schema version。
- `source_name` 缺省为 `asset-manifest`。
- `source_version` 缺省为 manifest 文件名。
- `data_version` 缺省为 `source_version`。
- `importer_version` 缺省为 `asset-manifest-1`。
- `content_hash` 缺省为 manifest 文本 SHA-256。

## 6. 等级属性覆盖

角色等级属性覆盖：

```text
1-90 每级
95
100
```

武器等级属性覆盖：

```text
1-90 每级
```

1 星和 2 星武器按源数据最高突破等级覆盖到 `70`。

可突破等级写入突破前和突破后双 phase：

```text
20
40
50
60
70
80
```

角色存在 `95` 和 `100`，它们是正式游戏等级点，不是本项目扩展等级。武器没有 `95` 和 `100`。

读取等级属性时，`ascended=True` 选择最高突破阶段，`ascended=False` 只在可突破等级选择较低突破阶段；非可突破等级该参数不改变结果。

示例：

```text
get_character_level_stats("character:10000002", 20, ascended=False) -> 20/0
get_character_level_stats("character:10000002", 20, ascended=True)  -> 20/1
get_character_level_stats("character:10000002", 37, ascended=False) -> 37/1
```

## 7. 技能倍率 `scaling`

`talent_scaling_entries.scaling_json` 保存随技能等级变化的倍率和数值表，不保存技能行为。

当前支持模式：

```text
level_table
constant
```

当前支持组件类型：

```text
flat
plain_ratio
plain_value
stat_ratio
```

Project Amber / Yatta 转换器当前只导入角色核心战斗天赋：

```text
normal_attack
elemental_skill
elemental_burst
```

`level_table` 必须包含：

```text
schema_version = 1
mode = level_table
level_min
level_max
components
```

每个 component 必须包含：

```text
kind
values
```

`values` 长度必须等于 `level_max - level_min + 1`。Project Amber / Yatta 当前导入天赋等级 `1-15`。

转换器会保留源字段对照信息：

```text
source
source_talent_key
source_skill_id
source_line_index
source_template
source_param
format
expression
```

百分比以小数倍率存储。

## 8. 效果参数 `params`

`effect_payloads.params_json` 和 `artifact_set_bonuses.params_json` 保存复杂效果参数，不解释为真实机制。

所有 params 必须包含：

```text
schema_version = 1
```

可包含 `components`。每个 component 的 `values` 必须是数组。

武器精炼效果包含：

```text
refinement_min
refinement_max
source_templates
components
```

如果存在精炼范围，component 的 `values` 长度必须等于：

```text
refinement_max - refinement_min + 1
```

角色固有天赋、特殊天赋、命座、武器效果和圣遗物效果当前都只保留参数，不在导入阶段解释为真实机制。

## 10. Project Amber / Yatta 导入规则

第一版源数据使用 Project Amber / Yatta 当前默认数据。

基础来源：

- 角色基础索引：`avatar/index.json`
- 角色详情：`avatar/{id}.json`
- 角色成长曲线：`static/avatarCurve.json`
- 武器基础索引：`weapon/index.json`
- 武器详情：`weapon/{id}.json`
- 武器成长曲线：`static/weaponCurve.json`
- 圣遗物套装基础索引和效果：`reliquary/index.json`

转换范围：

- 角色基础索引。
- 角色元素爆发 `cost`。
- 角色等级属性。
- 普通攻击、元素战技、元素爆发倍率。
- 固有天赋效果参数。
- 特殊天赋效果参数。
- 命座效果参数。
- 武器基础索引。
- 武器等级属性。
- 武器精炼效果参数。
- 圣遗物套装基础索引。
- 圣遗物套装效果参数。

导入规则：

- 缺少详情文件的资产只写基础索引，不写等级属性、倍率或效果参数。
- 角色、武器、圣遗物套装索引行的 `handler_key` 默认为空。
- 每个已转换角色详情必须恰好有一个 `talent.type == 1` 的元素爆发天赋；其有限非负 `cost` 写入 `burst_energy_cost`。缺详情、缺成本或多个爆发天赋会使转换失败，不能生成缺少能量上限的角色资产。
- 未实现真实机制的效果参数使用显式 `*.unimplemented_*` handler 标记。
- 1 星和 2 星普通武器没有 `affix` 时不写效果参数。
- 圣遗物套装按源站 `affixList` 排序生成 2 件和 4 件效果；只有一个效果的祭礼冠类套装按 1 件效果写入。
- 空名称且空描述的源站天赋占位条目会被跳过。

## 11. Handler 语义

`handler_key` 表示资产侧是否已绑定代码条目：

- `handler_key = NULL`（角色、武器、圣遗物套装）：已入库但未绑定任何代码条目。
- 唯一键（如 `character.test.constellation.c1`）：代码中已为该资产/效果添加
  handler 条目；具体实现程度（已实现、空实现、未实现）由内容注册表的
  `HandlerImplementationStatus` 标记说明，不由键名表达。
- `*.unimplemented_*` 占位键：代码中尚未添加该效果，仅保证编译与审计通过；
  该键不可视为真实 handler。

`generic.noop` 和 `generic.test_*` 只用于测试或最小闭环验证，不代表真实机制已经实现。

真实机制 handler 必须由 `content/` 显式注册，并由测试或 golden case 支撑。

### 11.1 handler 绑定维护命令

资产数据库是本地临时生成物，不进入 git；重建数据库后，唯一键绑定需要通过
维护命令重新应用：

```powershell
uv run genshin-sim assets set-handler --db data/assets/assets_full.db `
  --kind effect --key character:test:constellation:c1 `
  --handler-key character.test.constellation.c1
uv run genshin-sim assets show-handlers --db data/assets/assets_full.db `
  --kind effect --owner character:test
uv run genshin-sim assets reset-handler --db data/assets/assets_full.db `
  --kind effect --key character:test:constellation:c1
```

`--kind` 支持 `character`、`weapon`、`artifact-set`、`artifact-bonus`（需
`--pieces`）与 `effect`。设置时校验：

- 目标键必须真实存在；
- `--handler-key` 去空白后必须非空；
- 目标 handler 必须已在内容注册表注册（角色/武器/圣遗物/效果按类别分别检查）；
- 相同值重复设置为幂等操作。

`reset-handler` 语义：角色/武器/圣遗物套装清回 `NULL`；效果按 `effect_kind`
回到对应 `*.unimplemented_*` 占位键；套装效果回到
`artifact.unimplemented_set_bonus`。

## 12. Manifest 审计

`audit-manifest` 当前覆盖：

- 角色、武器、圣遗物套装基础键唯一性。
- 角色等级属性、武器等级属性、圣遗物套装效果、技能倍率、效果参数引用关系。
- 角色元素、武器类型、稀有度、属性枚举。
- 角色 `burst_energy_cost` 为有限非负数。
- 角色 `1-90 + 95 + 100` 等级覆盖。
- 3 星及以上武器 `1-90` 等级覆盖。
- 1 星和 2 星武器 `1-70` 等级覆盖。
- 可突破等级双 phase 覆盖。
- 圣遗物套装效果 `piece_count` 只能为 `1`、`2` 或 `4`。
- `artifact_set_bonuses.params` 基础 schema。
- `talent_scalings.scaling` 基础 schema、components 和 values 长度。
- `effect_payloads.params` 基础 schema、精炼范围和 values 长度。
- 角色效果 `unlock_key` 形状。

审计通过后再执行：

```powershell
uv run genshin-sim assets build --manifest data/assets/manifests/project_amber_yatta.json --db data/assets/assets.db
```

## 13. SQLite 校验

`assets validate` 当前覆盖：

- 资产库文件存在。
- 必需表存在。
- `characters.burst_energy_cost` 等当前 schema 必需列存在。
- `schema_version` 兼容。
- SQLite 外键检查通过。
- `artifact_set_bonuses.params_json`、`talent_scaling_entries.scaling_json`、`effect_payloads.params_json` 是 JSON object。
- `talent_scaling_entries.tags_json` 是 JSON list。

## 15. 读取协议

`AssetRepository` 提供只读接口：

```text
get_meta()
get_info()
list_characters()
get_character(character_key)
get_character_level_stats(character_key, level, ascended=True)
list_weapons(weapon_type=None)
get_weapon(weapon_key)
get_weapon_level_stats(weapon_key, level, ascended=True)
list_artifact_sets()
get_artifact_set(artifact_set_key)
get_artifact_set_bonuses(artifact_set_key, piece_count=None)
get_talent_scalings(character_key, talent_key)
get_effect_payloads(owner_key, effect_kind=None)
```

仓库返回资产模型对象，不向调用方暴露 SQL row。

SQLite 仓库打开连接时启用：

```text
PRAGMA foreign_keys = ON
PRAGMA query_only = ON
```
