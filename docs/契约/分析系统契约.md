# 分析系统契约

> 状态：已确认（2026-08-12 实现落地定稿）。
> 本文定义分析系统对外稳定接口：查询模型、路径表达式、结果形状、中间模型、指标口径、属性面板形状与稳定性规则。系统设计见[分析系统设计](../架构/分析系统设计.md)。
> 最后更新：2026-08-12

## 1. 术语

- **状态还原器**：把初始快照 + 事件流折叠为任意帧状态视图的加工器。
- **数据寻址**：用结构化查询/路径表达式定位结果库数据的能力。
- **中间模型**：事件流加工出的稳定序列（伤害序列、治疗序列）。
- **指标**：由中间模型派生的摘要数值。
- **对比**：多个查询结果的并置呈现。
- **面板同步器**：属性系统内检查并发布属性面板差异的组件。

## 2. 查询模型

### 2.1 StateQuery

字段：

- `session_ids`：一个或多个运行。
- `frames`：单帧或多帧（第一版支持列表）。
- `paths`：路径列表，每条独立解析。

约束：路径解析互相独立，不做关联查询。

### 2.2 EventQuery

字段：

- `session_id`：单个运行。
- `event_types`：一个或多个事件类型。
- `frame_min` / `frame_max`：可空。
- `payload_path`：可空；空 = 返回整个事件载荷。
- `filters`：载荷路径等值匹配列表（第一版只支持等值）。
- `offset` / `limit`：分页，必须显式限制。

### 2.3 查询结果

状态结果：`session_id`、`frame`、`path`、`value`（值或节点）。

事件结果：`session_id`、`ordinal`、`frame`、`event_type`、`path`、`value`（载荷字段或整个载荷）。

## 3. 路径表达式

内部使用类型化查询对象；对外路径表达式是 UI/CLI 可读形式，解析后映射到查询对象。

- 状态路径从 providers 树取值，段之间用点分隔：`team.characters[slot=1].current_hp`。
- 包含特殊字符（冒号、点）的字典键用引号键：`attributes.subjects["character:slot_1"]["stat.atk.total"]`；相邻方括号段无需额外分隔符。
- 实体筛选使用键值形式：`characters[slot=1]`、`characters[combat_entity_id=character:slot_2]`；作为路径终点时返回全部匹配项，路径继续时要求恰好一个匹配。
- 取值粒度支持字段与节点。
- 事件查询表达事件类型 + 载荷路径 + 等值过滤（外部字符串语法待 UI 接入时定稿）。

## 4. 中间模型

### 4.1 伤害序列

每条伤害记录字段（已确认）：

- `frame`：事件帧；时间以帧为原始单位，秒为派生展示 = 帧 ÷ 60。
- `damage_id`：伤害结算引用（`DamageResult.request_id`）。
- `source_ref`、`target_ref`：来源/目标实体 id（`entity_id`）。
- `amount`：最终伤害（`final_damage`）。
- `damage_kind`：伤害类型（`damage_type`）。
- `event_ref`：来源事件在运行事件流中的序号（ordinal）。

来源：`DAMAGE_RESOLVED` 事件的 `result`。

### 4.2 治疗序列

字段与伤害序列对称：`frame`、`healing_id`（`HealingResult.healing_id`）、`source_ref`、`target_ref`（`entity_id`）、`amount`（`final_healing`）、`healing_kind`（首版固定 `healing`，细分后续）、`event_ref`（ordinal）。

来源：`HEALING_RESOLVED` 事件的 `result`。

### 4.3 稳定性

序列字段只增不改；配冻结测试。

## 5. 指标契约

第一版指标（全部从中间模型派生，不直接读事件）：

- 总伤害：伤害序列 `amount` 之和。
- DPS：总伤害 ÷ 整场秒数；整场秒数 = `frames_run ÷ frames_per_second`（帧转秒，60 fps）。
- 最高/平均单次伤害：伤害序列统计。
- 伤害占比：按来源角色、按伤害类型。
- 总治疗、治疗占比（按来源角色）。

每个指标输出带口径说明：`key`、`value`、`definition`（定义字符串），占比指标带 `group`。帧率（`frames_per_second`，首版 60）与整场时间基准随指标模型返回，避免不同口径误比较。

## 6. 属性面板契约

### 6.1 初始快照 attributes provider

形状（已确认）：

```json
{
  "frame": 0,
  "subjects": {
    "character:slot_1": {
      "stat.atk_total": {"value": 1500.0, "applied_terms": []},
      "stat.hp_max": {"value": 12000.0, "applied_terms": []}
    }
  }
}
```

`applied_terms` 每项包含 `provider_key`、`source_ref`、`stage`、`value`、`audit_tags`（即“属性被什么影响”的证据）。第一版不存 `rejected_terms` 与 `dependency_trace`。

### 6.2 ATTRIBUTE_PANEL_CHANGED

状态变化事件，默认记录；只在面板发生有效变化时发布。载荷：

```json
{
  "frame": 120,
  "subject_ref": "character:slot_1",
  "changes": [
    {
      "attribute_key": "stat.atk_total",
      "before_value": 1500.0,
      "after_value": 1800.0,
      "after_terms": []
    }
  ]
}
```

还原器按 `subject + attribute_key` 更新面板；查询属性节点返回 value + `applied_terms`。

## 7. 状态还原器行为契约

- 输入：初始快照 + 有序事件 + 目标帧。
- 输出：指定帧状态视图；视图顶层带 `fold_status`：`{provider: "folded" | "baseline" | "excluded"}`。
- 未覆盖领域保持初始快照基线并标记 `baseline`；标记必须透传到 UI，不得当作精确结果。
- 事件只应用 `frame <= 目标帧` 的行，按事件序（ordinal）折叠。

第一版可折叠领域：`team`、`cooldown`、`buff`、`shield`、`infusion`、`attributes`；其余已注册 provider（`energy`、`aura`、`aura_icd`、`reaction`、`resonance`、`moonsign`、`space`、`content_state` 等）保持初始快照基线并标记 `baseline`。显式排除：空间实体位置/生命周期更新（跟随、刷新、延长）、移动垂直状态（高度/速度/重力）、Reaction Gate 记录（窗口/计数/就绪帧）、动作中断/完成。逐领域证据核对表见[结果库契约](./结果库契约.md)第 5.1 节。

## 7.1 对比模型

对比的核心定义：把满足条件查询到的数据并置呈现；任何数据都可对比（跨运行、同运行不同帧、不同实体、不同领域）。

- `ComparisonQuery`：`label` + `StateQuery` 或 `EventQuery`。
- `ComparisonColumn`：一次查询的结果列（`label` + 结果集合）。
- `ComparisonResult`：多列并置（`columns`）。

约束：

- 对比至少需要一个查询；标签必须非空且不重复。
- 结果每项仍带自身定位信息（session/frame/path/ordinal/event_type），每个格子可追溯来源。
- 具体对比方案（对齐规则、聚合口径、展示形式）在此基础上增加限制，不属于核心模型。

## 8. 稳定性规则

## 8. 稳定性规则

- 模型字段只增不改、语义不变；破坏性变更走新模型/新版本。
- 对外路径表达式的已有路径语义不允许变化。
- 冻结测试：伤害/治疗序列字段、属性面板形状。
- 冻结测试：指标与对比模型字段。
- 模型版本第一版随结果库 schema 版本演进。
