## 4. 阶段 F：真实护盾 content（待推进）

选择一个规则简单、资料充分的真实角色护盾，打通：

```text
资产与 handler_key -> content action / impact -> ShieldGrantRequest
-> ShieldRuntime / ShieldStore -> CharacterDamageTakenCoordinator -> HealthRuntime
-> 事件与结果持久化
```

实现前输入：当前版本技能描述和资产倍率；等级、天赋等级和创建属性；持续时间、元素、授予策略和 conflict key；长按、命座、固有天赋或特殊倍率影响。抗打断需求只记录为后续系统输入，不写入临时布尔字段。

验收要点：

- 使用真实资产输入，不以测试参数替代正式数据链路。
- 创建公式中间量和最终原生容量可审计。
- 切换场上角色后动态护盾强效正确；刷新、替换和过期行为与来源一致。
- handler 缺失或数据错误在组装阶段失败。
- 事件和结果库记录可复现完整过程，并至少有一个可复现的创建与承伤 golden case。
