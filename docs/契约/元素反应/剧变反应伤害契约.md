# 剧变反应伤害契约

> 状态：已实现。本文冻结剧变反应共享的来源捕获、Damage 输入、公式与审计语义。

最后更新：2026-08-01

## 1. 所有权

- Reaction 决定反应方向、基础倍率，并在 occurrence 形成时冻结来源缩放基础。
- Damage 拥有等级系数表、元素精通收益、抗性乘区、最终公式和 DamageResult 审计。
- 协调器只把 `GeneratedDamageImpactEffect` 转换为统一 Damage Impact，不按 reaction key 推导倍率。

普通剧变伤害不读取攻击力、技能倍率、普通伤害加成或暴击属性。

## 2. 来源与等级系数

稳定来源分类：

```text
TransformativeReactionSourceKind
├── character
└── enemy_environment
```

稳定直接表 key：

```text
damage.transformative_level_multiplier.character
damage.transformative_level_multiplier.enemy_environment
```

直接表由 `core/systems/damage/level_multipliers.py` 单点维护。查询不插值、不外推、不钳制；未知来源、非整数等级或表外等级在计划阶段失败。

第二版生产触发入口只支持队伍角色。保留 `enemy_environment` 数据不代表已经存在敌方或环境主动 Impact 入口。

## 3. 捕获式缩放基础

即时剧变 occurrence 使用 `CapturedTransformativeScalingBasis` 冻结：

```text
basis_ref
captured_frame
source_ref
source_kind
source_level
elemental_mastery
reaction_bonus
reaction_profile_key
damage_profile_key
level_multiplier_table_key
level_multiplier
source_observation_ref
source_owner_slot
```

规则：

- `source_level`、`elemental_mastery` 和等级系数在 occurrence 形成时读取；
- 普通超载、超导和碎冰的 `reaction_bonus = 0.0`；
- 后续 settlement round 不重新读取来源等级、元素精通、Profile 或等级系数；
- 每个受击目标仍读取结算时的对应元素抗性；
- 负元素精通、非有限数值、缺少角色 owner slot 或不一致的 Profile 引用必须在写入前失败。

## 4. TransformativeReactionInput

Damage 使用的稳定字段：

```text
occurrence_ref | cause_ref
reaction_profile_key
source_kind
source_level
level_multiplier_table_key
level_multiplier
elemental_mastery
mastery_bonus
reaction_bonus
base_multiplier
defense_policy
```

`base_multiplier` 必须来自 `GeneratedDamageImpactEffect.transformative_base_multiplier`。协调器不得按 `reaction_key`、`damage_kind_key` 或 Damage Profile 维护普通超载、超导、碎冰、感电等反应的倍率副本。

## 5. 公式

```text
mastery_bonus = 16 * EM / (EM + 2000)

damage =
    level_multiplier
    * base_multiplier
    * (1 + mastery_bonus + reaction_bonus)
    * resistance_multiplier
```

普通剧变固定：

- `can_crit = false`；
- `elemental_amount = 0`；
- `defense_policy = approximate_unity`；
- 防御乘数按 `1.0` 近似，不调用普通防御公式。

`approximate_unity` 是明确的工程近似，不表示游戏中的防御影响绝对为零。

## 6. 派生伤害 Effect

`GeneratedDamageImpactEffect` 至少冻结：

```text
effect_ref
effect_group_ref
effect_order
cause / parent_occurrence_ref
main_attack_tag
damage_profile_key
damage_element
gate_definition_key
damage_kind_key
captured_scaling_basis
transformative_base_multiplier
elemental_amount = 0
can_crit = false
strike_type?
```

元素量为零只禁止 Aura ICD、附着和元素施加型反应。稳定 `strike_type` 仍可作为状态型反应证据；当前普通超载用它表达钝击。

## 7. 审计与验证

DamageResult 必须可审计来源分类、等级、直接表 key、等级系数、元素精通、精通收益、反应加成、基础倍率、防御策略和目标抗性乘区。

长期至少覆盖：

- 直接表首尾与表外失败；
- `EM = 0` 和非零 EM；
- 负数、非有限输入和未知来源失败；
- 不可暴击与 `approximate_unity`；
- occurrence 后来源属性变化不影响已捕获输入；
- 不同目标按各自当前抗性结算。

具体反应数值见[超载反应契约](./反应/超载反应契约.md)、[超导反应契约](./反应/超导反应契约.md)和[碎冰反应契约](./反应/碎冰反应契约.md)。Damage 领域说明见[伤害系统设计](../../架构/系统/伤害系统设计.md)。
