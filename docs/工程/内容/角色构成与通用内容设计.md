## 1. 文档定位

本文记录关于以下问题的讨论结论与当前方向：

- 一个角色由哪些部分构成
- `generic/` 应该放什么
- 角色侧哪些构成更适合先标准化

本文不是完整实现说明书，也不把底层 builder API 当作设计起点。

## 2. 已收敛的方向

### 2.1 `generic/` 的定位

`generic/` 放的是**会被角色、武器、圣遗物等内容调用的通用内容**。

它是 content 层的通用构成 / 可复用部件，不是：

- 具体角色、武器、圣遗物的独有实现替代品
- 领域结算系统
- 通用脚本引擎
- 仅服务于测试装配的空占位符集合

### 2.2 现有 `generic.noop` / `generic.test_*` 的定性

当前仓库中的：

```text
generic.noop
generic.test_character
generic.test_weapon
generic.test_artifact_set
generic.static_modifiers
```

主要是**装配与测试占位 key**。

已确认理解：

- 它们会被默认 registry 注册，并被测试资产 / 装配测试使用
- 当前实现基本是 `NoOpRuntimeHandler`，不提供真实内容行为
- 它们**没有必要**为了“补齐 generic”而去做成真正通用内容实现
- 它们不主导 `generic/` 的设计
- 不需要为此建立 `generic/testing/` 目录

`generic.static_modifiers` 虽有正式能力意味的名字，当前同样是占位；若未来做真实静态属性通用能力，应视为新设计，而不是“把占位符实现掉”。

### 2.3 设计切入方式

不从过细的底层拼装函数出发，例如先设计大量：

```text
build_xxx_request(...)
build_yyy_action(...)
```

这类能力可以是后续实现细节，但不应反客为主。

正确切入方式是：

```text
先看角色 / 武器 / 圣遗物由什么构成
-> 找出其中跨内容重复出现的构成部件
-> 再决定哪些进入 generic
```

### 2.4 content 与处理层的关系

与[内容系统设计](../../架构/内容系统设计.md)第 7 节一致：

```text
content / generic  -> 定义“有什么”和标准构成如何装配
领域系统 / 协调器  -> 处理“怎么合并、怎么生效、怎么结算”
```

## 3. 角色最小构成

当前作为讨论基线的角色构成如下。

```text
角色
├── 1. 身份
│   ├── handler_key
│   ├── version
│   └── 组装入口
│
├── 2. 静态资料消费
│   ├── 资产参数进入 content 的方式
│   └── 面板 / 倍率 / CD / 能量等静态值的编译结果
│
├── 3. 可操作技能集
│   ├── 输入解释
│   ├── 动作定义
│   └── 衔接 / 取消 / 连段等动作控制
│
├── 4. 机制效果
│   ├── 伤害
│   ├── 治疗
│   ├── 护盾
│   ├── Buff / 标记
│   ├── 能量相关
│   └── 创造物 / 其他
│
├── 5. 私有状态
│   └── 只属于该角色的资源、标记、阶段
│
└── 6. 被动与触发
    └── 天赋 / 命座具体效果 / 事件型后续
```

### 3.1 最小可仿真角色

几乎必须：

1. 身份与 `version`
2. 至少能解释输入并进入动作
3. 至少一个可验证效果（通常是伤害或治疗）

常有，但不要求一次做完：

4. 完整普攻链
5. E / Q 与公共条件
6. 私有状态
7. 被动

明确后置：

8. 复杂 hook 被动
9. 高独有资源规则

## 4. 角色侧更适合先标准化的构成

讨论中已明确：角色方面应优先关注**所有角色都有、且大部分相同**的部分。

当前优先对象：

### 4.1 普通攻击

共性：

- 所有角色都有
- 通常是基础可重复攻击槽
- 常为多段连段
- 受普攻天赋等级驱动

角色私有：

- 段数、帧表、倍率
- 是否附魔 / 附元素
- 特殊改写

方向：

```text
适合沉淀“标准普通攻击槽位 / 连段骨架”
不适合做成“一个 generic 普攻打所有角色”
```

### 4.2 重击

共性：

- 所有角色都有重击槽
- 都由特定输入进入
- 都有自身时间与效果点

差异：

- 不同武器类型与角色的重击形态差异较大
- 部分角色重击会明显变形

方向：

```text
可沉淀“标准重击槽位”
但可能需要分型
不能过早收成单一重击模板覆盖全部角色
```

### 4.3 天赋 / 技能等级

共性：

- 普攻天赋
- 元素战技天赋
- 元素爆发天赋
- 等级影响倍率与相关参数
- 可被命座等效果提高技能等级

方向：

```text
适合沉淀“角色天赋等级消费框架”
即等级如何进入普攻 / 重击 / E / Q 等参数
```

### 4.4 命座

共性：

- 都有 C0 到 C6 的解锁式增强结构

差异：

- 每个命座的具体效果几乎全是角色私有

方向：

```text
适合沉淀“命座解锁与挂载框架”
不适合把具体 C1/C2/... 效果实现塞进 generic
```

## 5. 当前分层理解

```text
1. 包私有层
   handler_key / version
   interpreter 私有判断
   私有状态
   独特技能规则
   具体命座效果

2. 通用构成层（generic 候选）
   普通攻击槽位 / 连段骨架
   重击槽位骨架
   天赋等级框架
   命座解锁框架
   后续再考虑标准直伤 / 治疗等效果部件

3. 领域处理层
   伤害 / 治疗 / Buff / 能量 / 冷却 / 协调器
```

## 6. 暂不作为角色 generic 主体的部分

- E / Q 的独特机制脑
- 角色私有资源与特殊状态机
- 复杂被动触发
- 现有 noop / test 占位 key 的“正式实现化”

## 7. 建议的后续讨论顺序

1. **普通攻击**作为通用构成，最小包含什么
2. **重击**与普攻共享什么、哪里必须分型
3. **天赋等级**如何进入各技能参数
4. **命座**解锁框架与具体效果贡献如何分工

在上述构成讨论清楚前，不先下落过细的底层 builder 清单。

## 8. 仍待确认
