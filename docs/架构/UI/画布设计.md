# 画布设计

> 状态：正式规范。
> 本文定义 UI 工作流画布的产品形态、区域模型、数据模型、节点连线语义与分析区域承载方式。
> 最后更新：2026-08-29。

## 1. 产品定位

- 新项目应用端定位为分析工具，核心能力围绕仿真结果、战斗复盘、参数扫描和结果对比逐步展开。
- UI 的一等公民是“批”（一组模拟输入）；单次模拟输入是批的特例。
- 采用单一无限画布承载完整链路：配置 → 模拟 → 分析；画布即工作流，工作流可保存、复用与重跑。
- 产品始终以画布为中心，不设置脱离工作流上下文的独立运行历史页面；历史结果通过分析区域的数据提供节点进入当前工作流。
- 工作流选择、新建、重命名和管理属于顶部栏，不占用画布节点工具区；顶部栏同时承担“全部运行”入口。

### 1.1 用户认知边界

- 界面假定用户熟悉原神中的角色、武器、圣遗物、队伍、目标和战斗过程，不假定用户理解项目代码、数据契约或存储结构。
- 常规界面使用显示名称和任务语义，不暴露或要求用户输入 `asset_key`、`handler_key`、JSON 路径、`session_id` 等内部标识。
- 内部标识只允许出现在明确的排障或开发入口中，不能成为常规配置、运行和分析流程的必需知识。

## 2. 整体模型

- 画布上创建“区域”，区域是画布对象：创建时选择类型（配置区域/分析区域）与名称，可移动、缩放；第一版不支持折叠；允许存在多个同类型区域。
- 节点放入区域获得归属；游离节点可以作为草稿存在，但不能连接或参与运行。
- 模拟节点是画布级节点，不归属任何区域；输入侧只连接配置区域的边界输出，输出侧只连接分析区域的边界输入。
- 数据语言随区域切换：配置区域流经片段数据与输入文档；模拟节点把输入集合转换为会话集合；分析区域流经会话数据与派生结果。
- 工作流定义保存于 `<data_dir>/workflows/`，一个 JSON 文件一个工作流。

## 3. 数据模型

### 3.1 根数据与片段数据

- 根数据：携带根身份的完整 JSON 文档，自根节点出发。
- 片段数据：节点直接产生、不携带根的修改内容。
- 根数据之间不可合并；片段数据之间可以合并（深合并），合并结果仍为片段数据。
- 片段数据遇到根数据时，将整条片段链按顺序应用到根文档，产出新的根数据。

### 3.2 覆盖规则

- 覆盖只发生在同一叶子字段存在多个写入者时。
- 覆盖被允许，但画布必须显示警告：被覆盖节点提示“将被节点 X 覆盖，最终不生效”，覆盖节点提示覆盖了哪些字段。
- 生效顺序由连线/端口顺序决定，后生效者覆盖先生效者。
- 覆盖不阻止运行；配置区域的边界输出始终展示应用后的最终文档、成员数量和校验状态，供用户核对。

### 3.3 会话数据

- 模拟节点输出一组 `session_id`（会话数据），是分析区域的数据起点。
- 分析区域的数据语义见[分析区域设计](./分析区域设计.md)：会话维度显式化，框架不做隐式按成员展开。

## 4. 区域模型

- 区域类型：配置区域、分析区域。
- 区域是强规则边界：画布对象面板按区域类型提供；连线必须遵守“配置区域内 ↔ 模拟节点 ↔ 分析区域内”的阶段顺序；配置节点不得直接连接分析节点。
- 每个配置区域固定拥有一个边界输出，代表该区域形成的一组完整模拟输入；区域内参与输出的节点必须先汇入该边界，不能直接连接区域外对象。
- 每个分析区域固定拥有一个边界输入，接收画布级源节点（模拟节点 / 数据提供节点）的会话组；区域外对象不能越过边界直接连接分析节点，区域内节点从边界输入取得数据。
- 分析区域的边界输入是区域内数据的唯一输入源；边界输入可以不连接，此时区域内没有数据来源，节点保持未连接/空态。历史结果通过画布级数据提供节点连入边界输入。
- 区域边界端口属于区域，不是可移动节点。区域移动或调整尺寸时，外部连线只跟随边界端口，不依赖内部节点位置。
- 多个同类型区域允许，例如两个配置区域各生成一批输入，都汇入同一模拟节点。
- 第一版区域不开放嵌套。
- 区域通过画布对象面板中的区域项拖入画布创建，创建后自动进入一次命名态（默认名“配置区域”全选，直接输入即替换，点画布别处保持默认名）；可随时重命名、调整大小；创建后配置区域头部提供「区域校验」与「区域运行」入口（见[项目决策记录](../../决策/项目决策记录.md) 2.28），分析区域头部提供「运行分析」入口（见[分析区域设计](./分析区域设计.md) 8.1）。
- 区域重命名：双击区域名称或 hover 头部出现的铅笔按钮进入行内编辑；Enter/失焦提交，Esc 取消，空名或全空格不提交并恢复原名；名称最长 60 字符、不要求唯一，重命名进入撤销历史。
- 区域尺寸调整：选中区域后拖动右下角手柄（textarea 样式）调整大小，松手提交为一个撤销步骤；最小 400×240；缩放只改区域边界，内部节点绝对位置不变。区域缩到小于内部节点边界时在问题列表给出警告。
- 画布对象面板提供“全部 / 配置 / 分析”显式筛选。点击配置或分析区域、点击区域内节点时切换到对应类型；点击模拟节点或画布空白处保持当前筛选。鼠标移动、悬停和拖拽现有对象不得切换画布对象面板内容。
- 创建入口为纯拖入：区域项拖到画布任意位置即创建（允许与现有区域重叠）；节点项拖入区域即归属，拖到空白画布成为游离草稿。第一版不提供点击创建，面板不维护“添加目标”。
- 拖拽反馈：拖拽中显示半透明对象预览；节点预览进入兼容区域时区域边框高亮；落在空白或不兼容位置时预览标“草稿”。放下后新对象自动选中并标记未保存。
- 落点判定：以节点中心（放下位置）所在区域决定归属；多个区域重叠时归最后创建（z 序在上）的区域。
- 游离草稿使用虚线边框与“草稿”徽标；不能连线、不能参与运行，校验以警告/错误在问题列表定位；把草稿拖回兼容区域即恢复归属，不设专门菜单。
- 工作空间采用有边界的弹性布局：工具区可以收起，画布随窗口与工具区伸缩；第一版不支持任意停靠、插件面板、用户自定义工作区和移动端布局。
- 第一版面向桌面鼠标与键盘，最低内容视口为 `1280 × 720`。
- 左侧工具区采用“常驻窄工具轨 + 按需展开面板”：工具轨提供节点和问题入口，两者共享一个展开面板；面板收起后工具轨仍保持可用。工具内容只由用户明确点击切换，不随鼠标移动或悬停变化。第一版不设置“大纲”工具。

## 6. 模拟节点

- 一个模拟节点 = 一个批次：按输入连线收集所连配置区域边界输出的成员，各自提交一个批次；多个区域连同一节点时按连线顺序合并成一批，一个区域连多个节点时数据复制、各自成批（2026-08-22 确认，见[项目决策记录](../../决策/项目决策记录.md) 2.28）。
- 模拟执行唯一路径：配置区域边界输出 → 模拟节点，不存在绕过模拟节点的模拟提交。未连接模拟节点的配置区域给警告并不参与任何批次；错误只挂在“批次无法成立”（所连成员为 0 或超过上限 200）。
- “全部运行”按画布顺序依次串行执行各节点的批次：前一批到终态才提交下一批；某批失败不中断后续批次；取消停止当前批次并跳过剩余。
- 批次运行名称取该节点所连第一个区域的元信息名称；并发度为模拟节点参数（1–16，缺省“自动”即 `min(4, CPU)`）；第一版不支持结果复用，重跑即重新执行。
- 输出每个成员的 `session_id`，作为会话数据组交给分析区域。
- 状态反馈按成员展开：排队、运行中、成功、失败、取消；失败原因贴近对应成员。
- 提供“取消整批”动作：排队成员立即取消，运行中成员跑完后标记取消并显示“正在停止”；成员级取消后续版本支持。
- 模拟节点不记录状态，职责只限分发与管理模拟；需要重新获取结果时从配置重新运行。

## 7. 分析区域

分析区域的节点模型、端口语言、执行模型与交互设计由[分析区域设计](./分析区域设计.md)统一承载；节点 kind 与参数契约见[节点与区域契约](../../契约/ui/节点与区域契约.md)，查询计划与执行端点见[分析系统契约](../../契约/分析系统契约.md)。本画布文档不维护分析节点清单与组展开语义。

## 8. 连线语义

- 分支：一个输出连到多个下游时，数据复制到每个分支。
- 汇入顺序：多个上游连到同一节点时按节点输入端口顺序执行，先连先应用；用户可调整端口顺序。
- 入线顺序交互：同一输入端口存在多条入线时，端口旁显示数量徽标，点击后在画布内弹出顺序列表，按当前顺序列出来源节点并支持上移/下移；顺序变化立即更新覆盖警告。第一版不提供拖拽排序，连线数组顺序即生效顺序。
- 连线路径：MVP 使用自动布线；手动路径调整后置。
- 禁止环路：画布必须是 DAG；检测到环时标出环上连线并阻止运行。
- 组标记：组端口显示成员数量徽标；配置区域的组输出连线显示展开倍数（×N），分析区域会话组不做隐式展开。
- 区域约束：跨区连线只允许经过画布级源节点（模拟节点 / 数据提供节点）与区域边界端口；数据语言不匹配的连线报错。
- 边界约束：跨区域连线只能连接区域边界端口与画布级源节点（模拟节点 / 数据提供节点）。外部对象不能直接连接区域内节点，区域内节点也不能直接连接区域外对象。

## 9. 保存与重跑

- 工作流定义文件保存于 `<data_dir>/workflows/`，JSON 格式，包含：schema_version、配置/模拟/分析三部分的节点与连线、节点参数、视图配置、画布布局（区域与节点位置）。
- 编辑期临时状态（视口、选中、拖拽）不保存。
- 重跑模式：
  - 全部重跑：重新执行配置、模拟、分析整条链。
  - 仅分析重跑：使用数据提供节点从结果库提供会话，只重新执行分析部分。
  - 增量重跑第一版不做。
- 数据提供节点把所选会话作为节点配置保存；分析区域边界输入不保存会话，模拟节点会话来自其 `last_sessions`（并随批次保存 `last_input_fingerprint` 供过期判定，见[分析区域设计](./分析区域设计.md) 8.2），数据提供节点会话来自其节点参数。
- 模拟节点不记录状态；重新获取模拟结果从配置重新运行。
- 分析是派生层，重跑分析不修改结果库真值。
- 保存必须由用户明确触发，界面持续显示未保存状态；运行不会隐式保存或清除未保存提示。
- 保存按钮保持普通样式，未保存状态由顶部栏徽标承担，不对按钮做警告强调。

## 10. 运行与导航

- 顶部栏提供“全部运行”，执行工作流运行：构建（前端编译与图校验，失败零批次提交）→ 模拟（按画布顺序依次串行执行每个模拟节点的批次）→ 终态联动结果面板；阶段模型见[项目决策记录](../../决策/项目决策记录.md) 2.28。顶部栏不提供运行模式选择菜单。配置区域头部提供「区域校验」与「区域运行」两个入口：「区域校验」复用构建与逐批校验后停止，不提交模拟；语义见 2.28。分析区域头部提供「运行分析」：获取输入（边界连接的模拟节点缺会话时自动补跑并写回 `last_sessions`）→ 数据处理（区域级查询计划一次执行）→ 视图加载；语义见[分析区域设计](./分析区域设计.md) 8.1。重跑模式仍区分全部重跑与仅分析重跑，但入口由对应区域/分析能力承担。
- 运行过程以执行轨迹表达（见[项目决策记录](../../决策/项目决策记录.md) 2.28）：一次运行 = 有序步骤序列（配置节点的方法应用步骤按「根节点 → 边界输出」拓扑序排列、区域边界收拢步骤、批次提交前的区域校验步骤、模拟节点批次步骤），每步引用画布对象并承载状态与诊断；构建阶段按方法逐步限速推进，「运行动画」开关可在设置中关闭。
- 执行期间节点按状态着色：未运行、等待、运行中、成功、失败、结果过期；着色由执行轨迹步骤状态驱动，运行中对象的连线高亮，未参与本次运行的对象置灰；错误贴近对应字段或节点；视图节点成功后直接显示结果。
- 运行期间禁止会改变工作流含义的编辑，避免执行中修改造成结果不一致；查看、平移、缩放、选择和问题跳转等非语义导航仍可使用。
- 字段和节点附近显示局部反馈，同时提供集中的问题列表用于汇总、筛选和跳转；两者不能互相替代。
- 删除：主路径为选中对象后按 Delete（Backspace 同样生效），Esc 先清除选择。删除节点连带删除其全部连线，删除连线只删该条；多选删除作为一个原子撤销步骤。节点悬浮时头部显示 24px 删除按钮，区域仍为选中时显示，平时隐藏。焦点在输入框或编辑器内时删除键优先编辑文本。删除不弹确认，运行期间删除禁用；删除后校验立即刷新，破坏链路的诊断可在问题列表定位。
- 撤销/重做：所有语义编辑（创建、移动、调整大小、连线、排序、删除、参数提交、重命名、路径修改）进入撤销历史；多选删除、拖动结束、输入提交各计一步；视口、选择与正在输入的文本不进历史。历史基于模型操作，不保存 DOM 快照，按工作流独立。撤销到与最后保存一致时未保存徽标消失。运行期间撤销/重做禁用。
- 快捷键：Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 与 Ctrl+Y 重做；Ctrl/Cmd+S 保存；Ctrl/Cmd+Enter 全部运行；Ctrl/Cmd+= 与 Ctrl/Cmd+- 缩放，Ctrl/Cmd+0 适应全部；方向键微移选中节点（1px，Shift 时 10px）。焦点在输入框时 Ctrl/Cmd+Z 交给输入框原生撤销，Ctrl/Cmd+S 与运行快捷键保持全局生效。撤销/重做按钮位于工具轨顶部，禁用时置灰。
- 导航范围：
  - 平移：鼠标中键拖拽（浏览器原型不验证中键手感）；空白画布左键拖拽做框选；点击选择区域/节点，拖动区域标题栏移动区域，拖动节点头部移动节点。
  - 缩放：滚轮以鼠标位置为中心，范围 25% ~ 400%；提供适应全部与定位选中。
  - 搜索节点定位。
  - 小地图：结构总览，显示区域、节点、连线、模拟节点与当前视口；支持定位选中和折叠/展开。
  - 书签第一版不做。
- 画布视觉：动态背景固定为氛围层；网格使用单层 24px 点阵；空画布显示“拖入区域开始”；小地图与左侧图标按钮位于画布右下角。
- 连线交互：从输出端口拖到输入端口建立连接；端口按数据语言区分标记，组端口显示“N 个值”；连线路径可手动调整。

## 11. 工程边界

- `frontend/` 通过 `server/` HTTP API 调用 `application/` 能力，不直接访问 SQLite，不组装仿真核心对象，不实现分析算法。配置区域边界预览调用 `POST /inputs/validate`，运行状态轮询 `GET /runs/{run_id}`。
- 校验分工：前端编译期诊断只负责提前反馈；`POST /inputs/validate` 是提交前的最终执行校验，两端口径不一致时以后者为准。
- 画布实现需区分：WorkflowDefinition（持久化定义）、WorkflowEditorState（编辑与临时交互状态）、WorkflowValidator（类型、路径、环、覆盖与区域校验）、WorkflowRuntime（展开、应用、提交已展开成员并跟踪批次状态）。后三者落在 `frontend/`。
- 画布编辑状态不进入 `core/`。CLI 不运行工作流。后端批次 API 只接受 `(item_id, SimulationInput)`，工作流 JSON 仅作不透明存档。
- 工作流定义、节点类型与编辑器数据、批量配置变体、UI API 契约已创建于 `docs/契约/ui/`。
