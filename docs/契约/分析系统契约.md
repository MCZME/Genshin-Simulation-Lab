# 分析系统契约

> 状态：已确认（2026-08-25 分析算子化重做 v2 定稿）。本版以「取数节点 + 关系算子 + 查询计划一次编译执行」取代 v1 的模板目录与单模板执行端点；v1 四张模板、`GET /api/v1/analysis/templates` 与 `POST /api/v1/analysis/templates/{template_id}/execute` 全部退役，退役与迁移规则见第 9 节。
> 系统设计与模块落位见[分析系统设计](../架构/分析系统设计.md)；UI 节点模型与交互见[分析区域设计](../架构/UI/分析区域设计.md)。

## 1. 术语

- **取数节点**：分析子图的数据入口，按会话组从结果库读出一张基础表（`fetch_runs` / `fetch_events`）。
- **算子节点**：对输入表做纯关系变换的节点（过滤、投影、排序、分组聚合、截断、连接、计算列）。
- **会话组**：会话 ID 的有序去重列表；唯一语义是约束取数节点的行范围，算子节点不感知会话概念。
- **条件组**：过滤节点的结构化条件列表，见第 5 节。
- **形状**：某节点输出表的列清单（列名 + 类型），由第 7 节规则静态推导。
- **查询计划**：前端从工作流子图编译出的结构化执行请求（节点清单 + 参数 + 输入关系 + 输出清单），不含任何 SQL 文本。

## 2. 节点种类与端口

| kind | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `fetch_runs` | 无（会话组经区域边界注入） | `table` | 读 `simulation_runs` |
| `fetch_events` | 无（同上） | `table` | 读 `simulation_events` |
| `filter` | `table` ×1 | `table` | 条件组过滤 |
| `project` | `table` ×1 | `table` | 选列 + 可选重命名 |
| `sort` | `table` ×1 | `table` | 多列排序 |
| `aggregate` | `table` ×1 | `table` | 分组聚合 |
| `limit` | `table` ×1 | `table` | 行数截断 |
| `join` | `table` ×2 | `table` | 等值连接（inner / left） |
| `compute` | `table` ×1 | `table` | 受限数值计算列 |

- 端口数据语言沿用两套：`session_group`（仅区域边界 → 取数节点）与 `table`（其余全部连线）。
- 会话维度不是隐式机制：所有源表携带 `session_id` 列，逐场、跨场汇总、跨批对比都是 `session_id` 与普通列上的显式操作。
- 节点参数随工作流定义保存（前端拥有）；算子的参数结构与形状规则是本契约（后端拥有），两端各自实现、靠契约测试对齐。

## 3. 取数节点

### 3.1 `fetch_runs`

```json
{
  "snapshot_columns": [
    { "path": "team.slots.0.character.asset_key", "name": "char_1_key", "type": "string" }
  ]
}
```

- 参数全部可省略。会话组作为唯一行范围约束。
- 固定输出列 = `simulation_runs` 全部列（见[结果库契约](./结果库契约.md)第 4.2 节）**除去** `input_snapshot_json` 与 `initial_snapshot_json` 两列（大 JSON 整体不进入分析管道）；类型映射 `TEXT→string`、`INTEGER→int`。
- `snapshot_columns`（≤ 64 个）从 `input_snapshot_json` 按点分路径提取具名列，规则同第 3.2 节提取列；成员指标的条件列（变体身份）经此获得，路径清单来自输入快照契约文档。

### 3.2 `fetch_events`

```json
{
  "event_types": ["DAMAGE_RESOLVED", "HEALING_RESOLVED"],
  "frame_min": 0,
  "frame_max": 18000,
  "payload_columns": [
    { "path": "amount", "name": "damage", "type": "float" }
  ]
}
```

- 全部字段可省略：`event_types` 缺省为全部事件类型；`frame_min` / `frame_max` 缺省不限；事件类型与帧过滤属于取数参数（利用现有索引做谓词下推），行级筛选仍归过滤算子。
- 固定输出列：`session_id`、`ordinal`、`frame`、`event_type`，其后依次接提取列。
- 提取列 ≤ 64 个；`path` 为 `data_json` 内的点分路径；值按声明类型转换，路径缺失或无法转换置 `NULL`；`type ∈ string | int | float | bool`。
- 事件类型名与 payload 字段的稳定性继承结果库契约（类型名冻结、字段只增不改），本契约不重复维护清单；编辑器可选项来自第 6.3 节 schema 端点。

## 4. 表达式语言

### 4.1 条件组（过滤节点参数）

```json
{
  "mode": "all",
  "conditions": [
    { "column": "dps", "op": "gte", "value": 50000 },
    { "column": "weapon_1_key", "op": "in", "value": ["a", "b"] },
    { "column": "end_frame", "op": "is_not_null" }
  ]
}
```

- `mode ∈ all | any`，单层条件列表，不支持嵌套；嵌套 AST 是后续升级方向，本形状可平滑演进。
- 空条件组（`conditions` 缺省或 `[]`）按恒真语义编译为透传，不报错。
- 操作符白名单：

| 操作符 | 编译形态 | 适用类型 | 备注 |
| --- | --- | --- | --- |
| `eq` | `col = ?` | string / int / float / bool | |
| `ne` | `(col != ? OR col IS NULL)` | 同上 | 采用符合直觉的可空语义 |
| `not_in` | `(col NOT IN (?) OR col IS NULL)` | 同上 | 空数组校验报错 |
| `in` | `col IN (?, ...)` | 同上 | 空数组校验报错 |
| `gt` / `gte` / `lt` / `lte` | `col > ?` 等 | 仅 int / float | 字符串字典序无分析意义，校验拒绝 |
| `is_null` / `is_not_null` | 一元 | 全类型 | 无 `value` 载荷 |

- 文本匹配（LIKE 类）、`between`、正则、列与列比较全部不进白名单。
- 所有字面量以绑定参数执行（prepared statement 语义）；列名必须存在于该节点输入形状中才允许引用。排除明确不做拼接 SQL。

### 4.2 计算列表达式（计算列节点参数）

```json
{ "name": "dps", "expr": {
  "op": "/",
  "left": { "col": "total_damage" },
  "right": { "op": "/", "left": { "col": "frames_run" }, "right": { "lit": 60 } } } }
```

- `op ∈ + - * /`；叶子只能是 `{ "col": 列名 }` 或 `{ "lit": 数值字面量 }`；深度上限 16。
- `/` 一律按浮点语义执行（不发生整数截断）；除数为 0 结果为 `NULL`。
- 表达式中引用的列必须存在且为数值类型。

## 5. 算子参数与形状推导

每个算子的输出形状由输入形状与参数唯一确定；规则在本节冻结，前端（编辑器与校验）与后端（执行前防御性检查）各自实现同一套推导，不一致的计划以 `400 / validation_failed` 拒绝。

### 5.1 过滤 `filter`

- 参数：第 4.1 节条件组。输出形状 = 输入形状。

### 5.2 投影 `project`

```json
{ "columns": [ { "name": "total_damage", "as": "damage" }, { "name": "session_id" } ] }
```

- 输出 = 按列出顺序的子集；`as` 可省略；输出列名不得重复；类型随源列。
- `columns` 至少一列，空数组校验失败。

### 5.3 排序 `sort`

```json
{ "keys": [ { "column": "dps", "direction": "desc" }, { "column": "session_id", "direction": "asc" } ] }
```

- 至少一列；`direction ∈ asc | desc`；输出形状 = 输入形状。

### 5.4 分组聚合 `aggregate`

```json
{
  "group_by": ["session_id"],
  "aggregates": [
    { "fn": "sum", "column": "damage", "as": "sum_damage" }
  ]
}
```

- 聚合函数白名单：`sum` / `count` / `avg` / `max` / `min` / `stddev` / `p95`；除 `count` 外要求源列为数值类型。
- `group_by` 与 `aggregates` 至少提供其一；两者皆空校验失败。
- 输出形状 = 分组列（原名原序）+ 聚合列；聚合列命名：`as` 省略时自动为 `<fn>_<column>`，输出列名不得重复。
- 类型映射：`count → int`；`min / max / sum → 随源列`；`avg / stddev / p95 → float`。
- 语义约定：`count` 为该列非空计数；`stddev` 为**总体标准差**（除以 n，与 v1 口径一致）；`p95` 为线性插值分位数；口径以后端实现为唯一真值并配 golden 断言。

### 5.5 截断 `limit`

- 参数 `{ "count": n }`，`1 ≤ n ≤ 10000`；输出形状 = 输入形状。

### 5.6 连接 `join`

```json
{ "left_key": "session_id", "right_key": "session_id", "mode": "left" }
```

- 仅按键等值连接；`mode ∈ inner | left`（左表保留全部行）。多输入口的第一个输入为左表。
- 输出形状 = 左表全部列 + 右表中与左表不重名的列；右表需要保留的重名列应先经投影改名。左连接时右表列补 `NULL`。

### 5.7 计算列 `compute`

- 参数：第 4.2 节表达式数组（≥1）；输出形状 = 输入形状 + 计算列（追加在末尾）；表达式列类型恒为 `float`（`+ - *` 在两侧均为 int 时结果为 int）。

## 6. 查询计划执行

### 6.1 `POST /api/v1/analysis/query`

```json
{
  "session_ids": ["a1b2c3", "d4e5f6"],
  "nodes": [
    { "id": "runs1", "kind": "fetch_runs" },
    { "id": "ev1", "kind": "fetch_events", "params": { "event_types": ["DAMAGE_RESOLVED"], "payload_columns": [ { "path": "amount", "name": "damage", "type": "float" } ] } },
    { "id": "agg1", "kind": "aggregate", "params": { "group_by": ["session_id"], "aggregates": [ { "fn": "sum", "column": "damage" } ] }, "inputs": ["ev1"] },
    { "id": "j1", "kind": "join", "params": { "left_key": "session_id", "right_key": "session_id", "mode": "inner" }, "inputs": ["runs1", "agg1"] },
    { "id": "c1", "kind": "compute", "params": { "columns": [ { "name": "dps", "expr": { "op": "/", "left": { "col": "sum_damage" }, "right": { "op": "/", "left": { "col": "frames_run" }, "right": { "lit": 60 } } } } ] }, "inputs": ["j1"] }
  ],
  "outputs": ["c1"]
}
```

- 计划即子图的规范序列化：节点带 `kind`、`params`、有序 `inputs`（取数节点无 inputs）；**不含任何 SQL 文本**。
- 校验规则（失败一律 `400 / validation_failed`，`details` 逐项给出 `node_id` 与原因）：DAG 无环；inputs 数量符合算子定义；全图形状可推导；列引用存在且类型合法；`outputs` 非空且 ≤ 32 且均为计划内节点。
- 后端将各节点编译为 CTE 链在结果库上一次执行，中间结果不出后端；响应只携带 `outputs` 声明的表：

```json
{
  "tables": {
    "c1": {
      "columns": [ { "name": "session_id", "type": "string" }, { "name": "dps", "type": "float" } ],
      "rows": [["a1b2c3", 61500.0]],
      "truncated": false
    }
  }
}
```

### 6.2 上限

- `session_ids` ≤ 1000（有序去重，超限 `validation_failed`）。
- 每张返回表硬上限 10000 行，超出置 `truncated: true`；v1 不分页。
- v1 的「关系表 5000 行上限」随中间表不再出后端而退役。

### 6.3 `GET /api/v1/analysis/schema`

取数节点编辑器的可读 schema 数据源：

```json
{
  "tables": {
    "simulation_runs": { "columns": [ { "name": "frames_run", "type": "int", "description": "实际运行帧数" } ] }
  },
  "event_types": [
    { "name": "DAMAGE_RESOLVED", "fields": [ { "path": "amount", "type": "float", "description": "结算伤害值" } ] }
  ]
}
```

内容来自结果库契约的冻结清单与事件类型文档，端点只做聚合转发，不另立真值。事件类型清单以 core `EVENT_SPECS` 为真值源完整聚合；payload 字段映射当前只登记已有明确消费需求的事件类型（`DAMAGE_RESOLVED` / `HEALING_RESOLVED` / `BUFF_APPLIED` / `BUFF_REMOVED`），其余事件类型 `fields` 为空，编辑器允许手动填写载荷路径，映射随视图需求登记。

## 7. 错误语义

- 计划或参数校验失败：`400 / validation_failed`，`details` 数组逐项给出 `node_id` 与原因码（未知列、类型不匹配、环、输入数量不符、超限等）。
- 其余沿用仓库通用错误结构；v1 的 `404 / not_found`（未知模板）随模板退役不再出现。

## 8. golden 断言

- 聚合函数口径（含 `p95` 插值）、`/` 浮点语义与除零置 `NULL`、`ne` 可空展开、形状推导规则，均以后端实现为唯一真值，配最小 golden 用例锁定。

## 9. v1 退役与存量迁移

- 下线：`session_metrics`、`timeline_rows`、`share_rows`、`metric_summary` 四张模板；`GET /api/v1/analysis/templates`；`POST /api/v1/analysis/templates/{template_id}/execute`；「值链 / 关系链」概念（跨列运算归计算列，表间组合归连接）。
- 存量工作流定义加载时：`processing` 与 `query_config` 节点及其连线移除，视图节点保留并呈空态；不做结构等价自动转换，用户以取数节点 + 算子重建分析链。
- 时间轴持续段配对（Buff 施加/移除按实例配对）等非关系代数逻辑不在本契约内，留待专门处理节点扩展。

## 10. 稳定性规则

- 节点 `kind`、参数结构、操作符与聚合函数白名单、形状推导规则冻结：只增不改，不改名不改语义；破坏性变更走契约新版本。
- 事件类型与 payload 字段稳定性继承[结果库契约](./结果库契约.md)，本文不重复声明。
- 对外端点形状是契约；变更走 API 版本升级。
