# UI 工作流实现规划

> 状态：生效，切片 1 已完成，随实现推进持续维护。
> 本文只排定实现切片、依赖顺序与验收，不重复定义端点、图语义或变体规则。正式契约见 [UI API 契约](../契约/UI API 契约.md)、[工作流定义契约](../契约/工作流定义契约.md)、[批量配置变体契约](../契约/批量配置变体契约.md) 与[节点类型与编辑器数据契约](../契约/节点类型与编辑器数据契约.md)。
> 关联：[项目决策记录](../决策/项目决策记录.md) 2.29、[迁移阶段安排](./迁移阶段安排.md)、[前端工程规范](./前端工程规范.md)。

## 1. 目标

- 工作流是 UI 产品面；CLI 不提供工作流的创建、校验或运行。
- 后端不实现工作流图引擎，只做工作流 JSON 不透明存档、已展开成员校验与批次运行。
- 前端拥有图语义：区域、节点、连线、校验、片段合并、变体展开、成员预览。
- 第一条纵向链路：根节点 → 配置区域（含枚举/区间）→ 模拟桥 → 结果摘要。

## 2. 实施切片

按依赖关系排定六个切片。切片 1、2、4 可并行；切片 3 依赖 1、2；切片 5 依赖 3、4；切片 6 依赖全部。

### 切片 1：后端批次执行模型（已完成）

- 落点：`application/batch/`、`application/services/`、`application/facade.py`。
- 内容：
  - 定义 `BatchMember`、批次状态视图与 `BatchRunService`。
  - 继续复用现有单任务 `SimulationJobRunner` 与 worker，批次层只做 `run_id -> member_id -> job_id` 映射、并发、取消和状态派生。
  - 支持 `POST /inputs/validate` 所需的已展开成员校验：结构校验、`item_id` 唯一、成员上限 200、资产存在性与可运行性。
  - facade 增加成员校验、提交批次、查询批次、取消批次能力。
- 验收：
  - 成员顺序与提交顺序一致。
  - 成功、部分失败、全部失败、取消均可通过状态视图表达。
  - 排队成员立即取消；运行中成员进入 `stopping`，跑完标 `cancelled`。
  - 任一份输入失败时批次不提交，并返回带 `item_id` 的诊断。
  - 超过 200 个成员被拒绝。
- 验证：批次服务专项测试、facade 批次集成测试，以及 application、任务 runner 和进程 worker 回归测试均已通过。

### 切片 2：工作流存档

- 落点：`application/services/workflows.py`、`infrastructure/file_storage/workflow_store.py`。
- 内容：
  - 定义 `WorkflowStore` 协议与不透明 JSON 文件实现。
  - 服务端生成安全 `id`；列表、读取、整份替换保存、删除。
  - 不解析图语义、不校验节点/连线、不接受任意文件路径。
- 验收：
  - 创建返回空骨架；保存为整份替换；重命名通过保存 `meta.name` 完成。
  - 不存在的 `id` 返回 not found，不隐式创建。
  - 文件位于 `<data_dir>/workflows/`，一个工作流一个 JSON。

### 切片 3：HTTP API 与 DTO

- 落点：`server/`，OpenAPI 由契约生成前端类型。
- 内容：
  - 按 [UI API 契约](../契约/UI API 契约.md) 暴露 MVP 端点。
  - 补齐 facade 缺口：结果列表 `offset`、`damage_metrics`、资产 `q` 搜索与展示字段。
  - 隐藏 `data_dir`、数据库路径与 `handler_key`。
- 验收：
  - 16 个 MVP 端点可调用，错误响应统一为 `{code, message, details}`。
  - 批次轮询只使用 `GET /runs/{run_id}`，不拆成员子资源。
  - OpenAPI 可生成前端 TypeScript 类型。

### 切片 4：前端图语义编译

- 落点：`frontend/src/workflow/`。
- 内容：
  - 定义模型：`WorkflowDefinition`、区域、节点、端口、连线。
  - 语义注册表：MVP 配置节点、枚举/区间、模拟桥。
  - 校验器：区域归属、端口类型、DAG、覆盖警告、路径语法、成员上限。
  - 批次编译器：根数据 + 片段链深合并、枚举/区间展开、同路径覆盖、不同路径叉乘、稳定 `item_id`。
  - 输出与 `POST /inputs/validate`、`POST /runs` 请求一致的已展开成员。
- 验收：
  - 纯 TypeScript，不依赖 React Flow，可单测。
  - 区间使用十进制计算，避免浮点累积；步长、终值包含规则与契约一致。
  - 调整枚举顺序后成员连线仍按 `item_id` 指向。
  - 覆盖警告、超限错误可结构化返回。

### 切片 5：画布纵向切片

- 落点：`frontend/src/components/`、`frontend/src/state/`、`frontend/src/api/`。
- 内容：
  - React Flow 画布壳、配置区域、节点编辑器、模拟桥、问题面板。
  - `WorkflowEditorState` 与 `WorkflowDefinition` 双向转换。
  - API 客户端：工作流存档、输入校验、批次提交、轮询、结果摘要。
  - 第一条链路：根节点 → 配置区域（含枚举/区间）→ 模拟桥 → 结果摘要。
- 验收：
  - 配置区域边界展示最终成员数量、校验状态与覆盖警告。
  - 点击运行后提交已展开成员，轮询 `GET /runs/{run_id}` 更新节点状态。
  - 模拟桥按成员展示 `queued / running / stopping / completed / failed / cancelled`。
  - 运行完成后展示摘要指标；部分失败按成员呈现。

### 切片 6：端到端验收

- 内容：
  - 前端编译 → 校验 → 提交 → 轮询 → 指标展示的完整链路。
  - 覆盖失败、取消、部分失败、成员顺序与重跑。
  - 同步修正本规划与相关契约。
- 验收：
  - 第一条纵向链路稳定可用。
  - 后端不解析工作流图；CLI 不提供工作流命令。
  - 契约、工程规范与实现一致。

## 3. 并行与依赖

```text
切片 1 后端批次      ─────────┐
切片 2 工作流存档     ─────────┤→ 切片 3 HTTP API → 切片 5 画布
切片 4 前端图语义编译 ─────────┘                    ↓
                                          切片 6 端到端验收
```

- 切片 1、2、4 互相独立。
- 切片 3 需要批次与存档能力，不依赖前端编译器。
- 切片 5 需要前端编译器与 HTTP API。
- 切片 6 是最终集成，不在中途铺开全部画布外围功能。

## 4. 暂不实现

- 分析区域节点（查询/指标/聚合/对比/视图）与对应端点。
- 工作流图校验、节点类型注册表等后端 API。
- 按工作流 ID 或内联图提交运行。
- SSE/WebSocket 推送；第一版统一轮询。
- 批次运行状态持久化；第一版以内存注册表为主。
- 资产图像、输入/结果上传下载、结果详情中的输入与初始快照。
- 资产库构建与更新端点（继续走 CLI/安装包流程）。

## 5. 需要先拍板的点

1. **批次状态生命周期**：已确认第一版使用 `BatchRunService` 内存注册表，服务重启后旧批次不可查；若后续要求重启恢复，再独立设计批次库，不提前做。
2. **区间十进制实现**：前端不引入重依赖时，用整数缩放或定点十进制；在切片 4 开始前定稿，保证成员顺序与 `item_id` 测试稳定。

## 6. 主要风险

- 资产可运行性校验已在切片 1 接入资产仓库与内容注册表；对外诊断不暴露 `handler_key`，HTTP DTO 仍待切片 3 完成。
- 前端编译器与后端输入校验可能产生两套校验口径；以 `POST /inputs/validate` 为最终执行校验，前端诊断只负责提前反馈。
- 批次层复用单任务 runner 时不要跨进程共享 SQLite 连接或已组装运行时对象。
- 画布交互是产品复杂度较高的部分，切片 5 只覆盖第一条纵向链路，避免在 MVP 阶段铺开全部画布外围功能。
