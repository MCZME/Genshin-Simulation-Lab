# 结晶反应设计

> 状态：已实现
> 最后更新：2026-08-01
> 对应契约：[结晶反应契约](../../../../契约/元素反应/反应/结晶反应契约.md)

## 1. 定位

普通结晶由岩元素命中火、水、雷或冰 Aura 触发。它不产生反应伤害，也不形成普通岩 Aura，而是创建一个带元素、来源捕获值和生命周期的晶片状态，并在战场空间中建立一一对应的 `REACTION_OBJECT` 投影。

晶片被类型化拾取入口消费后，协调器原子结束 Reaction State、删除 Space Entity，并通过 Shield 的窄计划端口授予同元素结晶护盾。物理碰撞、距离检测和拾取资格不是 Reaction 或 Shield 的职责。

## 2. 领域所有权

| 领域 | 拥有内容 |
| --- | --- |
| Reaction | 方向、元素量消费、成立 Gate、来源捕获、晶片语义状态和生命周期终态 |
| Aura | 火水雷冰 Aura 数量与消耗提交 |
| Aura ICD | 本次岩元素是否提供正元素预算 |
| Space | 晶片实体的位置、朝向、存在投影和版本化实体计划 |
| Shield | 护盾容量公式、冲突策略、活动护盾聚合和受伤吸收 |
| Coordination | Aura、Reaction、Space、Shield 计划的准备、交叉校验、无回调提交和事实顺序 |

Reaction State 不复制空间坐标，Space Entity 不复制元素量、来源捕获值或拾取终态。结晶反应不直接 import 或修改 Shield、Space 的 Runtime 或 Store。

## 3. 方向与基础效果

普通结晶只支持后手岩元素：

| 方向 | Aura | 晶片元素 |
| --- | --- | --- |
| `incoming_geo_on_pyro` | 火 | 火 |
| `incoming_geo_on_hydro` | 水 | 水 |
| `incoming_geo_on_electro` | 雷 | 雷 |
| `incoming_geo_on_cryo` | 冰 | 冰 |

火、水、雷、冰不能反向触发普通结晶。无伤害的岩元素施加只要经过 Aura ICD 后仍有正元素预算，也可以触发结晶。

一次成立的普通结晶产生：

- 一个 `ReactionOccurrence`；
- 一个 Aura 消费变更；
- 一个目标级成立 Gate 变更；
- 一个 `CrystallizeShardState` 创建意图；
- 一个 `SpatialEntityCreationEffect`；
- 不产生 `GeneratedDamageImpactEffect`。

## 4. 元素量与成立 Gate

设通过 Aura ICD 的岩元素预算为 `G`，候选 Aura 当前量为 `A`：

```text
geo_consumed = min(G, 2 * A)
aura_consumed = geo_consumed / 2
remaining_geo = G - geo_consumed
remaining_aura = A - aura_consumed
```

岩元素预算不形成持久岩 Aura。未消耗的岩预算只供同一次显式候选序列继续判定。

普通结晶使用目标级成立 Gate：

- 窗口 `60` 帧；
- 窗口内最多成立 `1` 次；
- 同一目标上的不同来源、不同晶片元素共享 Gate；
- Gate 必须在 Aura 消费、occurrence、晶片状态和空间实体创建之前预检；
- Gate 阻止时不消费 Aura、不创建 occurrence、不创建晶片，也不留下单侧空间投影；
- `frame == ready_frame` 时重新可用。

## 5. 复合候选顺序

`CrystallizeRule` 本身只接受单 Aura；复合状态必须由 Reaction Runtime 的显式候选序列展开，不能依赖 Registry 注册顺序或隐式遍历。

### 5.1 水雷共存

水雷共存目标固定按雷、再水尝试：

```text
Electro -> Hydro
```

第一次雷结晶成立后会在同帧打开共享 Gate，因此第二次水结晶被 Gate 阻止。结果是只创建雷晶片；水 Aura 保留，岩预算是否还有剩余不改变这一结论。

队伍具备月结晶 capability 时，水步骤优先尝试[月结晶](./月结晶反应设计.md)候选：雷结晶照常成立，岩预算足够时水步骤改为月结晶成立（不受普通成立 Gate 约束），同一批内同时产生雷晶片与月结晶月笼/累计记录；不具备 capability 时维持本节普通水结晶被 Gate 阻止的结论。

### 5.2 冻结状态

岩命中活动冻结状态时，普通结晶不能直接读取隐藏水或冰。只有本次命中同时具有钝击语义并先完成碎冰，后续候选才可以读取已经暴露的隐藏元素并尝试结晶。

因此：

- 钝击岩命中可先碎冰，再对暴露的隐藏水或冰尝试结晶；
- 非钝击岩命中不会绕过冻结状态读取隐藏元素；
- 结晶候选仍受同一目标级成立 Gate 约束。

## 6. 来源捕获与护盾基础值

结晶成立时通过专用来源观察读取触发者等级和元素精通，并立即冻结为 `CapturedCrystallizeShieldBasis`。晶片创建后，来源属性变化不得改写已有晶片。

```text
elemental_mastery_bonus = (40 / 9) * EM / (1400 + EM)
native_absorption = level_coefficient * (1 + elemental_mastery_bonus)
```

其中：

- `level_coefficient` 只能查找已冻结的 `1-100` 级三位小数直接表；
- 不允许曲线拟合、插值或范围外外推；
- `EM` 必须为有限非负数；
- 90 级、`0 EM` 的审计基准为 `1851.060`；
- `native_absorption` 是晶片携带的原生护盾容量，不包含受保护角色当前护盾强效或来伤元素吸收倍率。

## 7. 晶片状态与空间投影

每个成功 occurrence 创建独立的 `CrystallizeShardState`：

```text
instance_ref = reaction-state:crystallize-shard:<occurrence_ref>
space_entity_ref = reaction_object:crystallize_shard:<occurrence_ref>
```

状态保存：

- 所属目标与创建 occurrence；
- 火、水、雷或冰晶片元素；
- 触发来源和捕获的护盾基础；
- `created_frame`、`expires_at_frame`；
- `active`、`picked` 或 `expired` 生命周期状态；
- 终态帧与 revision。

晶片活动区间为半开区间 `[created_frame, expires_at_frame)`，普通生命周期固定 `900` 帧。`next_required_frame` 只在活动状态下返回到期帧。

Space 使用目标当前位置和朝向作为稳定创建锚点，实体类型为 `REACTION_OBJECT`，标签包含 `reaction_object` 和 `crystallize_shard`。当前实现不声称模拟精确掉落偏移、移动、受击或场上数量上限。

## 8. 跨领域事务

### 8.1 创建

成功结晶在第一次写入前准备并校验 Aura、Aura ICD、Reaction Gate、Reaction State 与 Space Entity 的全部计划。晶片状态和空间实体必须满足一一 binding；任一版本、前值、锚点或 binding 校验失败时，整个交互批次不提交。

### 8.2 到期

`ReactionBoundEntityExpiryCoordinator` 在到期帧原子提交：

```text
CrystallizeShardState(active -> expired)
SpaceEntity(remove)
```

到期帧已经不属于活动区间，因此同帧拾取必须失败。到期流程不创建护盾。

### 8.3 拾取

`CrystallizeShardPickupCoordinator` 接受已经完成物理资格判断的类型化请求，并按 `operation_id` 幂等执行：

```text
CrystallizeShardState(active -> picked)
SpaceEntity(remove)
ShieldGrantPlan(commit)
```

三方计划在第一次写入前完成版本、完整前值、binding 与授予策略校验；提交阶段不重新查询、不重新计算、不回调其他领域。任一准备或校验失败时，晶片仍保持活动、空间实体仍存在、护盾不创建。

## 9. 结晶护盾

拾取普通晶片时：

- 护盾元素与晶片元素一致；
- 容量直接使用晶片捕获的 `native_absorption`；
- 护盾持续时间固定为从拾取帧起 `900` 帧；
- 默认保护范围为 `active_team:team:player`；
- 普通结晶护盾共享 `reaction.crystallize.shield` 冲突键；
- 授予策略为 `REPLACE`，新结晶护盾替换同冲突键的活动实例。

护盾强效、同元素吸收倍率、多个适用护盾的吸收顺序和角色受伤结算继续由 Shield 与角色受伤协调器动态处理，不写回晶片状态。

## 10. 事实与快照

结晶不新增 `CRYSTALLIZE_*` 专属事件类型：

- 成功反应使用 `REACTION_OCCURRED`、Aura/interaction 和成立 Gate 的通用审计记录；
- 晶片创建、拾取或到期通过 `REACTION_STATE_CHANGED` 记录完整状态变化；
- 拾取授盾发布 `SHIELD_GRANTED`，替换旧盾时可先发布 `SHIELD_REMOVED`；
- Space Snapshot 只保存实体存在和空间投影，不保存 Reaction 或 Shield 真值。

事实只能在所有领域提交完成后发布。发布期间 Reaction、Space 与 Shield 进入写保护，订阅者不能同步反向修改当前批次状态。

## 11. 非目标

当前普通结晶不实现：

- 物理碰撞、距离、阵营和实际拾取资格；
- 自动拾取和自动扫描晶片；
- 精确掉落位置、移动、受击或不可拾取延迟；
- 场上晶片数量上限及旧晶片延迟清理；
- 角色专属晶片消费、特殊覆盖规则和 content 效果；
- 月结晶。

这些能力需要各自的可信数值来源、窄协议和 golden case，不能通过扩展当前协调器的任意参数提前实现。
