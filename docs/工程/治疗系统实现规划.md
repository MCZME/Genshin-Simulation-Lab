# 治疗系统实现规划

> 状态：第一轮已完成，阶段 D 首个真实治疗能力已完成。
> 架构职责见[治疗系统设计](../架构/系统/治疗系统设计.md)，公共数据与行为契约见[治疗系统契约](../契约/治疗系统契约.md)。
> 最后更新：2026-08-09。

## 1. 实施目标

建立独立于生命状态的治疗数值结算能力，并通过事件和 `HealthRuntime` 完成单目标治疗闭环。

第一轮只覆盖类型化请求入口，不接入真实 content 或 `ImpactKind.HEAL`。

本节描述第一轮边界；阶段 D 已在此基础上接入首个真实治疗能力（见阶段记录）。

## 2. 第一轮范围

已完成：

- 多 component 治疗请求、结果和结构化错误。
- 治疗基础值、治疗加成与受治疗加成公式。
- 纯计算 `HealingResolver`。
- `HEALING_RESOLVED` 事件和通用 JSON 持久化。
- `HealingRequestHandler`、生命系统 adapter 和 assembler 暴露。
- 普通、溢出、满血、零治疗和生命提交失败测试。
- 超大整数、聚合溢出和事件引擎错配回归测试。

未包含：

- 真实角色、武器、命座或圣遗物治疗 content。
- 队伍、范围和多目标治疗分发。
- `ImpactKind.HEAL` payload 与 dispatcher 接线。
- 周期治疗、快照、生命之契和生存状态。
- 真实数值 golden case、UI 和 analysis。
- `SimulationInput`、资产库 schema 或结果库 schema 变更。

## 5. 阶段 D 任务

阶段 D 首个真实治疗能力（芭芭拉环持续治疗与爆发治疗）已完成，验收路径已满足；其余角色/范围治疗按以下开放任务继续推进。

已完成：

1. 选择真实治疗能力（芭芭拉环持续治疗与爆发治疗）并复核机制来源、倍率、固定值、目标、时序和快照规则。
2. 设计 `ImpactKind.HEAL` 到 `HealingRequest` 的 content payload 与目标引用契约。
3. 由 content 构造治疗请求，禁止直接修改当前生命；纵向集成验证见 `tests/integration/content/barbara/`。
4. 建立最小真实数值验证：爆发治疗与环持续治疗的预期数值由纵向测试锁定。

待推进：

1. 范围治疗与更通用的多目标展开规则：单体与全队已由芭芭拉覆盖，范围治疗仍待定型。
2. 接入更多真实角色/范围治疗 content，并为每个能力补充可信来源与数值验证。
3. 治疗快照、生命之契和生存状态按后续需求单独评审（周期治疗已由芭芭拉环持续治疗覆盖）。

阶段 D 验收：至少一个真实治疗能力可以从运行时影响请求进入治疗 handler，数值具有可信来源并可由 golden case 复现（芭芭拉环持续治疗与爆发治疗已满足该验收路径）。

## 8. 完成判定

阶段 A-C 当前满足：

- 治疗公式独立于生命状态并生成不可变理论结果。
- 多 component、负加成、零治疗和溢出行为可验证。
- resolver 不依赖事件或生命系统。
- handler 固定按“理论结算事实 -> 生命提交”编排，并保证共用事件引擎。
- 满血和零治疗不产生虚假生命变化事件。
- 治疗事件无需结果库 schema 变更即可持久化。
- assembler 暴露的 handler 可以实际提交角色生命并产生有序事件。

阶段 D 首个真实治疗能力已随芭芭拉内容完成；其余角色/范围治疗完成后继续更新本规划状态与能力矩阵。
