# 分析系统设计

> 状态：已确认（2026-08-25 分析能力重做定稿）。原 analysis 顶层模块及其 processors（状态还原、数据寻址、序列、指标、对比）已删除，分析能力按“数据 = 结果库内容、处理 = SQL 模板”重做。
> 关联：[分析系统契约](../契约/分析系统契约.md)、[分析系统规划](../工程/分析系统规划.md)、[结果存储系统设计](./结果存储系统设计.md)、[结果库契约](../契约/结果库契约.md)、[分析区域设计](./UI/分析区域设计.md)、[模块边界设计](./模块边界设计.md)。

## 1. 定位

分析系统是结果存储系统的派生层：基于结果库真值（运行记录、输入快照、初始快照、事件流）加工出可展示、可比较的结果表。分析不写库、不改变结果库真值；所有派生结果可重建。

核心模型：

- **数据 = 结果库内容**，形式即数据库形式（`simulation_runs`、`simulation_events` 两张主表 + JSON 字段）。
- **处理 = SQL 模板**：模板由后端拥有，前端只提交“模板 id + 参数绑定 + 关系表”。
- 每次模板执行返回**一张表**（列 + 行 + 截断标记）；展开参数 v1 只有 `union` 模式。

## 2. 模块边界

不再保留顶层 `analysis/` 模块，职责按既有依赖方向落位：

| 模块 | 职责 | 约束 |
| --- | --- | --- |
| `infrastructure/results_sqlite/templates.py` | 模板注册表：声明 + SQL + 可选 Python 行变换；参数绑定、关系 CTE/临时表拼装、行数上限 | SQL 与结果库 schema 强耦合，声明与实现同处 |
| `application/models.py`、`application/services/analysis_templates.py` | 模板契约模型（`TemplateDeclaration`、`TemplateResult` 等）与用例门面（`AnalysisTemplatesService`） | 只做声明级校验，不接触数据库实现 |
| `application/facade.py` | 公开能力出口：模板目录与执行 | 入口层唯一调用点 |
| `server/` | `GET /api/v1/analysis/templates`、`POST /api/v1/analysis/templates/{template_id}/execute` | DTO 层，不直接访问 infrastructure |

依赖方向：`server / cli -> application -> 模板执行协议 <- infrastructure 实现`。模板执行协议（`AnalysisTemplateExecutor`）定义在 `application/services/protocols.py`，由 `SQLiteAnalysisTemplateExecutor` 实现。

## 3. 模板契约

每张模板由四部分组成（全部后端拥有）：

- **SQL**：对结果库的查询语句；关系输入用 `{{名称}}` 占位，执行时替换为连接级临时表。
- **参数声明**：名称、类型、必填/可空、绑定类别。绑定类别：`static`（节点卡内输入）、`config`（查询参数配置节点）、`session_group`（会话组展开）、`upstream_column`（上游结果表选列，值链）。
- **关系输入声明**：名称 + 所需列；下游 SQL 把上游结果表当作输入关系（临时表/CTE 语义）。
- **输出形状**：列名 + 类型；v1 不做语义标签，列语义由模板文档说明。

参数绑定必须是安全的参数替换（prepared statement 语义），不允许拼接 SQL。展开参数 v1 只有 `union` 模式：一句 SQL 带 IN 列表执行一次，输出一张表，`session_id` 是输出列；`per_value`（逐会话执行、组输出）不进 v1。

## 4. 执行模型

- 前端按拓扑序逐节点执行模板；每个节点一次执行请求，上游结果表随下游请求传回。
- 关系输入以“columns + rows”传输，后端校验列与声明匹配后写入连接级临时表，再替换 `{{名称}}` 执行 SQL。
- 值链：下游参数值来自上游结果表某一列，前端把列值取出来放进 `params`，API 层面无特殊机制。
- 行数限制：结果行硬上限 10000，超出置 `truncated: true`；关系表上限 5000 行，超限拒绝；v1 不分页。
- 时间轴等模板允许注册 Python 行变换（如持续段的事件配对），模板契约（参数/输出声明）不变。

## 5. 稳定性规则

- 模板集只增不改：`template_id`、参数声明、关系输入声明与输出列语义冻结；破坏性变更走新模板。
- 输出列名与类型冻结；列只增不改。
- 对外端点形状（模板目录、执行请求/响应）是契约，变更走 API 版本升级。

## 6. 与结果存储系统的关系

- 真值层：运行记录、输入快照、初始快照、事件流（结果库）。
- 派生层：模板执行结果（结果表）；可重建，不落库。
- 物化（跳变表等）只按性能需要建立，永远可重建。
