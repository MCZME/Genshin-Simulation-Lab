# 星超导反应契约

> 状态：正式规范。
> 本文固定星超导独立反应的稳定标识、候选与元素消费、极星辉域 State、队伍共享计数与窗口结算、层数系数映射及独立星烁伤害公式的请求边界。
> 最后更新：2026-09-12。

## 1. 稳定标识

| 类型 | 稳定键或值 |
| --- | --- |
| 星超导 | `reaction.stellar_conduct` |
| 星超导 Handler | `reaction_handler.stellar_conduct` |
| 冰触发雷方向 | `stellar_incoming_cryo_on_electro` |
| 雷触发冰方向 | `stellar_incoming_electro_on_cryo` |
| 冰触发雷 Profile | `reaction_profile.stellar_conduct.incoming_cryo_on_electro` |
| 雷触发冰 Profile | `reaction_profile.stellar_conduct.incoming_electro_on_cryo` |
| 极星辉域 State | `reaction_state.polestar_field` |
| 极星辉域空间 Profile | `reaction_spatial_profile.polestar_field` |
| 队伍共享计数 State | `reaction_state.stellar_conduct_counter` |
| 星超导 capability | `reaction_capability:stellar_conduct` |
| 星烁伤害公式 | `damage_formula.stellar_reaction` |
| 星烁伤害输入/结算 | `StellarReactionDamageInput` / `StellarReactionDamageResolution` |
| 星烁伤害模式 | `character_direct` / `reaction_composite` |
| 领域队伍作用域 | `player_team` |

命名不使用社区俗称 `star_superconduct`，也不复用 `lunar_*` 命名空间。星超导 Definition 必须由 `create_default_reaction_bootstrap()` 组合进生产 bundle；缺失注册在组装阶段失败。星超导不注册普通 Reaction Damage Profile、Damage kind 或 Damage Gate。

## 2. 候选与元素消费

星超导只匹配以下条件同时满足的交互：

1. 请求携带 `reaction_capability:stellar_conduct`；
2. 请求携带上游确认的角色来源集合 `character_source_refs`；
3. 当前触发来源 `source_ref` 属于该角色集合；
4. 冰雷方向：冰触发正雷 Aura，或雷触发正冰 Aura。

星超导 `selection_priority` 为 `110`，高于普通超导默认 `0`；无 capability 或合法角色触发来源时星候选不匹配，普通超导继续生效。capability 存在但后续计划缺少空间锚点、binding 不一致或其他技术前提缺失时整批失败，不静默回退为普通超导。

| incoming_element | observed_aura_kind | 消费关系 |
| --- | --- | --- |
| `cryo` | `electro` | `1:1` |
| `electro` | `cryo` | `1:1` |

```text
consumed = min(incoming_amount, aura_amount)
```

星超导 occurrence 不产生公共反应伤害，也不声明普通 Damage Gate；剩余后手元素量的处理与普通超导一致（不自动形成持久 Aura）。

## 3. 极星辉域 State

极星辉域 State 字段：

```text
instance_ref / space_entity_ref / subject_ref
created_by_occurrence_ref / trigger_source_ref / team_ref
created_frame / expires_at_frame / revision
```

约束：

- `instance_ref` 必须等于 `reaction-state:polestar-field:{created_by_occurrence_ref}`，`space_entity_ref` 必须等于 `reaction_object:polestar_field:{created_by_occurrence_ref}`；
- `expires_at_frame >= created_frame + 420`，创建时等于 `created_frame + 420`；领域生命周期的真值是"最近一次触发后 420 帧"；
- 刷新必须保留 `instance_ref`、`subject_ref`、`space_entity_ref`、`trigger_source_ref`、`created_by_occurrence_ref` 和创建帧，只延展存在时间并递增 `revision`；
- 刷新批次必须包含同一 Space 实体的生命周期更新：保留创建帧与位置，仅同步 `expires_at_frame`；State 刷新与 Space 更新数量一一对应，缺失或不一致时批次校验失败。

创建/刷新/替换规则（由 `plan_polestar_field_occurrence` 形成确定性计划）：

- 触发目标位置（Space 实体锚点）处于当前领域外（X/Z 距离 `> 12`）时：移除旧领域 State 与 Space 实体，以新位置创建新领域；
- 处于当前领域内（X/Z 闭区间 `<= 12`，忽略 Y 轴）时：保留实例与圆心，刷新 `expires_at_frame = frame + 420`，并同步更新 Space 实体的生命周期投影；
- 无领域时在触发目标当时位置创建，圆心与角色位置无关；
- 同一队伍至多一个领域，同一批次出现多个待建领域时由批次校验失败；
- 到期帧由 `PolestarFieldExpiryCoordinator` 原子移除 State、Space 实体与队伍共享计数。

半径 `12`、无限高度与 `420` 帧持续时间为实现基线；半径来源尚未完全确定，精确帧边界待来源化用例确认（见第 9 节）。

## 4. 队伍共享计数 State 与附着记录

计数 State 字段：

```text
instance_ref / subject_ref / team_ref
window_start_frame / next_settlement_frame / window_index
pending_count / settled_stacks
recorded_record_refs / excluded_attack_refs / revision
```

约束：

- `instance_ref` 必须等于 `reaction-state:stellar-conduct-counter:{team_ref}`，slot scope 为队伍；
- `next_settlement_frame = window_start_frame + 240`；
- `window_index` 从 `1` 连续递增；`revision` 随每次变更递增；
- `recorded_record_refs` 与 `excluded_attack_refs` 不能重复。

附着记录使用 `StellarConductAttachmentRecord`：

```text
record_ref / attack_ref / element / frame / target_refs
```

- `element` 只允许冰或雷；`target_refs` 为非空去重序列；
- 追加必须满足：计数与领域 State 存在、领域未到期、`record_ref` 未在当前窗口记录、`attack_ref` 不在 `excluded_attack_refs`、至少一个目标 X/Z 距离领域圆心 `<= 12`；
- 一次攻击对多个敌人的附着由调用方聚合为一条记录；双判的两次攻击为两条记录；同一攻击多目标与多个辉映角色都不重复计数；
- 新领域生成（创建或替换）时，触发该次星超导的攻击身份写入 `excluded_attack_refs`，只在当前窗口生效；
- 领域替换不重置计数：窗口、层数与计时跨领域替换继承，共享会话结束时才整体移除。

## 5. 周期结算

`4` 秒（`240` 帧基线）窗口到期时：

1. 帧规范化把本帧 due 的计数结算冻结为 `StellarConductCounterSettlementRootWork`（cause kind `stellar_conduct_counter_settlement`，`tick_index = window_index`）；
2. 同一批次推进窗口：`settled_stacks = pending_count`、清空 `pending_count` / `recorded_record_refs` / `excluded_attack_refs`、`window_index += 1`、`next_settlement_frame += 240`；
3. scheduled root adapter（`reaction_scheduled_root_adapter.stellar_conduct`）返回无 Effect 的 `prepared`；State 缺失时返回 `cancelled_state_ended`；
4. 结算不生成公共反应伤害；协调器据此统一更新队伍角色的辉映·星烁 Buff 属于 Buff 接线切片。

层数查询按 `12` 层封顶：`stacks = min(settled_stacks, 12)`；State 保留原始计数。

## 6. 层数系数映射

直伤星烁基础系数（`n` 为结算层数快照）：

```text
n = 0            -> 1
1 <= n <= 12     -> 1.4 + 0.05 * n
n > 12           -> 2
```

辉映·星超导领域内冰/雷普通伤害增益：

```text
n = 0            -> 20%
1 <= n <= 12     -> 28% + 1% * n
n > 12           -> 40%
```

映射出处为[梅信心：伤害公式](https://meropide.cn/chs/reference/%E4%BC%A4%E5%AE%B3%E5%85%AC%E5%BC%8F/)（2026-09-10 版本基线）。冰/雷普通增伤通过辉映 Buff 的 `bonus.damage.cryo` / `bonus.damage.electro` 属性修正进入通用伤害增伤区；Buff 接线落地前该增益不生效。

## 7. 独立星烁伤害公式与请求边界

星烁伤害使用独立 `damage_formula.stellar_reaction`，不注册普通 Reaction Damage Profile 或 Damage kind；伤害分类使用主攻击标签 `reaction.stellar_conduct`。

`damage_formula.stellar_reaction` 请求校验（`DamageRequest`）：

- 必须携带 `StellarReactionDamageInput`；非星烁公式不得携带该输入；
- 不得同时携带增幅、二次增幅、剧变、激化或月曜反应输入；
- `mode = character_direct` 首期用于直伤星超导；`mode = reaction_composite` 留待星扩散阶段启用，用于逐参与者结算与 `0.60 / 0.30 / 0.05 / 0.05` 稳定权重聚合。

直伤星烁区间顺序：

```text
direct_stellar_damage =
  (
    scaling_value
    * stellar_base_multiplier
    * (1 + stellar_base_bonus)
    * (1 + 6 * elemental_mastery / (elemental_mastery + 2000) + stellar_bonus)
    * stellar_authority_multiplier
    + direct_stellar_feather_addition
  )
  * critical_multiplier
  * resistance_multiplier
  * (1 + stellar_ascension_bonus)
```

- 直伤星烁不能产生元素附着，也没有普通攻击、重击、下落攻击、元素战技或元素爆发伤害类型标签；
- 星烁基础系数、星烁基础增伤、星烁增伤、星烁大权区、直伤/反应星烁羽毛区和星烁擢升使用强类型字段，不通过普通 `DamageModifierTerm` 伪造；
- 公式实现无状态，不读取 Buff、ReactionState 或协调器；暴击沿用注入式 `CriticalDecisionProvider`；
- 结算器分支与 `DamageResult` 星烁审计尚未接入，当前 `damage_formula.stellar_reaction` 只冻结请求校验与无状态公式（见第 9 节）。

## 8. 事务、事实与错误边界

星超导候选、极星辉域 State/Space 创建与刷新、计数 State 变更、结算根与到期移除均使用 `prepare -> validate -> commit`。State、Space 与事实的前值/版本任一 stale 时，整批失败且不得部分提交；State 与 Space binding 不一致由 `validate_polestar_field_space_bindings` / `validate_polestar_field_space_terminalizations` 在提交前拒绝。

必须记录通用 `REACTION_OCCURRED`、`REACTION_STATE_CHANGED` 和 `ELEMENTAL_INTERACTION_RESOLVED`；周期结算不伪造 occurrence。同一 `record_ref` 重复记录、窗口外结算、刷新缩短存在时间、非冰雷附着元素都是显式失败；领域外目标与被排除的触发攻击是正常不计数结果。

## 9. 当前非目标与验收入口

契约不包含：

- 辉映·星烁 Buff 的统一创建/刷新/移除、离域约 1 秒延续与重置语义（Buff 接线切片）；
- 极星辉域来源复用普通超导物理减抗 Buff（同 Definition、属性词条与 conflict slot，不叠加为 `-80%`）的领域来源适配；
- 附着记录的上游事件接线（攻击/Aura 施加事件到 `StellarConductAttachmentRecord` 的聚合）；
- `damage_formula.stellar_reaction` 的结算器分支、`DamageResult` 星烁审计与角色直伤技能模组；
- 星扩散（星辉风旋、反应星扩散·风/冰与 `reaction_composite` 的生产启用）；
- `420` 帧、`240` 帧、半径 `12` 的精确数值冻结；当前为来源化实现基线，半径来源尚未完全确定，不作为正式数值 golden case。
