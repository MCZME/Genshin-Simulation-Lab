# 应用出口与入口边界设计

> 状态：已确认（2026-08-17）。
> 本文定义 Python 后端的公开能力出口，以及 `cli/`、`server/` 与内部模块的边界。具体领域职责、存储协议和 UI API 字段由对应架构与契约文档负责。

## 1. 总体决策

`application/` 是 Python 后端唯一的公开能力出口。CLI 与网页服务端都是入口适配层，只能通过 `genshin_sim.application` 的公开接口调用后端能力。

```text
frontend
    -> server
        -> application
cli
    -> application

application
    -> core / content / assets / analysis / infrastructure
```

这里的“唯一出口”约束外部入口调用，不要求内部模块之间的每次调用都重新经过 `application`。`core/` 仍保持纯仿真运行时核心，不能反向依赖 `application/`。

## 2. `application/` 的职责

`application/` 是面向产品用例的后端门面和编排层，负责：

- 暴露稳定的应用能力、请求模型、响应模型和应用错误。
- 编排配置、资产、工作流存档、任务、仿真执行、结果读取与分析调用。
- 管理一次应用实例所需的运行资源和生命周期。
- 通过协议调用具体存储、文件和任务执行实现，不在用例中编写具体 SQL。

入口层只依赖 `genshin_sim.application` 的公开出口。应用内部的 service、assembly、execution、jobs 和 batch 属于实现细节，除非被显式列入公开 API，不对入口层形成稳定承诺。

应用公开能力按产品边界分区，当前方向包括：

- 工作区与项目配置。
- 资产只读查询。
- 工作流 JSON 不透明存档（列表/读取/保存/删除），不校验图、不编译变体。
- 已展开成员的输入校验、批次提交、批次状态和整批取消。
- 结果详情、事件和摘要指标。
- 资产按类型搜索与详情（不暴露 `handler_key`）。

具体 `Application` 能力清单、启动选项和生命周期 API 在实现前单独定稿，本文不提前冻结类名或目录细节。

## 3. 入口模块

### 3.1 `cli/`

`cli/` 是命令行入口，负责：

- 解析命令行参数。
- 将参数转换为 application 请求。
- 调用 application 公开能力。
- 将响应格式化为终端输出并选择进程退出码。
- 处理 CLI 专属的日志和交互表现。

CLI 不直接访问 SQLite、文件存储、任务 runner、分析处理器或仿真核心组装器。CLI 不提供工作流的创建、校验或运行。

### 3.2 `server/`

`server/` 是 Python 网页服务端入口，与 `cli/` 同级。它负责：

- 创建和托管 HTTP 服务。
- 路由、请求/响应 DTO、OpenAPI、统一错误映射和中间件。
- 托管前端构建产物。
- 管理一个 application 实例的服务生命周期。
- 将 HTTP 请求转换为 application 请求，并将 application 响应转换为 HTTP 响应。

`server/` 不实现领域公式、工作流校验、批量展开、分析算法或 SQLite 查询，也不直接组装 `Simulator`。

HTTP 服务端不是 `infrastructure/` 的子模块。`infrastructure/` 提供 server 通过 application 间接使用的外部技术实现，例如 SQLite、文件存储、日志和进程任务执行。

## 4. 内部模块边界

| 模块 | 主要职责 | 是否供 `cli/`、`server/` 直接调用 |
| --- | --- | --- |
| `core/` | 仿真领域运行时、领域系统与跨系统协调 | 否 |
| `content/` | 角色、武器、圣遗物和 handler 实现 | 否 |
| `assets/` | 资产数据对象和仓库协议 | 否 |
| `analysis/` | 结果读取侧的派生加工 | 否 |
| `infrastructure/` | SQLite、文件、日志、任务执行等技术实现 | 否 |
| `application/` | 对外能力出口和应用用例编排 | 是，仅通过公开出口 |
| `cli/` | 命令行入口适配 | 不适用 |
| `server/` | HTTP 服务入口适配 | 不适用 |

应用层可以依赖内部模块完成用例，但内部模块不能把 `cli/` 或 `server/` 当作业务依赖。`server/` 的 HTTP DTO 与领域 dataclass 分离；pydantic 等传输层类型只在 `server/` 内使用。

## 5. 依赖与验证规则

- `cli/` 和 `server/` 只能从 `genshin_sim.application` 公共出口导入应用能力。
- 入口层不得导入具体 repository、writer、job runner、`SimulationAssembler`、`Simulator`、content registry 或 analysis processor。
- `application/` 不暴露可变 Store、数据库连接或具体基础设施对象。
- `core/` 不依赖 `application/`、`server/`、`cli/`、`infrastructure/`、`content/` 或 `assets/`。
- 新增入口能力时，先在 application 定义稳定用例和模型，再在 CLI 或 server 中增加适配。
- 入口边界需要通过导入检查和最小集成测试验证，不能只依靠目录约定。
