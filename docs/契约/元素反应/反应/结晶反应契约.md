## 2. Profile 契约

普通结晶方向必须使用 `CrystallizeReactionProfile`：

```text
CrystallizeReactionProfile
├── profile_key
├── reaction_key
├── direction_key
├── trigger_element = GEO
├── shard_element = PYRO | HYDRO | ELECTRO | CRYO
├── establishment_gate_definition_key
├── state_key
├── formula_key
└── lifetime_frames = 900
```

`trigger_element` 不是岩或 `shard_element` 不属于火、水、雷、冰时必须稳定失败。普通结晶 Profile 不声明 Damage Profile 或 Aura application Profile。

## 3. 元素交互与消费

普通结晶只接受后手岩元素和单个火、水、雷或冰 Aura 候选。设岩预算为 `G`，Aura 量为 `A`：

```text
incoming_consumed = min(G, 2 * A)
aura_consumed = incoming_consumed / 2
remaining_incoming = G - incoming_consumed
remaining_aura = A - aura_consumed
```

成立结果必须同时满足：

- `incoming_consumed > 0`；
- occurrence 的 transition 使用对应 Aura kind；
- 晶片元素等于被反应 Aura 的元素；
- 不包含反应伤害 Effect；
- 岩预算不形成持久 Aura。

## 4. 成立 Gate

`reaction_gate.crystallize.establishment` 固定为：

```text
window_frames = 60
max_occurrences = 1
scope = target-level
```

同一目标的不同来源和不同晶片元素共享 Gate。Gate blocked 必须发生在任何 Aura 消费、occurrence、State 或 Space 创建之前，并返回无反应成立结果。`frame == ready_frame` 时 Gate 可再次通过。

## 5. 复合候选契约

- 水雷共存固定按 `ELECTRO`、`HYDRO` 展开候选；同帧第二个候选由共享 Gate 阻止。
- `CrystallizeRule` 不得自行遍历多 Aura 并选择一个方向。
- 活动冻结状态下不得直接读取隐藏水或冰。
- 只有钝击岩命中先完成碎冰后，后续候选才可读取已暴露的隐藏元素。
- 非钝击岩命中不得从冻结状态派生普通结晶候选。

## 6. 来源观察与捕获值

结晶成立必须提供 `CrystallizeSourceObservation`：

```text
CrystallizeSourceObservation
├── source_ref: ElementalSourceRef
├── source_level: int
└── elemental_mastery: finite non-negative float
```

捕获结果为：

```text
CapturedCrystallizeShieldBasis
├── source_ref
├── captured_frame
├── source_level
├── source_elemental_mastery
├── crystallize_level_coefficient
├── elemental_mastery_bonus
└── native_absorption
```

公式固定为：

```text
elemental_mastery_bonus = (40 / 9) * EM / (1400 + EM)
native_absorption = crystallize_level_coefficient * (1 + elemental_mastery_bonus)
```

等级系数使用代码内冻结的 `1-100` 级三位小数直接表。等级必须是 `1` 到 `100` 的整数；范围外查找必须抛出 `CrystallizeLevelOutOfRangeError`，不得拟合或外推。90 级、`0 EM` 的 golden 值为 `1851.060`。

`captured_frame` 必须等于晶片创建帧；`source_ref` 必须等于晶片触发来源。捕获后不得根据来源后续属性变化重新计算。

## 7. 晶片状态契约

```text
CrystallizeShardState
├── instance_ref
├── subject_ref
├── space_entity_ref
├── element
├── created_by_occurrence_ref
├── trigger_source
├── captured_shield_basis
├── created_frame
├── expires_at_frame
├── lifecycle_state: active | picked | expired
├── terminal_frame
└── revision
```

引用必须确定性派生：

```text
instance_ref = reaction-state:crystallize-shard:<occurrence_ref>
space_entity_ref = reaction_object:crystallize_shard:<occurrence_ref>
```

不变量：

- `expires_at_frame = created_frame + 900`；
- 活动区间为 `[created_frame, expires_at_frame)`；
- `active` 的 `terminal_frame` 必须为空；
- `picked` 的终态帧必须位于活动区间；
- `expired` 的终态帧必须等于 `expires_at_frame`；
- 活动状态的 `next_required_frame` 等于到期帧，终态返回空；
- 多个晶片使用独立实例，不共享单例 State slot。

## 8. 空间投影契约

每个晶片创建意图必须带一个 `SpatialEntityCreationEffect`，并满足：

- `space_entity_ref` 与 State 完全一致；
- `owner_key = reaction.crystallize`；
- `source_key = instance_ref.value`；
- 实体类型为 `REACTION_OBJECT`；
- tags 包含 `reaction_object`、`crystallize_shard`；
- 创建与到期帧和 State 一致；
- 创建锚点来自目标的当前稳定位置与朝向。

Space 只拥有实体存在、位置、朝向和版本；不得保存晶片元素、捕获公式或生命周期终态的第二份真值。

## 9. 拾取请求与结果

```text
CrystallizeShardPickupRequest
├── operation_id: non-empty string
├── frame: non-negative int
├── shard_ref: ReactionStateInstanceRef
└── protection_ref: ShieldProtectionRef = active_team
```

```text
CrystallizeShardPickupResult
├── shard_ref
├── element
├── trigger_source
├── captured_shield_basis
├── created_frame
├── expires_at_frame
├── picked_frame
└── shield_grant: ShieldGrantResult
```

相同 `operation_id` 和完全相同请求必须返回已提交结果；相同 `operation_id` 对应不同请求必须抛出 `CrystallizeShardOperationConflictError`。

未知、已拾取和已到期晶片分别稳定失败为：

- `CrystallizeShardNotFoundError`；
- `CrystallizeShardAlreadyPickedError`；
- `CrystallizeShardExpiredError`。

请求不包含距离、碰撞、阵营或拾取者资格字段；这些条件必须由调用协调器之前的上层物理流程判定。

## 10. 护盾授予契约

拾取活动晶片生成 `ShieldGrantRequest`：

```text
mechanic_key = reaction.crystallize.shield
handler_key = reaction_handler.crystallize.shield
element = shard.element
duration_frames = 900
flat_absorption = captured_shield_basis.native_absorption
grant_policy = REPLACE
conflict_key = reaction.crystallize.shield
protection_ref = request.protection_ref
```

创建来源必须是 `character:*` 的触发来源，否则稳定失败。默认保护范围是 active team。护盾过期帧从拾取帧计算，不继承晶片剩余生命周期。

结晶护盾只冻结原生容量；受保护角色的护盾强效和来伤元素倍率由 Shield Runtime 在承伤时动态计算。

## 11. 事务与失败边界

创建事务必须在首次写入前校验 Aura、ICD、Reaction Gate、Reaction State、Space Entity 及 State/Entity binding。任一计划 stale、前值不符、目标锚点缺失或声明不一致时，所有领域保持原状。

到期事务必须原子提交 `active -> expired` 和已绑定实体删除。

拾取事务必须按以下顺序完成准备与预校验：

1. 校验晶片存在且处于活动区间；
2. 准备 `active -> picked` State plan；
3. 准备 Space remove plan；
4. 准备 `ShieldGrantPlan`；
5. 校验三个领域计划和 State/Entity binding；
6. 无回调提交三个领域；
7. 发布已提交事实。

Reaction、Space 或 Shield 任一校验失败时，不得部分消费晶片、部分删除实体或部分授予护盾。`commit_prevalidated` 不得重新查询、计算、发布事实或产生可恢复的领域业务分支。

## 12. 事实与审计

- 成功结晶使用通用 `REACTION_OCCURRED`，不新增 `CRYSTALLIZE_OCCURRED`。
- 晶片创建、拾取和到期使用 `REACTION_STATE_CHANGED`，不新增 `CRYSTALLIZE_SHARD_*` 事件类型。
- 拾取授盾使用 Shield 的 `SHIELD_GRANTED`、`SHIELD_REMOVED` 等既有事实。
- Gate blocked 进入交互审计，但不得伪造 occurrence 或晶片事实。
- Reaction Snapshot 保存晶片状态与 Gate；Space Snapshot 保存实体投影；Shield Snapshot 保存活动护盾聚合。
