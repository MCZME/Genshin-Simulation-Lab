# 配置区域设计

> 状态：正式规范。
> 本文定义配置区域的产品定位、区域模型、节点模型、边界输出、变体展开、校验运行与编辑器约定。
> 最后更新：2026-08-29。

## 1. 定位与边界

- 配置区域回答“模拟什么”：把用户配置整理为一组完整 `SimulationInput` 文档或变体成员。
- 配置区域不执行模拟，不读取结果库，不进入分析派生层；提交运行由模拟节点承担。
- 配置区域是画布的一部分，随工作流保存、校验和重跑。
- 配置区域与分析区域是强规则边界：连线必须遵守“配置区域内 → 模拟节点 → 分析区域内”的阶段顺序；配置节点不得直接连接分析节点。
- 第一版画布实现包含配置区域与模拟节点；分析区域是已定稿设计，尚未进入 MVP。

## 2. 区域模型

- `region.kind = configuration`。
- 配置区域固定拥有一个边界输出 `out`，没有独立输入端口。
- 边界输出同时作为区域内节点链的汇入目标与连接模拟节点的输出源。
- 边界端口属于区域，不是可移动节点；区域移动或调整尺寸时，外部连线只跟随边界端口。
- 节点通过 `region_id` 获得归属；游离节点不能连接或参与运行。
- 区域内参与输出的节点必须先汇入边界输出，不能直接连接区域外对象。
- 多个配置区域允许同时存在，例如两个区域各生成一批输入，都汇入同一模拟节点。
- 区域名称同时作为该输入流程的用户可识别名称；创建后自动进入一次命名态。

## 3. 节点模型

### 3.1 当前节点集

| 节点类型 | 职责 | 默认目标路径 | 参数 |
| --- | --- | --- | --- |
| 根节点 | 提供空 `{}` 或加载输入文件 | 无 | 文件路径（可选） |
| 元信息 | 写 `meta`（名称与描述） | `meta` | 名称（必填）、描述 |
| 角色 | 写队伍槽位角色 | `team[i].character` | 槽位 i（1–4）、角色、等级、命座、天赋三项（1–10） |
| 武器 | 写队伍槽位武器 | `team[i].weapon` | 槽位 i |
| 圣遗物 | 写队伍槽位圣遗物 | `team[i].artifacts` | 槽位 i（1–4）、套装列表（0–2 条）、属性词条行列表 |
| 目标 | 写场景目标 | `scene.targets[i]` | 目标索引 i、展示名、等级、位置、八项元素抗性 |
| 按键轨迹 | 写按键输入轨迹 | `input_trace` | 无 |
| 运行选项 | 写运行控制项 | `run_options` | 无 |
| 枚举 | 对目标路径输出一组显式值 | 由用户指定 | 路径、取值列表、标签 |
| 区间 | 对目标路径输出数值序列 | 由用户指定 | 路径、起点、终点、步长、标签 |

节点 `kind`、稳定端口和参数 schema 以[节点与区域契约](../../契约/ui/节点与区域契约.md)为真值源；本文只维护用户可见的产品设计。

### 3.2 通用节点属性

- 节点默认支持多个具有稳定 `port_id` 的独立输入、输出端口；单输入/单输出是特例。
- 同一输入端口允许多条入线：多条上游按端口顺序先连先应用，片段合并由多输入节点隐式完成；共享子图只应用一次。
- 端口基数分为单值输出和组输出：单值端口每条连线携带一个值或片段；组端口输出有序成员组并触发下游展开。
- 枚举/区间是多输出节点的现成实例：组主端口输出完整成员组，同时可按“成员 N”展开为 `out:<item_id>` 成员投影端口。
- 显式枚举的每个成员拥有稳定 `item_id`，成员投影端口绑定 `item_id` 而非数组下标；调整枚举顺序不得改变已有连线指向。
- 组主端口和成员投影端口可以分别连接；多路独立输出重新汇入时不得静默恢复成组、拼接或叉乘。
- 目标路径：节点类型声明默认路径；路径在画布上可见可改；队伍槽位、目标索引等作为节点参数。

### 3.3 根数据、片段与覆盖

- 根数据：携带根身份的完整 JSON 文档，自根节点出发。
- 片段数据：节点直接产生、不携带根的修改内容；片段之间可深合并。
- 片段链按连线/端口顺序应用到根文档，产出新根数据。
- 覆盖只发生在同一叶子字段存在多个写入者；覆盖允许但必须警告，被覆盖节点和覆盖节点在界面上都给出明确提示。
- 生效顺序由端口顺序决定，后生效者覆盖先生效者。

## 4. 边界输出

- 配置区域边界输出收拢区域内有效输入，形成一组完整输入文档。
- 配置区域没有独立输入端口：区域内节点链经各自尾节点直接汇入边界输出，多条汇入按连线顺序应用。
- 区域内没有有效数据汇入时，边界输出显示为空并阻止运行。
- 边界输出承担最终输入数量、校验与预览，不执行模拟。
- 边界输出始终展示应用后的最终文档、成员数量与校验状态，供用户核对。
- 配置区域边界预览调用 `POST /api/v1/inputs/validate`，不创建任务、不写结果库。

## 5. 变体展开

- 枚举节点：值类型为资产 / 数值 / 文本 / JSON 片段，每项拥有稳定 `item_id`。
- 区间节点：从 `start` 开始，只要下一步 `≤ end` 就继续生成；小数步长使用十进制算术计算，避免浮点累积误差。
- 多个组输出相遇时按目标路径区分：目标路径不同则叉乘组合；目标路径相同则不叉乘，按覆盖规则处理并显示覆盖警告。
- 批次成员数量上限为 200；超过上限时配置区域边界输出直接报校验错误并阻止运行。
- 每个成员拥有稳定 `item_id` 与确定展开顺序；调整枚举顺序或区间参数后，已有连线按 `item_id` 保持指向。
- 变体展开的输入输出模型、参数形状和校验规则见[批量配置变体契约](../../契约/ui/批量配置变体契约.md)。

## 6. 校验与运行

- 前端 `WorkflowValidator` 负责类型、路径、环、覆盖、区域归属和成员上限等图校验。
- 配置区域头部提供「区域校验」与「区域运行」两个入口：「区域校验」复用构建与逐批校验后停止，不提交模拟；「区域运行」复用全部运行编排并只执行目标区域。
- 配置区域构建是逐方法过程：节点 = 方法，按“根节点 → … → 区域边界输出”的拓扑序逐节点应用；区域以“边界收拢”步骤收尾。
- 构建阶段按方法逐步限速推进，「运行动画」可在设置中关闭；分析区域运行不使用逐节点限速。
- 前端编译期诊断只负责提前反馈；`POST /inputs/validate` 是提交前的最终执行校验，两端口径不一致时以后者为准。
- 模拟执行唯一路径：配置区域边界输出 → 模拟节点。未连接模拟节点的配置区域给警告并跳过，不参与任何批次。

## 7. 编辑器约定

- 节点即编辑器：所有编辑都在画布内、节点内部直接展开，不跳转侧栏或独立页面。
- 节点整体不折叠，以保留画布上的所见即所得关系；节点内部次要分组可以折叠，折叠后保留内容与状态摘要。
- 文本/数字输入在节点内保持本地瞬态，失焦或 Enter 提交并形成一个撤销步骤；下拉、资产选择等点选类操作即时提交。
- 字段错误在字段旁以红边框与修复提示呈现，节点自适应增高，同时进入问题列表。
- 资产选择器在节点内显示当前资产的名称与图像，点击展开可搜索列表；不可运行资产使用面向用户的状态说明。
- 路径修改只做语法级检查，结构校验在配置区域输出完成。
- 枚举节点由用户声明值类型，支持展开成员投影端口并把单个枚举值连接到独立分支。
- 按键轨迹节点全部数据通过可视化编辑完成，不提供 JSON 输入；编辑精度按帧，同键块自动避免重叠。

## 8. 暂不实现

- 玩家节点：第一版使用默认位置/朝向。
- 规则节点：`rules` 第一版为空结构。
- 合并节点：片段合并由多输入节点隐式完成。
- 资产筛选：后续版本支持。
