# 战场空间设计

> 状态：阶段性结论，已同步至内容创建空间实体的最小运行时。
> 本文档记录 `core/space` 的当前职责、边界和运行时模型。

## 1. 目标

`Space` 用于描述一次仿真中的战场空间实体，回答“某个位置附近有哪些候选空间实体”。

第一版目标：

- 保存当前场上角色的空间实体。
- 保存多个简单目标点位。
- 保存内容创建的带生命周期空间实体。
- 提供 X/Z 平面范围查询。
- 支持按实体类型、生命周期和排除列表过滤查询结果。
- 为动作层提供候选空间实体 id。

第一版不做：

- 真实 3D 物理。
- 刚体碰撞。
- 目标挤压。
- 复杂敌人体型。
- 多 hitbox。
- 真实索敌优先级。
- 命中、伤害、反应或元素附着结算。
- 内容创建对象的后续 tick 行为或机制结算。

## 2. 核心结论

角色在 `Space` 中有空间实体，但完整角色运行态不属于 `Space` 容器本身。当前运行时由 `SpaceRuntime` 作为空间运行态入口，持有 `Space`、队伍运行态引用、目标运行态集合和内容创建对象运行态。

目标在 `Space` 中也是空间实体，但目标只作为简单点位靶子参与查询。项目支持多目标战场；这里的“简单”指每个目标不在空间层建模复杂体型、碰撞或多部位判定。

因此，`Space` 中统一保存轻量空间实体：

```text
SpatialEntity
├── entity_id
├── kind
├── position
├── lifecycle
├── facing
├── active_slot
├── owner_key
├── source_key
└── tags
```

当前实体类型：

```text
ACTIVE_CHARACTER
TARGET
CREATED_OBJECT
```

`Space` 只保存空间实体和查询所需的通用字段；内容创建对象的 `object_key`、`behavior_key`、tick 间隔和对象参数由 `CreatedObjectRuntimeState` 保存。

## 3. 当前场上角色

第一版只为当前场上角色创建一个空间实体：

```text
entity_id = "player:active"
kind = ACTIVE_CHARACTER
active_slot = 当前场上槽位
```

后台角色默认没有独立空间实体。切人时不创建新位置，也不为后台角色保留单独位置；切人成功后由动作层请求队伍运行态更新当前槽位，并同步 `player:active.active_slot`。

完整角色运行态由 `CharacterRuntimeState` 表示，归 `TeamRuntimeState` 持有。角色的属性、能量、技能状态、Buff、动作状态等不进入 `Space`，仍由队伍、角色、动作和系统运行态负责。`CharacterRuntimeState.combat_entity_id` 是角色战斗身份，`Space` 中的 `player:active` 是当前场上角色空间实体，两者通过 `active_slot` 关联。

## 4. 多目标点位

配置中的多个 `scene.targets` 会在组装阶段映射为空间实体：

```text
entity_id = "target:<target_id>"
kind = TARGET
position = scene.targets[].position
```

目标的等级、抗性等战斗参数不属于 `Space` 容器，而由 `TargetRuntimeState` 保存，并通过 `TargetRuntimeCollection` 管理多个目标。`TargetRuntimeCollection` 由 `SpaceRuntime` 直接持有和提供，用于把空间候选实体解析成目标运行态引用。`TargetRuntimeState.spatial_entity_id` 默认使用 `target:<target_id>`，与 `Space` 中的目标空间实体关联。

第一版 `TargetRuntimeState` 只承接 `scene.targets` 中已经存在的目标 id、等级、抗性和空间实体关联，不引入生命值、元素附着、韧性等尚未确认的战斗状态。

## 5. 内容创建空间实体

动作影响可以通过 `ImpactRequest(kind=create_entity)` 请求创建内容定义的空间实体。该链路不引入独立 `summons` 模块，游戏语义上的召唤物、场地物或临时造物只要存在于战场空间中，都按带生命周期的空间实体处理。

当前链路：

```text
ActionImpactPoint
-> ImpactRequest(kind=create_entity)
-> ImpactRuntime 通过 SpaceRuntime 转交 CreatedObjectRuntime
-> CreatedObjectRuntime 创建或刷新 CreatedObjectRuntimeState
-> ImpactRuntime 通过 SpaceRuntime 将 state.entity 同步到 Space
```

内容创建对象在 `Space` 中的空间实体字段：

```text
entity_id = request.params.entity_id 或 "created_object:<object_key>:<index>"
kind = CREATED_OBJECT
position = request.params.position
facing = request.params.facing 或默认朝向
lifecycle = created_frame / expires_at_frame
owner_key = request.params.owner_key 或 "slot:<owner_slot>"
source_key = request.params.source_key 或 action_key / impact_key
tags = request.params.tags
```

`CreatedObjectRuntime` 负责对象创建、刷新、实例数量上限、生命周期过期和 tick 请求生成；它由 `SpaceRuntime` 持有。`Space` 只负责登记该对象的空间实体，并在查询时按当前帧过滤未创建或已过期实体。

无空间位置、不参与空间查询的持续逻辑不应放入 `Space` 或 `CreatedObjectRuntime`，应归机制、状态或 hook 处理。更完整的内容侧约束见：[内容系统设计草案](./内容系统设计草案.md) 与 [动作系统设计草案](./动作系统设计草案.md)。

## 6. 空间动作消费协调

`SpaceRuntime` 是空间运行态的直接入口，负责持有和协调与战场空间实体相关的运行态对象：

- `Space`：空间实体、生命周期过滤和范围查询。
- `TeamRuntimeState`：`player:active` 对应的队伍共享角色运行态引用。
- `TargetRuntimeCollection`：多个目标运行态集合。
- `CreatedObjectRuntime`：内容创建空间实体的运行态。

动作消费只是 `SpaceRuntime` 的一个功能。`SpaceRuntime` 会按空间实体把已接受的动作实例分发给对应运行态消费器。它不定义原神机制，也不计算伤害、治疗、反应或 Buff；它只解决“哪个空间实体背后的运行态消费这个 `ActionInstance`”。

当前第一版注册：

```text
(actor_entity_id="player:active", action_key="team.switch")
-> TeamSwitchActionConsumer
-> TeamRuntimeState.switch_to(target_slot)
-> Space.update_active_character_slot(active_slot)
```

因此，`TeamActionController` 只把 `keyboard.1~4` 翻译成 `team.switch` 动作时间轴；切人是否因 busy 被动作层拒绝由 `ActionManager` 决定，目标槽位是否有效和 `active_slot` 修改由切人消费器调用 `TeamRuntimeState` 完成。

## 7. 配置映射

`scene.player` 描述当前场上角色的初始空间实体：

```json
{
  "player": {
    "position": {"x": 0, "y": 0, "z": 0},
    "facing": {"x": 0, "y": 0, "z": 1}
  }
}
```

如果省略 `scene.player`，默认位置为 `(0, 0, 0)`，朝向为 `(0, 0, 1)`。

`scene.targets` 继续用于描述多目标战场：

```json
{
  "targets": [
    {
      "id": "target_1",
      "level": 90,
      "position": {"x": 0, "y": 0, "z": 5},
      "resistance": {}
    }
  ]
}
```

内容创建空间实体不直接写入 `scene`。它们由运行时动作影响或内容对象 tick 产生的 `create_entity` 请求创建，并在仿真过程中同步到 `Space`。

## 8. 查询语义

当前普通范围查询只使用 X/Z 平面：

```text
distance_xz(query_center, entity.position) <= radius
```

`position.y` 保留给下落攻击等高度敏感机制，暂不参与普通半径判定。

`entities_in_radius` 会转换为 `CircleArea` 查询；`entities_in_area` 会按以下条件过滤：

```text
entity_id 不在 exclude_entity_ids
entity.lifecycle 在 Space 当前帧处于 active
kinds 为空或 entity.kind 属于 kinds
area.contains(entity.position)
```

`Space` 查询返回的是候选空间实体，不代表最终命中：

```text
Space.query / entities_in_radius
-> candidate_entity_ids
-> candidate_targets
-> 后续动作、命中、伤害和反应系统继续判断
```

动作实例记录 `candidate_entity_ids`，并可通过 `TargetRuntimeCollection` 解析出 `candidate_targets`。两者都仍然只是候选：`candidate_entity_ids` 表示空间查询内的目标空间实体，`candidate_targets` 表示这些空间实体中能关联到目标运行态的候选目标引用。第一版 `ActionImpactPoint` 会携带同一组候选信息；未声明偏移时影响点位于动作开始帧，角色内容也可以声明相对动作开始帧的偏移或关闭默认影响点。它仍只是动作时间轴上的候选影响点。动作实例不再记录 `target_ids`，避免把空间候选误认为最终命中目标。

当前 `ActionManager` 的动作空间查询默认只把 `TARGET` 解析为候选目标；`CREATED_OBJECT` 可以通过 `Space` 按类型查询，但不会自动变成 `candidate_targets`。

## 9. 模块边界

`core/space` 属于纯核心运行时。

允许：

- 依赖 `core` 内部纯数据结构。
- 复用 `core/entity_states` 中的通用生命周期值对象。
- 作为 `SimulationContext.space_runtime` 挂载。
- 作为可按帧推进的运行时对象更新当前查询帧。
- 接收 `ImpactRuntime` 同步过来的内容创建空间实体。
- 持有 `TargetRuntimeCollection` 并提供目标运行态解析。
- 持有 `CreatedObjectRuntime` 并同步内容创建空间实体。
- 通过 `SpaceRuntime` 协调空间实体动作实例的运行态消费。

禁止：

- 依赖 `assets`。
- 依赖 `content`。
- 依赖 `application`。
- 访问 SQLite 或文件系统。
- 持有武器、圣遗物、结果库对象或内容层贡献对象。
- 持有内容创建对象的 tick 行为、机制结算逻辑或内容专属状态。
- 定义具体原神机制或直接结算伤害、治疗、反应、Buff。

## 10. 代码组织

`core/space` 按职责拆分文件，避免使用含义过泛的 `models.py`：

```text
core/space/
├── geometry.py        -> Vector3、CircleArea 等空间几何值对象
├── entities.py        -> SpatialEntityKind、SpatialEntity 等空间实体模型
├── created_objects.py -> CreatedObjectRuntime、CreatedObjectRuntimeState 等内容创建空间对象运行态
├── runtime.py         -> SpaceRuntime、空间实体运行态持有与动作消费器
├── space.py           -> Space 容器与查询接口
└── __init__.py        -> 对外导出稳定入口
```

外部模块优先从 `genshin_sim.core.space` 导入公开类型，不直接依赖具体文件路径。

`SpatialEntity.lifecycle` 和内容创建空间对象运行态使用 `core/entity_states/lifecycle.py` 中的通用生命周期对象，避免在空间模块内复制实体生命周期概念。
