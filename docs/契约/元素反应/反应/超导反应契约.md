## 2. 签名与元素量

| incoming_element | observed_aura_kind | 消费关系 |
| --- | --- | --- |
| `cryo` | `electro` | `1:1` |
| `electro` | `cryo` | `1:1` |

```text
consumed = min(incoming_amount, aura_amount)
```

后手与先手都扣除 `consumed`。无伤害元素施加也能形成 occurrence、独立伤害和减抗 Effect；序列结束后的后手剩余量不自动形成持久 Aura。

## 3. Reaction Profile 与伤害

两个方向都冻结：

```text
damage_element = cryo
base_multiplier = 1.5
elemental_amount = 0
can_crit = false
strike_type = None
```

伤害读取目标冰抗。90 级角色、`EM = 0`、零反应加成、抗性乘数 `1.0` 的 golden 值为：

```text
1446.853 * 1.5 = 2170.2795
```

共享公式见[剧变反应伤害契约](../剧变反应伤害契约.md)。

## 4. Effect Group 与范围

每个 occurrence 产生一个 `ReactionEffectGroup`：

```text
effect 0 = GeneratedDamageImpactEffect
effect 1 = ReactionStatusEffect
```

两个 Effect 共享以 occurrence 主体为锚点的 X/Z 平面 5 米闭区间查询和稳定 `target_order`，但按 capability 形成不同子集：

- hostile + `damage`：进入 Damage Gate 和冰伤计划；
- hostile + `attribute_status`：进入物理减抗 Buff 计划；
- Damage Gate blocked 不阻止 Status Effect。

## 5. Damage Gate

```text
window_frames = 30
max_damage_instances = 2
```

同一半开窗口前两次允许，第三次及以后阻止；第 `N + 30` 帧建立新窗口。slot 身份和 blocked 语义遵守[元素反应运行时与事务契约](../运行时与事务契约.md)。

## 6. 物理减抗

`ReactionStatusEffect` 固定：

```text
duration_frames = 720
value = -0.40
attribute = resistance.physical
```

Buff 契约：

- 生效区间为 `[applied_frame, applied_frame + 720)`；
- `application_policy = replace`；
- `value_refresh_policy = replace_latest`；
- `max_stacks = 1`；
- 同一目标跨来源共享 conflict slot，不叠加为 `-0.80`；
- replace 原子移除旧实例并创建携带最新 occurrence 来源的新实例；
- 事实顺序为 `BUFF_REMOVED(reason=replaced)` 后 `BUFF_APPLIED(outcome=replaced)`。

Reaction 只声明状态 Profile、数值和持续时间。协调器的显式 adapter 负责转成 `ApplyBuffRequest`；BuffStore 是 Debuff 生命周期的唯一真值。

## 7. 正常空结果与失败

以下不形成普通超导：

- 后手不是冰或雷；
- 没有对应的正普通雷/冰 Aura；
- ICD 后预算为零；
- 同元素施加。

关系不适用、缺少某个目标 capability 或 Damage Gate blocked 是目标级正常结果。缺 Status adapter、Buff Definition、Damage Profile、Gate Definition或非法来源捕获必须在提交前失败。
