# 战场空间设计

> 状态：阶段性结论，已同步至内容创建空间实体的最小运行时；第二版反应目标资格边界与第六版结晶反应实体计划、到期删除及生产装配已落地。
> 本文档记录 `core/space` 的当前职责、边界和运行时模型。

最后更新：2026-07-23

## 1. 目标

`Space` 用于描述一次仿真中的战场空间实体，回答“某个位置附近有哪些候选空间实体”。

第一版目标：

- 保存当前场上角色的空间实体。
- 保存多个简单目标点位。
- 保存内容创建的带生命周期空间实体。
- 提供 X/Z 平面的 Circle、CircleSector 和定向 Box 范围查询；当前代码已实现 Circle，其余形状按统一 Damage Impact 契约补齐。
- 支持按实体类型、生命周期和排除列表过滤查询结果。
- 为动作层提供候选空间实体 id。

第一版不做：

- 真实 3D 物理。
- 刚体碰撞。
- 目标挤压。
- 复杂敌人体型。
- 多 hitbox。
- 真实索敌优先级。
- 命中、伤害、反应或元素附着结算。
- 内容创建对象的后续 tick 行为或机制结算。

## 2. 核心结论

角色在 `Space` 中有空间实体，但完整角色运行态不属于 `Space` 容器本身。当前运行时由 `SpaceRuntime` 作为空间运行态入口，持有 `Space`、队伍运行态引用、目标运行态集合和内容创建对象运行态。

目标在 `Space` 中也是空间实体，但目标只作为简单点位靶子参与查询。项目支持多目标战场；这里的“简单”指每个目标不在空间层建模复杂体型、碰撞或多部位判定。

因此，`Space` 中统一保存轻量空间实体：

```text
SpatialEntity
├── entity_id
├── kind
├── position
├── lifecycle
├── collision_box
├── facing
├── active_slot
├── owner_key
├── source_key
└── tags
```

`collision_box` 默认圆柱：底半径 `0.5`、高 `1.0`；`position.y` 视为实体基座
高度，碰撞箱从基座向上延伸。当前命中判定仍只使用 X/Z，碰撞箱高度保留给
下落攻击等高度敏感机制（碰撞时机等）。

当前实体类型：

```text
ACTIVE_CHARACTER
TARGET
CREATED_OBJECT
REACTION_OBJECT
```

`Space` 只保存空间实体和查询所需的通用字段；内容创建对象的 `object_key`、`behavior_key`、tick 间隔和对象参数由 `CreatedObjectRuntimeState` 保存。

位置写入口由 `MovementSystem` 独占：`SpaceRuntime.apply_displacement` 只供
Movement 领域写入实体位置，动作不再直接修改空间实体位置，需要位移时通过
`ImpactKind.MOVEMENT` 意图表达。

`REACTION_OBJECT` 不属于 `CreatedObjectRuntime`，也不获得 Target、Damage 或 Aura capability。它只表示由 Reaction State 拥有机制语义、由 Space 拥有位置和活动投影的实体。

## 3. 当前场上角色

第一版只为当前场上角色创建一个空间实体：

```text
entity_id = "player:active"
kind = ACTIVE_CHARACTER
active_slot = 当前场上槽位
```

后台角色默认没有独立空间实体。切人时不创建新位置，也不为后台角色保留单独位置；切人成功后由动作层请求队伍运行态更新当前槽位，并同步 `player:active.active_slot`。

完整角色运行态由 `CharacterRuntimeState` 表示，归 `TeamRuntimeState` 持有。角色的属性、能量、技能状态、Buff、动作状态等不进入 `Space`，仍由队伍、角色、动作和系统运行态负责。`CharacterRuntimeState.combat_entity_id` 是角色战斗身份，`Space` 中的 `player:active` 是当前场上角色空间实体，两者通过 `active_slot` 关联。

## 4. 多目标点位

配置中的多个 `scene.targets` 会在组装阶段映射为空间实体：

```text
entity_id = "target:<target_id>"
kind = TARGET
position = scene.targets[].position
```

目标的等级、抗性等战斗参数不属于 `Space` 容器，而由 `TargetRuntimeState` 保存，并通过 `TargetRuntimeCollection` 管理多个目标。`TargetRuntimeCollection` 由 `SpaceRuntime` 直接持有和提供，用于把空间候选实体解析成目标运行态引用。`TargetRuntimeState.spatial_entity_id` 默认使用 `target:<target_id>`，与 `Space` 中的目标空间实体关联。

第一版 `TargetRuntimeState` 只承接 `scene.targets` 中已经存在的目标 id、等级、抗性和空间实体关联，不引入生命值、元素附着、韧性等尚未确认的战斗状态。

## 5. 内容创建空间实体

动作影响可以通过 `ImpactRequest(kind=create_entity)` 请求创建内容定义的空间实体。该链路不引入独立 `summons` 模块，游戏语义上的召唤物、场地物或临时造物只要存在于战场空间中，都按带生命周期的空间实体处理。

当前链路：

```text
ActionImpactPoint
-> ImpactRequest(kind=create_entity)
-> ImpactRequestDispatcher 转交 CreatedObjectRuntime
-> CreatedObjectRuntime 创建或刷新 CreatedObjectRuntimeState
-> CreatedObjectRuntime 通过 SpaceRuntime 将 state.entity 同步到 Space
```

内容创建对象在 `Space` 中的空间实体字段：

```text
entity_id = request.params.entity_id 或 "created_object:<object_key>:<index>"
kind = CREATED_OBJECT
position = request.params.position
facing = request.params.facing 或默认朝向
lifecycle = created_frame / expires_at_frame
owner_key = request.params.owner_key 或 "slot:<owner_slot>"
source_key = request.params.source_key 或 action_key / impact_key
tags = request.params.tags
```

`CreatedObjectRuntime` 负责对象创建、刷新、实例数量上限、生命周期过期和 tick 请求生成；它由 `SpaceRuntime` 持有。`Space` 只负责登记该对象的空间实体，并在查询时按当前帧过滤未创建或已过期实体。

无空间位置、不参与空间查询的持续逻辑不应放入 `Space` 或 `CreatedObjectRuntime`，应归机制、状态或 hook 处理。更完整的内容侧约束见：[内容系统设计](./内容系统设计.md) 与 [动作系统设计](./动作系统设计.md)。

## 6. 与动作系统协作

`SpaceRuntime` 是空间运行态的直接入口，负责持有和协调与战场空间实体相关的运行态对象：

- `Space`：空间实体、生命周期过滤和范围查询。
- `TeamRuntimeState`：`player:active` 对应的队伍共享角色运行态引用。
- `TargetRuntimeCollection`：多个目标运行态集合。
- `CreatedObjectRuntime`：内容创建空间实体的运行态。

`SpaceRuntime` 不再按 `(actor_entity_id, action_key)` 消费普通动作实例。动作实例由 `ActionManager` 拥有并通过其 `Action` 执行具体逻辑；需要空间查询、位置同步或创建空间对象时，Action 或机制请求通过 `SpaceRuntime` 的受控接口协作。

切人由 `TeamSwitchAction` 实例执行：

```text
TeamSwitchAction.on_start()
-> TeamRuntimeState.switch_to(target_slot)
-> SpaceRuntime.update_active_character_slot(active_slot)
```

`SpaceRuntime` 不判断切人是否允许，也不持有切人动作生命周期。动作准入、具名锁和中断由 `ActionManager` 处理。

## 7. 配置映射

`scene.player` 描述当前场上角色的初始空间实体：

```json
{
  "player": {
    "position": {"x": 0, "y": 0, "z": 0},
    "facing": {"x": 0, "y": 0, "z": 1}
  }
}
```

如果省略 `scene.player`，默认位置为 `(0, 0, 0)`，朝向为 `(0, 0, 1)`。

`scene.targets` 继续用于描述多目标战场：

```json
{
  "targets": [
    {
      "id": "target_1",
      "level": 90,
      "position": {"x": 0, "y": 0, "z": 5},
      "resistance": {}
    }
  ]
}
```

内容创建空间实体不直接写入 `scene`。它们由运行时动作影响或内容对象 tick 产生的 `create_entity` 请求创建，并在仿真过程中同步到 `Space`。

## 8. 查询语义

当前普通范围查询只使用 X/Z 平面：

```text
distance_xz(query_center, entity.position) <= radius
```

`position.y` 可以保留在空间实体记录中，但当前 Damage Impact AOE 不使用高度参与命中判定。

统一 Damage Impact 的二维 AOE 语义：

```text
OrientedBox(width, depth, local_offset_xz)
Circle(radius, local_offset_xz)
CircleSector(radius, angle, local_offset_xz)
```

- 原始 Box `(x, y, z)` 使用完整边长 `x/z`，`y` 不参与当前查询。
- 原始 Circle `(R, H, Angle)` 使用半径与圆心角，`H` 不参与当前查询，未标注角度为 `360°`。
- Sphere 在当前 X/Z 模型中投影为同半径 Circle。
- 圆柱（如低空/高空坠地 `3.0,2.0` / `3.5,2.0`）同样投影为同半径 Circle，
  高度不参与当前查询。
- 本地偏移和形状朝向随 Action 索敌确定的攻击方向旋转。

AOE 语义：索敌阶段按索敌范围选择最近目标，Damage Impact 的球 AOE 以该目标
为锚点解析实际受击目标；资料表中的本地偏移叠加到锚点。

`entities_in_radius` 会转换为 `CircleArea` 查询；`entities_in_area` 会按以下条件过滤：

```text
entity_id 不在 exclude_entity_ids
entity.lifecycle 在 Space 当前帧处于 active
kinds 为空或 entity.kind 属于 kinds
area.contains(entity.position)
```

`Space` 查询返回满足几何和实体类型过滤的候选空间实体；Impact 在冻结本次目标集合后形成最终目标级 interaction：

```text
Action targeting query
-> 瞄准目标与攻击方向
-> Damage Impact AOE query
-> candidate targets
-> 冻结 target interactions
-> 元素与伤害结算
```

`ActionImpactPoint` 的 `TargetingSpec` 只负责索敌、选择瞄准目标和确定攻击方向，不等同于 Damage Impact 的实际 AOE。实际受击目标在 Impact 到期时由 AOE 重新查询并冻结。

`candidate_entity_ids` 表示空间查询内的候选实体，`candidate_targets` 表示其中能关联到 `TargetRuntimeState` 的候选目标引用；两者都不代表最终命中、伤害结算或反应触发。`CREATED_OBJECT` 与 `REACTION_OBJECT` 可以按空间实体类型查询，但不会自动成为目标运行态引用。

### 8.1 第二版反应目标资格

Space 不拥有阵营、敌对关系、伤害资格或 Buff 资格。普通超载、超导由元素协调器通过窄 `ReactionTargetEligibilityPort` 把空间候选转换为：

```text
subject_ref
spatial_entity_id
distance_xz
relation
capabilities
reason
```

- `scene.targets` 组装出的 `TARGET + TargetRuntimeState` 视为 hostile，并按实际运行态端口提供 `damage`、`attribute_status` capability。
- 当前场上角色和队伍创建物属于 self 或 ally，不接收第二版反应效果。
- Created Object 或环境主体没有显式资格 Provider 时为 `neutral_or_unknown` 且没有 capability。
- `REACTION_OBJECT` 不进入 `TargetRuntimeCollection`，默认同样没有普通 Damage 或 Aura capability。
- 不新增 `SimulationInput` 阵营字段，不根据 tags、显示名称或 key 文本猜测资格。
- 协调器冻结结果后按 X/Z 距离、主体种类、主体 id 排序；通用 Space 容器仍只返回几何候选。

完整字段和正常阻止语义见[元素反应运行时与事务契约](../契约/元素反应/运行时与事务契约.md)。

## 9. 版本化实体计划

第六版为跨领域原子提交增加了 Space 自己的计划接口：

```text
SpaceEntityMutationPlan
├── operation_id
├── frame
├── expected_entity_version
├── creations
└── removals  # 完整 SpatialEntity 前值
```

- `Space` 保存当前帧、统一实体 version 和已提交 operation 的幂等回执；帧推进本身不增加实体 version。
- planner 在私有工作投影中累计创建与删除，同一 id 不能同时出现在两类变更中；本版不把移动或任意 update 放进计划。
- validate 无副作用，先检查相同 `operation_id` 的幂等回执，再检查帧、version、创建 id 与删除完整前值；commit 只替换已准备的内存投影，不查询、不计算、不回调、不发布事实。
- 非空计划只增加一次 entity version，空计划不伪造变化。直接 add、update、remove 的真实实体变更也使用同一 version；这样内容对象同步不会绕过 stale 检查。
- `EntityLifecycle` 是不可变值对象，内容创建对象到期时必须替换整个 `SpatialEntity`。因此 `get_entity()` 和 `entities` 可以安全返回共享的不可变记录。
- `SpaceSnapshot` 保存 frame、entity version 和按 `entity_id` 稳定排序的实体，不保存结晶公式、拾取状态或其他 Reaction 真值。
- `ReactionSpatialPlanningAdapter` 在 `REACTION_STATE_CHANGED` 发布期间进入 Space 事实写保护；订阅者不能同步 add、update、remove 实体，从而不会破坏已提交的结晶 State/Entity binding。

第六版晶片的创建、到期和拾取只能使用此计划接口；直接写接口仅供组装、动作位置同步与 `CreatedObjectRuntime` 同步使用。

## 10. 模块边界

`core/space` 属于纯核心运行时。

允许：

- 依赖 `core` 内部纯数据结构。
- 复用 `core/entity_states` 中的通用生命周期值对象。
- 作为 `SimulationContext.space_runtime` 挂载。
- 作为可按帧推进的运行时对象更新当前查询帧。
- 接收 `ImpactRuntime` 同步过来的内容创建空间实体。
- 持有 `TargetRuntimeCollection` 并提供目标运行态解析。
- 持有 `CreatedObjectRuntime` 并同步内容创建空间实体。
- 通过 `SpaceRuntime` 协调空间实体动作实例的运行态消费。

禁止：

- 依赖 `assets`。
- 依赖 `content`。
- 依赖 `application`。
- 访问 SQLite 或文件系统。
- 持有武器、圣遗物、结果库对象或内容层贡献对象。
- 持有内容创建对象的 tick 行为、机制结算逻辑或内容专属状态。
- 定义具体原神机制或直接结算伤害、治疗、反应、Buff。

## 11. 代码组织

`core/space` 按职责拆分文件，避免使用含义过泛的 `models.py`：

```text
core/space/
├── geometry.py        -> Vector3、CircleArea 等空间几何值对象
├── entities.py        -> SpatialEntityKind、SpatialEntity 等空间实体模型
├── errors.py          -> Space 实体计划冲突错误
├── mutations.py       -> SpaceEntityMutationPlan、回执等不可变计划模型
├── snapshots.py       -> SpaceSnapshot
├── created_objects.py -> CreatedObjectRuntime、CreatedObjectRuntimeState 等内容创建空间对象运行态
├── runtime.py         -> SpaceRuntime、空间实体运行态持有与受控同步接口
├── space.py           -> Space 容器与查询接口
└── __init__.py        -> 对外导出稳定入口
```

外部模块优先从 `genshin_sim.core.space` 导入公开类型，不直接依赖具体文件路径。

`SpatialEntity.lifecycle` 和内容创建空间对象运行态使用 `core/entity_states/lifecycle.py` 中的通用生命周期对象，避免在空间模块内复制实体生命周期概念。
