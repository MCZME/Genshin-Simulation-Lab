# 冻结反应契约

> 状态：已实现。冻结普通水冰冻结的方向、元素量、抗性、状态 Link 与连续生命周期。

最后更新：2026-08-01

## 1. 稳定 key

| 用途 | 值 |
| --- | --- |
| Reaction | `reaction.frozen` |
| Handler | `reaction_handler.frozen` |
| Frozen State | `reaction_state.frozen` |
| Recovery State | `reaction_state.freeze_recovery` |

方向与 Profile：

| direction_key | profile_key |
| --- | --- |
| `incoming_hydro_on_cryo` | `reaction_profile.frozen.incoming_hydro_on_cryo` |
| `incoming_cryo_on_hydro` | `reaction_profile.frozen.incoming_cryo_on_hydro` |

## 2. 签名与元素量

| incoming_element | observed_aura_kind | 消费关系 |
| --- | --- | --- |
| `hydro` | `cryo` | `1:1` |
| `cryo` | `hydro` | `1:1` |

```text
reaction_amount = min(incoming_amount, aura_amount)
produced_frozen_amount = 2 * reaction_amount
```

双方各扣除 `reaction_amount`。先手剩余量作为藏元素保留；序列结束后的后手剩余量不自动形成持久 Aura。冻结 occurrence 不创建当前伤害调整或 Damage Effect。

## 3. Profile、Aura 与 State

两个方向必须使用 `StateReactionProfile`。`FROZEN` Aura 与 `FrozenState` 必须具有同一 `ElementalStateLinkRef`，并满足：

- 同主体同时存在或同时不存在；
- `FROZEN` Aura 的 `state_link_refs` 只包含该 Link；
- `FrozenState.state_link_ref` 等于该 Link；
- 冻元素量只保存在 Aura；
- 创建、刷新、自然到期和碎冰移除都经过跨系统 Link 预校验。

`FrozenState` 使用共享 `ReactionStateSlot.FROZEN`；`FreezeRecoveryState` 使用共享 `ReactionStateSlot.FREEZE_RECOVERY`，两者不能同时存在。

## 4. 冻结抗性

`FreezeResistanceObservation` 稳定字段：

```text
subject_ref
frame
value
```

`value` 必须是 `[0, 1]` 内的有限数值，主体和帧必须与 Reaction 请求一致。当前生产默认值固定为 `0.0`；未提供观察时不得报缺失错误，也不得查询未定义的 AttributeKey。

```text
effective_amount = produced_frozen_amount * (1 - value)
```

`effective_amount = 0` 时 occurrence 和普通元素消费仍提交，但不创建 `FROZEN` Aura、`FrozenState` 或到期工作。

## 5. 连续冻结与帧语义

稳定常量：

```text
minimum_decay_rate = 0.4 GU/s
active_acceleration = 0.1 GU/s^2
thawed_recovery = 0.2 GU/s^2
frames_per_second = 60
```

```text
duration_seconds = (sqrt(v^2 + 0.2 * D) - v) / 0.1
duration_frames = ceil(duration_seconds * 60)
```

整数帧边界只消除浮点噪声，不改变真实分数帧向上取整。到期区间为半开区间。

活动续冻必须先投影当前帧的剩余量和速率，再使用：

```text
refreshed_amount = max(projected_current_amount, new_effective_amount)
```

刷新保留 `FrozenState.instance_ref`、Aura instance 和 Link，更新速率基准帧与 `next_required_frame`。

## 6. 生命周期与事实

`next_required_frame` 是活动冻结自然到期帧，帧协调器不得跨过它。到期帧原子移除 linked Aura/State；解冻速率大于 `0.4` 时创建不带 Link、`next_required_frame = None` 的 `FreezeRecoveryState`，否则不创建恢复记录。

状态提交后发布 `REACTION_STATE_CHANGED`；Aura、occurrence、State 和最终 batch 事实顺序遵守[元素反应运行时与事务契约](../运行时与事务契约.md)。

## 7. 失败与验证

Link 缺失、主体不一致、Aura/State 单边存在、状态前值冲突、抗性越界或 stale plan 必须在提交前失败。无匹配水冰 Aura、ICD 后预算为零是正常空结果。
