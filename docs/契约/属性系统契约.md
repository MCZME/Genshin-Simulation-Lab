# 属性系统契约

> 状态：第一版已确认。
> 本文档固定属性系统的公共 key、数据模型、枚举值、解析公式、错误语义、快照结构和 application 装配规则。架构背景见[属性系统架构](../架构/属性系统设计.md)。

最后更新：2026-07-11

## 1. 适用范围

本契约适用于：

- core/attributes 的公共模型和解析行为。
- application/assembly/attributes.py 的资产、配置和 content 装配边界。
- content 私有属性与 ModifierProvider 接入。
- 属性查询、审计和快照测试。

本契约不定义伤害、治疗、反应公式或结果库具体 schema。

## 2. 通用规则

- key 和枚举使用本文给出的稳定小写字符串值。
- 百分比使用小数倍率，例如 20% 保存为 0.2。
- 属性值第一版统一使用 Python float。
- bool 不能作为数字传入属性模型。
- NaN、正无穷和负无穷必须在模型边界拒绝。
- 属性主体只支持角色和目标。
- 显示名称不得参与身份或冲突判断。

## 3. AttributeKey

AttributeKey 是不可变字符串值对象。

~~~text
AttributeKey
└── value: str
~~~

格式：

~~~text
^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$
~~~

公共 key 由 core/attributes/keys.py 提供常量。content 私有 key 使用同一值对象。

## 6. 引用模型

### 6.1 AttributeSubjectRef

~~~text
AttributeSubjectRef
├── kind: AttributeSubjectKind
└── entity_id: str
~~~

- entity_id 必须是非空字符串。
- 角色使用 CharacterRuntimeState.combat_entity_id。
- 第一版组装器生成 character:slot_{slot}。
- 目标使用 target:{target_id}。

### 6.2 RuntimeSourceRef

~~~text
RuntimeSourceRef
├── kind: RuntimeSourceKind
├── source_key: str
└── instance_id: str | None
~~~

source_key 必须非空；instance_id 提供时必须非空。source ref 只表达贡献来源，不替代属性主体引用。

## 7. 属性定义

### 7.1 AttributeDefinition

~~~text
AttributeDefinition
├── key: AttributeKey
├── owner_kinds: frozenset[AttributeSubjectKind]
├── policy_key: str
├── dependencies: tuple[AttributeKey, ...]
├── default_value: float
├── missing_value_policy: MissingValuePolicy
├── lower_bound: float | None
├── upper_bound: float | None
├── override_policy: OverridePolicy
├── visibility: AttributeVisibility
└── namespace_owner: str | None
~~~

校验：

- owner_kinds 不能为空。
- policy_key 必须非空并引用已注册 policy。
- default 和 bounds 必须是有限数字。
- lower_bound 不能大于 upper_bound。
- 公共属性不能声明 namespace_owner。
- 私有属性必须声明 namespace_owner，且 key 必须以 namespace_owner 加点号开头。

缺基础值时：

- use_default：使用 default_value。
- error：抛出 MissingAttributeValueError。

default_value 是解析代数默认值，不用于隐藏游戏规则默认面板。

### 7.2 AttributeDefinitionRegistry

registry 负责注册属性定义和 stacking group，拒绝重复 key；未知属性抛出 UnknownAttributeError。

registry 在组装期间可注册，进入运行时后按只读方式使用。

### 7.3 content 私有定义

content 通过 ContentRuntimeContribution.attribute_definitions 提供私有定义。

- definition.namespace_owner 必须等于 contribution.handler_key。
- content 不能覆盖公共属性或其他 content 的属性。
- 不符合约束时组装失败。

## 8. 查询模型

### 8.1 AttributeQueryContext

~~~text
AttributeQueryContext
├── tags: frozenset[str]
├── source_ref: RuntimeSourceRef | None
└── target_ref: AttributeSubjectRef | None
~~~

tags 必须全部是非空字符串。

### 8.2 AttributeQuery

~~~text
AttributeQuery
├── subject_ref: AttributeSubjectRef
├── attribute_key: AttributeKey
├── frame: int
└── context: AttributeQueryContext
~~~

frame 必须是非负整数。

### 8.3 AttributeResolveOptions

~~~text
AttributeResolveOptions
└── trace_level: TraceLevel = full
~~~

trace level 只控制审计明细，不改变 final value。

| Level | applied_terms | rejected_terms | dependencies |
| --- | --- | --- | --- |
| none | 空 | 空 | 空 |
| applied | 保留 | 空 | applied 级 |
| full | 保留 | 保留 | 完整 |

## 9. 基础贡献

### 9.1 BaseAttributeContribution

~~~text
BaseAttributeContribution
├── attribute_key: AttributeKey
├── value: float
└── source_ref: RuntimeSourceRef
~~~

value 必须是有限数字。

### 9.2 BaseAttributeSet

BaseAttributeSet 按以下键保存不可变 contribution tuple：

~~~text
(AttributeSubjectRef, AttributeKey)
~~~

同一主体和属性可以存在多个基础 contribution。不存在 contribution 时返回空 tuple，default 由 policy 处理。

## 10. Modifier 契约

### 10.1 ModifierTerm

~~~text
ModifierTerm
├── target_key: AttributeKey
├── stage: ModifierStage
├── value: float
├── provider_key: str
├── source_ref: RuntimeSourceRef
├── stacking_group: str | None
└── audit_tags: tuple[str, ...]
~~~

value 必须有限，provider_key 必须非空。stacking_group 和 audit_tags 提供时必须非空。

term 不包含 condition、priority 或 emission_index。

### 10.2 ProviderAttributeRead

~~~text
ProviderAttributeRead
├── attribute_key: AttributeKey
└── subject_scope: ProviderAttributeSubjectScope
~~~

### 10.3 ModifierProviderSpec

~~~text
ModifierProviderSpec
├── provider_key: str
├── reads: tuple[ProviderAttributeRead, ...]
├── writes: frozenset[AttributeKey]
├── private_namespace: str | None
└── owner_ref: AttributeSubjectRef | None
~~~

- reads 声明 provider 可以通过 session 读取的属性。
- writes 声明 provider 可以产生的 target key，不能为空。
- private_namespace 声明可访问的 content 私有命名空间。
- owner_ref 表达 provider 归属主体。

未声明 read/write 或非法私有访问抛出 ProviderDependencyViolationError。

### 10.4 ModifierProvider

~~~text
ModifierProvider
├── provider_spec
└── contribute(query, session) -> Sequence[ModifierTerm]
~~~

contribute 必须无副作用。

### 10.5 StaticModifierProvider

静态 provider 可以绑定 subject_ref。绑定后只对相同 query.subject_ref 返回 term。角色突破属性和武器副属性必须按槽位绑定。

### 10.6 content 接入

推荐入口：

~~~text
ContentRuntimeContribution.attribute_providers
~~~

用于直接贡献原生 ModifierProvider。

兼容入口：

~~~text
ContentRuntimeContribution.modifiers
~~~

legacy modifier：

- 只有已注册属性 target 会接入 resolver。
- owner_ref 必须可转换为 character 或 target。
- provider 按 owner_ref 绑定主体。
- 返回值必须是 core ModifierTerm。

新属性行为优先使用 attribute_providers。

## 11. ResolutionPolicy

### 11.1 base_sum

适用 stat.hp.base、stat.atk.base、stat.def.base。

允许 stage：base_add。

~~~text
base_value =
    contributions 非空：fsum(contribution.value)
    否则：按 MissingValuePolicy 取 default 或报错

result = fsum(base_value, all base_add values)
~~~

### 11.2 total_stat

适用 stat.hp.max、stat.atk.total、stat.def.total。必须有且只有一个 dependency。

允许 stage：percent_add、flat_add、final_multiplier。

~~~text
base = dependency.final_value
percent = fsum(percent_add values)
flat = fsum(flat_add values)

result = base * (1 + percent) + flat

for term in stable final_multiplier order:
    result *= 1 + term.value
~~~

final_multiplier=0.2 表示乘以 1.2。

### 11.3 additive

适用其他第一批公共属性及选择该 policy 的私有属性。

允许 stage：flat_add。

~~~text
base_value =
    contributions 非空：fsum(contribution.value)
    否则：按 MissingValuePolicy 取 default 或报错

result = fsum(base_value, all flat_add values)
~~~

### 11.4 bounds

policy 计算后应用 lower_bound 和 upper_bound。应用 bounds 后，零值规范为正 0.0。

## 12. stacking group 与 override

### 12.1 ModifierStackingGroupDefinition

~~~text
ModifierStackingGroupDefinition
├── group_key: str
├── target_key: AttributeKey
├── stage: ModifierStage
└── policy: ModifierStackingPolicy
~~~

- highest 保留最大 value。
- lowest 保留最小 value。
- 未选 term 进入 rejected_terms。
- 同一 group 的 target 和 stage 必须与定义一致。
- 不支持 latest；时间覆盖由机制运行时处理。

### 12.2 override

- forbidden：出现 override 时抛 InvalidModifierStageError。
- single：允许一个 override。
- 多个 override 抛 ConflictingOverrideError。
- override 替换普通 policy 结果，然后应用 bounds。
- 第一批公共属性全部 forbidden。

## 13. provider 依赖与 session

读取作用域：

- query_subject：当前 query.subject_ref。
- query_target：query.context.target_ref。
- provider_owner：provider 归属主体。

缺少 query target 时抛 MissingQueryTargetError。

静态校验：

- reads/writes 属性必须注册。
- 私有访问必须匹配命名空间。
- writes 不能为空。
- provider_key 不能重复。
- 明确同主体循环在组装阶段拒绝。
- stacking group stage 必须被目标 policy 允许。

运行时循环使用完整 AttributeQuery 身份，包括 subject、key、frame 和 context。

memo 只属于一个 AttributeResolutionSession。不同顶层 resolve 默认重新解析。第一版无跨顶层缓存和 revision token。

## 14. AttributeResolution

~~~text
AttributeResolution
├── attribute_key: AttributeKey
├── subject_ref: AttributeSubjectRef
├── final_value: float
├── base_value: float
├── applied_terms: tuple[ModifierTerm, ...]
├── rejected_terms: tuple[ModifierTerm, ...]
├── dependency_resolutions: tuple[AttributeResolution, ...]
├── policy_key: str
└── trace_metadata: Mapping[str, object]
~~~

模型不可变，trace_metadata 只读。默认 resolve(query) 使用 TraceLevel.FULL。

## 15. 属性快照

### 15.1 模型

~~~text
AttributeSnapshotEntry
├── attribute_key: AttributeKey
├── context: AttributeQueryContext
├── value: float
├── applied_terms: tuple[ModifierTerm, ...]
├── rejected_terms: tuple[ModifierTerm, ...]
└── dependency_trace: tuple[AttributeResolution, ...]

AttributeSnapshot
├── snapshot_id: str
├── frame: int
├── subject_ref: AttributeSubjectRef
├── entries: tuple[AttributeSnapshotEntry, ...]
└── trace_level: TraceLevel
~~~

### 15.2 snapshot 接口

~~~text
snapshot(
    snapshot_id,
    queries: tuple[AttributeQuery, ...],
    trace_level=applied,
)
~~~

- queries 不能为空。
- 所有 query 必须有相同 frame 和 subject_ref。
- entry 必须保留原 query.context。
- 所有 query 在同一 session 中解析。
- none 不保存 term 和 dependency。
- applied 保存 applied term 和 applied 级 dependency。
- full 保存 applied、rejected 和完整 dependency。
- 快照不可变，不随后续状态变化失效。

## 16. 数值与稳定顺序

- 加法使用 math.fsum。
- final multiplier 按稳定 term 顺序相乘。
- term 排序使用 target、stage、provider、source、instance、audit tag 和 value。
- resolver 不进行显示舍入。
- UI 和 analysis 负责显示格式化。
- 真实规则需要取整时，由专用 policy 或机制实现。

## 19. 模块依赖

允许：

~~~text
content -> core.attributes
application.assembly -> assets + content + core.attributes
~~~

禁止：

~~~text
core.attributes -> assets
core.attributes -> content
core.attributes -> application
core.attributes -> infrastructure
core.attributes -> ui
~~~

## 20. 测试要求

至少覆盖：

- key、引用、definition 和 missing value。
- 三种 policy、stacking 和 override。
- provider reads/writes、私有命名空间和循环。
- session memo 与 trace level。
- 快照不可变性和 query context。
- 非有限值、math.fsum 和 -0.0。
- 多角色静态 modifier 隔离。
- legacy modifier owner 隔离。
- content 私有定义和原生 provider 装配。

## 21. 暂缓范围

- 真实内容属性 golden case。
- 领域 Store 动态 modifier 生命周期与简单 Buff 验证切片。
- 跨顶层缓存和 revision token。
- 属性快照结果库 schema。
- 伤害、治疗和反应消费属性的契约。
- UI 属性面板。

这些内容进入对应阶段时应新增或更新相应契约。公共 key 和基础解析语义的破坏性变更必须通过明确契约升级。
