## 1. 产品定位（工作定义，待最终确认）

- 分析区域是用户对仿真结果进行查看、比较、解释并得出判断的画布空间：配置区域回答“模拟什么”，模拟节点回答“跑这批”，分析区域回答“跑出来说明什么”。
- 分析区域的产出是答案和结论：不是新的模拟输入，也不是新的仿真；不改动结果库真值。
- 分析区域随工作流保存，是画布的一部分，不是脱离画布上下文的独立报告页。
- 结果即时变化：视图配置或数据变化后，结果立即重新求值；分析区域不能做成配置区域那样的“方法式”处理链。

## 2. 已确认结论

### 2.1 区域模型

- 区域是数据语言的边界；边界端口是跨区域数据的唯一出入口；**数据只沿连线流动**（该规则适用于配置区域与分析区域）。
- 分析区域边界输入是区域内数据的唯一输入源，提供整个区域的数据来源。
- 区域内任何节点必须沿连线从边界输入取得数据；未连接节点是草稿，不能获得数据。
- 边界输入的上游只能是画布级源节点：模拟节点、数据提供节点。
- 边界输入**允许多源合并**：模拟节点与数据提供节点可同时连入，会话组按连线顺序合并。
- 数据提供节点是画布级节点，不属于分析区域内部；历史结果经它连入边界输入。
- 分析区域不关心数据来源；来源归属由源节点（模拟节点 / 数据提供节点）负责。
- 会话组 = 会话 ID 的有序列表，不携带来源标签或其它元数据。
- 区域本身不承担会话数、来源、成功/失败状态的汇总展示（批次状态在模拟节点，历史选择状态在数据提供节点）。

### 2.2 已废弃的旧条款

- “分析区域的边界输入可以不连接；此时可由区域内的数据提供节点选择历史结果。边界输入与内部数据提供节点是两个明确数据源，不互相替代或隐式合并。”——数据提供节点作为区域内独立数据源的表述不再成立。

### 2.3 执行模型（倾向，待确认）

- 分析区域是声明式、响应式的视图空间：视图自包含数据源、取数口径与展示形式；改配置只重算该视图。
- 视图之间无顺序、互不依赖，都是对同一批会话的独立“读法”；不存在分析构建步骤或方法轨迹。
- 端口语言见 2.8：`会话组` / `查询参数` / `结果表` / `展示配置`。
- 每个视图有独立状态（加载中 / 有数据 / 空 / 错误 / 过期）与缓存键（数据源指纹 + 配置）。

### 2.4 展示形式

- 需要图表形式（如饼图）作为视图的展示方式之一；具体图表种类与范围待定。

### 2.5 数据处理节点（模板查询）

- 数据处理节点是**通用一种**节点：节点引用一个查询模板，节点参数就是模板变量（如“列出某会话的事件”，`session_id`、`frame_min`、`frame_max`、`event_type` 都是参数）。
- 模板由**后端拥有**：每个模板 = SQL + 参数声明 + 关系输入声明 + 输出形状声明；前端节点不传 SQL 字符串，只传“模板 id + 参数绑定”。
- 模板声明：
  - **参数**：名称、类型、必填/可空、绑定类别。绑定类别分：静态（节点卡内输入）、会话组展开、配置节点提供、上游结果列（值链）。
  - **关系输入**：名称 + 所需列；下游 SQL 用占位符（如 `{{source}}`）引用，后端执行时把上游结果表拼为 CTE/派生表，不落地。
  - **输出形状**：列名 + 类型。v1 不做语义标签；列语义由模板文档说明。
- 展开参数（会话组绑定）：v1 只有 `union` 模式——一句 SQL 带 IN 列表执行一次，输出一张表，`session_id` 是输出列；`per_value`（逐会话执行、组输出）不进 v1。
- 处理节点串联两种机制（均支持，由模板声明决定参数或关系输入）：
  - **值链**：下游参数值来自上游结果表某一列；选列在下游节点参数区完成（连线上游后从该表列中选）。
  - **关系链**：下游模板声明关系输入，上游结果表整体作为关系输入。
- 参数绑定必须是安全的参数替换（prepared statement 语义），不允许拼接 SQL。
- 模板集是后端契约：只增不改；自定义模板后置。v1 模板按视图需求驱动，共四张：
  - `session_metrics`（每会话指标）：每会话一行——`session_id`、`run_name`、`frames_run`、各槽位变体列（角色/武器/等级/精炼/命座）、`total_damage`、`dps`、`highest_hit`、`average_hit`、`total_healing`、`damage_count`、`healing_count`；供成员指标表与指标柱状图。
  - `timeline_rows`（时间轴行）：统一行形状 `session_id`、`track`、`start_frame`、`end_frame`（可空）、`value`（可空）、`label`（可空）；供单场时间轴。
  - `share_rows`（占比行）：`group`、`value`（百分比由视图计算）；供占比饼图。
  - `metric_summary`（指标汇总）：关系输入 `source`（指标列），输出 `metric`、`avg`、`max`、`min`、`stddev`、`p95`；作为关系链的消费样例。
  - 原始事件查询、状态折叠等模板后置，等有消费视图（复盘视图、曲线等）时再登记。
- `timeline_rows` 的执行允许后端代码后处理（如持续段的事件配对），模板契约（参数/输出声明）不变；纯 SQL 表达不了的逻辑由模板注册的 Python 行变换承担。
- 执行模型：前端按拓扑序逐节点执行；每个模板执行返回一张表，上游结果表随下游请求传回后端（关系链由后端拼装）。
- 模板目录与执行端点：
  - `GET /api/v1/analysis/templates`：返回模板声明列表，前端据此生成节点卡表单与校验连线。
  - `POST /api/v1/analysis/templates/{template_id}/execute`：请求 = 参数绑定（`session_ids` 展开参数即为普通 `string[]` 参数）+ 关系表（`columns` + `rows`）；响应 = `columns` + `rows` + `truncated`。
  - 行集硬上限 10000 行，超出置 `truncated: true`；关系表上限 5000 行，超限拒绝；v1 不分页，事件类模板靠帧范围/事件类型参数收敛数据量。
- 后端落点：`infrastructure/results_sqlite/templates.py` 负责执行（模板声明与 SQL 同处），`application/` 提供模板模型与用例门面，`server/` 出模板目录与执行端点；原 `analysis/` 顶层模块已删除，前端节点卡只做模板选择与参数编辑。

### 2.6 配置节点的作用域

- 配置节点是独立参数提供者，本身不消费会话数据；需要数据才能做的选择由处理节点或会话组承担。
- 配置节点按用途拆成两类（与视图按形态拆分同一逻辑，不做带模式参数的通用配置节点）：
  - **查询参数配置**（一种通用 kind）：给处理节点提供查询参数。节点卡为行式编辑：每一行 = 参数名 + 值；参数名下拉选项来自所连处理节点模板声明中“允许配置节点提供”的参数，值编辑器按参数类型生成。允许多个查询参数配置节点连同一个处理节点（各提供一部分参数）；一个节点只能连一个处理节点。
  - **展示配置**（四种 kind，各对应一种视图）：给视图节点提供列绑定。表格配置（条件列/数据列）、时间轴配置（轨道列/起点列/终点列/值列/标签列）、饼图配置（分组列/值列/标签列）、柱状图配置（X 轴列/Y 轴列/系列列）。列选项来自视图输入表的列（前端沿“配置节点 → 视图 → 处理节点”解析）；一个视图 v1 必须且只能连一个对应展示配置节点（缺失报错）。
- 查询参数来源：处理节点内静态配置、上游会话组展开（`session_id`）、配置节点提供（普通标量/列表参数）。
- 会话选择 v1 只通过会话组（边界输入 / 数据提供节点）；查询参数配置不承担选场。

### 2.7 节点模型原则（上下文无关）

- **节点是上下文无关的输入→输出单元**：节点不关心输入从哪来、输出被谁用；只声明“接收什么输入、提供什么输出”。
- 节点允许**多输入、多输出**；处理节点之间**允许串联**，处理节点的输出可以分支给多个下游。
- 图的连通性、端口语言匹配、无环等由前端图校验器负责，节点自身不感知图结构。
- 分析区域是**声明式数据流图**：每个节点是纯函数，输出由输入派生；依赖变化自动向下游传播，结果即时更新。这区别于配置区域的“方法式”（节点作为方法、按拓扑序应用、有构建轨迹）。

### 2.7.1 交互原则（节点内状态节点内交互）

- **节点内的状态在节点内交互，其它状态在节点外。**
- 列顺序是视图节点内部状态：在节点内直接调整（拖列头调整顺序）。
- **列显隐不是视图职责**：视图显示收到的全部数据。v1 的数据获取阶段选择落实在事件类模板的参数上（`event_types`、帧范围等行过滤）；固定列模板输出全部列，任意列隐藏后置（需要模板列选择参数与动态输出形状支持）。
- **数据消费方式（哪些列是条件列/数据列）属于配置节点**：视图节点不知道列归属，只按配置节点提供的绑定渲染。

### 2.8 端口语言与数据集

- 分析区域端口语言四套：
  - `会话组`：会话 ID 列表；边界输入与数据提供节点输出；只能进处理节点的展开参数。
  - `查询参数`：查询参数配置节点输出；只能进处理节点的可配置参数。
  - `结果表`：处理节点执行模板的输出（列名 + 类型）；可以进视图数据输入、下游处理节点的关系输入；结果表的列可以绑定到下游值参数。
  - `展示配置`：展示配置节点输出（按视图种类区分）；只进对应视图的配置输入。
- 每个模板执行返回一张表；展开参数 v1 只有 `union` 模式。
- 视图数据输入是**单表语义**：允许一条或多条同结构入线，行拼接为一张表后按同一套绑定渲染；不同结构的表连入由校验器拒绝。视图不设“来源”概念。
- 连接规则按语言 + 形状匹配；不匹配由前端校验器报错。
- 处理节点串联的两种机制（均支持）：
  - **值链**：上游结果表某一列的值作为下游模板参数值；选列在下游节点参数区完成。
  - **关系链**：下游 SQL 把上游结果表当作输入关系（CTE/派生表语义）引用，例如对上游的每会话指标表做聚合；关系输入由模板声明（名称 + 所需列）。

### 2.9 视图节点划分

- 视图节点按具体形态拆成节点种类，不做带模式参数的通用视图节点。已设计：`成员指标表`、`单场时间轴`、`占比饼图`、`指标柱状图`；其余（汇总统计表等）后续设计。
- 饼图与柱状图**拆成两个节点种类**，不通过“图表类型”配置节点区分。
- 视图节点是纯渲染终端：数据来自数据处理节点输出，展示来自配置节点。

### 2.10 对比

- **对比不是独立节点或独立视图**。
- **视图不设“多来源”能力**：同结构的数据是同一份数据，视图按单表语义消费（多条同结构入线行拼接）；需要区分批次/场次时，由结果表里的身份列（`session_id`、变体条件列）承担，并经配置节点绑定（条件列、X 轴、系列列等）。
- 不同结构的数据无法被同一套展示配置覆盖，不能进同一视图；需要并置/对比时由处理模板合并为带来源列的输出表（数据层能力），不进入视图职责。
- 产品决策“多结果对比第一版不强制包含”继续有效。

### 2.11 数据提供节点与模拟节点的会话保留

- 数据提供节点**只提供会话级历史列表**：按名称、时间、状态筛选，多选会话，输出会话组；不提供批次展示，不做“批次 → 成员”展开。
- 所选会话作为节点配置随工作流保存。
- 模拟节点**保存最近一次批次产生的会话 ID**；需要整批数据时，只能经模拟节点的最近一次批次获取（连入分析区域边界输入）。
- 模拟节点最近一次会话 ID **随工作流持久化**：写入模拟节点参数 `last_sessions`（会话 ID 列表），重开工作流后分析区域仍可读取。
- “结果详情暴露输入摘要/成员标签”仍为结果 API 后置能力，不阻塞分析区域第一版。

### 2.12 具体视图：成员指标表

- 作用：参数扫描 / 批结果总览，回答“每个成员表现如何、哪个条件组合最优”。
- 行 = 会话；列分两类：
  - **条件列**：该会话的输入条件（如武器类型、等级、精炼等变体参数），说明这一行是什么配置。
  - **数据列**：需要分析的指标（DPS、总伤害、最高/平均伤害、总治疗等）。
- 条件列来自会话的输入摘要（变体身份），由 `session_metrics` 模板以固定列输出（v1 为 `asset_key` 原始值）；显示名解析与可选列参数后置。会话组本身仍只有 session ID。
- **条件列与数据列绑定由表格配置节点指定**（节点外内容），不是模板声明；模板只输出通用行表；视图节点不知道列归属，按绑定渲染（条件列与数据列分区显示）。
- 视图功能只包含：**排序、列内最大/最小高亮**；列绑定由配置节点提供；不做“哪一行最优”的判断（那是用户的结论）。
- 列内最大/最小高亮是节点内操作：在数据列表头选择“高亮最大 / 高亮最小”，可清除。
- 视图按单表语义消费：多条同结构入线行拼接后按同一套绑定渲染；不设来源标签。
- **排序规则**：
  - 数据列：单列排序（点表头切换升/降），不做多列组合排序。
  - 条件列：支持多列组合排序，**组合顺序 = 用户点击表头的顺序**（先点击的列为主排序键，后点击的列为次级排序键）；例如先点武器类型、再点等级，与先点等级、再点武器类型结果不同；每列方向可切换。
  - 效果：按主排序键分组、组内按次级排序键排序，**分组是排序的自然结果，不需要显式分组功能**。
  - 提供“清除排序”小操作，一次清除全部排序状态。
  - 默认无排序：按数据集行序显示，排序完全由用户点击驱动。
- 显式分组表头（组内排序、组间比较）后置。
- 列顺序在节点内拖拽调整，允许跨区调整显示位置，但跨区不改变绑定（分区由配置节点绑定决定，顺序由节点内拖拽决定）。
- 视觉分区：条件列固定在左侧、数据列在右侧，中间分隔线 + 数据区轻微底色差异。
- 大批量呈现：节点卡内滚动 + 窗口化渲染，不搞分页；显示“共 N 行”；节点可调整大小以改变展示区域。
- 状态直接呈现在内容区：加载中为表格区域骨架、无数据为空表提示、错误为表格区域内错误信息。
- 待定：数值格式化（v1 按列类型默认格式化，自定义格式后置）。

### 2.13 具体视图：单场时间轴

- 作用：回答“这一场是怎么打的”——以时间为横轴，展示关键事件与状态段的时序。
- v1 数据范围：**瞬时点 + 持续段**：
  - 点：伤害结算、治疗结算、护盾吸收、实际扣血、能量直接变化/微粒结算、反应发生、动作开始、切人、按键、附着 ICD 等（带数值的标记）。
  - 段：Buff 施加→移除、护盾授予→移除、附魔、Aura、冷却进行、月曜增伤等（起点到终点的横条）。
  - 曲线（HP / 能量 / 属性面板值）后置，依赖状态折叠更完整覆盖。
- 轨道组织：**按事件类别**（伤害、治疗、护盾、Buff、冷却……），标记/段内用颜色和标签表达角色等实体信息；不按实体开轨。
- 会话选择是数据获取阶段的事（v1 通过会话组选择，模板取单场行；会话组含一场即单场），视图只渲染收到的行。
- **统一行形状**：每行 = 轨道列（事件类别）+ 起点列（帧，必需）+ 终点列（可空，段才有值）+ 值列（可空）+ 标签列（可空）；点行终点为空。时间轴只消费一种数据集形状。
- **时间轴配置节点角色清单**：轨道列（必选）、起点列（必选）、终点列（可选）、值列（可选）、标签列（可选）。
- **节点内交互**：视口缩放/平移、刻度单位切换（帧/秒）、悬停标记/段显示详情（数值、标签、起止帧）。
