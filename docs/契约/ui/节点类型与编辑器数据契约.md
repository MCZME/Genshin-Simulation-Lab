# 节点类型与编辑器数据契约

> 状态：已确认（2026-08-17）；2026-08-17 确认语义注册表归前端。
> 2026-08-20 补充：配置区域无独立输入端口，边界输出同时作为区域内节点链的汇入目标与连接模拟节点的输出源。
> 2026-08-22 术语统一：该节点统一称「模拟节点」，不再使用「模拟桥/桥节点」；注册表类别值 `bridge` 取消，画布级节点以 `region: null` 表示。
> 关联：[工作流定义契约](./工作流定义契约.md)、[批量配置变体契约](./批量配置变体契约.md)、[项目决策记录](../../决策/项目决策记录.md) 2.28。

## 1. 职责与分工

- 语义注册表在 `frontend/`：节点类型、端口模型、片段形状、参数 schema、区域约束与节点级校验。
- 编辑器组件映射也在 `frontend/`：`node_kind -> React 组件`、图标、默认尺寸、面板排序等展示元数据。
- 语义模块与展示模块以稳定 `node_kind` 为公共 key，互不循环依赖；后端不持有节点注册表。
- 显式注册，不自动扫描；未注册 kind 在前端加载/校验阶段报错。

## 2. NodeKindSpec

每个节点类型是一个描述对象，至少包含：

| 字段 | 含义 |
| --- | --- |
| `kind` | 稳定 key，冻结后只追加不改名 |
| `display_name` | 用户可识别名称 |
| `region` | `configuration` / `analysis` / `null`（画布级，不归属区域） |
| 端口模型 | 输入输出端口、数据语言、单值/组基数、连接数约束 |
| 片段形状 | 默认目标路径与参数形状；只声明路径，不读取 SimulationInput schema |
| 参数 schema | 类型化节点参数，供编辑器生成表单与校验 |
| 默认参数 | 创建节点时写入的默认值；编译阶段沿用同一默认值 |
| 节点级校验 | 该类型特有的校验规则 |

以上字段全部由 `frontend/src/workflow/registry.ts` 的 `NodeKindSpec` 声明；片段构造（`fragment`/`groupFragments`）、默认参数（`defaultParams`）与节点级校验（`validate`）已收进注册表。

## 3. MVP 节点注册表

配置区域（`configuration`）：

| kind | 默认路径 | 关键参数 |
| --- | --- | --- |
| `root` | 无 | 文件路径（可选） |
| `meta` | `meta` | 名称（必填）、描述 |
| `character` | `team[i].character` | 槽位 i（1–4）、角色、等级、命座、天赋三项（1–10） |
| `weapon` | `team[i].weapon` | 槽位 i |
| `artifact` | `team[i].artifacts` | 槽位 i（1–4）、套装列表（1–2 条，每条含套装与件数 1/2/4） |
| `target` | `scene.targets[i]` | 目标索引 i、展示名、等级、位置、八项元素抗性 |
| `input_trace` | `input_trace` | 可视化编辑；受支持按键集合见[按键输入契约](../按键输入契约.md) |
| `run_options` | `run_options` | 无 |
| `enum` | 用户指定 | 路径、取值列表、标签 |
| `range` | 用户指定 | 路径、起点、终点、步长、标签 |

画布级节点（`region: null`）：

| kind | 职责 | 关键参数 |
| --- | --- | --- |
| `simulation` | 消费输入文档集合，按成员执行，输出会话组 | 并发度 `concurrency`（整数 1–16，可选；缺省「自动」，不传走后端 `min(4, CPU)`） |

### 3.1 MVP 默认参数

前端创建节点时写入默认参数，编译阶段在没有显式参数时沿用同一默认值：

- 角色：等级 `90`、命座 `0`、天赋 `{normal_attack: 1, elemental_skill: 1, elemental_burst: 1}`。
- 武器：等级 `90`、精炼 `1`。
- 圣遗物：`sets` 一条 `{asset_key: 空, pieces: 4}`；`sets` 最多 2 条；件数限 `1/2/4`；`stats` 保持 `{}` 占位，MVP 不编辑。
- 目标：展示名「遗迹守卫」、等级 `90`、位置 `(0, 0, 5)`、八项元素抗性 `10`。

目标任务 `id` 由目标索引自动生成（`target_<index>`），编辑器不提供 `id` 编辑；展示名 `label` 只用于界面与结果展示，不参与仿真识别。
- 运行选项：`max_frames` 为 `18000`。
- 模拟节点：`concurrency` 不写入默认参数（键缺省即「自动」）；提交批次时仅在参数存在且为 1–16 整数时随请求传出。
- 按键轨迹：`items` 为空数组；数据只使用 `items`，轨道是可视化布局概念，不写入参数。

队伍槽位 `slot` 为 1 起始正整数；后端解析时 `level`、`slot` 为必填字段，因此前端必须在编译产物中给出这些字段。

分析区域节点（查询/指标/聚合/对比/视图/数据提供）不在 MVP 注册；后续只做注册新增，不重构画布。

## 4. 参数 schema

参数 schema 使用类型化字段，供前端生成表单：

- `string` / `integer` / `number` / `boolean` / `text`
- `asset_ref`：引用资产类型，编辑器使用资产搜索选择器
- `list`：有序取值列表（枚举节点）
- `range`：起点/终点/步长（区间节点）
- `object` / `json_fragment`：JSON 片段

常规界面展示显示名称与状态说明，不暴露 `asset_key`、`handler_key`、JSON 路径。路径由节点类型与参数推导（如 `team[slot-1].character`），固定路径节点不提供路径编辑；只有枚举/区间节点在表单中配置目标路径。

## 5. 端口模型

- 端口有稳定 `port_id`；节点默认支持多个独立输入端口与多个输出端口，单输入/单输出是特例。
- 同一输入端口允许多条入线：多条上游按端口顺序（端口内按连线顺序）先连先应用，片段合并由多输入节点隐式完成。
- 基数：单值输出 / 组输出。组输出触发下游展开。
- 成员投影端口：枚举/区间节点可展开单个成员端口（`out:<item_id>`），绑定稳定 `item_id`；折叠后已有连线保留并显示成员标签。
- 成员投影端口连线只携带对应成员：编译按端口过滤变体，同一节点的不同成员分支互斥，不互相覆盖。
- 多路独立输出重新汇入时不得静默恢复成组、拼接或叉乘；汇入语义由下游端口或显式节点声明。

## 6. 编辑器数据契约

前端注册表为每个 `node_kind` 提供：

- 编辑器组件（React）
- 图标与节点类型色
- 默认节点宽度与最小/最大尺寸
- 画布对象面板排序与分组
- 收起时的摘要渲染规则

展示元数据不进入语义注册表，不参与校验与变体展开。

## 7. 特殊行为

- 配置区域边界输出：区域模型内置，不进入节点注册表；配置区域没有独立输入端口，边界输出同时作为区域内节点链的汇入目标与连接模拟节点的输出源。
- 模拟节点：任务分发、成员状态、整批取消，绑定 `simulation` kind 的特殊行为。
- 视图节点：分析区域实现时设计，MVP 不注册。
