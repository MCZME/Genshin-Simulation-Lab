# 事件类型

> 状态：正式规范。
> 本文记录当前已确认的 `EventType`、默认记录规则和载荷类型；事件系统整体设计见[系统设计](./系统设计.md)。
> 最后更新：2026-08-29。

## 1. 范围

当前事件类型覆盖已经确认的模拟器生命周期、输入事实、输入会话边界、伤害结算事实、治疗结算事实、角色生命值状态变化、护盾授予/吸收/应用闭环、状态效果第一版创建/刷新/叠层/替换/离场事实、元素能量载体和直接能量变化事实，以及元素附着/ICD/反应与下坠移动事实。

`HEALING_RESOLVED` 已随治疗系统当前契约实现；护盾新增事件已随护盾核心运行时实现；`BUFF_APPLIED` 与 `BUFF_REMOVED` 已随状态效果第一版工程闭环实现。元素附着/ICD/反应事件与下坠移动事件已随对应运行时实现并登记；`CONTENT_STATE_CHANGED` 已随内容状态 `state_patch` 写入链路实现。

## 2. 事件类型

| 事件类型 | 分类 | 默认记录 | 含义 |
| --- | --- | --- | --- |
| `SIMULATION_STARTED` | `BOUNDARY` | 是 | 一次仿真开始运行。 |
| `SIMULATION_ENDED` | `BOUNDARY` | 是 | 一次仿真结束。 |
| `FRAME_STARTED` | `BOUNDARY` | 否 | 进入某一帧。 |
| `FRAME_ENDED` | `BOUNDARY` | 否 | 某一帧处理完成。 |
| `INPUT_KEY_RECEIVED` | `INTENT` | 是 | 某个配置输入事实在当前帧进入运行时处理。 |
| `INPUT_SESSION_BOUNDARY_REACHED` | `INTENT` | 是 | 某个输入会话边界被 `ActionManager` 处理。 |
| `DAMAGE_RESOLVED` | `FACT` | 是 | 一次伤害数值已经完成结算，但尚不表示目标生命已经扣减。 |
| `HEALING_RESOLVED` | `FACT` | 是 | 一次理论治疗量已经完成结算，但尚不表示目标生命已经增加。 |
| `CHARACTER_HEALTH_CHANGED` | `STATE_CHANGE` | 是 | 角色当前生命已经发生有效变化。 |
| `CHARACTER_MAX_HP_CHANGED` | `STATE_CHANGE` | 是 | 角色最大生命同步导致当前生命按比例调整；不属于普通生命变化。 |
| `SHIELD_GRANTED` | `STATE_CHANGE` | 是 | 护盾实例已经创建、替换、刷新、叠加或保留。 |
| `SHIELD_CAPACITY_CHANGED` | `STATE_CHANGE` | 是 | 护盾原生剩余量已经因吸收、刷新或叠加发生变化。 |
| `SHIELD_REMOVED` | `STATE_CHANGE` | 是 | 护盾因耗尽、过期、替换或显式原因离开活动状态。 |
| `SHIELD_ABSORPTION_RESOLVED` | `FACT` | 是 | 一次正伤害的并行护盾吸收已经完成。 |
| `DAMAGE_APPLIED` | `FACT` | 是 | 一份正伤害已经以角色为目标完成护盾与血量提交。 |
| `BUFF_APPLIED` | `STATE_CHANGE` | 是 | Buff 实例已经创建、替换、刷新、叠层或到顶刷新。 |
| `BUFF_REMOVED` | `STATE_CHANGE` | 是 | Buff 实例因过期、替换、驱散、消费或显式原因离开活动状态。 |
| `INFUSION_APPLIED` | `STATE_CHANGE` | 是 | 附魔/转化来源已创建、刷新或替换。 |
| `INFUSION_REMOVED` | `STATE_CHANGE` | 是 | 附魔/转化来源因过期、替换、驱散、消费或显式原因离开活动状态。 |
| `ENERGY_PICKUP_SPAWNED` | `STATE_CHANGE` | 是 | 元素微粒或晶球已经进入在途队列。 |
| `ENERGY_PICKUP_SETTLED` | `FACT` | 是 | 一个在途元素能量载体已经向当前队伍完成结算。 |
| `DIRECT_ENERGY_CHANGE_RESOLVED` | `FACT` | 是 | 一次直接恢复、直接扣除或爆发扣能已经提交。 |
| `CHARACTER_ENERGY_CHANGED` | `STATE_CHANGE` | 是 | 角色当前元素能量已经发生有效变化。 |
| `AURA_ICD_RESOLVED` | `FACT` | 是 | 元素附着 ICD 已提交本次命中系数；携带游标 `before/after` 完整记录。 |
| `AURA_APPLIED` | `STATE_CHANGE` | 是 | 普通附着或同元素叠加已提交；携带应用前/后完整组件。 |
| `AURA_DEPLETED` | `STATE_CHANGE` | 是 | Aura 自然衰减归零并移除 Component；携带前后元素量。 |
| `AURA_INTERACTION_RESOLVED` | `FACT` | 是 | Reaction 驱动的 Aura 元素量变化已提交；携带消耗量与前后元素量。 |
| `REACTION_STATE_CHANGED` | `STATE_CHANGE` | 是 | ReactionState 完整创建、替换或移除已提交。 |
| `REACTION_OCCURRED` | `FACT` | 是 | 无状态普通 Reaction occurrence 已提交。 |
| `ELEMENTAL_INTERACTION_RESOLVED` | `FACT` | 是 | 整批元素交互已完成状态提交与关联伤害结算。 |
| `MOVEMENT_COLLIDED` | `FACT` | 是 | 下坠碰撞事实已提交。 |
| `MOVEMENT_LANDED` | `FACT` | 是 | 落地事实已提交；携带下落起始帧与高度。 |
| `RESONANCE_ACTIVATED` | `FACT` | 是 | 元素共鸣激活集合已确定；在首个模拟帧时间推进阶段发布一次。 |
| `ACTION_STARTED` | `FACT` | 是 | 动作实例进入运行阶段；供月兆等机制判断元素战技/爆发开始。 |
| `MOONSIGN_LEVEL_SET` | `FACT` | 是 | 月兆等级与月兆角色集合已确定；首个模拟帧发布一次。 |
| `MOONSIGN_BONUS_APPLIED` | `STATE_CHANGE` | 是 | 非月兆角色 E/Q 触发的覆盖式月曜增伤已应用。 |
| `MOONSIGN_BONUS_EXPIRED` | `STATE_CHANGE` | 是 | 月曜增伤到期清除。 |
| `TEAM_SWITCHED` | `FACT` | 是 | 队伍当前场上角色切换请求已处理；携带请求槽位、切换前/后槽位与是否接受。 |
| `COOLDOWN_CHANGED` | `STATE_CHANGE` | 是 | 冷却充能或就绪帧已变化；携带 `before/after` 充能与就绪帧证据。 |
| `CONTENT_STATE_CHANGED` | `STATE_CHANGE` | 是 | 宿主内容状态挂载已提交补丁；携带补丁字段与前后完整状态。 |
| `SPACE_ENTITY_CREATED` | `STATE_CHANGE` | 是 | 空间实体已经登记到 Space；携带完整实体。 |
| `SPACE_ENTITY_REMOVED` | `STATE_CHANGE` | 是 | 空间实体已经从 Space 移除；携带移除前实体。 |
| `ATTRIBUTE_PANEL_CHANGED` | `STATE_CHANGE` | 是 | 属性面板发生有效变化；携带变化字段的 before/after 值与 after 修饰项。 |

说明：

- `SIMULATION_STARTED` 和 `SIMULATION_ENDED` 覆盖 `BOUNDARY` 的默认记录规则，默认进入记录。
- `FRAME_STARTED` 和 `FRAME_ENDED` 继承 `BOUNDARY` 默认规则，不默认记录，避免每帧产生大量结果数据。
- 输入事件属于意图事件，只说明输入事实或会话边界进入处理，不说明动作成功或状态变化。
- `INPUT_KEY_RECEIVED` 记录原始按键事实和关联的输入会话 id，不记录派生的 `held_frames`。
- `INPUT_SESSION_BOUNDARY_REACHED` 记录会话边界、解释器 binding 和是否会调用解释器，用于解释 release 为什么可能因 `detached/canceled` 被跳过。
- `TEAM_SWITCHED` 无论切换是否被接受都会发布，载荷携带 `accepted` 与状态；只有 `accepted=True` 才改变当前场上角色。
- `COOLDOWN_CHANGED` 在冷却提交后按事实顺序发布，覆盖开始、缩短、重置、充能恢复与链完成；状态由冷却领域快照 + 事件前后值折叠还原。
- `CONTENT_STATE_CHANGED` 只在补丁造成实际状态变化时发布；补丁与当前值一致时不发布。载荷携带 `owner_ref`、`state_key`、`fields` 与 `before/after` 完整状态，供“初始快照 + 事件”折叠还原。
- `SPACE_ENTITY_CREATED` / `SPACE_ENTITY_REMOVED` 在空间变更提交后按事实顺序发布，覆盖反应对象与内容创建对象的登记/移除；首版不发布实体位置、刷新、延长等更新事件，与移动状态还原边界保持一致。
- `ATTRIBUTE_PANEL_CHANGED` 由属性系统面板同步器在机制结算后比较发布；只在面板发生有效变化时发布，载荷只含变化字段（`before_value` / `after_value` / `after_terms`），供“初始快照面板 + 事件”折叠还原。
- `AURA_APPLIED` 载荷携带应用前/后的完整 `AuraComponent`（含贡献账本），支持同元素叠加、刷新与替换的折叠还原。
- `DAMAGE_RESOLVED` 保存不可变 `DamageResult`，可以驱动后续机制；生命系统未来使用独立状态变化事件表达伤害已经应用。`result` 保留摘要，`audit` 保存完整伤害公式审计，供伤害事件详情消费。
- `HEALING_RESOLVED` 保存不可变 `HealingResult`，由 `HealingRequestHandler` 在生命提交前发布；满血和零治疗仍保留该理论结算事实。字段与序列化见[治疗系统契约](../../契约/治疗系统契约.md)。
- `CHARACTER_HEALTH_CHANGED` 保存不可变 `CharacterHealthChangeResult`，只在角色生命真实变化时发布；零伤害、满血恢复和被最低生命限制完全阻止的扣血不发布该事件。
- `CHARACTER_MAX_HP_CHANGED` 只用于最大生命同比变化的状态记录，不触发普通生命变化机制；作为状态变化默认记录，供“初始快照 + 事件”折叠还原当前生命。
- `SHIELD_CAPACITY_CHANGED` 和 `SHIELD_REMOVED` 按稳定 `instance_id` 发布；耗尽时先发布容量变化，再发布移除。
- `SHIELD_ABSORPTION_RESOLVED` 只在正伤害且有活动护盾参与时发布；无盾和零伤害不伪造吸收事实。
- `DAMAGE_APPLIED` 在 `CharacterIncomingDamage.amount > 0` 且目标是角色时发布，并保存 `CharacterDamageTakenRecord`。完全吸收时仍发布，但不会因此产生 `CHARACTER_HEALTH_CHANGED`；零伤害不发布。
- 护盾事件的详细字段、发布条件和序列化见[护盾系统契约](../../契约/护盾系统契约.md)。
- `BUFF_APPLIED` 和 `BUFF_REMOVED` 的详细字段、批量应用顺序和 JSON 序列化见[状态效果系统契约](../../契约/状态效果系统契约.md)。
- `INFUSION_APPLIED` 和 `INFUSION_REMOVED` 的详细字段、发布顺序和序列化见[元素附魔系统契约](../../契约/元素附魔系统契约.md)。
- `ENERGY_PICKUP_SETTLED` 即使所有角色实际获得量均为 `0` 也会发布；`DIRECT_ENERGY_CHANGE_RESOLVED` 即使实际变化为 `0` 也会发布，以保留溢出和未应用量审计。
- `CHARACTER_ENERGY_CHANGED` 只在 `effective_amount > 0` 时发布；微粒/晶球接收结果由 `ENERGY_PICKUP_SETTLED` 聚合，不再额外发布直接结算事实。
- 能量事实只在状态提交后发布。事件 handler 不得同步写入能量，必须进入下一结算轮次或未来帧。
- 能量事件的 payload 字段、发布顺序和序列化见[元素能量系统契约](../../契约/元素能量系统契约.md)。
- 除 `DAMAGE_APPLIED` 的目标调整外，表中事件已经恢复运行时发布逻辑；当前代码差异见[角色受伤协调器契约](../../契约/角色受伤协调器契约.md)。
- 事件使用结构化 payload，不使用松散 `data` 字典作为核心事件对象的载荷。

## 3. 载荷

| 载荷类型 | 用途 | 字段 |
| --- | --- | --- |
| `EmptyPayload` | 无字段事件。 | 无 |
| `SimulationEndedPayload` | 仿真结束事件。 | `stop_reason`、`end_frame`、`frames_run` |
| `InputKeyReceivedPayload` | 输入按键事实进入运行时处理事件。 | `key`、`phase`、`order`、`session_id` |
| `InputSessionBoundaryPayload` | 输入会话边界进入 `ActionManager` 处理事件。 | `session_id`、`key`、`phase`、`order`、`press_frame`、`held_frames`、`physical_state`、`control_state`、`owner_kind`、`owner_slot`、`interpreter_id`、`binding_scope`、`will_interpret`、`skip_reason` |
| `DamageResolvedPayload` | 伤害数值完成结算的事实事件。 | `result`、`audit` |
| `HealingResolvedPayload` | 理论治疗量完成结算的事实事件。 | `result` |
| `CharacterHealthChangedPayload` | 角色当前生命变化状态事件。 | `result` |
| `CharacterMaxHpChangedPayload` | 角色最大生命同步状态事件。 | `result` |
| `ShieldGrantedPayload` | 护盾授予状态事件。 | `result` |
| `ShieldCapacityChangedPayload` | 护盾原生容量变化状态事件。 | `result` |
| `ShieldRemovedPayload` | 护盾移除状态事件。 | `result` |
| `ShieldAbsorptionResolvedPayload` | 并行护盾吸收事实事件。 | `result` |
| `DamageAppliedPayload` | 正伤害以角色为目标完成护盾与血量提交。 | `record` |
| `BuffAppliedPayload` | Buff 创建、替换、刷新或叠层状态事件。 | `result` |
| `BuffRemovedPayload` | Buff 离场状态事件。 | `result` |
| `InfusionAppliedPayload` | 附魔/转化来源创建、刷新或替换状态事件。 | `result` |
| `InfusionRemovedPayload` | 附魔/转化来源离场状态事件。 | `result` |
| `EnergyPickupSpawnedPayload` | 元素微粒或晶球已入队。 | `record` |
| `EnergyPickupSettledPayload` | 元素微粒或晶球已经完成队伍结算。 | `result` |
| `DirectEnergyChangeResolvedPayload` | 直接恢复、直接扣除或爆发扣能已提交。 | `result` |
| `CharacterEnergyChangedPayload` | 角色当前元素能量已有效变化。 | `result` |
| `AuraIcdResolvedPayload` | 元素附着 ICD 命中系数已提交事实事件。 | `result` |
| `AuraAppliedPayload` | 普通附着或同元素叠加已提交状态事件。 | `result` |
| `AuraDepletedPayload` | Aura 自然衰减归零并移除 Component 状态事件。 | `result` |
| `AuraInteractionResolvedPayload` | Reaction 驱动的 Aura 元素量变化事实事件。 | `result` |
| `ReactionStateChangedPayload` | ReactionState 创建/替换/移除状态事件。 | `change` |
| `ReactionOccurredPayload` | 无状态 Reaction occurrence 事实事件。 | `occurrence` |
| `ElementalInteractionResolvedPayload` | 整批元素交互完成事实事件。 | `record` |
| `MovementCollidedPayload` | 下坠碰撞事实事件。 | `entity_id`、`frame` |
| `MovementLandedPayload` | 落地事实事件。 | `entity_id`、`frame`、`fall_start_frame`、`fall_height` |
| `ResonanceActivatedPayload` | 元素共鸣激活集合已确定。 | `active_keys`、`team_size`、`established_frame` |
| `ActionStartedPayload` | 动作实例开始运行。 | `instance_id`、`frame`、`action_key`、`owner_slot`、`ability_key` |
| `MoonsignLevelSetPayload` | 月兆等级确定。 | `level`、`moonsign_character_refs`、`established_frame` |
| `MoonsignBonusAppliedPayload` | 月曜增伤应用。 | `frame`、`source_ref`、`value`、`expires_at_frame` |
| `MoonsignBonusExpiredPayload` | 月曜增伤到期。 | `frame`、`source_ref`、`value` |
| `ContentStateChangedPayload` | 内容状态挂载变化状态事件。 | `frame`、`owner_ref`、`state_key`、`fields`、`before`、`after` |
| `SpaceEntityCreatedPayload` | 空间实体登记状态事件。 | `frame`、`entity` |
| `SpaceEntityRemovedPayload` | 空间实体移除状态事件。 | `frame`、`entity` |
| `AttributePanelChangedPayload` | 属性面板变化状态事件。 | `frame`、`subject_ref`、`changes` |

- `DamageResolvedPayload` 的 `result` 与 `audit` 形状由[伤害系统契约](../../契约/伤害系统契约.md)第 9 节定义；`audit` 存储载荷由[结果库契约](../../契约/结果库契约.md)第 5.3 节定义。

## 4. 后续扩展

新增事件类型时必须同步补充：

- `EventType` 成员。
- 对应 payload 类型。
- `EVENT_SPECS` 条目。
- 本文档中的事件表和载荷对应关系。

状态效果后续新增触发型 Buff、周期命令或专用结果投影时，必须先升级[状态效果系统契约](../../契约/状态效果系统契约.md)，再补充新的事件或 payload。

元素附着/ICD/反应与下坠移动事件已随对应 Runtime/协调器实现登记，见上表；`REACTION_RESOURCE_CHANGED` 仍为预留名称，未实现前不加入事件表。元素反应详细语义见[元素反应事务、事实与验证](../系统/元素反应/事务、事实与验证.md)与[元素反应协调器设计](../协调/元素反应协调器设计.md)。
