# 资产系统设计

> 状态：正式规范。
> 本文描述资产系统：它把外部静态数据（Project Amber / Yatta）校验并构建为只读 SQLite 资产库，再经 `AssetRepository` 提供给组装与内容层；字段与 schema 真值见[资产数据库契约](../契约/资产数据库契约.md)。
> 最后更新：2026-09-05。

## 1. 定位

资产系统负责把外部静态数据转换为项目内部可验证、可分发、只读的资产库，并在仿真组装阶段提供资产读取能力。

资产系统不负责实现具体角色、武器、圣遗物机制。资产库只保存基础索引、等级属性、倍率表、效果参数与 `handler_key`，真实行为由 `content/` 的 handler 实现。

## 2. 分层

资产系统按数据形态分为五层：

```text
外部源站 raw JSON
-> source cache
-> 标准资产 manifest
-> SQLite 资产库
-> AssetRepository 协议
```

- 外部源站 raw JSON：来自 Project Amber / Yatta 当前默认 API。
- source cache：开发期本地缓存，用于调试转换器和追溯源字段。
- 标准资产 manifest：源站无关的资产导入边界。
- SQLite 资产库：正式运行时携带的只读生成产物。
- `AssetRepository`：应用和组装层读取资产的稳定协议。

正式发布和运行时只依赖 SQLite 资产库，不依赖 source cache。

## 3. 模块职责

资产链路横跨四个模块：

### 3.1 `assets/`：资产数据层

保存资产数据对象、仓库协议与相关错误（`models.py`、`repository.py`、`errors.py`、`composite.py`）。该模块不读取 SQLite、不抓取网络数据，也不实现导入流程。

### 3.2 `infrastructure/assets_project_amber/`：源站适配层

负责抓取 Project Amber / Yatta 源站响应、保存 raw JSON cache，并把 cache 转换为标准资产 manifest。转换器按角色、武器、圣遗物、公共工具拆分实现；该层只认识源站字段，不直接写 SQLite。

### 3.3 `infrastructure/assets_sqlite/`：资产库适配层

负责定义与初始化资产库 schema、读取并审计 manifest、原子化写入 SQLite、校验资产库，并实现 `SQLiteAssetRepository`。该层不实现具体游戏机制。

### 3.4 `application/` 与 `content/`：消费侧

- `application/` 通过 `AssetRepository` 读取资产，并在组装阶段把 `asset_key -> 资产对象 -> handler_key -> content handler` 连起来；缺资产、缺 handler 或 JSON payload 不合法时在组装阶段报错。
- `content/` 读取资产对象中的 `handler_key`、`TalentScalingEntry` 与 `EffectPayload` 实现真实机制；不访问 SQLite，也不从源站字段推断数据来源。

## 4. 数据构建流程

开发期完整流程：

```text
genshin-sim assets fetch-source
-> data/assets/sources/project_amber_yatta/...
-> genshin-sim assets build-manifest
-> data/assets/manifests/project_amber_yatta.json
-> genshin-sim assets audit-manifest
-> genshin-sim assets build --manifest
-> data/assets/assets.db
-> genshin-sim assets validate
```

- `assets build --manifest` 先写临时数据库，校验通过后再替换目标库，避免留下半成品资产库。
- `assets build` 无 `--manifest` 时只生成最小烟测库，用于开发闭环，不代表真实资产导入。
- handler 绑定的维护命令与写回 manifest 规则见[资产数据库契约](../契约/资产数据库契约.md)的 handler 绑定章节。

## 5. 数据来源边界

第一版正式数据来源为 Project Amber / Yatta 当前默认数据。

source cache 是开发期中间产物：

- 可以保存到本地用于调试。
- 不进入正式发布包。
- 不写入 SQLite 资产库表。
- 不作为运行时依赖。

SQLite 资产库通过 `source_name`、`source_version`、`source_language`、`data_version`、`importer_version`、`built_at` 与 `content_hash` 标识构建来源。

## 6. 导入范围

当前 Project Amber / Yatta 转换器导入：

- 角色基础索引、角色 1-90 + 95 + 100 等级属性、普攻/战技/爆发核心倍率、固有天赋与命座效果参数。
- 武器基础索引、武器等级属性与精炼效果参数。
- 圣遗物套装基础索引与套装件数效果参数。

未实现真实机制的效果参数使用显式 `*.unimplemented_*` handler 标记，表示数据已入库但机制尚未实现。

## 7. 运行时读取

运行时只通过 `AssetRepository` 读取资产：

```text
get_meta()
get_info()
list_characters()
get_character()
get_character_level_stats(..., ascended=True)
list_weapons()
get_weapon()
get_weapon_level_stats(..., ascended=True)
list_artifact_sets()
get_artifact_set()
get_artifact_set_bonuses()
get_talent_scalings()
get_effect_payloads()
```

`core/` 不依赖 `AssetRepository`；资产读取发生在 `application/assembly` 等组装阶段，组装完成后 `core/` 接收纯运行时对象。

### 7.1 开发者测试资产（不落库）

开发者模式（`config.toml` 的 `[developer] enabled`）下的测试资产不进入 SQLite 资产库，由代码直接定义：

- 数据对象定义在 `content/test/assets.py`，由 `content/test/asset_repository.py` 的 `TestAssetRepository` 提供与 SQLite 实现相同的只读协议。
- `assets/composite.py` 提供 `CompositeAssetRepository`：主库优先、测试库兜底；测试资产键与正式键按命名约定不相交。
- 装配接线在 `application/bootstrap.py`：开发者模式下把 `asset_repository` 换成组合仓库；正常模式不构造组合仓库、不导入测试包，测试资产完全不可见。
- 批处理子进程通过 `developer_mode` 标志透传，worker 按标志构造组合仓库。
- 自动化代码测试不依赖 `content/test` 的资产仓库；需要合成资产时使用 `backend/tests/helpers/fixture_assets.py` 写入临时 SQLite 资产库，见[测试规范](../工程/测试规范.md) 3.3。

## 8. 质量门

资产数据进入正式库前必须经过三层验证：

1. manifest loader：检查 JSON 结构、必填字段、未知字段和基础类型。
2. manifest audit：检查唯一键、引用关系、枚举、等级覆盖、倍率表和效果参数基础 schema。
3. SQLite validate：检查表结构、schema version、外键和 JSON payload 可解析性。

当前导入链路已通过上述三层验证；验证通过只表示导入链路可用，不表示对应角色、武器、圣遗物机制已经实现。
