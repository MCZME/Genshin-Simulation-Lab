# 分析系统规划

> 状态：生效，持续维护。
> 本文按[分析系统设计](../架构/分析系统设计.md)排定落地方案，登记第一版范围、阶段目标与工程关注点。
> 最后更新：2026-08-23

## 1. 定位

本文是分析系统的落地路线图：按小切片实现还原/查询、中间模型、指标与对比，遵守“analysis 不写库、不画 UI、不直接访问 SQLite”的边界。

## 2. 分阶段落地

1. 阶段 A：状态还原器 + 属性面板
   - 初始快照 `attributes` provider（第 0 帧面板 + `applied_terms`）。
   - 属性系统面板同步器与 `ATTRIBUTE_PANEL_CHANGED` 事件。
   - 还原器第一组领域（队伍、生命、能量、冷却、Buff、护盾、附魔）；未覆盖领域返回基线 + 标记。
   - 状态：已落地。属性面板（provider + 同步器 + 事件）、第一组还原领域与 `fold_status` 已实现；Buff/护盾/附魔应用载荷已补 `instance_after` 完整实例证据。
2. 阶段 B：查询与数据寻址
   - `StateQuery` / `EventQuery` 结构化查询对象。
   - 路径解析（字段/节点、键值筛选）与查询结果模型。
   - 事件查询过滤与分页。
   - 状态：已落地。路径解析器（标识符/引号键/键值筛选）、`StateQuery`（多运行/多帧/多路径）、`EventQuery`（类型/帧范围/载荷路径/等值过滤/分页）与 `ResultsService` 查询门面已实现。
3. 阶段 C：中间模型
   - 伤害序列、治疗序列（原始数值）。
   - 冻结测试。
   - 状态：已落地。`DamageSequenceEntry` / `HealingSequenceEntry` 与构建函数已实现，字段冻结测试已覆盖。
4. 阶段 D：指标
   - 总伤害、DPS、最高/平均单次伤害、伤害占比、总治疗与治疗占比。
   - 指标输出带口径说明。
   - 状态：已落地。`DamageMetrics` / `MetricValue` / `ShareValue` 与 `build_metrics` 已实现，`ResultsService.damage_metrics` 门面已接入；字段冻结测试已覆盖。
5. 阶段 E：对比
   - 查询结果并置模型；先支持任意数据并置，再按需求加对齐/聚合方案。
   - 状态：已落地。`ComparisonQuery` / `ComparisonColumn` / `ComparisonResult` 与 `build_comparison` 已实现，`ResultsService.compare` 门面已接入；字段冻结测试已覆盖。

## 3. 第一版范围与排除

第一版包含：

- 单帧/多帧状态查询、事件查询（等值过滤）。
- 伤害/治疗序列；摘要指标（整场口径）。
- 属性面板（值 + `applied_terms`）。

明确排除（后续增强）：

- 窗口 DPS：第一版只算整场 DPS（帧转秒 = `frames_run / 60`）。
- 指标寻址：查询模型暂不寻址派生指标。
- `rejected_terms` / `dependency_trace`：属性计算证据第一版只存 `applied_terms`。
- 连续帧增量折叠：逐帧序列查询优化，等单帧查询落地且性能实测后再做。
- Reaction Gate 记录：随结果存储待确认项。

遗留待确认（自迁移阶段安排收束转入）：

- 状态还原测试扩展：Aura/ICD/Reaction/空间等领域补充 baseline 断言或显式排除说明。
- 空间实体位置/生命周期更新（跟随、刷新、延长）是否必须还原待确认；暂以[结果库契约](../契约/结果库契约.md)第 5.1 节登记为准。

## 4. 工程关注点

- 帧率收敛：当前 `FRAMES_PER_SECOND = 60` 分散在三处（内容效果、Aura、Reaction），实现时收敛为共享定义；DPS 口径依赖它。
- 属性面板同步点：第一版正确性优先；面板比较与发布频率的性能优化（按需触发）在实测后处理。
- 事件查询必须分页/限流，事件流可能很大。
- 还原器未覆盖领域的标记要透传到 UI，避免把基线当精确结果展示。
- 契约冻结测试：伤害/治疗序列与属性面板形状。
- 文档同步：转正式后更新文档入口、模块边界设计，并在[结果库契约](../契约/结果库契约.md)第 5.1 节登记属性面板纳入与 analysis 还原覆盖。

## 5. 与结果存储/分析契约的衔接

- 属性初始面板“首版排除”结论已反转（analysis 需要属性面板），纳入 `attributes` provider 与 `ATTRIBUTE_PANEL_CHANGED`，见[结果库契约](../契约/结果库契约.md)第 5.1 节。
- 属性面板事件属新增事件类型，登记同步[事件类型](../架构/事件系统/事件类型.md)与冻结测试。
- Aura/ICD/Reaction/Movement 事件类型已登记到[事件类型](../架构/事件系统/事件类型.md)。
- 状态折叠测试随阶段 A/B 落地；还原覆盖的遗留待确认见第 3 节。
