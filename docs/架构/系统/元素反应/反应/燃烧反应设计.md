# 燃烧反应设计

> 状态：已实现
> 最后更新：2026-08-02
> 对应契约：[燃烧反应契约](../../../../契约/元素反应/反应/燃烧反应契约.md)

## 1. 定位

普通燃烧由火元素命中普通草或激元素，或者草元素命中普通火触发。它不是一次性伤害，而是由一个派生 `BURNING` Aura 和一个目标级 `BurningState` 共同表示的持续反应。

燃烧建立时会产生一次下一结算轮次的火元素剧变伤害；状态存续期间，底层类草 Aura 按特殊速率消耗，并按独立游标生成周期伤害和主体火元素施加。燃烧不拥有 Aura、Damage 或 Space 的运行时，只通过强类型计划声明跨系统效果。

## 2. 领域所有权

| 领域 | 拥有内容 |
| --- | --- |
| Reaction | 方向、Profile、首次 occurrence、`BurningState`、Gate 语义、来源快照和周期原因 |
| Aura | 普通火/草/激元素及派生 `BURNING` 的元素量、贡献、衰减和 Link 投影 |
| Damage | 剧变公式、等级系数、元素抗性读取和伤害结果 |
| Space | 燃烧周期伤害的范围目标选择 |
| Coordination | 状态计划、帧规范化、跨系统预校验、周期物化、提交和事实顺序 |

Reaction 不复制 Aura 当前元素量，不直接执行 Damage 公式，不直接查询或修改 Space/Aura/Damage Runtime。协调器也不按字符串 key 增加燃烧专用写分支；状态帧和周期根通过强类型 adapter 注册。

## 3. 方向与首次建立

| 方向 | 后手元素 | 先手 Aura |
| --- | --- | --- |
| `incoming_pyro_on_dendro` | 火 | 草 |
| `incoming_pyro_on_quicken` | 火 | 激元素 |
| `incoming_dendro_on_pyro` | 草 | 火 |

请求必须有正的 ICD 后入射元素量和剧变来源观察。首次建立不把火草元素量消费掉：`Reaction` transition 的 `incoming_consumed` 和 `aura_consumed` 均为零；普通后手 Aura 的附着和 `20%` 标准附着损耗由 Aura 计划处理。

首次建立的跨域效果包括：

- 一个 `ReactionOccurrence` 和一个 `BurningStateEstablishmentIntent`；
- 固定 `2 GU` 的 `AuraKind.BURNING`，不使用自然衰减档案；
- 当前帧产生一个 `NEXT_SETTLEMENT_ROUND` 的 1 米范围火剧变伤害 Effect Group，包含主体；
- `BurningState` 与燃元素、普通草或激元素通过同一 `ElementalStateLinkRef` 原子绑定。

首次 Effect Group 的伤害由统一 Damage Impact 流程执行，不在当前 Reaction 调用栈中直接结算。

## 4. Aura、Link 与状态

普通草或激元素在燃烧期间使用 `AuraDecayMode.REACTION_MANAGED`，其元素量仍由 Aura Store 唯一保存。每个类草 Component 独立参与特殊消费；存在普通火时，普通火可与燃元素和类草 Aura 共存，但普通火不属于燃烧继续条件。

`BURNING` 是 Reaction 创建的派生 Aura：

- 固定建立为 `2 GU`；
- 不自然衰减；
- 只能通过火性质反应被消费，或在类草 Aura 全部耗尽时随状态清理；
- 必须携带唯一 Burning Link，且该 Link 必须同时出现在至少一个受 Reaction 管理的 DENDRO/QUICKEN Component 上。

同一目标最多有一个共享 `BurningState`。状态保存：

```text
instance_ref
subject_ref
burning_aura_link_ref
dendro_like_link_refs
created_by_occurrence_ref
current_effect_owner
captured_scaling_basis
created_frame
next_dendro_like_depletion_frame
next_damage_tick_frame / next_damage_tick_index
next_pyro_application_frame / next_pyro_application_index
revision
```

状态不复制燃元素或类草当前量。`next_required_frame` 是类草预计耗尽、伤害周期和施火周期三个帧游标的最小值。

## 5. 类草特殊消费

燃烧期间每个与 Burning Link 关联的普通草或激元素 Component 都按完整速率独立消费：

```text
1 / 150 GU per frame = 0.4 GU per second at 60 FPS
```

该速率替代普通自然衰减，不在其上叠加。每个 Component 单独减少相同速率；不是把速率在多个 Component 之间分摊。帧规范化先提交类草消费，再检查状态连续性。

如果本帧所有类草 Component 都耗尽，协调器在物化任何周期工作前原子删除 `BurningState` 和 `BURNING`，因此同一帧不再产生伤害或周期火。若只耗尽其中一个 Component，保留剩余 Component；激元素耗尽时同时结束其关联 `QuickenState`。

## 6. 来源捕获与维护

首次建立和合法的正火/正草维护都会捕获来源等级、元素精通、剧变 Profile、等级系数和 `reaction_bonus`，并保存为 `CapturedTransformativeScalingBasis`。周期伤害只读取状态快照，不实时读取来源属性。

活动燃烧再次收到正火或正草时：

- 不产生新的 occurrence；
- 不补充或重置 `2 GU` 燃元素；
- 不重置伤害或施火游标；
- 按普通 Aura 规则处理对应底层 Aura，并替换 `current_effect_owner` 和捕获快照。

周期生成的火施加带有 `state_maintenance_allowed=false`，不会把燃烧自身的周期火当成来源维护。`0 GU` 施加不能刷新来源。来源失效通知不会结束状态，已有快照继续使用，直到状态正常结束或被合法维护替换。

## 7. 伤害与 Gate

燃烧伤害属于 `TRANSFORMATIVE_REACTION`，基础倍率固定为 `0.25`：

```text
damage = level_multiplier
       * 0.25
       * (1 + 16 * EM / (EM + 2000) + reaction_bonus)
       * pyro_resistance_multiplier
```

当前普通燃烧固定 `reaction_bonus = 0.0`。伤害不使用攻击力、暴击、普通伤害加成或标准防御公式；审计中的防御乘数固定为 `1.0`，目标火抗由 Damage 读取。伤害元素量为 `0`，不会再次附着火。

周期伤害以主体为锚点，对 X/Z 平面半径 `1 m` 内的全部合法敌对目标逐目标生成火伤害，包含主体。范围查询和目标快照属于 Space/协调器，不属于 Reaction 规则。

伤害 Gate 的作用域为 `effect_owner + damage_target + burning damage kind`：窗口 `120` 帧，窗口内最多接受 `8` 次。Gate 只阻止伤害，不阻止类草消费、状态游标前进或周期火施加。建立时的首个伤害和后续周期伤害共享同一规则。

## 8. 周期与结算顺序

建立 occurrence 的立即伤害在当前交互提交后进入下一 settlement round。状态建立后的游标为：

- 下一次周期伤害：`created_frame + 15`，之后每 `15` 帧；
- 下一次周期火：`created_frame + 15`，之后每 `120` 帧；
- 周期火施加量：`1 GU`，只作用于燃烧主体，不进入 Aura ICD。

伤害周期和施火周期使用同一个 `BurningCycleRootWork`，但保留两个独立的 `ScheduledStateTickCause`。同帧同时到期时固定先准备伤害 Effect Group，再准备周期火 Impact Batch；周期火触发的后续反应进入后续 settlement round。

状态已经结束或 Link 投影不一致时，scheduled root 只返回取消结果，不生成效果，不伪造 occurrence。

## 9. 其他火性质反应与熄灭

后手水、冰、雷、风或岩作用于同时存在的普通火和燃元素时，Reaction Runtime 使用同一后手预算分别计算两个火性质 Component 的消费。未使用的分支预算不能互相转移；同一交互只形成一个对应反应效果，而不是两个 occurrence。

燃元素分支耗尽时，当前交互追加 `BurningStateTerminationIntent(BURNING_DEPLETED)`，原子移除 `BurningState` 和 `BURNING`，并恢复剩余类草为普通衰减。剩余后手预算只有在已有公共候选规则能够确定时才继续进入其他草反应；进入尚未注册的绽放或激化候选时稳定失败，不能静默丢弃或猜测顺序。

熄灭后保留未耗尽的普通火、草或激元素 Aura。后续新的正火或正草施加可以重新建立新的 occurrence、State、Link、`2 GU` 燃元素和建立伤害。

## 10. 事务、事实与边界

建立、维护、帧消费、周期物化和终止都采用 prepare、validate、无回调 commit。Aura、Reaction、Damage 和协调计划任一版本或 Link 校验失败时，本批次不得部分提交。

燃烧不新增专属 EventType：

- 建立使用通用 `REACTION_OCCURRED`；
- State 建立、维护和终止使用 `REACTION_STATE_CHANGED`；
- 周期 cause、Gate、Effect Group 和 Damage ref 通过通用 payload 审计；
- Damage 结果由 Damage 系统发布，Aura 变化由 Aura 系统发布。

当前不实现环境草地、火把和热源传播、自身燃烧或自伤、目标死亡检测上游、燃烧暴击、控制效果、角色专属改写、非零燃烧反应加成以及未注册的吸收/注入路径。
