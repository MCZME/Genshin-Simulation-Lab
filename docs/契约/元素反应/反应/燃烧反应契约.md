# 燃烧反应契约

> 状态：已实现
> 最后更新：2026-08-02
> 对应设计：[燃烧反应设计](../../../架构/系统/元素反应/反应/燃烧反应设计.md)

## 1. 稳定标识

| 类型 | 稳定键 |
| --- | --- |
| 反应 | `reaction.burning` |
| Handler | `reaction_handler.burning` |
| 火命中草方向 | `incoming_pyro_on_dendro` |
| 火命中激元素方向 | `incoming_pyro_on_quicken` |
| 草命中火方向 | `incoming_dendro_on_pyro` |

## 2. Definition 与 Profile

燃烧 Definition 必须使用 `ReactionEntryKind.ELEMENTAL_INTERACTION`，声明三组一一对应的 `ReactionTriggerSignature` 和 `TransformativeReactionProfile`：

```text
incoming_pyro_on_dendro  = PYRO on DENDRO
incoming_pyro_on_quicken = PYRO on QUICKEN
incoming_dendro_on_pyro  = DENDRO on PYRO
```

三个方向的 `trigger_element` 分别为火、火、草；伤害元素统一为火；`base_multiplier=0.25`；伤害 Profile、Gate 和 damage kind 必须使用本契约稳定键。Profile 不保存当前 Aura 数量、目标选择或运行时 Gate Record。

## 3. 评估输入与建立结果

燃烧评估必须满足：

- 入射元素量为正，且为 Aura ICD 后的实际预算；
- 目标观察包含对应正先手 Aura，或处于可维护的活动 `BurningState`；
- 提供 `TransformativeSourceObservation` 或已捕获的等价来源快照；
- 观察到的 State、`BURNING` Aura 和类草 Link 投影彼此一致。

首次建立的 `ElementalTransitionEffect` 使用对应先手 Aura，但 `incoming_consumed=0`、`aura_consumed=0`；正常后手 Aura 附着由状态计划按标准 `20%` 损耗执行。成功建立必须产生一个 occurrence 和一个建立意图，不得产生第二个同目标 Burning State。

建立意图必须创建固定 `2 GU` 的 `AuraKind.BURNING`，并关联至少一个 DENDRO/QUICKEN Component。建立 occurrence 必须包含一个 `NEXT_SETTLEMENT_ROUND`、半径 `1.0`、`include_anchor=true` 的火剧变伤害 Effect Group。

## 4. Aura 与 Link 契约

`BURNING` Component 必须满足：

- `current_amount` 建立为 `2 GU`；
- 恰好携带一个 Burning Link；
- `decay_mode=AuraDecayMode.STATE_LINKED`；
- 不携带自然衰减 Profile；
- 与至少一个 `DENDRO` 或 `QUICKEN` Component 共享该 Link。

与该 Link 关联的 DENDRO/QUICKEN Component 必须使用 `decay_mode=AuraDecayMode.REACTION_MANAGED`。普通火可以共存，但不是燃烧状态的连续性条件。Aura Store 是所有当前元素量和贡献的唯一真值。

## 5. BurningState 契约

```text
BurningState
├── instance_ref
├── subject_ref
├── burning_aura_link_ref
├── dendro_like_link_refs
├── created_by_occurrence_ref
├── current_effect_owner
├── captured_scaling_basis
├── created_frame
├── next_dendro_like_depletion_frame
├── next_damage_tick_frame / next_damage_tick_index
├── next_pyro_application_frame / next_pyro_application_index
└── revision
```

不变量：

- 目标级 `ReactionStateSlot.BURNING` 最多一个实例；
- `burning_aura_link_ref` 必须包含在 `dendro_like_link_refs` 中；
- `captured_scaling_basis.source_ref == current_effect_owner`；
- 三个 next frame 都必须晚于 `created_frame`；
- 三个 next frame 的最小值是 `next_required_frame`；
- State、燃元素和每个类草 Component 的 Link 必须完整双向投影；
- State 不复制任何 Aura 当前量。

## 6. 类草消费与时序

燃烧期间每个关联 DENDRO/QUICKEN Component 按 `1/150 GU/frame` 独立消费。预计耗尽帧使用精确有理数向上取整：

```text
next_dendro_like_depletion_frame = frame + ceil(amount / (1/150 GU))
```

每帧规范化顺序固定为：

1. 消费所有关联类草 Component；
2. 检查类草与燃元素连续性并处理终止；
3. 物化到期燃烧伤害；
4. 物化到期周期火施加。

建立后游标固定为：

```text
next_damage_tick_frame = created_frame + 15
next_damage_tick_index = 1
next_pyro_application_frame = created_frame + 15
next_pyro_application_index = 1
```

后续伤害间隔为 `15` 帧，周期火间隔为 `120` 帧，周期火施加量为 `1 GU`。同帧到期时伤害 cause 排在周期火 cause 之前。周期火只生成主体当前目标的 `ReactionGeneratedImpactBatch`，不进入 Aura ICD；周期火自身不得触发 BurningState 维护。

## 7. 来源快照

`CapturedTransformativeScalingBasis` 至少冻结：

```text
source_ref
captured_frame
source_level
elemental_mastery
reaction_bonus
reaction_profile_key
damage_profile_key
level_multiplier_table_key
level_multiplier
source_observation_ref
source_owner_slot
```

首次建立和正火/正草维护必须提供有限、非负的元素精通和有效等级系数。当前燃烧固定 `reaction_bonus=0.0`。来源维护保留 State 实例及两个周期游标，只增加 revision 并替换 owner/basis。周期火、零元素量施加和 owner 失效通知不得刷新 basis。

## 8. 伤害与 Gate

燃烧 Damage Profile 必须选择 `damage_formula.transformative_reaction`，Damage Element 为火，使用共享剧变等级系数和以下反应区：

```text
level_multiplier
* 0.25
* (1 + 16 * EM / (EM + 2000) + reaction_bonus)
* pyro_resistance_multiplier
```

当前 `reaction_bonus` 固定为 `0.0`，防御审计乘数为 `1.0`，不暴击，不读取攻击力或普通伤害加成，伤害元素量为 `0`。

`reaction_gate.burning.damage` 必须配置：

```text
window_frames = 120
max_instances = 8
scope = effect_owner + damage_target + damage_kind
```

Gate blocked 只取消本笔伤害；不得回滚类草消费、周期游标、状态或周期火。建立首个 Effect 和周期 Effect 共用该 Gate 身份规则。

## 9. 复合火性质候选

后手水、冰、雷、风或岩同时面对普通 `PYRO` 和 `BURNING` 时，两个分支必须使用同一后手预算独立计算消费，未消费预算不在分支间转移，并且整次交互最多生成一个对应反应效果。若燃元素耗尽，必须追加 `BurningStateTerminationIntent(BURNING_DEPLETED)`，移除 State 与 `BURNING`，恢复剩余类草的标准衰减。

熄灭后的剩余预算进入未注册草反应候选时必须稳定失败；不得伪造 occurrence、静默丢弃或依赖 Registry 注册顺序猜测。

## 10. 维护、终止与事务

活动维护使用强类型 `BurningStateMaintenanceIntent`，不得创建 occurrence、补充燃元素或重置游标。终止使用 `BurningStateTerminationIntent`：

- `BURNING_DEPLETED`：要求燃元素已归零，原子清理 State/Link；
- `SUBJECT_UNAVAILABLE`：清理燃元素并恢复剩余类草标准衰减。

建立、维护、帧消费、周期根和终止在单个元素交互批次内完成 prepare/validate/commit。任何 Aura、Reaction、Gate、Damage 或 Link 计划 stale 时不允许部分写入。周期根状态不存在或 revision 不匹配时稳定取消。

Reaction 只发布通用 `REACTION_OCCURRED`、`REACTION_STATE_CHANGED` 和交互审计；不得新增 `BURNING_*` EventType。Damage 和 Aura 事实由其所属系统发布。
