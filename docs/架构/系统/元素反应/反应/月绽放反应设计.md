# 月绽放反应设计

> 状态：已实现（第一条纵向切片）
> 最后更新：2026-08-07

## 1. 定位

月绽放是与普通绽放机制簇并列的独立反应，使用独立 `reaction.lunar_bloom` Definition、Rule、Profile、资源状态和月曜伤害路径，不归入 `mechanics/bloom/` 机制目录。

月绽放与普通绽放共享水草元素消费、草原核 `DendroCoreState` 和 Space 创建声明。共享部分由中立草原核创建计划提供，月绽放不反向依赖普通绽放实现。

月绽放在满足队伍 capability、角色触发来源和严格水草元素签名时排他选中；本次交互只产生月绽放 occurrence，不同时产生普通绽放 occurrence。没有 capability 或合法角色触发来源时，月候选不匹配，普通候选继续生效。

月绽放反应本身不产生任何伤害。伤害只来自角色技能消费草露后造成的角色月绽放伤害，属于角色月曜伤害，不由 Reaction occurrence 声明伤害 Effect。

## 2. 领域所有权

| 领域 | 月绽放相关职责 |
| --- | --- |
| Aura | 水、草元素量、贡献账本、精确消费与后值 |
| Reaction | 独立 Definition、严格水草候选、参与者冻结、草原核创建声明、草露资源和月曜 Damage Effect |
| Space | 草原核 `REACTION_OBJECT` 的位置与生命周期投影（与普通绽放共享） |
| Damage | 角色月曜伤害的公式、组分结算和审计（由角色技能触发，不属于反应自身） |
| Coordination | 把 Aura/Space 证据编排为月绽放计划，并以批次原子提交草露资源；不生成月曜伤害 Effect |

## 3. 稳定 Definition 与方向

```text
reaction.lunar_bloom / reaction_handler.lunar_bloom

lunar_incoming_hydro_on_dendro
lunar_incoming_dendro_on_hydro
```

月绽放只接受普通草与水的两个方向，不接受 `QUICKEN`。候选要求请求同时携带 `reaction_capability:lunar_bloom`、上游确认的角色来源集合，并且当前触发来源属于该角色集合。

水草消费关系与普通绽放一致：水触发草或激元素按 `hydro_used = min(T, 2 * A)`、`dendro_like_used = hydro_used / 2`；草触发水按 `dendro_used = min(T, A / 2)`、`hydro_used = dendro_used * 2`。两侧实际消费均为正时才产生月绽放 occurrence。

## 4. 草原核共享创建

月绽放每次 occurrence 与普通绽放一样原子创建一份 `DendroCoreState` 和对应 Space 实体，生命周期、队伍池容量和绑定规则由中立草原核创建计划统一拥有：

```text
DendroCoreState
├── instance_ref
├── subject_ref
├── space_entity_ref
├── created_by_occurrence_ref
├── core_creator_ref
├── dynamic_scaling_basis
├── pool_scope = player_team
├── created_frame
├── expires_at_frame = created_frame + 360
├── creation_sequence
└── revision
```

草原核后续爆炸、超绽放和烈绽放继续使用普通剧变 Damage，不属于反应月绽放伤害。

## 5. 参与者

月绽放 occurrence 在消费前从实际使用的 Aura Component 贡献和当前触发角色冻结 `participant_refs`，来源去重后按稳定顺序保存。capability provider 若没有实际贡献且不是触发者，不会自动进入参与者集合。

参与者快照当前用于反应审计，不生成伤害 Effect；角色月绽放伤害的属性与来源由施放技能的角色决定。

## 6. 草露资源

草露由 Reaction 持有队伍级 `LunarBloomDewState`，当前基线为容量 `3`、恢复窗口 `150` 帧、每帧 `1/150`。触发月绽放时先规范化到当前帧，再保留已有 Fraction 进度并刷新恢复截止帧；资源计划与 Aura、ReactionState 和 Gate 使用同一 Store version 校验提交。

Reaction 已提供角色技能使用的消费接口：`ReactionResourcePlanner.consume_lunar_bloom_dew(team_ref, amount)`。接口只接受正整数草露，消费前规范化到当前帧，不足、未生成或非法数量直接拒绝；消费保留恢复窗口与规范化游标，并随资源计划原子提交。角色技能侧的具体消费时机、最低值、最大消费量和回退顺序仍待角色内容设计确认。

## 7. 月曜伤害

月绽放没有反应伤害，只有角色月绽放伤害。角色技能消费草露后，由角色侧构造 `LunarReactionDamageInput(mode=CHARACTER_DIRECT)`，通过统一 Damage Impact 进入 `DamageRequestHandler`；伤害属性、暴击和抗性基于施放技能的角色。

月曜生产数值已按已确认资料注册到默认 Damage Formula Registry：

```text
等级基数：80=1077.4，90=1446.9，95=1561.5，100=1674.8
月曜精通系数 = 6 × EM / (EM + 2000)
角色月绽放倍率 = 1.0
```

月曜伤害结果使用 `DamageResult.lunar_reaction_resolution` 保存组分、排序、权重和审计；该路径没有独立的 Reaction 专用伤害端口，也不会把普通草原核爆炸改成月曜伤害。

## 8. 当前边界与验收入口

当前边界：

- 角色 content 的正式 capability 绑定仍待角色内容设计；golden case 使用临时 capability 端口。
- 角色技能侧尚未接入草露消费和角色月绽放伤害入口；Reaction 侧的消费接口已提供。
- 角色 capability 由 `ContentUnit.reaction_capabilities` 经 assembly 转换为 `ReactionCapabilityEvidence`；动态角色状态、正式角色名单和 capability 生命周期仍属于角色 content 设计。
- 角色专属草露、山月草露、诳言之核和其他角色资源不由本反应公共资源接口猜测或代替；新增资源必须由对应角色 content 与 Reaction 计划共同定义。
- 月曜伤害无反应 Gate：月绽放不产生反应伤害，角色技能伤害走技能自身的伤害规则。
- 草原核无特殊空间行为，与普通绽放完全一致。
- 正式契约已迁移；月感电/月结晶不在此范围。

主要验收入口：

- `tests/unit/core/systems/reaction/test_lunar_bloom.py`
- `tests/golden/reactions/test_lunar_bloom_damage_boundary.py`

资料基线：项目维护者确认的[月曜反应通论](https://www.miyoushe.com/ys/article/73142429)仅作为本机制的资料来源；正式语义以本设计、契约、生产代码和 golden case 共同验证。
