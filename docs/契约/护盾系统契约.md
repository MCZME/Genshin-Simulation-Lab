# 护盾系统契约

> 状态：第一版领域聚合契约与结晶晶片授予计划已实现。
> 本文冻结护盾领域的枚举、公式、聚合状态、计划、结果、Impact payload 和快照。角色伤害输入与最终受伤记录见[角色受伤协调器契约](./角色受伤协调器契约.md)。

最后更新：2026-08-01

## 1. 适用范围

本契约覆盖：

- `core/systems/shield/` 的目标公共模型。
- 护盾创建公式和授予策略。
- `ShieldRecord` 聚合不变量。
- 多保护范围、并行吸收和 ShieldMutationPlan。
- `ShieldGrantPlan` 的授予预校验、完整记录替换和事实发布。
- `ImpactKind.SHIELD` payload。
- 护盾事实 payload 与快照序列化。

不覆盖真实角色倍率、结晶等级表、敌方盾条、抗打断数值或 UI 模型。

普通结晶晶片、拾取请求和结晶护盾映射见[结晶反应契约](./元素反应/反应/结晶反应契约.md)；本文只冻结 Shield 领域通用授予与聚合语义。

## 2. 通用数值规则

- 数值接受 `int | float`，拒绝 `bool`。
- 所有数值必须有限。
- 容量、来伤和倍率按字段校验非负或正数。
- `abs(value) <= 1e-12` 的容量残差归一化为 `0.0`。
- frame 为非负整数；持续帧数为正整数。
- tags 归一化为 `frozenset[str]`，成员必须是非空字符串。

## 4. ShieldInstanceRef

护盾事件、结果和快照使用领域专用实例引用：

```text
ShieldInstanceRef
├── domain_key = "shield"  # 稳定序列化常量
└── sequence: int
```

序列化形式：

```json
{"domain_key": "shield", "sequence": 1}
```

不得只保存裸 sequence 作为事件和持久化引用。`ShieldInstanceRef` 由护盾领域定义；其他领域不要求复用该运行时类型。通用原则见[领域运行态设计](../架构/领域运行态设计.md)。

## 5. ShieldProtectionRef

字段：

```text
kind: ShieldProtectionKind
protection_id: str
```

稳定 key：

```text
{kind}:{protection_id}
```

默认队伍保护：

```text
kind = active_team
protection_id = team:player
```

生命周期清理依据由 protection 直接推导：

| Protection | 清理依据 |
| --- | --- |
| `active_team:team:player` | 对应玩家队伍 |
| `character:<entity_id>` | 对应角色实体 |

## 6. 创建公式

### 6.1 ShieldScalingTerm

```text
component_key: str
attribute_key: AttributeKey
coefficient: float
```

coefficient 为有限非负数。component key 在同一公式内唯一，只允许读取公共属性。

### 6.2 ShieldNativeMultiplierTerm

```text
multiplier_key: str
multiplier: float
source_context: RuntimeSourceRef
```

multiplier 为有限非负数，key 在同一公式内唯一。该项只表示护盾自身原生倍率，不表示公共护盾强效。

### 6.3 ShieldCapacityFormula

```text
scaling_terms: tuple[ShieldScalingTerm, ...]
flat_absorption: float
native_multipliers: tuple[ShieldNativeMultiplierTerm, ...]
```

至少一个 scaling term 或正 flat absorption。公式本身不可变。

### 6.4 ShieldCapacityFormulaResult

保存：

- 每个属性分量结果。
- flat absorption 和 base absorption。
- 每个原生倍率及合并倍率。
- 最终 native absorption。

最终 native absorption 必须为有限正数。

## 7. ShieldGrantRequest

```text
grant_id: str
frame: int
mechanic_key: str
handler_key: str
protection_ref: ShieldProtectionRef
creator_ref: AttributeSubjectRef(character)
source_context: RuntimeSourceRef
element: ShieldElement
duration_frames: int
grant_formula: ShieldCapacityFormula
grant_policy: ShieldGrantPolicy
conflict_key: str
capacity_limit_formula: ShieldCapacityFormula | None
tags: frozenset[str]
```

约束：

- grant、mechanic、handler 和 conflict key 非空。
- creator 必须是角色主体。
- duration 为正整数。
- 只有 `add_capped_refresh` 可以且必须提供 capacity limit formula。
- 请求不包含 `grants_interruption_resistance`；该能力等待抗打断系统正式契约。

## 8. ShieldGrantResolution

Resolver 输出：

```text
grant_id
frame
creator_ref
protection_ref
component_results
flat_absorption
native_multiplier_results
granted_absorption
capacity_limit?
attribute_trace
source_context
```

granted absorption 和非空 capacity limit 为有限正数。属性 trace 保存创建时查询结果，不包含动态护盾强效。

## 9. ShieldState

领域状态字段：

```text
protection_ref: ShieldProtectionRef
creator_ref: AttributeSubjectRef(character)
source_context: RuntimeSourceRef
element: ShieldElement
maximum_native_absorption: float
remaining_native_absorption: float
conflict_key: str
grant_snapshot_ref: str
tags: frozenset[str]
```

`ShieldState` 不保存：

- instance ref。
- mechanic key 或 handler key。
- created frame 或 expires at frame。
- 动态护盾强效或元素有效盾量。
- 抗打断预留布尔值。

活动记录必须满足：

```text
0 < remaining_native_absorption <= maximum_native_absorption
```

耗尽后的非活动审计记录允许 remaining 为零。

## 10. ShieldRecord

完整领域记录：

```text
ShieldRecord
├── instance_ref: ShieldInstanceRef
├── mechanic_key: str
├── handler_key: str
├── created_frame: int
├── expires_at_frame: int
├── lifecycle_state: active | expired | removed
├── removed_frame: int | None
├── removal_reason: ShieldRemovalReason | None
└── state: ShieldState
```

聚合不变量：

- `instance_ref.domain_key == "shield"`。
- 活动记录满足 ShieldState 活动容量约束。
- mechanic key、handler key 和生命周期只存在于 ShieldRecord 元数据。
- 有限生命周期使用半开区间 `created_frame <= frame < expires_at_frame`。
- 非活动记录必须保存 removed frame 和 removal reason。
- ShieldStore 中不存在缺少 ShieldState 的活动实例。

## 11. ShieldGrantResult

```text
resolution: ShieldGrantResolution
outcome: ShieldGrantOutcome
instance_ref: ShieldInstanceRef
replaced_instance_ref: ShieldInstanceRef | None
remaining_before: float
remaining_after: float
maximum_after: float
expires_at_before: int | None
expires_at_after: int
```

授予后的 remaining 和 maximum 为正数，且 remaining 不大于 maximum。刷新策略保留完整 instance ref；replace 创建新引用。

## 11.1 ShieldGrantPlan

结晶晶片等跨领域流程不能直接调用 `ShieldRuntime.grant()` 再补写其他领域，必须使用授予计划：

```text
ShieldGrantPlan
├── operation_id
├── frame
├── expected_store_version
├── expected_records
├── replacement_records
├── result: ShieldGrantResult
├── capacity_changes
└── removals
```

`prepare_grant()` 负责解析创建帧公式、冲突策略和完整替换集；`validate()` 只检查版本、前值和重复提交；`commit_prevalidated()` 只提交已准备的完整记录，不重新查询属性、不计算公式、不发布事实。

## 12. ShieldMutationPlan

护盾所有状态变化使用不可变领域计划：

```text
operation_id: str
frame: int
expected_store_version: int
expected_records: tuple[ShieldRecord, ...]
replacement_records: tuple[ShieldRecord, ...]
facts: tuple[ShieldFact, ...]
```

规则：

- expected 和 replacements 按 instance ref 稳定排序。
- 同一计划中 instance ref 不重复。
- 任一 expected record 或 Store version 不匹配时，不得提交任何 replacement。
- 计划只能提交一次。
- facts 只能在完整记录替换成功后发布。

授予、刷新、替换、显式移除、到期和吸收可以使用领域专用 plan 子类型，但不增加任意字段 patch。`ShieldGrantPlan` 是授予专用子类型。

## 14. ShieldAbsorptionRequest

ShieldRuntime 接收领域请求，而不是最终角色受伤记录：

```text
damage_id: str
frame: int
target_ref: AttributeSubjectRef(character)
incoming_amount: float
element: Element
source_ref: AttributeSubjectRef | None
source_context: RuntimeSourceRef | None
tags: frozenset[str]
```

由 CharacterDamageTakenCoordinator 从 `CharacterIncomingDamage.amount` 适配。请求不包含 protection ref。

## 15. ShieldHitResult

```text
instance_ref
mechanic_key
protection_ref
element
native_before
native_cost
native_after
element_multiplier
shield_strength
shield_strength_multiplier
effective_multiplier
absorbable_incoming_damage
depleted
```

depleted 必须与 `native_after == 0` 一致。结果按完整 instance ref 稳定排序。

## 16. ShieldAbsorptionResult

```text
damage_id
frame
target_ref
incoming_amount
element
matched_protection_refs
active_character_shield_strength
shield_hits
protected_damage
health_bound_damage
had_active_shield_before
has_active_shield_after
depleted_instance_refs
```

不变量：

```text
incoming_amount == protected_damage + health_bound_damage
```

matched protection refs、hits 和 depleted refs 使用稳定排序。无匹配护盾或零伤害时 hits 为空，protected 为零。

## 17. ShieldStore

`ShieldStore` 是护盾聚合的唯一状态所有者，直接保存并提交完整 `ShieldRecord`。

对 Runtime 提供：

- 按 instance ref 查询完整记录。
- 按 frame、protection 和 mechanic key 查询活动记录。
- 按 protection + conflict key 查询冲突记录。
- 创建完整记录。
- 提交 ShieldMutationPlan。
- 按稳定顺序准备到期记录。

其他系统只能获得只读 view。Store 不公开独立 component add/remove，也不接受任意 patch。

## 18. ImpactKind.SHIELD

必填 payload：

```json
{
  "shield": {
    "mechanic_key": "example.shield",
    "handler_key": "example.shield.handler",
    "conflict_key": "example.shield",
    "duration_frames": 600,
    "grant_formula": {
      "scaling_terms": [],
      "flat_absorption": 1000,
      "native_multipliers": []
    }
  }
}
```

可选字段：

```text
protection_ref          # 默认 active_team:team:player
element                 # 优先使用 ImpactRequest.element，否则 none
grant_policy            # 默认 replace
capacity_limit_formula  # 仅 add_capped_refresh
tags                    # 默认空数组
```

`owner_slot` 用于从 SpaceRuntime 解析创建者。来源上下文由 handler 根据已注册内容和 ImpactRequest 构造，不由 payload 覆盖。

`handler_key` 当前仍保留在 payload 以兼容现有 content contribution；迁移时应优先从已注册 handler 上下文推导，并评审是否从 payload 删除。

## 19. 事件契约

| EventType | Payload | 发布条件 |
| --- | --- | --- |
| `SHIELD_GRANTED` | `ShieldGrantedPayload(result)` | 创建、替换、刷新、叠加或保留 |
| `SHIELD_CAPACITY_CHANGED` | `ShieldCapacityChangedPayload(result)` | 吸收或刷新导致容量变化 |
| `SHIELD_REMOVED` | `ShieldRemovedPayload(result)` | 耗尽、过期、替换或显式移除 |
| `SHIELD_ABSORPTION_RESOLVED` | `ShieldAbsorptionResolvedPayload(result)` | 正伤害且有匹配护盾 |

`DAMAGE_APPLIED` 不属于护盾事件契约，见[角色受伤协调器契约](./角色受伤协调器契约.md)。

## 20. 快照契约

`ShieldInstanceSnapshot`：

```text

mechanic_key
handler_key
protection_ref
creator_ref
source_context
element
maximum_native_absorption
remaining_native_absorption
created_frame

```

```text

```

## 21. 错误类型

目标错误层级：

```text
ShieldSystemError
├── ShieldValidationError
├── ShieldAttributeError
├── ShieldCapacityError
├── ShieldPolicyError
├── ShieldProtectionNotFoundError
├── ShieldInstanceNotFoundError
├── ShieldStateConflictError
├── ShieldPlanConflictError
└── ShieldAtomicCommitError
```

不匹配当前目标的护盾是正常过滤结果，不再使用 `ShieldTargetMismatchError` 表示调用方选择了错误 protection ref。

## 22. 序列化规则

- 枚举序列化为稳定字符串 value。
- instance ref 和 protection ref 使用结构化对象。
- tags 序列化为排序 tuple。
- 主体引用保存 kind 和 entity id。
- RuntimeSourceRef 保存 kind、source key 和 instance id。
- 结果保留参与审计的中间量。
- 新增或删除字段属于契约变化，必须同步事件持久化测试和本文。

## 23. 测试要求

除数值和公式测试外，至少覆盖：

- 完整实例引用和聚合稳定序列化。
- Store 中不存在缺失 ShieldState 的活动记录。
- 创建、替换、刷新、耗尽和到期的原子完整记录提交。
- plan version、完整前值、重复引用和重复提交冲突。
- 来伤不携带 protection ref，能匹配零个、一个或多个保护范围。
- 事件 payload、快照和结果库 JSON 往返。

## 24. 当前实现

公共实现已使用 ShieldInstanceRef、ShieldState、ShieldRecord、ShieldStore 和完整记录 MutationPlan。ShieldComponent、ShieldComponentStore、裸整数护盾引用、临时抗打断布尔值以及 shield package 内的 CharacterIncomingDamage 均已从正式护盾 API 移除。

角色伤害输入与最终应用记录由角色受伤协调器拥有；护盾端只接收 ShieldAbsorptionRequest 并返回不可变 ShieldAbsorptionPlan。
