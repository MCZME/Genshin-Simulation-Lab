## 1. 目标

- 工作流是 UI 产品面；CLI 不提供工作流的创建、校验或运行。
- 后端不实现工作流图引擎，只做工作流 JSON 不透明存档、已展开成员校验与批次运行。
- 前端拥有图语义：区域、节点、连线、校验、片段合并、变体展开、成员预览。
- 第一条纵向链路：根节点 → 配置区域（含枚举/区间）→ 模拟节点 → 终态联动与结果面板；摘要指标展示按[项目决策记录](../决策/项目决策记录.md) 2.29 后置到分析区域。

## 2. 实施切片（已全部完成）

| 切片 | 交付 | 主要落点 |
| --- | --- | --- |
| 1 后端批次执行模型 | `BatchMember`、批次状态视图、`BatchRunService` 与已展开成员校验；facade 批次提交、查询、取消 | `application/batch/`、`application/services/`、`application/facade.py` |
| 2 工作流存档 | `WorkflowStore` 协议与不透明 JSON 文件实现；服务端生成安全 `id` | `application/services/workflows.py`、`infrastructure/file_storage/workflow_store.py` |
| 3 HTTP API 与 DTO | 按 [UI API 契约](../契约/ui/UI API 契约.md) 暴露 MVP 端点；错误响应统一 `{code, message, details}`；OpenAPI 生成前端类型；隐藏 `data_dir`、数据库路径与 `handler_key` | `server/` |
| 4 工程搭建与图语义编译 | Vite + React + React Flow + Vitest 工程与质量门禁；`WorkflowDefinition` 模型、语义注册表、结构化校验器、变体编译器（纯 TypeScript，可单测） | `frontend/src/workflow/` |
| 5 画布纵向切片 | EditorState 双向转换器与 API 客户端；React Flow 画布、配置区域、节点编辑器、问题面板；第一条链路可运行 | `frontend/src/components/`、`frontend/src/state/`、`frontend/src/api/` |
| 6 端到端验收 | 编译 → 校验 → 提交 → 轮询 → 结果联动的完整链路验收，覆盖失败、取消、部分失败与重跑 | 全链路集成验收 |
| 7 结果面板重构 | 「结果」工具面板承接结果库历史浏览（决策 2.29）；移除旧 ResultPanel；构建失败改走顶部错误横幅 | `frontend/src/components/panels/` 等 |
| 8 节点取消与指标后置 | 两级取消（本批取消 / 整次取消）；批次监控收敛为进度条聚合；指标数值退出第一版 UI（决策 2.29） | `frontend/src/components/nodes/run.tsx`、`shell/TopBar.tsx` |
| 9 区域运行与校验阶段 | 区域运行与「区域校验」共用构建编排；加载时资产批量预检；跨节点检查按连线判定参与范围（决策 2.28） | `frontend/src/workflow/runner.ts`、`asset_preflight.ts` |

切片 4 与 5 曾合并为同一连续开发阶段推进；该排期安排已完成使命，不再展开。

## 3. 暂不实现

- 分析区域节点（查询/指标/聚合/对比/视图）与对应端点。
- 工作流图校验、节点类型注册表等后端 API。
- 按工作流 ID 或内联图提交运行。
- SSE/WebSocket 推送；第一版统一轮询。
- 批次运行状态持久化；批是内存调度实体，终态保留查询窗口后释放，规则见[批处理调度设计](../架构/批处理调度设计.md)。
- 资产图像、输入/结果上传下载、结果详情中的输入与初始快照。
- 资产库构建与更新端点（继续走 CLI/安装包流程）。
