# 月兆系统设计

> 状态：第一版已实现：等级判定、初辉/满辉只读状态、非月兆角色月曜增伤
> 与月曜 `reaction_bonus` 注入。具体月兆角色的初辉/满辉专属强化依赖角色
> content，尚未接入。
> 最后更新：2026-08-10

## 1. 定位

`core/systems/moonsign/` 是挪德卡徕地区效果（月兆）领域。它唯一拥有：

- 月兆等级（无 / 初辉 / 满辉）与月兆角色集合。
- 非月兆角色施放元素战技/元素爆发后的覆盖式月曜增伤记录。
- 供元素反应捕获查询的月曜增伤只读端口。

月兆角色识别使用角色 `ContentUnit.metadata` 的 `moonsign: true` 标记，
不改资产库 schema。

## 2. 规则

- 1 名月兆角色 -> 「月兆·初辉」；2 名及以上 -> 「月兆·满辉」；满辉同时
  包含初辉语义。
- 满辉时，非月兆角色施放元素战技或元素爆发后的 1200 帧（20 秒）内，
  按角色自身元素为附近所有角色的月曜反应伤害提供增伤，至多 36%；
  无法叠加，后施放覆盖先施放，到期自动清除。
- 火/雷/冰按攻击力、水按生命值上限、岩按防御力、风/草按元素精通计算，
  公式见[月兆契约](../../契约/月兆契约.md)。

## 3. 结构

```text
core/systems/moonsign/
├── models.py        MoonsignLevel / MoonsignScaling / MoonsignStatSnapshot /
│                    MoonsignBonusRecord
├── resolver.py      等级判定与非月兆月曜增伤纯公式
├── store.py         MoonsignStore：等级、月兆角色集合与增伤记录唯一真值
├── runtime.py       MoonsignRuntime：FACT_RESPONSE 消费 ACTION_STARTED、
│                    应用/到期清理、快照与端口
├── ports.py         LunarDamageBonusPort / MoonsignLevelReadPort
├── snapshots.py     MoonsignSnapshot
└── errors.py        领域错误
```

## 4. 事件与事实

- `ACTION_STARTED`：`ActionManager._start_instance` 在动作实例进入 RUNNING
  时发布，载荷含 `action_key`、`owner_slot` 与 `ability_key`
  （`elemental_skill` / `elemental_burst`）。
- `MOONSIGN_LEVEL_SET`：Runtime 首个模拟帧发布一次。
- `MOONSIGN_BONUS_APPLIED`：满辉下非月兆角色 E/Q 触发增伤时发布。
- `MOONSIGN_BONUS_EXPIRED`：增伤到期清除时发布。

## 5. 月曜伤害注入

`ElementalSettlementCoordinator` 通过 `LunarDamageBonusPort` 在构造
`LunarReactionDamageInput` 时读取当前月曜增伤，叠加进
`reaction_bonus`；无月兆或未生效时为 0，不影响既有月反应 golden case。

## 6. 装配

```text
角色 ContentUnit.metadata.moonsign == true
-> application/assembly/moonsign.py build_moonsign_bundle()
   -> MoonsignStore.set_level（组装期一次）
   -> MoonsignRuntime（属性解析器、元素缩放参数、元素槽位表）
-> RuntimeAssembler
   -> FACT_RESPONSE 注册 moonsign runtime
   -> ElementalSettlementCoordinator(lunar_damage_bonus_port=runtime)
   -> 快照 provider "moonsign"
```

## 7. 当前不实现
