# 生命值系统实现规划

> 状态：第一轮（阶段 A-D）已完成；开放任务见第 3 节。
> 最后更新：2026-08-23。
> 长期架构以[生命值系统设计](../架构/系统/生命值系统设计.md)为准，事件契约见[事件类型](../架构/事件系统/事件类型.md)，治疗数值与生命提交的字段映射见[治疗系统契约](../契约/治疗系统契约.md)。

## 1. 文档定位

本文只保留第一版交付范围与开放任务，不重复 `HealthState`、`HealthRuntime` 的模型、公式、提交顺序、事件契约与边界——这些统一维护在[生命值系统设计](../架构/系统/生命值系统设计.md)。

## 2. 已交付范围

第一轮建立角色当前生命的稳定运行时边界，未修改 `SimulationInput`、资产库 schema 或结果库 schema：

| 阶段 | 交付 |
| --- | --- |
| A：角色生命状态 | `HealthState`、`CharacterRuntimeState.health` 与按角色主体索引的 `CharacterHealthStore` |
| B：生命提交运行时 | `HealthRuntime` 承伤、恢复、直接扣血请求与统一结果；最大生命同比同步入口；结构化错误 |
| C：组装接入 | frame 0 解析最终 `stat.hp.max` 并满血初始化；注册 `HealthRuntime`，经 `AssembledSimulation.health_runtime` 暴露 |
| D：事件与持久化 | `CHARACTER_HEALTH_CHANGED` / `CHARACTER_MAX_HP_CHANGED`；零变化不发布事件；通用事件 JSON 往返 |
| E（部分）：上游接入 | 治疗接入与角色承伤协调已完成，分别由治疗系统阶段 C 与[角色受伤协调器设计](../架构/协调/角色受伤协调器设计.md)承接 |

主要落位：`core/entity_states/health.py`、`core/entity_states/characters.py`、`core/systems/health/`、`application/assembly/assembler.py`。

明确排除（另行评审，不随开放任务自动进入范围）：场景目标生命、击败、移除和索敌过滤；死亡、复活、免死等生存状态机；初始残血配置、UI 生命条与专用结果表。

## 3. 开放任务

1. 动态最大生命 modifier 的生效与失效通知及同步触发点：依赖 Buff/状态效果生命周期明确后接入（受控同步入口已由[生命值系统设计](../架构/系统/生命值系统设计.md)第 9 节提供）。
2. 真实角色生命消耗最小可复现案例：需要可信来源与 golden case。
3. 角色生存状态机：确有动作、复活或战斗结束需求时单独评审。
