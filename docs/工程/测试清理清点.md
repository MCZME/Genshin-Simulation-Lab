## 2. 清点结论

按“失败时是否破坏已确认行为/契约”的标准，多数测试是高价值的，尤其是 core、golden、integration、application、server 与前端 workflow/state/api。为了减数量而直接删除这些测试，会实质降低仿真确定性与契约保护。

可清理空间集中在四类：

1. 内容层数据常量测试：断言硬编码数据本身，与测试规范“不默认测试内容数据”冲突。
2. 前端重复壳测试与低价值渲染断言：只证明“能渲染”，不锁定交互或契约。
3. 超大文件与同构参数化：不减少真值，但显著增加维护和审查成本。
4. 少数 smoke 重复：例如 CLI/server 的 `--help` 和 App 标题渲染。

因此，如果目标是“用例数量显著下降”，仅靠清理低价值用例做不到；真正的数量大头是 core 与 golden 的安全网。要么接受保留这些用例，要么通过“更少的强集成/golden 替代大量 unit”的迁移路线减数（高风险，需单独决策）。
