# 前端工程规范

> 状态：正式规范。
> 本文定义 `frontend/` 的工程边界、技术选型、目录结构、状态数据流、组件与节点编辑器约定、画布实现、质量门禁和开发方式。
> 最后更新：2026-09-03。

## 1. 定位与边界

- `frontend/` 是仓库根目录下的独立 Web 前端工程，与 `backend/` 并列。
- 前端是纯客户端：只通过 `server/` 的 HTTP API 调用后端 application 能力，不 import 任何 Python 代码，不直接访问 SQLite，不组装仿真核心对象，不实现分析算法，不调用 CLI。
- UI 与 CLI 共享资产、仿真与结果等应用服务；CLI 不运行工作流。`application/` 不依赖前端实现；`core/` 不感知 UI 状态。
- Node.js 与 pnpm 只存在于开发/构建期；运行时由 Python 服务托管前端静态文件。
- 桌面形态与网页服务形态共用同一份前端构建产物；差异只在启动方式（server 入口 + 后置的桌面启动层）。
- 产品以“批”为一等公民，单次模拟输入是批的特例；主界面为单一无限画布，配置 → 模拟 → 分析整条链在画布上承载。

## 2. 技术选型

- React + TypeScript + Vite。
- 画布：React Flow（核心开源组件；Pro 商业组件未批准前不引入）。
- 包管理器：pnpm；提交 `pnpm-lock.yaml`。
- Node 版本通过 `package.json` 的 `packageManager` 与 `engines` 固定。
- 状态：`AppState`、`EditorState`、`RunState` 为纯 TypeScript 模块，不依赖 React。
- 类型：后端 OpenAPI -> `openapi-typescript` 生成 API 类型；不手写两套类型。

## 3. 目录结构

```text
frontend/
├── src/
│   ├── app/               # 应用外壳：导航、全局状态、错误反馈
│   ├── theme/             # 主题 token
│   ├── workflow/          # 定义模型、语义注册表、校验、变体编译
│   ├── state/             # AppState / EditorState / RunState
│   ├── api/               # HTTP API 客户端与类型
│   ├── components/
│   │   ├── canvas/        # 画布、区域、节点卡、连线层、框选、小地图
│   │   ├── nodes/         # 节点编辑器与 registry.tsx
│   │   ├── panels/        # 工具栏、对象面板、问题面板、结果面板（结果库浏览器）
│   │   ├── shell/         # 应用壳、设置弹窗、顶部栏、工具轨、状态栏
│   │   └── common/        # 输入框、资产选择器、表格、徽标等原语
│   └── views/             # 非画布页面：项目初始化
├── package.json
├── pnpm-lock.yaml
├── vite.config.ts
└── tsconfig.json
```

目录按功能域组织，不按组件类型建目录。`application/` 与 `infrastructure/` 的具体分层见[模块边界设计](../架构/模块边界设计.md)。

## 4. 状态与数据流

### 4.1 状态层

- `AppState`：当前项目/工作区、可用服务、当前视图。
- `EditorState`：只装语义状态——选中对象、节点已提交位置、连线、区域归属、已提交节点参数，以及按工作流独立的撤销/重做历史与最后保存引用；`dirty` 由当前定义与最后保存定义比较派生。
- `RunState`：运行期状态，不持久化。当前为「工作流运行」单块：`run` 为当前/最近一次工作流运行，含构建限速轨迹、按模拟节点索引的批次视图与终态。

分析区域运行态不进入上述持久/历史状态：schema 目录、按节点 id 的结果表与状态、视图 `selection`、区域运行阶段由应用层持有并经 Context 下发，不写入 `WorkflowDefinition`。

UI 私有状态不持久化；可单测的纯 TypeScript 状态集中在 `state/`，组件内瞬态留在组件层。

### 4.2 单向数据流

- 单向数据流：语义事件 -> `EditorState` -> 组件渲染；命令式只允许出现在高频瞬态与定制绘制组件内部。
- 业务状态只有一个更新入口：任何命令式代码不得绕过桥接层直接修改业务状态。
- 瞬态状态不进全局状态：拖拽中的位置、鼠标坐标等高频状态留在组件内部；只有拖拽结束、连线落定等语义事件才提交到 `EditorState`。
- 视口（缩放/平移）不进 `EditorState`，归画布组件持有；节点不因视口变化重建。
- 结果库原始内容不进入 `EditorState`/持久化状态：结果面板按 `session_id` 引用分页读取，单项详情按 `item` 中的 `session_id` / `frame` / `ordinal` 按需取数。
- 分析查询返回的派生结果表（单表硬上限 10000 行）是受限运行时数据，由应用层按节点 id 缓存并经 Context 下发；视图排序、高亮、列顺序与 `selection` 等查看瞬态只留在组件与桥接层，不随工作流 JSON 保存。
- 画布布局、节点位置等持久化内容通过工作流存档 API 保存；保存是显式动作。

### 4.3 桥接层

桥接层不依赖前端框架，可单测：

- `converters.ts`：EditorState 与 WorkflowDefinition 双向转换。
- `api/`：把 HTTP API 包装为页面可用的异步调用；配置预览走 `POST /inputs/validate`。
- `runtime_subscription.ts`：轮询 `GET /runs/{run_id}` 更新 RunState；SSE/WebSocket 后置。

组件不直接拼装 HTTP 请求，统一通过 API 客户端获取能力。配置区域预览调用 `POST /api/v1/inputs/validate`；运行后只轮询 `GET /api/v1/runs/{run_id}`；分析区域启动时经 `GET /api/v1/analysis/schema` 加载取数目录，查询时把区域内可达子图编译为结构化计划并经 `POST /api/v1/analysis/query` 一次执行。资产选择器走 `GET /api/v1/assets/{asset_type}?q=`，使用响应里的 `asset_key` 写入输入文档。

## 5. 组件分类与生命周期

组件按功能域组织目录，不按组件类型建目录；每个组件在定义处标注类型。四类组件：

| 类型 | 职责 | 典型位置 |
| --- | --- | --- |
| 纯组件 | state 进、控件出，无内部状态 | 节点卡壳、区域框、状态徽标 |
| 编辑器组件 | 持有本地瞬态（文本、拖动、选择），提交语义事件 | 节点内编辑器、参数表单 |
| 实例组件 | 持有外部实例/焦点/绘制上下文，对外声明式 | 输入框包装、文件选择器、画布表面、连线绘制 |
| 桥接组件 | 对接异步（任务状态、查询结果），只转发数据与回调 | 运行状态展示、结果取数 |

实例组件契约：

- 自己持有控件实例（ref），自己管理焦点、IME、滚动位置等生命周期细节；
- 对外接口仍为声明式（数据 props + 语义回调）；
- 全局重渲染发生时不得重建自身或打断用户操作。

可复用的实例原语（输入框、文件选择器、画布表面等）收在 `ui/components/common/`，作为组件库基础件。

## 6. 节点注册表与编辑器

### 6.1 注册表分工

- 语义注册表在 `frontend/src/workflow/`：节点类型、片段形状、端口模型、参数 schema、区域约束与节点级校验。
- UI 注册表在 `frontend/src/components/nodes/registry.tsx`：`node_kind -> React 组件` 映射与展示元数据（图标、默认尺寸、面板排序）。
- 画布对象面板读语义注册表决定“当前区域有哪些对象”，再经 UI 注册表取编辑器组件；两侧以稳定 `node_kind` 为公共 key，互不循环依赖。
- 注册表显式注册，不自动扫描；WorkflowDefinition 中出现未注册 kind 时，加载/校验阶段报错，不静默忽略。
- 节点 `kind` 字符串冻结后只追加、不改名、不复用。

### 6.2 NodeKindSpec

每个节点类型是一个描述对象，至少包含：

- `kind` / `display_name`：稳定 key 与显示名。
- `region`：配置区域 / 分析区域 / 画布级（`null`，不归属区域）。
- 端口模型：输入输出端口、数据语言、单值/组输出、连接数约束。
- 片段形状：默认目标路径与参数形状；只声明路径，不读取 SimulationInput schema。
- 参数 schema：类型化节点参数，供编辑器生成表单与定义校验。
- 节点级校验规则。

展示元数据不进入语义注册表，不参与工作流校验、形状推导与变体展开。

### 6.3 特殊行为

纯描述性节点由 spec 与通用机制（片段应用、展开、查询）驱动。存在天生特殊行为的节点按 kind 显式绑定行为实现，不在 spec 中塞回调：

- 配置区域边界输出：收拢、校验、预览输入文档；属于区域模型，不进入节点类型注册表。
- 模拟节点：任务分发、按成员管理状态。
- 分析视图节点：展示终点，消费终端表；表格视图 `selection` 输出单行 `item`，饼图/柱状图 `selection` 输出分组命中的行集表。
- 展示配置节点：数据链上的可选转发节点，输入 `table` 并原样转发给对应视图；不加工数据、不进入查询计划。
- 获取单行与单项详情节点：只处理 `item` 数据对象；详情内容按需向结果库接口取数，不进入查询计划。饼图/柱状图的行集表输出不进入详情链。

### 6.4 编辑器元数据

前端 UI 注册表为每个 `node_kind` 提供：

- 编辑器组件：`node_kind -> React 组件`。
- 图标与节点类别色：同类节点共享一个主色。
- 默认节点宽度与最小/最大尺寸。
- 画布对象面板排序与分组。
- 收起时的摘要渲染规则。

### 6.5 节点类别色

- 节点颜色按类别映射，不按具体类型平铺。
- 类别色位于 `frontend/src/theme/tokens.ts` 的 `COLORS.nodeCategory`。
- 表格/饼图/柱状图归「展示视图」类别；帧状态、伤害、状态、角色状态等单项详情节点族归独立的「单项详情」类别（`itemDetail`），不归入展示视图（见[项目决策记录](../决策/项目决策记录.md) 2.51）。
- 画布对象面板按类别分组：配置区域为「运行设置 / 队伍配置 / 目标配置 / 操作输入 / 变体扫描」；分析区域为「数据获取 / 数据加工 / 展示配置 / 展示视图 / 单项详情」（见[项目决策记录](../决策/项目决策记录.md) 2.51–2.52）。
- 未注册节点回落灰色。
- 配置区域与分析区域使用区域色，不属于节点类别色。

### 6.6 节点卡与尺寸语义

- 节点卡采用固定的「头部 + 内容区 + 底部」结构：头部承载类型标识、草稿徽标与节点级操作入口；底部承载输入顺序入口、成员投影开关与标签、组输出计数和端口点。
- 状态表达不得只依赖颜色：选中、草稿、运行置灰与应用中等状态同时提供文本或图形标识。
- 视图节点悬停/选中时宽度与高度手柄常驻；节点宽高为画布几何、按轴随工作流保存，未拖宽的轴保持内容驱动或默认值。
- 视图节点宽度下限 560px，自适应软上限 960px；手柄可拖到超过软上限，上限为内容自然宽/内容估算值。
- 视图节点高度默认 360px、下限 240px，随画布几何保存；表格/柱状图高度手柄可拖到超过高度软上限 720px（上限为内容估算值，封顶 1440px），饼图高度夹持 240–720px。
- 表格视图宽度单模式内容驱动：min(内容自然宽, 960px)，内容超过软上限时右侧列裁剪隐藏；拖宽上限为内容自然宽。
- 柱状图节点尺寸按内容估算：宽度按类目数 × 系列数 × 目标柱宽，高度按最大值/最小非零值比值（最小柱高 6px，估算封顶 1440px）；自动尺寸夹持软上限（宽 960px、高 720px）。图表内部渲染由 ECharts 承担，不修改组件渲染。
- 饼图宽度与高度均为手动画布几何（默认 560×360，宽 560–960px、高 240–720px）。
- 按键轨迹节点宽度手动可调，默认 720px，夹持 560–1280px，随画布几何保存；高度随内容自适应。
- 伤害详情与角色状态详情节点卡宽度手动可调，默认 320px，夹持 280–960px，随工作流保存；高度随内容自适应。
- 其余视图沿用同一套尺寸语义，按具体视图补充。
- 尺寸语义常量与解析统一由 `frontend/src/workflow/view_size.ts` 持有。

## 7. 画布约定

- React Flow 承载视口、节点、连线、选择与缩放；区域、端口命中、校验反馈为自定义组件。
- 区域在渲染层映射为 React Flow 父容器节点，区域内节点通过 `parentId` 作为子节点渲染；子节点位置在渲染层换算为区域内相对坐标，持久化契约仍保存画布绝对坐标。
- 区域只支持调整矩形尺寸，不做内容缩放；拖动区域标题栏移动区域，内部节点绝对坐标同步平移。
- 该映射不改变语义模型：`regions` 仍独立于 `nodes`，区域边界端口属于区域。
- 区域是强语义边界：归属、合法连线、边界端口与数据语言由前端校验；配置输入以后端提交校验为准，分析查询计划以后端计划校验为准。
- 成员端口按需展开，不常驻全部成员；枚举/区间大集合使用预览与数量提示。
- 运行状态按成员展示；取消整批时运行中成员显示“正在停止”。

## 8. 应用壳与全局组件

### 8.1 顶部栏

- 顶部栏承载工作流上下文和工作流主操作，不承担画布工具、对象面板、问题列表和设置入口。
- 左侧为品牌 mark、工作流切换器和未保存状态；品牌 mark 独立于切换器选中态，切换器只包住当前工作流名称与下拉箭头。
- 工作流切换器提供切换、新建和重命名入口；重命名正式实现不使用系统 prompt。
- 切换器下拉展示存档列表（按更新时间倒序）与新建入口；列表项 hover 提供重命名与删除，删除在当前项内二次确认。
- 当前工作流有未保存改动时，切换或新建先进入三选确认（保存并继续 / 不保存继续 / 取消）；保存并继续失败时停留在原工作流。
- 新建工作流切到空白草稿，不立即创建后端文件，首次保存时才落盘；删除当前工作流后回到空白草稿。
- 应用启动优先打开 localStorage 记住的上次工作流，不存在或已删除时回退到列表第一个，列表为空时打开空白草稿。
- 右侧为保存和全部运行。保存按钮保持普通样式，未保存状态由徽标承担；顶部栏不提供运行模式菜单。
- 顶部栏“全部运行”执行完整链路：构建 → 模拟 → 刷新分析区域（终态联动）。配置区域头部提供「区域校验」与「区域运行」，校验不提交模拟；分析区域头部提供「运行分析」，执行获取输入 → 查询 → 视图加载。

### 8.2 设置弹窗

- 设置入口位于工具轨底部，使用 24px 设置图标按钮。
- 设置弹窗为居中模态，宽度 400px，单列分组表单：分组标题在上，设置项标签左、控件右。
- 包含三个分组：「工作区」只读展示数据目录（config.toml `workspace` 节）；「运行」提供「运行动画」开关；「开发者」提供「开发者模式」开关（config.toml `developer` 节，注册并可见 `content/test` 测试内容，提示重启服务后生效）。
- 设置持久化在后端项目配置（config.toml 的 `ui` / `developer` 节，经 `GET/PUT /api/v1/settings` 读写），不落在浏览器存储。
- 「运行」分组修改立即生效；「开发者」开关写入配置后需重启后端服务生效，不设置保存/取消按钮。

### 8.3 问题筛选

- 问题筛选按钮按严重程度着色：错误使用 danger、警告使用 warning、提示使用 info；全部保持中性。

### 8.4 画布导航与小地图

- 画布视图使用 translate + scale 世界坐标；平移、缩放与对象位置都基于同一世界坐标。
- 动态背景固定为氛围层，不随画布平移或缩放；网格使用单层 24px 点阵；空画布显示“拖入区域开始”。
- 应用打开/新建工作流时默认是空白画布；打开应用不会立即创建后端工作流文件，首次保存时才落盘；不提供载入示例入口，画布内容一律由用户拖入创建。
- 平移使用鼠标中键拖拽；空白画布左键拖拽做框选；点击选择区域/节点，拖动区域标题栏移动区域，拖动节点头部移动节点。
- 缩放以鼠标位置为中心，范围 25% ~ 400%；提供适应全部与定位选中。
- 小地图定位为结构总览，显示区域、节点、连线、模拟节点和当前视口；支持点击定位、定位选中和折叠/展开。
- 节点按角色类别共享颜色，画布对象面板、节点卡、拖拽预览和小地图共用同一套节点类别色；区域对象使用区域色。

## 9. 当前交付边界

- 当前画布实现包含配置区域、模拟节点、数据提供节点与分析区域，完整纵向链路（配置 → 模拟 → 分析）在同一画布承载。
- 配置区域节点集、边界输出和编辑约定见[配置区域设计](../架构/UI/配置区域设计.md)。
- 模拟节点消费配置区域边界输出交出的输入文档集合，调用任务系统执行仿真，按成员反馈状态。
- 分析区域最初不属于第一版 MVP（见[项目决策记录](../决策/项目决策记录.md) 2.1）；MVP 交付后的新功能阶段已按 v2 查询计划模型落地（见 2.30–2.32 及后续）：取数、关系算子、展示配置、视图与单项详情节点集、数据语言和端口约束以[节点与区域契约](../契约/ui/节点与区域契约.md)为准。
- 分析区域支持「运行分析」与定义变化自动重算：边界会话缺失或过期时先补跑模拟，再把区域内可达子图编译为一次结构化查询计划；运行模型见[分析区域设计](../架构/UI/分析区域设计.md)，查询执行契约见[分析系统契约](../契约/分析系统契约.md)。
- 分析区域沿用通用区域模型落地，后续扩展只做节点注册与契约追加，不重构画布与执行框架。
- 结果面板定位为「结果库历史浏览器」，不展示指标数值；指标数值出口由分析区域承担。
- `timeline` / `timeline_config` 不属于当前节点集。

## 10. 质量门禁

```powershell
pnpm lint
pnpm typecheck
pnpm test
```

- `pnpm test` 使用 Vitest，覆盖状态、转换、图校验、变体编译与 API 客户端纯逻辑。
- 组件层使用壳测试与人工/截图验证；Playwright 端到端测试后置。
- 前端与后端共享同一份契约文档；契约改动必须同步 OpenAPI 与类型生成。

## 11. 构建与开发

- 开发模式：`pnpm dev`，Vite 代理到本地后端（`/api` -> `http://127.0.0.1:<port>`）；后端单独以 `genshin-sim-server` 启动。
- 生产构建：`pnpm build`，产物由 server 入口启动时托管。
- 桌面安装包（PyInstaller + pywebview）后置；MVP 先保证 server 本地启动与网页服务两种模式。
