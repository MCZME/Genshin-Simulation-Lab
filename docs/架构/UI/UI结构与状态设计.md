## 1. 定位与边界

- `frontend/` 是独立 Web 前端工程，通过 `server/` 的 HTTP API 调用 application 公开能力。
- 前端不直接访问 SQLite、不组装仿真核心对象、不实现分析算法、不调用 CLI。
- UI 与 CLI 共享资产、仿真与结果等应用服务；CLI 不运行工作流。`application/` 不依赖前端实现；`core/` 不感知 UI 状态。
- 产品以“批”为一等公民，单次模拟输入是批的特例；主界面为单一无限画布，配置 → 模拟 → 分析整条链在画布上承载。

## 2. 顶层原则

### 2.1 声明式为主，命令式受控例外

UI 采用声明式结构（画布实现载体为 Web 前端 + React Flow，见 [项目决策记录](../../决策/项目决策记录.md) 2.27）。声明式是默认实现方式，命令式只允许作为受控例外出现：

1. 所有新组件先按“状态进、控件出、事件只调回调”编写。
2. 命令式只允许出现在两类地方：高频瞬态交互（拖拽、缩放、临时连线），以及定制绘制控件（时间轴、连线层、图表）。
3. 例外组件保持对外声明式接口：内部可以使用 ref、命令式绘制或局部更新，但对外仍接收数据与回调，上层不感知混合。
4. 瞬态状态不进全局状态：拖拽中的位置、鼠标坐标等高频状态留在组件内部；只有拖拽结束、连线落定等语义事件才提交到 EditorState。
5. 业务状态只有一个更新入口：任何命令式代码不得绕过桥接层直接修改业务状态。

### 2.2 性能与控件生命周期

性能压力集中在两类数据：

- 画布本体（节点、连线、区域）：通过渲染粒度控制。视口作为变换而非数据，节点以 id 为稳定 key，瞬态交互不触碰全局状态，校验等重逻辑不在手势路径上执行。
- 运行结果（事件流、序列、指标）：大体积数据不进 UI 状态。UI 只持有“查看哪一段”的引用，表格与时间轴按需取数、分页或窗口化渲染。

控件生命周期（焦点、输入法、文件选择器、滚动位置等）通过“实例组件”统一收口，实例拥有权契约见下。

## 3. 组件分类

组件按功能域组织目录，不按组件类型建目录；每个组件在定义处标注类型。四类组件：

| 类型 | 职责 | 典型位置 |
| --- | --- | --- |
| 纯组件 | state 进、控件出，无内部状态 | 节点卡壳、区域框、状态徽标 |
| 编辑器组件 | 持有本地瞬态（文本、拖动、选择），提交语义事件 | 节点内编辑器、参数表单 |
| 实例组件 | 持有外部实例/焦点/绘制上下文，对外声明式 | 输入框包装、文件选择器、画布表面、连线绘制 |
| 桥接组件 | 对接异步（任务状态、查询结果），只转发数据与回调 | 运行状态展示、结果取数 |

实例组件契约：

- 自己持有控件实例（ref），自己管理焦点、IME、滚动位置等生命周期细节；
- 对外接口仍为声明式（数据 props + 语义回调）；
- 全局重渲染发生时不得重建自身或打断用户操作。

可复用的实例原语（输入框、文件选择器、画布表面等）收在 `ui/components/common/`，作为组件库基础件。

### 3.1 节点卡结构与状态表达

- 节点卡采用固定的「头部 + 内容区 + 底部」结构：头部承载类型标识（类型色点 + 名称）、草稿徽标与悬浮显示的节点级操作入口；底部承载输入顺序入口、成员投影开关与标签、组输出计数和端口点。
- 节点卡宽度基准为 260px；内容区编辑约定、高度自适应与字段错误显示见[批处理工作流画布设计](./批处理画布设计.md) 5.5。
- 状态表达不得只依赖颜色：选中、草稿、运行置灰与应用中等状态同时提供文本或图形标识。

## 4. 状态层

UI 私有状态不持久化，全部为纯 Python 对象，不依赖 Flet，可单测。

- `AppState`：当前项目/工作区、可用服务、当前视图。
- `EditorState`：只装语义状态——选中对象、节点已提交位置、连线、区域归属、已提交节点参数，以及按工作流独立的撤销/重做历史与最后保存引用；`dirty` 由当前定义与最后保存定义比较派生。
- `RunState`：运行期状态，不持久化。当前为「工作流运行」单块（2.28 移除 `regionChecks`）：`run` 为当前/最近一次工作流运行，含构建限速轨迹、按模拟节点索引的批次视图（批次状态含校验中 / 校验通过）与终态，见[项目决策记录](../../决策/项目决策记录.md) 2.28、2.29。

分界规则：

- 视口（缩放/平移）不进 EditorState，归 CanvasView 实例组件持有；节点不因视口变化重建。
- 正在编辑的文本、拖拽中的位置、临时连线留在对应编辑器组件内部；提交时以语义事件进入 EditorState。
- 结果数据永远不进 UI 状态；UI 只持有 session 引用与视图范围。

```text
backend/src/genshin_sim/
├── application/

│   │   ├── nodes/         # 节点编辑器，按节点类型一个文件 + registry.tsx
```

## 6. 桥接层

桥接层不依赖前端框架，可单测：

- `converters.ts`：EditorState 与 WorkflowDefinition 双向转换。
- `api/`：把 HTTP API 包装为页面可用的异步调用；配置预览走 `POST /inputs/validate`。
- `runtime_subscription.ts`：轮询 `GET /runs/{run_id}` 更新 RunState；SSE/WebSocket 后置。

组件不直接拼装 HTTP 请求，统一通过 API 客户端获取能力。

## 7. 节点类型注册表

### 7.1 分工

- 语义注册表在 `frontend/src/workflow/`：节点类型、片段形状、端口模型、参数 schema、区域约束与节点级校验。
- UI 注册表在 `frontend/src/components/nodes/registry.tsx`：`node_kind → 编辑器组件` 映射与展示元数据（图标、默认尺寸、面板排序）。
- 画布对象面板读语义注册表决定“当前区域有哪些对象”，再经 UI 注册表取编辑器组件；两侧以稳定 `node_kind` 为公共 key，互不循环依赖。

### 7.2 NodeKindSpec

每个节点类型是一个描述对象，至少包含：

- `kind` / `display_name`：稳定 key 与显示名。
- `region`：配置区域 / 分析区域 / 画布级（`null`，不归属区域）。
- 端口模型：输入输出端口、数据语言（片段、输入文档、会话、查询结果、指标结果等）、单值/组输出、连接数约束。
- 片段形状：默认目标路径与参数形状；只声明路径，不读取 SimulationInput schema。
- 参数 schema：类型化节点参数，供编辑器生成表单与定义校验。
- 节点级校验规则。

注册表显式注册，不自动扫描；WorkflowDefinition 中出现未注册 kind 时，加载/校验阶段报错，不静默忽略。节点 kind 字符串冻结后只追加、不改名。

### 7.3 特殊行为

纯描述性节点由 spec 与通用机制（片段应用、展开、查询）驱动。存在天生特殊行为的节点按 kind 显式绑定行为实现，不在 spec 中塞回调：

- 配置区域边界输出：收拢、校验、预览输入文档；属于区域模型，不进入节点类型注册表。
- 模拟节点：任务分发、按成员管理状态。
- 视图节点：展示终点（分析区域实现时设计，MVP 不预建）。

## 8. MVP 画布范围

- 画布包含配置区域与模拟节点。
- 配置区域节点：根节点、元信息、角色、武器、圣遗物、目标、按键轨迹、运行选项，以及枚举/区间节点。
- 配置区域固定拥有一个边界输出（无独立输入端口），边界输出同时作为区域内节点链的汇入目标与连接模拟节点的输出源；边界负责收拢、校验和预览输入文档。
- 模拟节点：消费配置区域边界输出交出的输入文档集合，调用任务系统执行仿真，按成员反馈状态。
- MVP 不含分析区域：查询/指标/聚合/对比/视图等分析节点不进入 MVP，也不预建数据结构；区域模型仍按通用模型实现，分析区域后续只做注册新增，不重构画布。
- 枚举/区间节点进入 MVP：多组输出按“不同路径叉乘、同路径覆盖并警告”组合；成员上限 200；区间“下一步 ≤ 终点即包含”并使用 Decimal 计算；具体规则见[批量配置变体契约](../../契约/ui/批量配置变体契约.md)。
- 完整纵向链路（配置 → 模拟 → 分析在同一画布承载）是正式实现的链路目标；MVP 是这条链路的第一段交付（配置 + 模拟，含枚举/区间），分析区域后续接入。
- 结果摘要：展示位置已确认为外壳固定结果面板；结果面板定位为「结果库历史浏览器」，不展示指标数值（指标后置到分析区域），过程信息由画布执行轨迹承担，见[项目决策记录](../../决策/项目决策记录.md) 2.29。

## 9. 应用壳与全局组件

### 9.1 顶部栏

- 顶部栏承载工作流上下文和工作流主操作，不承担画布工具、对象面板、问题列表和设置入口。
- 左侧为品牌 mark、工作流切换器和未保存状态；品牌 mark 独立于切换器选中态，切换器只包住当前工作流名称与下拉箭头。
- 工作流切换器提供切换、新建和重命名入口；重命名正式实现不使用系统 prompt。
- 切换器下拉展示存档列表（按更新时间倒序）与新建入口；列表项 hover 提供重命名与删除，删除在当前项内二次确认。
- 当前工作流有未保存改动时，切换或新建先进入三选确认（保存并继续 / 不保存继续 / 取消）；保存并继续失败时停留在原工作流。
- 新建工作流切到空白草稿，不立即创建后端文件，首次保存时才落盘；删除当前工作流后回到空白草稿。
- 应用启动优先打开 localStorage 记住的上次工作流，不存在或已删除时回退到列表第一个，列表为空时打开空白草稿。
- 右侧为保存和全部运行。保存按钮保持普通样式，未保存状态由徽标承担；顶部栏不提供运行模式菜单。
- 顶部栏“全部运行”执行工作流运行：构建 → 模拟 → 终态（见[项目决策记录](../../决策/项目决策记录.md) 2.28）；区域头部提供「区域校验」+「区域运行」两个入口，区域校验不提交模拟（见 2.28）。

### 9.2 设置弹窗

- 设置入口位于工具轨底部，使用 24px 设置图标按钮。
- 设置弹窗为居中模态，宽度 400px，单列分组表单：分组标题在上，设置项标签左、控件右。
- 第一版包含两个分组：「工作区」只读展示数据目录（config.toml `workspace` 节）；「运行」提供「运行动画」开关（构建阶段逐节点限速推进，默认启用，2026-08-22 实现）。设置持久化在后端项目配置（config.toml 的 `ui` 节，经 `GET/PUT /api/v1/settings` 读写），不落在浏览器存储。外观分组的主题项后置。密度统一舒适，动态背景常开，不提供开关。
- 设置修改立即生效，不设置保存/取消按钮。

### 9.3 问题筛选

- 问题筛选按钮按严重程度着色：错误使用 danger、警告使用 warning、提示使用 info；全部保持中性。

### 9.4 画布导航与小地图

- 画布视图使用 translate + scale 世界坐标；平移、缩放与对象位置都基于同一世界坐标。
- 动态背景固定为氛围层，不随画布平移或缩放；网格使用单层 24px 点阵；空画布显示“拖入区域开始”，创建首个区域或节点后消失。应用打开/新建工作流时默认是空白画布；打开应用不会立即创建后端工作流文件，首次保存时才落盘；不提供载入示例入口，画布内容一律由用户拖入创建。
- 平移使用鼠标中键拖拽（浏览器原型不验证中键手感）；空白画布左键拖拽做框选；点击选择区域/节点，拖动区域标题栏移动区域，拖动节点头部移动节点。
- 缩放以鼠标位置为中心，范围 25% ~ 400%；提供适应全部与定位选中。
- 小地图定位为结构总览，显示区域、节点、连线、模拟节点和当前视口；支持点击定位、定位选中和折叠/展开。
- 小地图视觉：直角、外边框加粗、无阴影；百分比显示在小地图右上角；左侧直接放置图标按钮，不使用工具条；折叠后保留统一的纯图标展开按钮。
- 节点按角色类别共享颜色（10 类，见[项目决策记录](../../决策/项目决策记录.md) 2.34），画布对象面板、节点卡、拖拽预览和小地图共用同一套节点类别色；区域对象使用区域色（配置蓝 / 分析紫）。

- 画布交互性能目标与节点规模基准：MVP 规模小，规则先行；具体基准留待真实画布实现后实测。
- 画布实现技术栈已确认：Python + Web（React + React Flow），见[项目决策记录](../../决策/项目决策记录.md) 2.27。
- 工作流定义契约、节点类型与编辑器数据契约、批量配置变体契约、UI API 契约已创建于 `docs/契约/ui/`。
