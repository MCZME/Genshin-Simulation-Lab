# 元素共鸣契约

> 状态：静态切片与全部动态效果（附着时长、冷却、双雷微粒、双草精通、
> 双冰暴击、双岩增伤/减抗）已确认。数值基线：原神 BWIKI《队伍加成》页
> 2026-07-02 更新（覆盖月之八版本；双草 6.0、双岩 6.4 适配已包含）。
> 最后更新：2026-08-10

## 1. 稳定 key

```text
resonance.pyro
resonance.hydro
resonance.anemo
resonance.electro
resonance.cryo
resonance.geo
resonance.dendro
resonance.intertwined
```

key 是仿真识别与审计依据，不使用显示名称绑定行为。

## 2. 激活条件

| 条件 | 要求 |
| --- | --- |
| 同元素共鸣 | 队伍满员（>= 4 人）且该元素角色 >= 2 名 |
| 交织之护 | 队伍满员且不同元素角色 >= 4 名 |

规则：

- 多个共鸣可以同时激活。
- 无元素角色不参与元素计数与不同元素判定。
- 激活集合固定于组装期，运行期不改变，按 key 稳定排序。

## 3. 静态修饰

| 共鸣 key | 属性 | 阶段 | 值 | 审计标签 |
| --- | --- | --- | ---: | --- |
| `resonance.pyro` | `stat.atk.total` | `percent_add` | `0.25` | `atk_percent` |
| `resonance.hydro` | `stat.hp.max` | `percent_add` | `0.25` | `hp_percent` |
| `resonance.geo` | `bonus.shield.strength` | `flat_add` | `0.15` | `shield_strength` |
| `resonance.dendro` | `stat.elemental_mastery` | `flat_add` | `50.0` | `elemental_mastery` |
| `resonance.intertwined` | 全部 `resistance.*` | `flat_add` | `0.15` | `resistance` |

静态修饰对队伍中每个角色各展开一份，来源标识为
`RuntimeSourceRef(SYSTEM, "resonance:<key>")`，provider key 为
`resonance.static.slot_<slot>`。

## 4. 附着时长修正

角色主体被施加下列 Aura 时，附着自然持续时间按倍率缩放（附着量不变，
衰减率相应提高）：

| 共鸣 key | 目标 Aura | 倍率 |
| --- | --- | ---: |
| `resonance.pyro` | `cryo` | `3/5` |
| `resonance.hydro` | `pyro` | `3/5` |
| `resonance.electro` | `hydro` | `3/5` |
| `resonance.cryo` | `electro` | `3/5` |

实现模型：`AuraDurationTerm(term_key, source_ref, multiplier)` 进入
`AuraApplicationRequest.duration_terms`，`AuraDecayProfile` 按 term 乘积缩放
持续时间；多个激活共鸣对同一 Aura 的倍率相乘。只对角色主体生效，目标敌人
不受队伍共鸣影响。角色附着入口由 `CharacterAuraDurationTermPort` 提供 term，
装配时注入 `CharacterAuraImpactRequestHandler`。

## 5. 冷却时长修正

| 共鸣 key | 效果 |
| --- | --- |
| `resonance.anemo` | 全队角色元素战技/元素爆发冷却时长 × `0.95` |

`ResonanceCooldownDurationTermProvider` 实现 `CooldownDurationTermPort`；
`TimedImpactAction` 开始冷却时把 term 与内容自带 term 合并，进入既有冷却解析。

## 6. 反应触发效果

`ResonanceReactionStage`（位于 `core/coordination/resonance_reaction/`）
在 `FACT_RESPONSE` 阶段消费 `REACTION_OCCURRED` 事实，为下一结算轮次产生
强类型意图；共鸣领域只提交自己的冷却认领状态。

### 6.1 双雷微粒

- 触发反应：超导、超载、感电、月感电、原激化、超激化、超绽放。
- 效果：100% 掉落 1 个雷元素微粒；两次掉落间隔至少 300 帧（5 秒）。
- 冷却在反应发生帧认领，认领成功的反应才生成能量意图。
- 不包含星超导（确认不接入）。

### 6.2 双草精通

- `+30` 组（触发燃烧、原激化、绽放、月绽放）：全队角色元素精通 +30，
  持续 360 帧。
- `+20` 组（触发超激化、蔓激化、超绽放、烈绽放）：全队角色元素精通 +20，
  持续 360 帧。
- 两组使用不同 Buff 定义与冲突键，持续时间独立计算：
  `buff.definition:resonance.dendro.em_30` / `buff.definition:resonance.dendro.em_20`。

### 6.3 双冰暴击

- 攻击处于冰元素附着或冻结状态的目标（仅敌人目标）时，暴击率 +15%。
- `ResonanceCryoCritDamageProvider` 写入 `CRIT_RATE_ADD`，通过
  `TargetAuraFrozenReadPort` 查询目标状态；端口在装配期绑定 Aura 与 Reaction
  运行态。

### 6.4 双岩增伤与命中减抗

- 处于护盾庇护下或存在活动月笼（第一版按存在即生效，不判距离）时，
  造成的伤害 +15%：`ResonanceGeoDamageProvider` 写入 `DAMAGE_BONUS_ADD`，
  通过 `CharacterShieldPresenceReadPort` / `LunarCagePresenceReadPort` 判定。
- 上述条件满足时，角色对敌人造成伤害后为目标施加岩元素抗性 -20% 的 Buff，
  持续 900 帧（15 秒）：定义键
  `buff.definition:resonance.geo.res_shred`；由 `ResonanceReactionStage`
  消费 `DAMAGE_RESOLVED` 事实生成下一轮 `ApplyBuffRequest` 意图。

## 7. 领域模型

```text
ResonanceRequirement
├── kind: element_count | distinct_elements
├── element: Element | None
└── count: int

ResonanceStaticModifier
├── target_key: AttributeKey
├── stage: ModifierStage
├── value: float
└── audit_tags: tuple[str, ...]

ResonanceDefinition
├── key: str
├── requirement: ResonanceRequirement
├── static_modifiers: tuple[ResonanceStaticModifier, ...]
├── aura_duration_rules: tuple[ResonanceAuraDurationRule, ...]
└── cooldown_duration_multiplier: Fraction | None

TeamElementComposition
├── team_size: int
└── element_counts: tuple[(Element, int), ...]

ResonanceActivation
└── active_keys: tuple[str, ...]  # 排序去重
```

校验规则：

- 同元素条件必须指定非物理元素，人数 >= 2；异元素条件不能携带元素。
- 静态修饰值必须有限；同一共鸣内不允许重复（属性, 阶段）。
- 元素构成计数合计不能超过队伍人数；只保留计数大于 0 的元素。
- 激活集合 key 必须非空、去重且稳定排序。
- 共鸣定义 key 全局唯一。

## 8. 事件与快照

`RESONANCE_ACTIVATED`（`FACT`，默认记录）载荷：


`ResonanceSnapshot`：

```text

active_keys: tuple[str, ...]

established_frame: int = 0
last_electro_particle_frame: int | None
```

## 9. 装配与错误

`application/assembly/resonance.py::build_resonance_bundle(assets)` 输出
`ResonanceRuntimeBundle`（定义注册表、构成、激活集合、Store、静态 provider、
Aura/冷却端口）。`RuntimeAssembler` 额外注入双草 Buff 定义、反应响应阶段与
动作冷却端口。

以下情况在组装阶段以 `InvalidRuntimePayloadError` 失败：

- 角色资产元素不是七种元素之一或为物理。
- 共鸣定义重复。
- 激活集合引用不存在的定义。
