# 分析区域设计

> 状态：正式规范。
> 本文定义分析区域作为画布上查看、比较和解释仿真结果的数据视图空间，包括区域模型、数据语言、节点模型、执行与交互边界。
> 最后更新：2026-08-30。

## 1. 定位与边界

- 分析区域回答“跑出来说明什么”：用户对仿真结果进行查看、比较、解释并得出判断，不产生新的模拟输入，也不发起新的仿真。
- 分析区域是画布的一部分，随工作流保存和重跑；它不是脱离画布上下文的独立报告页，也不使用独立抽屉或独立页面承载分析结果。
- 分析区域是声明式数据流空间：节点是纯函数，输出由输入派生；依赖变化自动向下游传播，结果立即重新求值。
- 数据只沿连线流动。未连接分析区域边界输入的节点是草稿，不能获得数据，也不能参与查询。
- 时间相关数据不强制用时间轴呈现；`timeline` / `timeline_config` 不属于当前节点集。
- 本文不重复定义节点参数结构、查询计划或 HTTP 端点；稳定字段与校验以[节点与区域契约](../../契约/ui/节点与区域契约.md)和[分析系统契约](../../契约/分析系统契约.md)为准。

## 2. 区域模型

- 分析区域固定拥有一个边界输入 `in`，数据语言为 `session_group`。
- 边界输入是区域内数据的唯一输入源。上游只能是画布级源节点：`simulation` 或 `data_provider`。
- 边界输入允许多个源节点连入，会话组按连线顺序合并并去重。
- 分析区域不提供边界输出；区域内结果通过视图节点和单项详情节点呈现。
- 分析区域不承担批次状态、来源归属或成功失败汇总；这些信息由模拟节点和数据提供节点分别呈现。
- 跨区域连线只能连接区域边界端口与画布级源节点；区域外对象不能直接连接区域内节点。

## 3. 数据语言与节点模型

### 3.1 数据语言

分析区域使用四种数据语言：

| 语言 | 含义 | 来源 | 去向 |
| --- | --- | --- | --- |
| `session_group` | 会话 ID 的有序去重列表 | 分析区域边界输入、`simulation`、`data_provider` | 只能进 `fetch` |
| `table` | 列名 + 类型的一组行 | `fetch` 与关系算子 | 视图数据输入、下游算子、`single` |
| 展示配置 | 视图专用列绑定 | `table_config` / `pie_config` / `bar_config` | 只进对应视图配置输入 |
| `item` | 一个数据对象，表示一行、一个区间或一个曲线点 | 视图 `selection` 输出、`single` | 只能进单项详情节点 |

- 连接按数据语言和形状匹配；不匹配由前端图校验器报错。
- 会话维度显式化：所有源表携带 `session_id` 列。逐场查看、跨场汇总和跨批对比都通过 `session_id` 与普通列上的显式操作完成，框架不做隐式按会话展开。
- 视图数据输入是单表语义：允许一条或多条同结构入线，行拼接后按同一套绑定渲染；不同结构入线由校验器拒绝。
- 视图不设“多来源”概念。需要区分批次或场次时，由结果表身份列承担；需要并置不同结构时，先用连接或聚合等算子合并为带来源列的输出表。

### 3.2 节点模型

- 节点是上下文无关的输入输出单元，不关心输入来自哪里、输出被谁消费。
- 节点允许多输入、多输出；处理节点之间允许串联，输出可以分支给多个下游。
- 连通性、端口语言匹配、无环和形状推导由前端图校验器负责；节点自身不感知图结构。
- 当前分析区域节点集由[节点与区域契约](../../契约/ui/节点与区域契约.md)冻结：取数、关系算子、展示配置、视图和单项详情节点。
- 节点 `kind` 只追加、不改名、不复用；删除节点时同步修订契约、注册表和校验规则。

### 3.3 当前节点集

| kind | 数据流 | 说明 |
| --- | --- | --- |
| `fetch` | `session_group -> table` | 取数节点，`source` 切换运行记录/事件记录 |
| `filter` | `table -> table` | 条件过滤 |
| `project` | `table -> table` | 选列与重命名 |
| `sort` | `table -> table` | 多列排序 |
| `aggregate` | `table -> table` | 分组聚合 |
| `limit` | `table -> table` | 限制行数 |
| `join` | `table x2 -> table` | 等值连接 |
| `compute` | `table -> table` | 受限计算列 |
| `single` | `table -> item` | 显式取单项 |
| `table_config` | 展示配置 | 表格列绑定 |
| `pie_config` | 展示配置 | 饼图列绑定 |
| `bar_config` | 展示配置 | 柱状图列绑定 |
| `member_table` | `table + table_config`，可输出 `item` | 表格视图 |
| `pie` | `table + pie_config`，可输出 `item` | 饼图 |
| `bar` | `table + bar_config`，可输出 `item` | 指标柱状图 |
| `frame_state` | 输入 `item` | 帧状态详情 |
| `damage_detail` | 输入 `item` | 伤害事件详情 |
| `state_detail` | 输入 `item` | 状态实例详情 |
| `attribute_detail` | 输入 `item` | 属性值详情 |

`timeline` / `timeline_config` 不属于当前节点集。

## 4. 数据入口与关系算子

### 4.1 取数节点

`fetch` 是会话组的唯一消费点，显示名为「获取数据」。

- `source = runs` 读取 `simulation_runs`：固定输出列为运行记录表除两个大 JSON 外的全部列；`snapshot_columns` 从输入快照提取条件列。
- `source = events` 读取 `simulation_events`：固定输出列为 `session_id`、`ordinal`、`frame`、`event_type`，其后是 `payload_columns` 提取列。
- 取数节点只回答“提供哪一种数据”，不承担行级筛选；帧范围等筛选由下游 `filter` 承担。
- 事件类型和载荷字段的可选来源由 `GET /api/v1/analysis/schema` 提供；列名允许中文、字母、数字和下划线，可读名即列名。

### 4.2 关系算子

关系算子处理 `table -> table` 的纯关系变换：

- `filter`：单层条件组，操作符白名单按列类型约束。
- `project`：按顺序选列并可选重命名。
- `sort`：多列排序，每列 `asc / desc`。
- `aggregate`：分组聚合，函数白名单为 `sum / count / avg / max / min / stddev / p95`。
- `limit`：保留输入表前 N 行，N 范围 1–10000。
- `join`：等值连接，`inner / left`；第一路输入为主表。
- `compute`：受限四则表达式，支持 `+ - * /`、括号、数字常量、一元负号和列引用。

所有算子的输出形状由输入形状与参数唯一确定；前端推导驱动校验和列下拉，后端执行前独立防御性校验。

### 4.3 查询计划

- 前端把分析区域内从边界可达的子图编译为结构化查询计划，调用 `POST /api/v1/analysis/query` 一次执行。
- 计划只含节点 `kind`、`params`、有序 `inputs` 和 `outputs`，不含 SQL 文本。
- 后端将节点编译为 CTE 链在结果库上执行，中间结果不出后端；响应只携带输出终表。
- 会话组最多 1000 个会话；每张返回表硬上限 10000 行，超出置 `truncated: true`。
- 校验失败统一返回 `400 / validation_failed`，`details` 逐项定位到节点。

## 5. 视图

视图节点是纯渲染终端：数据来自数据处理节点输出，列绑定来自对应展示配置节点。每个视图必须且只能连接一个对应配置节点。

视图可以增加 `selection` 输出端口，语言为 `item`。用户点击表格行、饼图扇区、柱状图柱或其它可选中对象后，把该对象输出给下游单项详情节点；视图自身的整组渲染不变，选择是节点内瞬态状态。

### 5.1 表格

表格视图 `member_table` 用于参数扫描和批结果总览，回答“每个成员表现如何、哪个条件组合最优”。

- 行是会话，列分条件列和数据列。
- 条件列来自运行记录来源的快照提取列，说明这一行是什么配置；数据列是需要分析的指标。
- 列绑定由 `table_config` 指定：条件列/数据列双栏并排，支持拖拽排序、跨区移动和批量添加。
- 视图只做排序、最大/最小高亮和格式化；不做“哪一行最优”的判断。
- 排序规则：数据列单列排序；条件列支持多列组合排序，组合顺序等于点击表头的顺序。
- 大批量呈现：节点卡内滚动和窗口化渲染，不分页；后端 `truncated` 时显示“仅显示前 10000 行”。
- 数值格式化按列类型：int 千分位、float 保留两位小数并去尾零、string 原样、NULL 显示“—”。
- 条件列按 schema 声明的 `value_kind` 解析显示名；资产 key 经 `POST /api/v1/assets/resolve` 解析，枚举词表走前端词表，解析失败显示原始值。
- `session_id` 默认不展示；用户主动加入条件列绑定后按普通列显示。
- 尺寸语义：高度始终手动（默认 360px，夹持 240–720px）；宽度支持 `auto` 和 `fixed`，由 `table_config.width_mode` 与节点画布几何共同保存。
- 持久化边界：列绑定和 `width_mode` 随工作流保存；排序、高亮和显示顺序是瞬态查看状态，不随工作流保存。

### 5.2 饼图

饼图视图 `pie` 用于回答“伤害/治疗由谁构成”，把总量按维度切成扇区。

- `pie_config` 绑定分组列（必选）、值列（必选）和标签列（可选）。
- 渲染规则：按分组列值合并为扇区，值列数值求和；绑定标签列时扇区名取该组首行标签显示值，否则取分组列显示值；值列空值不参与求和，全空组不参与占比。
- 节点内提供图例（滚动）、悬停数值和占比；百分比按值列合计计算，不做其它数据加工。
- 选择交互：点击扇区把该组首行对象输出到 `selection` 端口，再次点击取消；修改绑定后选择重置。
- 值列必须是数值列；绑定列不在上游表中时节点内报错提示。
- 尺寸语义：宽度和高度均为手动画布几何；饼图没有展示配置节点，不使用 `table_config.width_mode`。
- 多占比组并排属于后续扩展。

### 5.3 指标柱状图

柱状图视图 `bar` 用于回答“各成员/各条件某项指标高低”。

- `bar_config` 绑定 X 轴列（必选）、Y 轴列（必选）和系列列（可选）。
- 渲染规则：按 X 列值分槽，槽内按系列列值分组并排；同一 X + 系列的多行求和合并为单柱，Y 值缺失的行不参与合计；类目默认按输入行序展示。
- 节点内提供悬停柱值。
- 选择交互：点击柱把该组首行对象输出到 `selection` 端口，再次点击取消；修改绑定后选择重置。
- Y 轴列必须是数值列；绑定列不在上游表中时节点内报错提示。
- 尺寸语义：宽度和高度均为手动画布几何；柱状图没有展示配置节点，不使用 `table_config.width_mode`。
- 多来源分组柱布局属于后续扩展。

## 6. 单项详情

### 6.1 数据对象

`item` 是分析区域的数据语言，表示一个具体数据对象：

- 表格行或聚合行；
- 序列中的点事实；
- 区间或持续状态对象；
- 曲线上的采样点。

单项详情不改变视图整组渲染，也不进入查询计划。

### 6.2 选择输出

视图节点可提供 `selection` 输出端口，语言为 `item`：

- 用户点击表格行、序列行、区间对象或曲线点后，视图把选中对象输出给下游详情节点。
- 选择状态是节点内瞬态，不随工作流保存。
- 没有下游详情节点时，选择不产生副作用。
- 当前交付边界：三个视图节点均注册 `selection` 端口，表格行点击、柱状图柱点击与饼图扇区点击选择交互均已落地（再次点击取消、排序或绑定变化重置）。

### 6.3 取单项

`single` 是 `table -> item` 的唯一显式转换入口，显示名为「取单项」。

- 第一版取输入表第一行；上游应先经过过滤、排序和限制行数确定唯一项。
- 单项详情节点不能自行接收整表。
- 空输入或零行输入显示“无数据”。
- 当前参数为空；取第 N 行属于后续扩展。

### 6.4 详情节点

单项详情节点族接收 `item`，输出为空，用于展示一个数据对象：

| kind | 输入对象 | 展示内容 |
| --- | --- | --- |
| `frame_state` | `{ session_id, frame }` | 指定帧的角色状态 |
| `damage_detail` | `{ session_id, ordinal }` | `DAMAGE_RESOLVED` 摘要与完整审计 |
| `state_detail` | Buff / 护盾 / 附魔 / 冷却实例 | 状态实例生命周期与字段 |
| `attribute_detail` | 属性值对象 | 属性 value 与 `applied_terms` |

- `frame_state` 数据来自 `GET /api/v1/results/{session_id}/frames/{frame}`。
- `damage_detail` 数据来自 `GET /api/v1/results/{session_id}/events/{ordinal}`。
- 伤害详情只读取 `DAMAGE_RESOLVED`，展示 `result` 摘要与 `audit` 完整审计，不串接护盾吸收、`DAMAGE_APPLIED` 或生命变化链路。
- 详情节点在画布内呈现，不新增独立抽屉或独立页面。

### 6.5 伤害详情呈现

`damage_detail` 节点卡按"伤害结算单"呈现（2026-08-30），替代早期 JSON 直出：

- 上下文条（2026-08-30）：元素徽标（实底元素色，样式对齐目标抗性网格的元素角标）→ 伤害名称（随元素着色，缺失时回退"伤害"）→ 帧数（小字弱化）→ 右对齐的 `source_ref → target_ref` 实体名；不再显示 `#ordinal` 序号，伤害类型移入名称悬停提示。
- 乘法链：`基础伤害 x 增伤 x 暴击 x 反应 x 防御 x 抗性 = 最终伤害`，链段直接显示该步乘数（不带乘号），段间以 `x` 连接。段序列按结算摘要动态生成，缺失或不适用的乘区整段省略，乘数为 1 的乘区无信息量同样省略（剧变/月曜路径的增伤、防御区恒为 1）。hover 任意乘数段显示该步累计轨迹；链段可点击。
- 结果行：`final_damage` 大字显示，暴击时染色并带「暴击」徽标；`debug_multiplier ≠ 1` 时追加"正式公式 `official_damage`"小字。
- 链段详情区分两部分（2026-08-30）：上部首行为乘区标题（基础区/增伤区/暴击区/反应区/防御区/抗性区），其后渲染当前乘区的计算公式骨架，可被伤害词条修饰的位置呈现为槽位（显示该位置当前合计值，点击与对应抽屉联动折叠）；数值为 0 的槽位不显示，值为 1 的括号组一并省略，公式保持最简形态。下部为按槽位分类的修饰项抽屉，默认全部展开，抽屉内依次为基础值行（属性/请求来源）、生效词条行、未生效词条行（划线）。倍率段按组件逐行渲染公式，词条跨组件时行内标注归属组件；抗性、反应区无伤害词条槽位，只显示公式构成并标注"无伤害词条修饰项"。默认选中基础段。
- `DamageModifierTerm` 词条按 `stage` 静态归属到对应链段的槽位抽屉展示。
- 伤害详情只呈现伤害审计，不呈现属性审计（2026-08-30）：`source_attribute_trace` / `target_attribute_trace` 等属性解析内容不在伤害详情展示；属性词条贡献由各内容效果以 `DamageModifierTerm` 进入伤害词条账单后呈现。
- 审计字段按已知字段白名单渲染，不提供原始 JSON 面板；前端未识别的新增字段不显示也不报错。
- `damage_detail` 节点卡宽度手动可调并随节点保存（默认 320，范围 280–960），高度随内容自适应。

## 7. 数据来源与会话保留

- `data_provider` 是画布级源节点，参数只有有序去重 `session_ids`，上限 1000，随工作流保存。
- 历史会话筛选、分页、刷新和失效提示是编辑器瞬态交互，不进入工作流定义。
- `simulation` 保存最近一次批次产生的 `last_sessions`，并随批次保存 `last_input_fingerprint`。
- `last_input_fingerprint` 是批次输入的有序来源区域加有序成员输入 JSON 的稳定哈希，用于判断 `last_sessions` 是否随配置区域参数变化而过期。
- 分析区域边界合并后的总会话数不得超过 1000。
- 已选会话在结果库中缺失时，查询自然无行，不阻断执行；编辑器提示缺失数量并提供一键清除。

## 8. 运行与自动重算

### 8.1 运行分析

分析区域头部提供「运行分析」，执行三阶段：

1. 获取输入：逐个检查边界源节点。`simulation` 在 `last_sessions` 缺失或为空、缺少 `last_input_fingerprint`、或指纹与当前配置区域展开结果不一致时补跑；`data_provider` 直接使用 `session_ids`，永不触发模拟。
2. 数据处理：区域级图校验通过后编译查询计划，调用 `POST /api/v1/analysis/query` 一次执行。
3. 视图加载：响应落入视图节点，更新加载、有数据、空、错误和过期状态。

任一阶段失败即整次中止；补跑失败或取消不进入查询阶段，旧结果保留并标记过期。

边界完全未连接源节点时运行报错；模拟节点需要补跑但未连接配置区域时运行报错。

### 8.2 自动重算

- 前端为每个分析区域维护可重算快照指纹：查询计划请求、节点参数、连线顺序和边界输入就绪状态。
- 快照变化后防抖 300ms 自动重算；只重新提交查询计划并更新视图，不触发模拟。
- 相同快照跳过请求；结果缓存后置。
- 自动重算带递增序号，过期响应丢弃；查询前保留旧表并标 `stale`。
- 图校验错误、schema 未加载时不自动重算。
- 缺会话或会话过期时不查询，只提示用户通过「运行分析」补跑。

## 9. 编辑器交互

- 分析区域节点在画布内编辑，不跳转独立页面。
- 节点内部状态在节点内交互：排序、高亮、列显示顺序、选择等是瞬态；参数和配置随工作流保存。
- `fetch` 节点卡只做摘要，配置进入画布内弹层；过滤、投影、排序、聚合、限制行数、合并表、计算列和取单项使用卡片直编。
- 列名即显示名：用户可在取数或投影阶段把列名改为中文可读名，下游下拉直接显示当前列名；改名不自动级联下游引用，失效引用由校验提示。
- 表格配置绑定在 `table_config` 节点卡内完成；视图节点卡不承载绑定表单。
- 饼图/柱状图配置（`pie_config` / `bar_config`）在节点卡内直编：卡顶显示绑定摘要行（未绑定显示「—」），表单行用列下拉并提示行级绑定状态（必选未绑定、绑定列不在上游表、字段级校验错误）；空态区分「未连视图」与「视图未接通数据源」。
- 展示配置节点、视图节点和单项详情节点沿用同一套节点卡与状态原则。

## 10. 范围外与后续方向

当前不进入设计或实现：

- 单场时间轴节点及其配置节点；
- 独立抽屉、独立页面或独立报告视图；
- 分析模板目录：如后续引入模板，只在前端生成一组普通节点，不新增后端端点；
- 任意列隐藏、分页、查询级行限和结果缓存；
- 多结果对比作为独立节点或独立视图；
- 序列、区间、曲线等时间呈现视图；
- 性能目标与节点规模基准。

第一版交付范围以项目决策记录为准；本文是分析区域当前生效设计，不改变“分析区域不进入 MVP”的既有交付决定。
