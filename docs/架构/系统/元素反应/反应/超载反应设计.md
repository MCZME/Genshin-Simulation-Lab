# 超载反应设计

> 状态：已实现。本文描述普通火雷超载及其当前钝击语义。

最后更新：2026-08-03

## 1. 定位

普通超载是无长期状态的即时剧变反应。它按 `1:1` 消费普通火/雷，在当前元素交互中形成 occurrence，并冻结一个同帧下一 settlement round 执行的 5 米范围 Damage Effect。

代码落点：

```text
core/systems/reaction/mechanics/overloaded/mechanic.py
```

公共模型、队列和事务规则见：

- [系统边界与领域模型](../系统边界与领域模型.md)
- [判定与执行流程](../判定与执行流程.md)
- [事务、事实与验证](../事务、事实与验证.md)

## 2. 方向与元素变化

显式方向：

```text
incoming_pyro_on_electro
incoming_electro_on_pyro
```

两个方向均使用 `consumed = min(incoming_amount, aura_amount)`，先手 Aura 和后手预算各扣除同一数量。超载不修正原始 Impact 的关联伤害；无伤害元素施加也能形成超载和后续独立伤害。

## 3. 剧变伤害

超载 Damage Effect 固定：

```text
damage element = pyro
base multiplier = 2.75
elemental amount = 0
can crit = false
strike type = blunt
```

来源等级、元素精通、等级系数和 Profile 在 occurrence 时捕获。最终 Damage 使用目标火抗以及共享剧变公式。

## 4. 范围与目标

Effect group 以 occurrence 主体为锚点，查询 X/Z 平面 5 米闭区间。协调器冻结候选及距离/主体引用顺序，再组合 relation 与 capability：

- `hostile + damage` 进入超载伤害；
- `hostile + aura` 可以参与钝击状态型反应；
- self、ally、neutral/unknown 或缺少对应 capability 只形成目标级正常阻止。

一个范围 hit 中每个目标独立读取火抗并检查 Gate。多个主体同时形成超载时保留全部 occurrence，由 Gate 控制重叠伤害，不丢弃反应事实。

## 5. Gate 与事务

超载 Gate 是来源、目标和超载 damage kind 分槽的 30 帧一次计数窗口。

单个 Effect group 是 round 1 原子 batch：先冻结全部目标，准备钝击状态反应、Gate 和 Damage，再统一校验并无回调提交。Gate blocked 只阻止该目标的超载伤害。

## 6. 钝击与碎冰

`StrikeType.BLUNT` 是超载命中的稳定语义，不是控制模型。冻结目标被超载范围命中时：

1. round 1 产生碎冰 occurrence；
2. 同批消费 Frozen Aura 与 FrozenState；
3. 碎冰 Damage Effect 进入 round 2；
4. 碎冰使用自己的物理伤害 Profile 与 Gate。

因此，即使超载 Damage Gate 已满，钝击仍然可以打碎冻结。当前不实现击退、硬直、削韧、停滞和空间位移。

## 7. 状态与生命周期

超载自身不创建 ReactionState、周期根、资源或空间实体。ReactionStore 只保存该伤害种类的 Gate Record。后续碎冰状态属于冻结/碎冰机制，不由超载目录拥有。

## 8. 验证

当前验证覆盖：

- 两个方向和 `1:1` 精确消费；
- 角色 90 级零精通公式；
- 5 米边界与稳定目标顺序；
- 同来源同目标 `30/1` Gate；
- 目标级正常阻止和事务失败；
- Gate blocked 时超载钝击仍触发碎冰。

稳定字段见[超载反应契约](../../../../契约/元素反应/反应/超载反应契约.md)。
