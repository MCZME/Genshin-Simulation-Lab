# 旧项目能力盘点

> 状态：草案。
> 本文档用于阶段 0 的迁移盘点。它不是实现说明，而是把旧项目能力按“重设计 / 直迁 / 待确认”分类，方便后续逐项迁移。

## 1. 盘点目标

- 梳理旧项目中仍然有价值的能力。
- 区分需要重新设计的部分与可以直接迁移的部分。
- 给每个能力指定新项目归属模块。
- 为第一批迁移任务准备验收方式和 golden case 入口。

## 2. 处理方式分类

### 2.1 需要重新设计

- 资源数据库。
- 动作序列与模拟组装边界。
- UI 与交互工作流。

动作序列单独成专题，不纳入第一批直迁范围。

### 2.2 优先直迁

- 运行时骨架：事件、上下文、模拟器。
- 核心数值与规则处理：伤害、反应、生命、护盾、能量、共鸣、规则。
- 纯机制工具：附着、ICD、附魔、元素转换等。
- 内容实现：角色、武器、圣遗物、通用 handler。
- 分析与批处理：结果加工、批量模型、结果摘要。
- 只要不依赖旧 UI 形态、旧数据库结构或旧动作序列契约，就优先直迁。

### 2.3 待确认

- 依赖旧 UI 形态的逻辑。
- 依赖旧数据库结构的逻辑。
- 依赖旧动作序列契约的逻辑。
- 暂无可信来源或 golden case 的机制数值。

## 4. 第一批直迁顺序

建议阶段 0 先冻结以下直迁顺序：

1. 事件系统与上下文骨架。
2. 模拟器骨架与帧推进。
3. 伤害、反应、生命、护盾、能量等核心系统。
4. 共鸣、规则、月曜、纳塔等附加规则系统。
5. 机制工具：附着、ICD、附魔等纯算法。
6. 结果持久化与分析加工的数据模型。
7. 一个最小内容切片：一名角色、对应武器、对应圣遗物效果。

## 5. 填写规则

- 每个能力只写一个主归属模块。
- 如果同一能力同时涉及重设计和直迁，以更高风险的一侧为准。
- 直迁不等于照搬，必须重新检查模块边界和依赖方向。
- 数值相关内容必须标注来源或 golden case。
- 迁移完成后，备注栏应记录对应测试文件或验收文档。

## 6. 阶段 0 产出

阶段 0 完成时，本表应至少补齐：

- 第一批直迁能力清单。
- 第一批重设计能力清单。
- 每项能力的目标模块。
- 每项能力的验收方式。
- 每项高风险能力的待确认问题。

## 7. 下一步

下一步建议先细化“直迁能力清单”，然后再单独展开“动作序列”这一项的重设计方案。
