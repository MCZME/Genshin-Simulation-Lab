# 分析系统设计

> 状态：已确认（2026-08-12 分析系统边界与实现定稿）。
> 本文定义分析系统（Analysis）的职责、模块边界、内部分层、数据寻址与查询模型、状态还原器、属性面板与对比模型。查询与指标的具体字段见[分析系统契约](../契约/分析系统契约.md)，分阶段落地见[分析系统规划](../工程/分析系统规划.md)。
> 最后更新：2026-08-12

## 1. 定位

分析系统是结果存储系统的派生层：基于结果库的真值（运行记录、初始快照、事件流）加工出可解释、可展示、可比较的数据模型。

- 结果数据服务于分析与可视化；第一职责是还原模拟过程。
- 还原是分析的地基：任意帧状态视图由“初始快照 + 事件”折叠得到，不依赖重跑。
- 分析层不写库、不画 UI、不直接访问 SQLite 实现；通过稳定读取协议消费结果库数据。

## 2. 模块边界

| 模块 | 职责 | 约束 |
| --- | --- | --- |
| ui / cli | 消费模型并展示 | 只调用 application；不直接调用 analysis，不访问结果库 |
| application | 用例编排 | 调用 analysis，对 analysis 返回的数据模型做再处理（组合、裁剪、整形），交给 ui/cli |
| analysis | 加工 | 直接读取结果库数据（稳定读取协议），分析处理后产出数据模型；不写库 |

依赖方向单向：

```text
ui / cli -> application -> analysis -> 结果库读取（稳定读取协议/仓库）
```

要点：

- analysis 不依赖 application 的具体服务；它定义的输入协议（事件行、运行详情等）由 application 的模型满足。
- analysis 产出的模型是稳定契约（见第 8 节），application 的再处理基于契约进行。
- 批量任务、CLI、UI 共用同一条调用链，不出现绕过 application 的路径。

## 3. 内部分层

analysis 内部按加工深度分层：

1. 还原/查询层：状态还原器 + 数据寻址。输入初始快照与事件流，输出任意帧状态视图、路径查询结果。
2. 中间模型层：把事件流加工为稳定的中间序列（第一版：伤害序列、治疗序列），只承载原始数值，不携带折叠状态。
3. 指标层：从中间模型派生指标（总伤害、DPS、占比、总治疗等），不直接读事件。
4. 对比层：把多个查询结果并置呈现；不预定义领域假设。

## 4. 数据寻址与查询模型

数据寻址是 analysis 的基础能力：任何数据都可以被查询并置对比。

第一版可寻址范围：状态数据（折叠得到的任意帧状态）与事件数据（事件流中的值）。派生指标寻址后续接入。

查询模型：

- `StateQuery`：运行（一个或多个 session）、帧（单帧或多帧列表）、路径列表；不做值过滤。
- `EventQuery`：单个 session、事件类型（一个或多个）、帧范围、载荷路径（可空）、载荷字段等值过滤（第一版）、分页。

查询结果统一为“定位信息 + 值”：状态结果带 session/frame/path，事件结果带 session/ordinal/frame/event_type/path。

外部表达（UI/CLI 输入）与内部结构化查询对象分离：内部用类型化查询对象，外部用可读路径表达式；两者有明确转换关系。路径支持字段与节点两级取值，实体筛选用键值形式（如 `characters[slot=1]`），不用数组位置。

## 5. 状态还原器

- 还原器把事件流“折叠”进初始快照基线，得到任意帧状态（“折叠”源自函数式 fold：初始值 + 序列累积；正式名称采用“状态还原器”）。
- 第一版覆盖：队伍场上角色、角色生命、能量、冷却、Buff、护盾、附魔。
- 第二梯队：Aura、ICD、内容状态、空间创建/移除、Reaction 状态。
- 未接入还原的领域：状态视图中保持初始快照基线，并带“未折叠”标记，不能作为精确结果使用。
- 首版显式排除：移动状态、空间实体位置/生命周期更新（与结果存储排除项一致）；属性面板不排除（见第 6 节）。

## 6. 属性面板

属性系统是查询式解析器（基础属性 + 修饰项 → 值），所有影响属性的机制最终都经过属性系统。属性面板设计：

- 初始快照 `attributes` provider：第 0 帧完整面板，形状基于 `AttributeSnapshot`（属性 key、值、`applied_terms` 计算证据）。
- 属性系统内设面板同步器：持有面板查询集合与上次发布面板，在机制结算完成后的相位检查差异；有差异才发布 `ATTRIBUTE_PANEL_CHANGED`，载荷只含变化字段（before/after 值 + after `applied_terms`）。
- 还原器按字段更新面板；查询属性节点返回 value + `applied_terms`，可回答“属性被什么影响”。
- 第一版不存 `rejected_terms` 与 `dependency_trace`（后续增强）。

## 7. 对比模型

对比的核心定义：把满足条件查询到的数据并置呈现。任何数据都可对比——跨运行、同运行不同帧、不同实体、不同领域。跨模拟对比只是其中一种情况；具体对比方案（对齐规则、聚合口径、展示形式）在核心之上增加限制，不作为核心模型的一部分。

## 8. 稳定性规则

- analysis 产出的模型（状态视图、查询结果、中间序列、指标、属性面板）字段只增不改、语义不变；破坏性变更走新模型/新版本。
- 对外路径表达式是契约：已使用的路径语义不允许变化，新增可以。
- 中间模型与属性面板形状配冻结测试，防止无意破坏。
- 模型版本第一版随结果库 schema 版本演进，不单独设分析层版本。

## 9. 与结果存储系统的关系

- 真值层：运行记录、输入快照、初始快照、事件流（结果库）。
- 派生层：analysis 的还原视图、中间模型、指标、对比结果；可重建，不落库。
- 物化（跳变表、连续帧折叠缓存）只按性能需要建立，永远可重建。
