# 前端工程规范

> 状态：已确认（2026-08-17），进入实现前必读。
> 关联：[UI 结构与状态设计](../架构/UI/UI结构与状态设计.md)、[UI API 契约](../契约/UI API 契约.md)、[模块边界设计](../架构/模块边界设计.md)。
> 2026-08-19 更新：服务启动入口为 `server/`（`genshin-sim-server`），不再使用 `genshin-sim ui`。

## 1. 定位与边界

- `frontend/` 是仓库根目录下的独立 Web 前端工程，与 `backend/` 并列。
- 前端是纯客户端：只通过 `server/` 的 HTTP API 调用后端 application 能力，不 import 任何 Python 代码，不直接访问 SQLite，不组装仿真核心对象。
- Node.js 与 pnpm 只存在于开发/构建期；运行时由 Python 服务托管前端静态文件。
- 桌面形态与网页服务形态共用同一份前端构建产物；差异只在启动方式（server 入口 + 后置的桌面启动层）。

## 2. 技术选型

- React + TypeScript + Vite。
- 画布：React Flow（核心开源组件；Pro 商业组件未批准前不引入）。
- 包管理器：pnpm；提交 `pnpm-lock.yaml`。
- Node 版本通过 `package.json` 的 `packageManager` 与 `engines` 固定。
- 状态：`AppState`、`EditorState`、`RunState` 为纯 TypeScript 模块，不依赖 React。
- 类型：后端 OpenAPI -> `openapi-typescript` 生成 API 类型；不手写两套类型。

## 3. 目录结构

```text
frontend/
├── src/
│   ├── app/               # 应用外壳：导航、全局状态、错误反馈
│   ├── theme/             # 主题 token
│   ├── workflow/          # 定义模型、语义注册表、校验、变体编译
│   ├── state/             # AppState / EditorState / RunState
│   ├── api/               # HTTP API 客户端与类型
│   ├── components/
│   │   ├── canvas/        # 画布、区域、节点卡、连线层、框选、小地图
│   │   ├── nodes/         # 节点编辑器与 registry.tsx
│   │   ├── panels/        # 工具栏、对象面板、问题面板、结果面板（结果库浏览器）
│   │   ├── shell/         # 应用壳、设置弹窗、顶部栏、工具轨、状态栏
│   │   └── common/        # 输入框、资产选择器、表格、徽标等原语
│   └── views/             # 非画布页面：项目初始化
├── package.json
├── pnpm-lock.yaml
├── vite.config.ts
└── tsconfig.json
```

## 4. 状态与数据流

- 单向数据流：语义事件 -> `EditorState` -> 组件渲染；命令式只允许出现在高频瞬态与定制绘制组件内部。
- 视口（缩放/平移）不进 `EditorState`，归画布组件持有。
- 结果数据不进 UI 状态；UI 只持有会话引用与视图范围，按需取数。
- 组件不直接拼装 HTTP 请求，统一通过 `api/` 客户端。
- 画布布局、节点位置等持久化内容通过工作流存档 API 保存；保存是显式动作。
- 配置区域预览调用 `POST /api/v1/inputs/validate`；运行后只轮询 `GET /api/v1/runs/{run_id}`。
- 资产选择器走 `GET /api/v1/assets/{asset_type}?q=`，使用响应里的 `asset_key` 写入输入文档。

## 5. 画布约定

- React Flow 承载视口、节点、连线、选择与缩放；区域、端口命中、校验反馈为自定义组件。
- 区域在渲染层映射为 React Flow 父容器节点，区域内节点通过 `parentId` 作为子节点渲染；子节点位置在渲染层换算为区域内相对坐标，持久化契约仍保存画布绝对坐标。区域只支持调整矩形尺寸，不做内容缩放；拖动区域标题栏移动区域，内部节点绝对坐标同步平移。该映射不改变语义模型：`regions` 仍独立于 `nodes`，区域边界端口属于区域。
- 节点类型注册表：`workflow/` 持有语义 spec，`components/nodes/registry.tsx` 映射 `node_kind -> 组件`。
- 区域是强语义边界：归属、合法连线、边界端口由前端校验；后端只校验提交的 `SimulationInput`。
- 成员端口按需展开，不常驻全部成员；枚举/区间大集合使用预览与数量提示。
- 运行状态按成员展示；取消整批时运行中成员显示“正在停止”。

## 6. 质量门禁

```powershell
pnpm lint
pnpm typecheck
pnpm test
```

- `pnpm test` 使用 Vitest，覆盖状态、转换、图校验、变体编译与 API 客户端纯逻辑。
- 组件层使用壳测试与人工/截图验证；Playwright 端到端测试后置。
- 前端与后端共享同一份契约文档；契约改动必须同步 OpenAPI 与类型生成。

## 7. 构建与开发

- 开发模式：`pnpm dev`，Vite 代理到本地后端（`/api` -> `http://127.0.0.1:<port>`）；后端单独以 `genshin-sim-server` 启动。
- 生产构建：`pnpm build`，产物由 server 入口启动时托管。
- 桌面安装包（PyInstaller + pywebview）后置；MVP 先保证 server 本地启动与网页服务两种模式。
